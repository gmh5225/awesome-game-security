`README.md`:

```md
# droid-vm

在**未 root 的 Android 手机**上跑一个带真 Magisk / KernelSU(LKM) / KernelPatch(KPM) 的 Android 环境。

底座不是容器也不是 QEMU，而是 **arm64 上的 Linux/UML** —— 真 Linux 内核以普通 aarch64 用户进程的方式运行，不需要 root、KVM 或 hypervisor。于是 guest 里：

- 有真内核、真块设备、真 mount/overlayfs → 官方 Magisk 管理器走真机流程，模块真挂载；
- 能 `modprobe` 真 `.ko` → KernelSU 的 LKM 模式可用（模块须为本内核重编）；
- 能把 KernelPatch 编进内核 → APatch 的 KPM 路线可用；
- guest 本身就是 root，**不需要任何 root 权限模拟层**。

## 内核底座：`lakitu12/linux-um-arm64-gki`

不自建内核树，直接消费 **[lakitu12/linux-um-arm64-gki](https://github.com/lakitu12/linux-um-arm64-gki)**：Android 17 GKI（6.18.32）之上 95 个提交的 arm64 UML 移植。它已经解决了几件我们本来要自己做的大工程：

| 能力 | 状态 |
|---|---|
| **SMP** | `CONFIG_SMP=y`、`NR_CPUS=16`、`ncpus=` 默认「宿主核数−1」；实测 4 个 CPU 密集任务 3.19–3.76×。**ptrace 模式强制单核**，须 `seccomp=on` 才有多 vCPU |
| 同进程多线程 | 需 `stub_slots=N`（默认 1；app domain 仍会 RCU stall，未开） |
| 显示 | `umfb` 帧缓冲：脏块镜像到宿主文件/fd，配 `umview` 或 app 的 display sink |
| 图形加速 | virtio-gpu over virtio-uml PCI，2D 后端 `ci/vugpu2d.py` |
| 根盘 | ext4 与 **qcow2**（读写、refcount、压缩描述符） |
| Android guest | `config/android-guest.config`：binder/binderfs、PSI、netfilter 全套，逐条是实测 boot gate |
| 产物 | `artifacts/linux-bionic`（静态 aarch64，bionic API 30）+ `artifacts/stub_exe_bionic`（必须放同一目录） |

已知短板：块 I/O 完成走进程级 `SIGIO`，全落到 CPU0，I/O 密集任务（`docker build`）扩不起来。

## 本仓库做什么

只做「裁剪 + 叠加 + 出包」：

- `.github/workflows/kernel.yml` — 浅克隆该内核树，装 NDK r28c，按需合并 `config/page4k.config`，再叠加我们的 `kernel/config/magisk-lkm.config`，产出可直接放手机的产物
- `kernel/config/magisk-lkm.config` — 模块加载 / `KALLSYMS_ALL` / kprobe（KernelSU LKM 与第三方 `.ko` 的前提）
- `rootfs/mkrootfs-alpine.sh` — M0 用 Alpine ext4 根盘 + 手机端 `run.sh`

## 页大小

本机宿主是 4 KB 页。guest 默认 16 KB 在 4 KB 宿主上能跑（4 宿主页对 1 guest 页），但 **redroid-13 那一代 Android 用户态是 4 KB 的**，所以默认按 `pages4k=true` 出 4 KB 变体，与宿主 1:1。

`docs/M0-phone.md`:

```md
# M0：手机上跑到 shell、验多核与 umfb

目标：不 root，用 Termux 把 UML 内核跑成 aarch64 用户进程进 Alpine shell，确认
**`nproc > 1`**（`seccomp=on` 的多 vCPU 路径通了）与 **umfb 能写出帧**。

目标机红米 Note 13 Pro：宿主内核 5.10、Android 16 / SDK 36、`arm64-v8a`、
**PAGE_SIZE 4096**、MemTotal ≈ 15.6 GB → 产物取 **`um-gki618-4k`**（4 KB 页变体）。

## 1. 产物（缺一不可）

| 文件 | 说明 |
|---|---|
| `linux-bionic` | 内核本体，静态 aarch64，跑起来就是一个进程 |
| `stub_exe_bionic` | **必须与内核同目录** |
| `alpine.ext4` | 根盘（Alpine 3.20 aarch64 + `/bin/sh`） |
| `run.sh` | 启动脚本，已带 `seccomp=on` |
| `kernel-config.txt` | 核对 `.config` 用，不参与启动 |

## 2. 部署（Termux）

```sh
mkdir -p ~/droidvm && cd ~/droidvm
unzip -o ~/storage/downloads/um-gki618-4k.zip -d ~/droidvm
chmod +x linux-bionic stub_exe_bionic run.sh
```

`uml_dir` 默认 `$HOME/.uml`，Termux 家目录可写；报错时显式加 `uml_dir=$HOME/.uml`。

## 3. 启动

```sh
cd ~/droidvm && ./run.sh
```

`run.sh` 等价于：

```sh
exec ./linux-bionic mem=2048M ubd0=alpine.ext4 root=/dev/ubda rw \
     init=/bin/sh con0=null,fd:1 seccomp=on "$@"
```

多余参数原样追加，试参数不必改脚本：

```sh
./run.sh ncpus=4
./run.sh seccomp=off                                   # 单核排障基线
./run.sh umlfb=$HOME/umfb.bin:720x1280-32,hz=30,tile=64
```

## 4. 验证清单（进 shell 后）

```sh
nproc ; grep -c processor /proc/cpuinfo    # 期望 > 1（默认 宿主核数-1）
dmesg | tail -30                           # 无 panic
free -m ; ls /dev | head -30               # 有 ubda / console / fb0
```

- **`nproc` = 1**：走的是 ptrace 单核路径 —— 先查 `run.sh` 里 `seccomp=on` 是否还在；
  在但仍单核，说明宿主/ROM 拦了 `PTRACE_SYSEMU`（5.10 应支持，先看 `uname -r`）。
- `stub_exe_bionic: No such file` → 与内核不同目录或缺执行位。

## 5. umfb

`umfb` 只有命令行给了 `umlfb=` 才脱离休眠（否则 probe 返回 `-ENODEV`）：

```
umlfb=<path|fd:N>:<W>x<H>[-32][,hz=<n>][,tile=<n>]
```

- `<path>`：宿主可写文件，内核把帧（含 magic + 头）镜像进去；`fd:N` 直接写已打开的 fd。
- `-32` = 32bpp；`hz` 刷新率；`tile` 脏块尺寸（越大越省 CPU）。
- 验证：`ls -l /dev/fb0`、`cat /sys/class/graphics/fb0/virtual_size` 应与命令行一致；
  宿主机 `$HOME/umfb.bin` 大小 =「头 + W*H*4」，guest 写屏后 `md5sum` 会变。

`umview`（上游 `tools/um-arm64/umview`，SDL2）是桌面查看器；Android 上先只验文件，
真正的显示走 M2 的 hwcomposer。

## 6. 失败对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动即退无输出 | 无执行位 / 架构不符 | `chmod +x`；`file linux-bionic` 应为 aarch64 |
| `ptrace: Operation not permitted` | ROM 安全策略拦 ptrace | 先用 `seccomp=off` 单核跑通 |
| `nproc`=1 | 见 §4 | 见 §4 |
| 没有 `/dev/fb0` | 命令行没给 `umlfb=` | 见 §5 |

## 7. 下一步（M1）

M0 通过后换成 redroid `13.0.0_64only` 拆层得到的 `/system` `/vendor`，
`init=/system/bin/servicemanager` 验 binderfs（`kernel-config.txt` 里
`ANDROID_BINDER_IPC`/`ANDROID_BINDERFS` 应为 `=y`）。

# 里程碑

- **M0**：出 `linux-bionic` + `stub_exe_bionic` + Alpine 根盘，手机上 boot 到 shell，确认 `nproc > 1`（`seccomp=on` 下）与 `umfb` 可写。
- **M1**：guest 换 Android rootfs（redroid `13.0.0_64only` 拆层得 `/system`、`/vendor`），拉 `servicemanager` 验证 binderfs 通。
- **M2**：zygote + surfaceflinger + 自写 hwcomposer，帧经 `umfb` 送出 guest。
- **M3**：App 化（bionic 二进制 + 帧共享内存 + 输入注入）。
- **M4**：官方 Magisk 真装真用；KernelSU LKM 与 KernelPatch KPM 用 UML 重编模块跑通。

## 我们自己要扛的风险

1. **图形栈**：`umfb` 是平面 framebuffer，Android 要的是 gralloc + hwcomposer；virtio-gpu 的 2D 后端能否顶住 SurfaceFlinger 未验证。这是最大未知。
2. **同进程多线程不并行**：`stub_slots` 在 app domain 还 RCU stall，Android 单进程多线程性能受限（多进程仍可并行）。
3. **guest vDSO 时间**：时间回绕问题要确认这棵树是否已修。
4. **模块生态**：KSU/KPM 模块必须为 UML 重编，现成 GKI `.ko`/`.kpm` 不能直接用。
5. 上游是个人项目，需长期跟 rebase（它有 `docs/gki-notes.md` 说明换 GKI drop 的坑）。

```

## 标题

Title (English): **`arm64 UML: add kprobes support so external kernel modules (KSU-style LKMs) can load`**

## 正文（English）

Hi, and thanks for maintaining this tree — it is the only arm64 UML + GKI base I found
that runs a real 6.18 kernel as an aarch64 userspace process on an unrooted Android
phone, which is exactly the use case I needed.

**Problem.** `CONFIG_KPROBES` cannot be enabled on `ARCH=um SUBARCH=arm64`:

* `HAVE_KPROBES` / `HAVE_KRETPROBES` are selected only in `arch/arm64/Kconfig`, and
  `ARCH=um` reads `arch/um/Kconfig` instead, so the symbols are never offered.
* Even after adding the `select`s, `arch/arm64/kernel/probes/*.c` does not compile: the
  port has no `asm/kprobes.h`, arm64's `struct pt_regs` accessors (`regs->pc`,
  `regs->pstate`, `regs->regs[n]`) do not exist in UML's pt_regs, the kprobes BRK
  encoding lives in a header that pulls the real `asm/memory.h`, and there is no trap
  path from a host `SIGTRAP` into `kernel/kprobes.c`.
* `set_memory_ro/rw/rox/...` (used by the module loader and probe memory protection)
  have no UML implementation.

This matters because a whole class of out-of-tree modules depends on kprobes:
KernelSU / SukiSU / KPM-style LKMs, live-patching modules, and anything calling
`register_kprobe()`. Without it an LKM builds but cannot hook anything, so the tree
cannot be used as a Magisk/KSU host — the main reason people want a real kernel under
UML in the first place.

**What the patch does** (four layers, all inside `arch/`):

1. **Trap routing.** `arch/um/os-Linux/signal.c` intercepts a host `SIGTRAP` first and
   hands the register file to `arch/arm64/um/kprobe-trap.c`, which materialises a
   `struct pt_regs` + a synthetic ESR (EC = 0x3c, comment = the BRK immediate) and calls
   the existing non-static handlers `kprobe_brk_handler()` /
   `kprobe_ss_brk_handler()` / `kretprobe_brk_handler()`, then writes the (possibly
   rewritten) registers back so host resume continues from the patched state.
   Recursion is blocked per CPU.
2. **Text patching.** UML has no `stop_machine()`, so
   `aarch64_insn_patch_text{,_nosync}()` are implemented directly: host `mprotect()` the
   page writable, `WRITE_ONCE` the instruction word, `__builtin___clear_cache()`,
   `smp_mb()`.
3. **Page permissions.** `set_memory_ro/rw/rox/rw_nx/x/nx` map onto a new
   `os_mem_set_prot()` helper (`mprotect` / `-errno`).
4. **Headers and config.** `arch/um/Kconfig` selects `HAVE_KPROBES` /
   `HAVE_KRETPROBES`; `arch/arm64/um/asm/kprobes.h` and
   `arch/um/include/asm/kprobes.h` forward to the real arm64 header when
   `CONFIG_KPROBES && __aarch64__` (x86 UML keeps `asm-generic/kprobes.h`); minimal
   UML-side `traps.h`, `gcs.h`, `daifflags.h` stand-ins replace headers that only make
   sense on real arm64 hardware; `debug-monitors.h` gets the
   `BRK64_OPCODE_KPROBES{,_SS}` encodings and `DBG_HOOK_*`; the arm64-only accesses in
   `probes/kprobes.c` (`pstate`, `pc`, `regs[]`) go through the `PT_REGS_*` accessors,
   and the EL2 `__hyp_text*` blacklist is compiled out under `CONFIG_UML`.

Kprobes uses the XOL model here (`arch_prepare_ss_slot` writes the original instruction
followed by `BRK64_OPCODE_KPROBES_SS`), so no hardware single-step is required.

**Testing.** On `ARCH=um SUBARCH=arm64` with `CONFIG_MODULES=y`, `CONFIG_KPROBES=y`,
`CONFIG_KRETPROBES=y`, `CONFIG_KPROBE_EVENTS=y`: the kernel builds clean with clang 20
(bionic target, 4 KiB pages) and boots under UML; `insmod`/`rmmod` of a trivial module
works; a test module registering a `kprobe` on a kernel function fires, and a
`kretprobe` returns through the trampoline.

Patch attached (`0001-um-arm64-kprobes-and-module-loading.patch`, 17 files). Happy to
split it per layer, or to move the trap entry out of `os-Linux/signal.c` if you would
rather have it in `arch/um/drivers`.

+	UM_RAW_X0,
+	UM_RAW_SP = 31,
+	UM_RAW_PC,
+	UM_RAW_PSTATE,
+	UM_RAW_WORDS,
+};

+{
+	struct pt_regs regs;
+	unsigned long pc = raw[UM_RAW_PC];
+	unsigned long esr;
+	unsigned int insn;
+	int cpu, imm, ret, i;
+	bool ours;
+
+	cpu = raw_smp_processor_id();
+	if (um_kprobe_busy[cpu])
+		return 0;
+
+	if (!kernel_text_address(pc))
+		return 0;
+
+	insn = READ_ONCE(*(unsigned int *)pc);
+	if ((insn & 0xffe0001f) != AARCH64_BREAK_MON)
+		return 0;

+	for (i = 0; i < 31; i++)
+		regs.regs[i] = raw[UM_RAW_X0 + i];
+	regs.sp = raw[UM_RAW_SP];
+	regs.pc = pc;
+	regs.syscallno = NO_SYSCALL;

/*
 * 宿主 SIGTRAP -> guest kprobes 的桥。
 *
 * 本文件按宿主头文件编译，碰不到 struct pt_regs：只把 mcontext 摊成 34 个字的
 * raw 数组交给内核侧的 um_arm64_kprobe_trap()，再把可能被改过的寄存器搬回去。
 */
#include <string.h>
#include <sys/ucontext.h>

extern int um_arm64_kprobe_trap(unsigned long *raw) __attribute__((weak));

int arch_um_kprobe_trap(mcontext_t *mc)
{
	unsigned long raw[34];
	int i;

	if (!um_arm64_kprobe_trap)
		return 0;

	for (i = 0; i < 31; i++)
		raw[i] = mc->regs[i];
	raw[31] = mc->sp;
	raw[32] = mc->pc;
	raw[33] = mc->pstate;

	if (!um_arm64_kprobe_trap(raw))
		return 0;

	for (i = 0; i < 31; i++)
		mc->regs[i] = raw[i];
	mc->sp = raw[31];
	mc->pc = raw[32];
	mc->pstate = raw[33];
	return 1;

	UM_RAW_X0,
	UM_RAW_SP = 31,
	UM_RAW_PC,
	UM_RAW_PSTATE,
	UM_RAW_WORDS,
};

/* 每核防递归：kprobe 的 handler 自己再触发 BRK 时不再进入 */
static int um_kprobe_busy[NR_CPUS];

int um_arm64_kprobe_trap(unsigned long *raw)
{
	struct pt_regs regs;
	unsigned long pc = raw[UM_RAW_PC];
	unsigned long esr;
	unsigned int insn;
	int cpu, imm, ret, i;
	bool ours;

	cpu = raw_smp_processor_id();
	if (um_kprobe_busy[cpu])
		return 0;

	if (!kernel_text_address(pc))
		return 0;

	insn = READ_ONCE(*(unsigned int *)pc);
	if ((insn & 0xffe0001f) != AARCH64_BREAK_MON)
		return 0;

	imm = (insn >> 5) & 0xffff;
	ours = (imm == KPROBES_BRK_IMM) || (imm == KPROBES_BRK_SS_IMM);
#ifdef CONFIG_KRETPROBES
	ours = ours || (imm == KRETPROBES_BRK_IMM);
#endif
	if (!ours)
		return 0;

	/*
	 * UML 的 struct pt_regs 只有 regs.gp[] 一个寄存器阵列，没有 regs/sp/
	 * pc/pstate/syscallno 这些成员，全部走 PT_REGS_* 宏。
	 */
	memset(&regs, 0, sizeof(regs));
	for (i = 0; i < 31; i++)
		PT_REGS_X(&regs, i) = raw[UM_RAW_X0 + i];
	PT_REGS_SP_REG(&regs) = raw[UM_RAW_SP];
	PT_REGS_IP(&regs) = pc;
	/*
	 * 这是内核态 BRK。UML 的 user_mode(regs) 读的是 uml_pt_regs.is_user
	 * （memset 已置 0），真 arm64 读的是 pstate 模式位，所以这里把模式位
	 * 也换成 EL1h，两边对「内核态」的判定才一致。宿主线程真正的 EL/DAIF
	 * 由信号帧自己保存，这个改动不回写。
	 */
	PT_REGS_PSTATE(&regs) = (raw[UM_RAW_PSTATE] & ~UM_PSR_MODE_MASK) |
				UM_PSR_MODE_EL1h;

	esr = ((unsigned long)ESR_ELx_EC_BRK64 << ESR_ELx_EC_SHIFT) | imm;

	um_kprobe_busy[cpu] = 1;
	switch (imm) {
	case KPROBES_BRK_IMM:
		ret = kprobe_brk_handler(&regs, esr);
		break;
	case KPROBES_BRK_SS_IMM:
		ret = kprobe_ss_brk_handler(&regs, esr);
		break;
#ifdef CONFIG_KRETPROBES
	case KRETPROBES_BRK_IMM:
		ret = kretprobe_brk_handler(&regs, esr);
		break;
#endif
	default:
		ret = 0;
		break;
	}
	um_kprobe_busy[cpu] = 0;

	if (!ret)
		return 0;

	for (i = 0; i < 31; i++)
		raw[UM_RAW_X0 + i] = PT_REGS_X(&regs, i);
	raw[UM_RAW_SP] = PT_REGS_SP_REG(&regs);
	raw[UM_RAW_PC] = PT_REGS_IP(&regs);
	return 1;
}
NOKPROBE_SYMBOL(um_arm64_kprobe_trap);

/*
 * 父架构在 arch/arm64/mm/fault.c 里实现，UML 的缺页路径不经过 kprobes，
 * 返回 0 表示「不由 kprobe 处理」，与父架构的语义一致。
 */
int kprobe_fault_handler(struct pt_regs *regs, unsigned int fsr)
{
	(void)regs;
	(void)fsr;
	return 0;
}

/*
 * 宿主侧页权限辅助。
 *
 * 内核文本是本进程 ELF 的 .text（RX 映射），要写入必须先让宿主把它改成可写；
 * 模块与 kprobe 指令槽是 vmalloc 来的普通内存，要执行又必须先改成可执行。
 * 这两件事只有宿主能做，所以放在 os-Linux。
 */
#include <errno.h>
#include <sys/mman.h>
#include <sys/types.h>

int os_mem_set_prot(void *addr, unsigned long len, int prot)
{
	if (mprotect(addr, (size_t)len, prot) == 0)
		return 0;

	return -errno;
}

/*
 * --- um-kprobes: patching ---
 *
 * kprobes 与模块需要的文本改写入口。父架构的实现在 arch/arm64/kernel/patching.c，
 * 它靠「可写别名映射」加 stop_machine 保证一致性；UML 两样都没有：内核文本就是本
 * 进程 ELF 的 .text（RX 映射），改写前得让宿主 mprotect 临时开写，改完再收回去；
 * 也没有 stop_machine（arch/um 全树没有这个设施），跨 CPU 只做屏障，本核清 I-cache。
 */
#include <linux/smp.h>
#include <linux/string.h>
#include <asm/page.h>

#define UM_PROT_READ	1
#define UM_PROT_WRITE	2
#define UM_PROT_EXEC	4

extern int os_mem_set_prot(void *addr, unsigned long len, int prot);

int aarch64_insn_patch_text_nosync(void *addr, u32 insn)
{
	unsigned long page = (unsigned long)addr & PAGE_MASK;
	int ret;

	ret = os_mem_set_prot((void *)page, PAGE_SIZE,
			      UM_PROT_READ | UM_PROT_WRITE | UM_PROT_EXEC);
	if (ret)
		return ret;

	WRITE_ONCE(*(u32 *)addr, insn);
	__builtin___clear_cache((char *)addr, (char *)addr + sizeof(insn));

	/* 收回到 RX：这片内存除了指令没有别的用途 */
	os_mem_set_prot((void *)page, PAGE_SIZE, UM_PROT_READ | UM_PROT_EXEC);
	return 0;
}

int aarch64_insn_patch_text(void *addrs[], u32 insns[], int cnt)
{
	int i, ret;

	for (i = 0; i < cnt; i++) {
		ret = aarch64_insn_patch_text_nosync(addrs[i], insns[i]);
		if (ret)
			return ret;
	}

	smp_mb();
	return 0;
}

/*
 * UML 侧的 set_memory_*()。
 *
 * 真机上是页表操作，UML 里只能让宿主 mprotect。两处依赖它：
 *   - alloc_insn_page() 要把 kprobe 指令槽改成只读可执行；
 *   - UML 的 vmalloc/execmem 内存默认不可执行，模块与指令槽最终要执行。
 */
#include <linux/kernel.h>
#include <linux/mm.h>
#include <asm/page.h>

#define UM_PROT_READ	1
#define UM_PROT_WRITE	2
#define UM_PROT_EXEC	4

extern int os_mem_set_prot(void *addr, unsigned long len, int prot);

static int um_set_mem(unsigned long addr, int numpages, int prot)
{
	unsigned long start = addr & PAGE_MASK;
	unsigned long end = PAGE_ALIGN(addr + (unsigned long)numpages * PAGE_SIZE);

	if (end <= start)
		return -EINVAL;

	return os_mem_set_prot((void *)start, end - start, prot);
}

int set_memory_ro(unsigned long addr, int numpages)
{
	return um_set_mem(addr, numpages, UM_PROT_READ);
}

int set_memory_rw(unsigned long addr, int numpages)
{
	return um_set_mem(addr, numpages, UM_PROT_READ | UM_PROT_WRITE);
}

int set_memory_rox(unsigned long addr, int numpages)
{
	return um_set_mem(addr, numpages, UM_PROT_READ | UM_PROT_EXEC);
}

int set_memory_rw_nx(unsigned long addr, int numpages)
{
	return um_set_mem(addr, numpages, UM_PROT_READ | UM_PROT_WRITE);
}

int set_memory_x(unsigned long addr, int numpages)
{
	return um_set_mem(addr, numpages,
			  UM_PROT_READ | UM_PROT_WRITE | UM_PROT_EXEC);
}

int set_memory_nx(unsigned long addr, int numpages)
