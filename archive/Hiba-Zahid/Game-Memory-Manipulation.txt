# 🎮 Game Memory Manipulation & Dynamic Analysis (`AssaultCube`)

![Tool](https://img.shields.io/badge/Tool-Cheat_Engine-blue)

## 📌 Executive Summary
This repository documents a hands-on practical exercise focused on **dynamic memory manipulation and runtime analysis** inside an offline, single-player game environment (`AssaultCube`)[cite: 13, 14]. Utilizing **Cheat Engine**, the project investigates how game applications store and update core attributes—such as health, ammunition, timers, and movement speed—within system memory (RAM)[cite: 13, 14, 15].

## 🔍 Core Practical Experiments & Methodology

### 1. Player Health & Ammunition Modification
* **Exact Value Scanning:** Scanned for initial integer states (e.g., health value of `100`, bullet count of `20`)[cite: 15, 16].
* **Value Filtering:** Triggered in-game actions (taking damage or firing weapons) to isolate memory addresses matching changed values[cite: 15, 16].
* **Memory Injection/Patches:** Overwrote target memory addresses (`008AFBE0`) to scale player health to `5000` and ammo counts to `9999`, confirming that numerical runtime variables directly govern player survivability and inventory[cite: 15, 16].

### 2. Time & Speed Manipulation (Speedhacking)
* **Speedhack Integration:** Deployed Cheat Engine's built-in speed control framework to alter global application timing (`Speed = 500`)[cite: 17].
* **Behavioral Observation:** Validated that time-scaling affects the entire game loop concurrently, modifying player movement velocity, enemy reaction rates, and environmental pacing[cite: 17].

### 3. Structure Analysis (Structure Spider)
* **Offset Mapping:** Leveraged the *Structure Spider* feature starting from known base regions (`00C0F080`) to inspect clustered memory blocks[cite: 18].
* **Layout Discovery:** Mapped how related game attributes (health, ammunition, and custom stats) are systematically organized close to one another in memory structures via relative offsets[cite: 18].

### 4. Low-Level Inspection via Memory Viewer
* **Assembly & Opcode Tracing:** Inspected raw memory regions and disassembly views (`ac_client.exe` offsets) to analyze how instructions (`mov`, `test`, `je`, arithmetic shifting operations) process stored data dynamically during execution[cite: 19, 20].

---

## 📊 Key Observations
* **Dynamic State Mapping:** In-game attributes exist as mutable numeric types in RAM; altering them yields immediate visual and mechanical feedback in the game client[cite: 20].
* **Multi-Layered Analysis:** Moving from simple exact value scans to advanced structure mapping and memory viewer debugging provides a comprehensive bridge between high-level game variables and low-level assembly execution[cite: 20].
