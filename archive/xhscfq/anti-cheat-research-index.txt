# Anti-Cheat Research Index

A structured index of my public engineering work and retained research
references related to defensive anti-cheat development, Windows kernel
security, virtualization, and reverse engineering.

> This repository is a research map. Repositories identified as forks are
> retained as technical references and are not presented as original work.

## Research Areas

| Area | Research focus |
| --- | --- |
| Anti-Cheat Architecture | Detection surfaces, telemetry design, trust boundaries, and validation |
| Windows Kernel Security | Driver trust, callbacks, process and thread context, memory integrity |
| Kernel Execution | Manual-mapped drivers, executable memory, shellcode, and abnormal execution |
| Graphics Integrity | Presentation-path hooks, overlays, and rendering modifications |
| Virtualization | Intel VT-x, EPT instrumentation, VM-exit analysis, and hardware tracing |
| Reverse Engineering | x86/x64 analysis, anti-debugging, devirtualization, and control-flow recovery |
| Game Technology | Unreal Engine runtime analysis and DirectX security boundaries |

## Research Methodology

Defensive anti-cheat research should be evaluated through a repeatable process:

1. Define the threat model and trust boundary.
2. Identify observable signals and required telemetry.
3. Evaluate false positives and compatibility risks.
4. Measure performance and operational cost.
5. Validate assumptions against representative test cases.
6. Document limitations and unsupported conclusions.

## Responsible Research

All material referenced here is intended for authorized security testing,
defensive anti-cheat engineering, malware analysis, interoperability, and
education.

This index does not endorse cheating, unauthorized access, disruption of online
services, or violation of software agreements.
