`README.md`:

```md
# Windows hardware identity inventory

`hwid.exe` is a native C++20, read-only Windows 10/11 x64 console tool.
It inventories what Windows and device drivers expose, with provenance,
confidence, mutability, availability, and per-field diagnostics. It does not
compute a combined machine fingerprint or claim that every value is unique.

## Build

Install Visual Studio 2022 or newer with **Desktop development with C++**, a
Windows 10/11 SDK, CMake 3.25 or newer, and Ninja. In an **x64 Native Tools
Command Prompt** or an initialized **Developer PowerShell**:

```powershell
cmake --preset windows-x64
cmake --build --preset windows-x64
ctest --preset windows-x64
.\build\windows-x64\hwid.exe --help
```

The preset builds Release with tests enabled. No packages are downloaded and
no third-party build dependencies are required. Alternatively, use a Visual
Studio generator (no Ninja required):

```powershell
cmake -S . -B build/vs2022 -G "Visual Studio 17 2022" -A x64
cmake --build build/vs2022 --config Release
ctest --test-dir build/vs2022 -C Release --output-on-failure
.\build\vs2022\Release\hwid.exe --json --redact
```

Use the generator matching your Visual Studio version. CMake's install target
can copy the executable to a chosen destination:

```powershell
cmake --install build/windows-x64 --prefix out
```

If multiple toolchains are installed, initialize the MSVC x64 environment
before configuring. An incomplete developer environment can select an unrelated
MinGW linker. After fixing the environment, use `cmake --fresh --preset windows-x64`.
The executable uses the MSVC runtime; other machines need the matching Microsoft
Visual C++ x64 Redistributable.

## Usage

```powershell
hwid.exe
hwid.exe --json
hwid.exe --verbose --redact
hwid.exe --component motherboard
hwid.exe --component storage --json
hwid.exe --tpm-info
```

Components: `system`, `motherboard`, `bios`, `tpm`, `storage`, `network`,
`usb`, `gpu`, `sdEmmc` (also `sd-emmc`), and `cpu`.
`--component` selects one collector; it does not run the other collectors.
`--tpm-info` is an alias for `--component tpm`.

Each collector also has a direct switch: `--system`, `--motherboard`, `--bios`,
`--tpm`, `--storage`, `--network`, `--usb`, `--gpu`, `--sd-emmc`, and `--cpu`.
For example, `hwid.exe --storage --json` runs only the storage collector.
Use one collector switch at a time; omitting the filter runs all ten.
Direct switches work with `--json`, `--verbose`, and `--redact`.

By default, stdout contains tables grouped by component and device, with
`Identifier`, `Value`, and `Status` columns. Values are not truncated.
Use `--verbose` to include provenance, confidence, mutability, raw values and
diagnostics below each table. `--json` switches stdout to machine-readable JSON.

Exit codes: **0** means the inventory completed, including partial failures;
**1** means a fatal application/output error; **2** means invalid arguments.
Inspect each result's `available`, `status`, and `error` for device failures.
The application never requests elevation or changes device/TPM configuration.

## Implemented collectors

| Category | Data and source | Limits |
| --- | --- | --- |
| System | WMI `Win32_ComputerSystemProduct.UUID`, vendor, name | Rejects malformed, zero and FF UUIDs; virtual/OEM firmware can change them |
| Motherboard | All WMI `Win32_BaseBoard` rows: manufacturer, product, serial | Retains and flags OEM placeholders |
| BIOS | WMI `Win32_BIOS` manufacturer, version, serial | Labels the BIOS-reported system/service serial without claiming a ROM-chip ID |
| Storage | SetupAPI disk interfaces, `IOCTL_STORAGE_QUERY_PROPERTY` descriptor, physical drive number where available | Serial is storage-stack reported; RAID/USB/virtual layers can substitute or hide it |
| Network | IP Helper adapters; current MAC and `GetIfEntry2` permanent MAC, type/status/hardware flag | Includes virtual interfaces; permanent MAC remains driver-reported |
| USB | Present USB devnodes, VID/PID, manufacturer, instance ID, unique-ID capability | Labels serial inferred from physical USB instance component; does not read iSerialNumber directly |
| TPM | TBS presence/version; WMI state and `IsReady`; CNG public EK/certificate blob SHA-256 | Readiness may require admin access; failures remain explicit; no certificate trust or attestation verification |
| GPU | All DXGI adapters: PCI model IDs, revision, local LUID, software flag; optional NVML UUID and board serial | DXGI LUID is transient; NVML enumeration is separate and not assumed to match DXGI ordering |
| SD/eMMC | Storage devices reporting SD/MMC bus types, storage-stack serial | CID explicitly unsupported in this version; USB readers may hide the card's bus type |
| CPU | CPUID vendor/brand/family/model/stepping/features; WMI processors | CPUID describes the current logical processor; modern x86/x64 unique serial explicitly unavailable |

NVIDIA NVML loads dynamically from the Windows system directory using a
restricted DLL search. Missing DLLs or unsupported functions do not abort the
scan. AMD/Intel vendor UUID backends are explicitly reported as unimplemented;
their adapters still receive DXGI inventory.

Protocol-specific NVMe queries, controller-specific SD CID paths, AMD/Intel
vendor identity backends, TPM key enrollment, and attestation are future
extensions from the plan. `--create-device-key` and `--tpm-attestation` are not
implemented; unknown options fail rather than silently doing something else.
Passive TPM inventory does not create persisted keys or export private keys.

## Results and privacy

JSON has `schemaVersion: 1`, a `redacted` flag, and ten component arrays.
Unselected component arrays are empty. Each record includes:

```json
{
  "component": "storage",
  "deviceName": "PhysicalDrive0",
  "identifierType": "Storage serial",
  "rawValue": "  EXAMPLE  ",
  "normalizedValue": "EXAMPLE",
  "source": "IOCTL_STORAGE_QUERY_PROPERTY/STORAGE_DEVICE_DESCRIPTOR.SerialNumberOffset",
  "confidence": "InterfaceAssigned",
  "status": "available",
  "potentiallyMutable": true,
  "available": true,
  "error": "Storage-stack-reported serial; bridge, RAID or virtual controller may substitute it. Not an NVMe namespace identifier."
}
```

The `error` field may also contain an explanatory caveat on an available result.
Statuses distinguish missing devices, access denial, unsupported operations,
unexposed fields, placeholders, and query failures. Numeric API codes and
HRESULTs are preserved in diagnostics. An empty enumeration produces a
not-present result. Failure in one collector does not prevent subsequent ones.

Normalization trims boundary whitespace/NULs without removing internal spaces.
UUIDs become lowercase and MACs uppercase colon-separated hex. Raw values are
retained, including placeholders. TPM output intentionally contains only hashes
of public provider blobs, not certificate contents; those hashes are still
persistent identifiers and are not an authentication proof.

Nothing is automatically transmitted or saved to disk. Both normal output and
`--json` can expose persistent identifiers. `--redact` masks **all** values,
device names, and diagnostics in both writers, including verbose raw values.
Structural metadata and statuses remain visible. Output is UTF-8, with JSON
escaping and escaped control characters in console strings. To save a report,
explicitly redirect stdout yourself.

## Validation

CTest includes normalization and malformed descriptor fixtures, Unicode/JSON
escaping, invalid placeholders, error isolation and access-denied classification,
missing devices, multiple records, redaction, CLI parsing, and a live inventory
smoke test. Tests use explicit checks in Release builds, not disabled `assert`s.
The integration script parses JSON with PowerShell and never logs raw IDs.

Local validation: MSVC 19.44 x64 Release with Windows SDK 10.0.26100.0 built
without warnings; all four CTest tests passed (35 unit/fixture checks). The
live scan ran without elevation and returned usable data for system,
motherboard, BIOS, TPM, storage, network, USB, GPU, and CPU. This host did not
expose an SD/MMC disk. Restricted and unsupported fields remained explicit.

Validation on this development host does not establish the entire hardware
matrix in the plan. Repeat `ctest` on Windows 10/11 physical machines and a
Hyper-V/VMware VM, as standard user, and check NVMe/SATA/RAID, USB bridges,
multiple NICs/GPUs, SD readers, absent/disabled TPM, and optional NVIDIA hardware.
No unavailable hardware is emulated as a successful identifier.

namespace hwid {
Options parseCli(std::span<const std::string_view> args) {
    Options o;
    auto select = [&](std::string_view name) {
        if (!o.component.empty()) throw std::invalid_argument("Specify only one component filter");
        o.component = name == "sd-emmc" ? "sdEmmc" : name;
        if (std::find(components.begin(), components.end(), o.component) == components.end())
            throw std::invalid_argument("Unknown component: " + o.component);
    };
    for (size_t i = 0; i < args.size(); ++i) {
        auto a = args[i];
        if (a == "--help" || a == "-h") o.help = true;
        else if (a == "--json") o.json = true;
        else if (a == "--verbose") o.verbose = true;
        else if (a == "--redact") o.redact = true;
        else if (a == "--component" || a == "--tpm-info") {
            if (a == "--tpm-info") select("tpm");
            else {
                if (++i == args.size()) throw std::invalid_argument("--component requires a name");
                select(args[i]);
            }
        }
        else if (a.starts_with("--") && (a == "--sd-emmc" ||
            std::find(components.begin(), components.end(), a.substr(2)) != components.end())) select(a.substr(2));
        else throw std::invalid_argument("Unknown option: " + std::string(a));
    }
    return o;
}
std::string_view usage() {
    return "hwid - read-only Windows hardware inventory\n"
        "Usage: hwid [--json] [--verbose] [--redact] [--component NAME]\n"
        "Default output: console tables grouped by component and device.\n"
        "Components: system motherboard bios tpm storage network usb gpu sdEmmc cpu\n"
        "Select one collector (omit to collect all):\n"
        "  --system      System UUID, vendor and name\n"
        "  --motherboard Motherboard manufacturer, product and serial\n"
        "  --bios        BIOS manufacturer, version and reported serial\n"
        "  --tpm         TPM presence, state and endorsement fingerprints\n"
        "  --storage     Disk bus, model, revision and serial\n"
        "  --network     Network addresses and adapter metadata\n"
        "  --usb         USB device IDs and serial information\n"
        "  --gpu         GPU identifiers\n"
        "  --sd-emmc     SD/eMMC storage identifiers and CID availability\n"
        "  --cpu         CPU identification and features\n"
        "  --component NAME  Equivalent named component filter\n"
        "  --tpm-info    Alias for --component tpm\n"
        "  --json        Versioned UTF-8 JSON with raw and normalized values\n"
        "  --verbose     Add sources, confidence, raw values and diagnostics below tables\n"
        "  --redact      Mask all values, device names and diagnostic text\n"
        "  --help        Show this help\n"

#include "Collectors.h"
#include "common/Error.h"
#include <iterator>
namespace hwid {
HardwareResults collectSafely(std::string_view component, const std::function<HardwareResults()>& collector) {
    try {
        auto results = collector();
        if (results.empty()) results.push_back(unavailable(std::string(component), "", "Inventory", "Windows enumeration", "No devices reported", IdStatus::NotPresent));
        return results;
    } catch (const WindowsError& e) {
        return {unavailable(std::string(component), "", "Inventory", "Windows API", e.what(), errorStatus(e.code))};
    } catch (const std::exception& e) {
        return {unavailable(std::string(component), "", "Inventory", "Collector", e.what(), IdStatus::QueryFailed)};
    }
}
HardwareResults collectAll(std::string_view component) {
    using Collector = HardwareResults(*)();
    constexpr Collector collectors[] = {collectSystem, collectMotherboard, collectBios, collectTpm, collectStorage,
        collectNetwork, collectUsb, collectGpu, collectSdEmmc, collectCpu};
    HardwareResults results;
    for (size_t i = 0; i < components.size(); ++i) {
        if (!component.empty() && component != components[i]) continue;
        auto rows = collectSafely(components[i], collectors[i]);
        results.insert(results.end(), std::make_move_iterator(rows.begin()), std::make_move_iterator(rows.end()));
    }
    return results;
}
}

#include "Collectors.h"
#include "common/Strings.h"
#include "windows/WmiClient.h"
#include <intrin.h>
#include <cstring>
namespace hwid {
HardwareResults collectCpu() {
    HardwareResults results;
    auto add = [&](std::string type, std::string value, std::string source) {
        results.push_back(identifier("cpu", "Current logical processor", type, value, source, IdConfidence::Informational, true, false));
    };
#if defined(_M_X64) || defined(_M_IX86)
    int regs[4]{};
    __cpuid(regs, 0);
    const int maxLeaf = regs[0];
    char vendor[13]{};
    std::memcpy(vendor, &regs[1], 4); std::memcpy(vendor + 4, &regs[3], 4); std::memcpy(vendor + 8, &regs[2], 4);
    add("Vendor", vendor, "CPUID leaf 0");
    if (maxLeaf >= 1) {
        __cpuidex(regs, 1, 0);
        auto eax = static_cast<unsigned>(regs[0]);
        auto family = (eax >> 8) & 15;
        auto model = (eax >> 4) & 15;
        if (family == 6 || family == 15) model |= ((eax >> 16) & 15) << 4;
        if (family == 15) family += (eax >> 20) & 255;
        add("Family", std::to_string(family), "CPUID.1.EAX");
        add("Model", std::to_string(model), "CPUID.1.EAX");
        add("Stepping", std::to_string(eax & 15), "CPUID.1.EAX");
        add("Feature bits ECX", hexNumber(static_cast<unsigned>(regs[2]), 8), "CPUID.1.ECX");
        add("Feature bits EDX", hexNumber(static_cast<unsigned>(regs[3]), 8), "CPUID.1.EDX");
    }
    __cpuid(regs, static_cast<int>(0x80000000u));
    if (static_cast<unsigned>(regs[0]) >= 0x80000004u) {
        char brand[49]{};
        for (unsigned i = 0; i < 3; ++i) { __cpuid(regs, static_cast<int>(0x80000002u + i)); std::memcpy(brand + i * 16, regs, 16); }
        add("Brand", std::string(brand, 48), "CPUID extended brand leaves");
    }
#else
    results.push_back(unavailable("cpu", "", "CPUID", "Compiler architecture", "CPUID is only implemented on x86/x64", IdStatus::NotSupported));
#endif
    auto wmi = collectSafely("cpu", [] {
        WmiClient client;
        HardwareResults rows;
        for (const auto& r : client.query(L"SELECT DeviceID, Name, ProcessorId FROM Win32_Processor", {L"DeviceID", L"Name", L"ProcessorId"})) {
            auto device = r.at(L"DeviceID").text;
            for (auto property : {L"Name", L"ProcessorId"}) {
                const auto& value = r.at(property);
                if (!value.error.empty()) rows.push_back(unavailable("cpu", device, utf8(property), "Win32_Processor." + utf8(property), value.error));
                else rows.push_back(identifier("cpu", device, utf8(property), value.text, "Win32_Processor." + utf8(property), IdConfidence::Informational, true, false));
            }
        }
        return rows;
    });
    results.insert(results.end(), wmi.begin(), wmi.end());
    results.push_back(unavailable("cpu", "", "Unique CPU serial", "x86/x64 CPU identification semantics",
        "A generally usable unique CPU serial is not exposed on modern x86/x64 PCs. CPUID and ProcessorId are identification data, not unique serials.", IdStatus::NotSupported));
    return results;
}
}

#include "Collectors.h"
#include "common/Error.h"
#include "common/Strings.h"
#include <dxgi1_2.h>
#include <wrl/client.h>
#include <memory>
#include <cstring>
namespace hwid {
namespace {
class IGpuIdentityProvider {
public:
    virtual ~IGpuIdentityProvider() = default;
    virtual HardwareResults collect() = 0;
};
class DxgiGpuProvider final : public IGpuIdentityProvider {
public:
    HardwareResults collect() override {
        Microsoft::WRL::ComPtr<IDXGIFactory1> factory;
        checkHr(CreateDXGIFactory1(IID_PPV_ARGS(&factory)), "CreateDXGIFactory1");
        HardwareResults results;
        for (UINT i = 0;; ++i) {
            Microsoft::WRL::ComPtr<IDXGIAdapter1> adapter;
            auto hr = factory->EnumAdapters1(i, &adapter);
            if (hr == DXGI_ERROR_NOT_FOUND) break;
            checkHr(hr, "IDXGIFactory1::EnumAdapters1");
            DXGI_ADAPTER_DESC1 desc{};
            hr = adapter->GetDesc1(&desc);
            if (FAILED(hr)) {
                results.push_back(unavailable("gpu", "DXGI adapter " + std::to_string(i), "Adapter description", "IDXGIAdapter1::GetDesc1", windowsError("GetDesc1", hr), errorStatus(hr)));
                continue;
            }
            auto name = "DXGI " + std::to_string(i) + " (" + utf8(desc.Description) + ")";
            auto add = [&](std::string type, std::string value, std::string field) {
                results.push_back(identifier("gpu", name, type, value, "DXGI_ADAPTER_DESC1." + field, IdConfidence::Informational, true, false));
            };
            add("Vendor ID", hexNumber(desc.VendorId, 4), "VendorId");
            add("Device ID", hexNumber(desc.DeviceId, 4), "DeviceId");
            add("Subsystem ID", hexNumber(desc.SubSysId, 8), "SubSysId");
            add("Revision", hexNumber(desc.Revision, 2), "Revision");
            add("Adapter LUID (local, transient)", hexNumber(static_cast<ULONG>(desc.AdapterLuid.HighPart), 8) + hexNumber(desc.AdapterLuid.LowPart, 8), "AdapterLuid");
            add("Software adapter", (desc.Flags & DXGI_ADAPTER_FLAG_SOFTWARE) ? "true" : "false", "Flags");
            results.push_back(unavailable("gpu", name, "Physical GPU UUID/serial", "DXGI",
                "DXGI does not expose a physical GPU serial/UUID. PCI IDs identify a model; LUID is only locally unique.", IdStatus::NotSupported));
        }
        return results;
    }
};
// Minimal stable NVML C ABI; no build-time dependency on NVIDIA headers or libraries.
class NvidiaGpuProvider final : public IGpuIdentityProvider {
    using Device = struct nvmlDevice_st*;
    using Init = int(__cdecl*)();
    using Shutdown = int(__cdecl*)();
    using Count = int(__cdecl*)(unsigned*);
    using GetDevice = int(__cdecl*)(unsigned, Device*);
    using GetString = int(__cdecl*)(Device, char*, unsigned);
    HMODULE module_ = nullptr;
    Shutdown shutdown_ = nullptr;
    bool initialized_ = false;
    template<class T> T symbol(const char* name) {
        auto address = GetProcAddress(module_, name);
        // GetProcAddress is Windows' documented runtime symbol resolution mechanism.
        T fn{};
        static_assert(sizeof(fn) == sizeof(address));
        std::memcpy(&fn, &address, sizeof(fn));
        return fn;
    }
public:
    ~NvidiaGpuProvider() override { if (initialized_ && shutdown_) shutdown_(); if (module_) FreeLibrary(module_); }
    HardwareResults collect() override {
        module_ = LoadLibraryExW(L"nvml.dll", nullptr, LOAD_LIBRARY_SEARCH_SYSTEM32);
        if (!module_) return {unavailable("gpu", "NVIDIA provider", "NVML UUID", "NVML (optional)",
            windowsError("LoadLibraryExW(System32/nvml.dll)", GetLastError()), IdStatus::NotSupported)};
        auto init = symbol<Init>("nvmlInit_v2"); shutdown_ = symbol<Shutdown>("nvmlShutdown");
        auto count = symbol<Count>("nvmlDeviceGetCount_v2");
        auto device = symbol<GetDevice>("nvmlDeviceGetHandleByIndex_v2");
        auto uuid = symbol<GetString>("nvmlDeviceGetUUID");
        auto name = symbol<GetString>("nvmlDeviceGetName");

            code = device(i, &gpu);
            if (code) { results.push_back(failure(label, "Device", "nvmlDeviceGetHandleByIndex_v2", code)); continue; }

            };

        }

HardwareResults storage(bool sdOnly) {
    const std::string component = sdOnly ? "sdEmmc" : "storage";
    HardwareResults results;
    const auto paths = deviceInterfaces(GUID_DEVINTERFACE_DISK);
    for (const auto& path : paths) {
        auto name = utf8(path);
        try {
            WinHandle handle(CreateFileW(path.c_str(), 0, FILE_SHARE_READ | FILE_SHARE_WRITE, nullptr, OPEN_EXISTING, 0, nullptr));
            if (!handle.valid()) throw WindowsError("CreateFileW(disk)", GetLastError());
            STORAGE_PROPERTY_QUERY query{}; query.PropertyId = StorageDeviceProperty; query.QueryType = PropertyStandardQuery;
            STORAGE_DESCRIPTOR_HEADER header{};
            DWORD returned = 0;
            if (!DeviceIoControl(handle.get(), IOCTL_STORAGE_QUERY_PROPERTY, &query, sizeof(query), &header, sizeof(header), &returned, nullptr))
                throw WindowsError("IOCTL_STORAGE_QUERY_PROPERTY(header)", GetLastError());

                throw std::runtime_error("Invalid storage descriptor size");
            std::vector<unsigned char> buffer(header.Size);
            if (!DeviceIoControl(handle.get(), IOCTL_STORAGE_QUERY_PROPERTY, &query, sizeof(query), buffer.data(), static_cast<DWORD>(buffer.size()), &returned, nullptr))
                throw WindowsError("IOCTL_STORAGE_QUERY_PROPERTY", GetLastError());
            if (returned < sizeof(STORAGE_DEVICE_DESCRIPTOR) || returned > buffer.size()) throw std::runtime_error("Truncated storage descriptor");
            STORAGE_DEVICE_DESCRIPTOR descriptor{};
            std::memcpy(&descriptor, buffer.data(), sizeof(descriptor));
            if (descriptor.Size > returned || descriptor.Size < sizeof(descriptor)) throw std::runtime_error("Inconsistent storage descriptor size");
            buffer.resize(descriptor.Size);
            const auto bus = descriptor.BusType;
            if (sdOnly && bus != BusTypeSd && bus != BusTypeMmc) continue;
            STORAGE_DEVICE_NUMBER number{};
            if (DeviceIoControl(handle.get(), IOCTL_STORAGE_GET_DEVICE_NUMBER, nullptr, 0, &number, sizeof(number), &returned, nullptr) && returned >= sizeof(number))
                name = "PhysicalDrive" + std::to_string(number.DeviceNumber);
            auto add = [&](std::string type, std::string value, std::string field, bool identity = false) {
                auto r = identifier(component, name, type, value, "IOCTL_STORAGE_QUERY_PROPERTY/STORAGE_DEVICE_DESCRIPTOR." + field,
                    identity ? IdConfidence::InterfaceAssigned : IdConfidence::Informational, true, identity);

                if (value.empty()) { r.status = IdStatus::NotExposed; r.error = "Storage driver does not expose this field"; }
                results.push_back(std::move(r));
            };
            add("Bus", busName(bus), "BusType");
            add("Vendor", descriptorString(buffer, descriptor.VendorIdOffset), "VendorIdOffset");
            add("Model", descriptorString(buffer, descriptor.ProductIdOffset), "ProductIdOffset");

HardwareResults collect(std::string component, std::wstring klass, std::vector<std::wstring> fields, std::wstring identity, std::string type) {
    WmiClient wmi;
    std::wstring query = L"SELECT ";
    for (const auto& f : fields) { if (query != L"SELECT ") query += L", "; query += f; }
    auto rows = wmi.query(query + L" FROM " + klass, fields);
    HardwareResults results;
    size_t index = 0;
    for (const auto& row : rows) {
        auto device = component + " " + std::to_string(index++);
        for (const auto& field : fields) {
            const auto& v = row.at(field);
            auto source = utf8(klass) + "." + utf8(field);
            auto label = field == identity ? type : utf8(field);
            if (!v.error.empty()) { results.push_back(unavailable(component, device, label, source, v.error)); continue; }
            auto r = identifier(component, device, label, v.text, source,
                field == identity ? IdConfidence::FirmwareAssigned : IdConfidence::Informational, true, field == identity);
            if (field == L"UUID") {
                r.normalizedValue = normalizeUuid(r.rawValue);
                r.available = !r.normalizedValue.empty();
                r.status = r.available ? IdStatus::Available : IdStatus::Invalid;
                r.error = r.available ? "" : "Invalid, all-zero or all-FF SMBIOS UUID";
            }
            results.push_back(std::move(r));
        }
    }
    return results;
}

std::string windowsError(std::string_view api, DWORD code) {
    wchar_t text[2048]{};

IdStatus errorStatus(DWORD code) {
    if (code == ERROR_ACCESS_DENIED || code == static_cast<DWORD>(E_ACCESSDENIED) || code == static_cast<DWORD>(WBEM_E_ACCESS_DENIED) || code == static_cast<DWORD>(NTE_PERM)) return IdStatus::AccessDenied;

    if (code == ERROR_NOT_FOUND || code == ERROR_FILE_NOT_FOUND || code == ERROR_DEVICE_NOT_CONNECTED) return IdStatus::NotPresent;
    return IdStatus::QueryFailed;
}

std::string utf8(std::wstring_view v) {
    if (v.empty()) return {};
    if (v.size() > static_cast<size_t>(std::numeric_limits<int>::max())) throw std::runtime_error("UTF-16 input too large");
    const auto size = static_cast<int>(v.size());
    int n = WideCharToMultiByte(CP_UTF8, WC_ERR_INVALID_CHARS, v.data(), size, nullptr, 0, nullptr, nullptr);
    if (!n) throw std::runtime_error("Invalid UTF-16 returned by Windows");
    std::string out(n, '\0');
    if (!WideCharToMultiByte(CP_UTF8, WC_ERR_INVALID_CHARS, v.data(), size, out.data(), n, nullptr, nullptr))
        throw std::runtime_error("UTF-16 conversion failed");
    return out;
}
std::string trim(std::string_view v) {
    auto pad = [](unsigned char c) { return c == 0 || std::isspace(c); };
    while (!v.empty() && pad(static_cast<unsigned char>(v.front()))) v.remove_prefix(1);
    while (!v.empty() && pad(static_cast<unsigned char>(v.back()))) v.remove_suffix(1);
    return std::string(v);
}
std::string lower(std::string v) {
    for (auto& c : v) c = static_cast<char>(std::tolower(static_cast<unsigned char>(c)));
    return v;
}
bool isPlaceholderHardwareId(std::string_view value) {
    const auto v = lower(trim(value));
    for (auto p : {"", "to be filled by o.e.m.", "to be filled by o.e.m", "default string", "none", "unknown", "not specified", "not applicable", "n/a"})
        if (v == p) return true;
    bool hasDigit = false;
    for (char c : v) {
        if (c == '0') hasDigit = true;
        else if (c != '-' && c != ':' && c != '{' && c != '}' && c != ' ') return false;
    }
    return hasDigit;
}
std::string normalizeUuid(std::string_view value) {
    auto v = lower(trim(value));
    if (v.size() == 38 && v.front() == '{' && v.back() == '}') v = v.substr(1, 36);
    if (v.size() != 36) return {};
    bool zero = true, ff = true;
    for (size_t i = 0; i < v.size(); ++i) {
        if (i == 8 || i == 13 || i == 18 || i == 23) { if (v[i] != '-') return {}; }
        else {
            if (!std::isxdigit(static_cast<unsigned char>(v[i]))) return {};
            zero &= v[i] == '0'; ff &= v[i] == 'f';
        }
    }
    return zero || ff ? std::string{} : v;
}
std::string hex(std::span<const unsigned char> bytes) {
    constexpr char digits[] = "0123456789ABCDEF";
    std::string out;
    for (auto b : bytes) { out += digits[b >> 4]; out += digits[b & 15]; }
    return out;
}
std::string mac(std::span<const unsigned char> bytes) {
    std::string out;
    for (auto b : bytes) { if (!out.empty()) out += ':'; out += hex({&b, 1}); }
    return out;
}
std::string hexNumber(std::uint64_t value, int width) {
    std::ostringstream out;
    out << std::uppercase << std::hex << std::setfill('0') << std::setw(width) << value;
    return out.str();
}
std::string descriptorString(std::span<const unsigned char> bytes, std::uint32_t offset) {
    if (!offset) return {};
    if (offset >= bytes.size()) throw std::runtime_error("Storage descriptor string offset outside buffer");
    auto start = bytes.begin() + offset;
    auto end = std::find(start, bytes.end(), 0);
    if (end == bytes.end()) throw std::runtime_error("Unterminated storage descriptor string");
    // STORAGE_DEVICE_DESCRIPTOR strings are ASCII. Reject malformed driver data.
    if (std::any_of(start, end, [](auto c) { return c > 127; })) throw std::runtime_error("Non-ASCII storage descriptor string");
    return std::string(start, end);
}
std::string jsonQuote(std::string_view value) {
    std::string out = "\"";
    for (unsigned char c : value) {
        switch (c) {
        case '"': out += "\\\""; break;
        case '\\': out += "\\\\"; break;
        case '\b': out += "\\b"; break;
        case '\f': out += "\\f"; break;
        case '\n': out += "\\n"; break;
        case '\r': out += "\\r"; break;
        case '\t': out += "\\t"; break;
        default: if (c < 32) out += "\\u00" + hex({&c, 1}); else out += static_cast<char>(c);
        }
    }
    return out + '"';
}

    constexpr std::string_view names[] = {"HardwareBacked", "ManufacturerAssigned", "FirmwareAssigned", "InterfaceAssigned", "Informational", "Unknown"};
    return names[static_cast<size_t>(v)];
}

    constexpr std::string_view names[] = {"available", "not supported", "not present", "access denied", "driver does not expose value", "invalid/placeholder", "query failed"};
    return names[static_cast<size_t>(v)];
}

std::string safe(std::string_view s, bool redact) { return redact && !s.empty() ? "[redacted]" : std::string(s); }
// Escape control characters in device-provided strings, including terminal escape sequences.
std::string console(std::string_view s) {
    auto quoted = jsonQuote(s);
    return quoted.substr(1, quoted.size() - 2);
}

void writeJson(std::ostream& out, const HardwareResults& results, bool redact) {
    out << "{\n  \"schemaVersion\": 1,\n  \"redacted\": " << (redact ? "true" : "false");
    for (auto component : components) {
        out << ",\n  " << jsonQuote(component) << ": [";
        bool first = true;
        for (const auto& r : results) {
            if (r.component != component) continue;
            if (!first) out << ',';
            first = false;
            out << "\n    {";
            auto field = [&](std::string_view k, std::string_view v) { out << jsonQuote(k) << ": " << jsonQuote(v) << ", "; };
            field("component", r.component); field("deviceName", safe(r.deviceName, redact));
            field("identifierType", r.identifierType); field("rawValue", safe(r.rawValue, redact));
            field("normalizedValue", safe(r.normalizedValue, redact)); field("source", r.source);
            field("confidence", toString(r.confidence)); field("status", toString(r.status));
            out << "\"potentiallyMutable\": " << (r.potentiallyMutable ? "true" : "false")
                << ", \"available\": " << (r.available ? "true" : "false") << ", \"error\": " << jsonQuote(safe(r.error, redact)) << '}';
        }
        out << (first ? "]" : "\n  ]");
    }
    out << "\n}\n";
}
void writeConsole(std::ostream& out, const HardwareResults& results, bool verbose, bool redact) {
    std::string previous;
    for (size_t begin = 0; begin < results.size();) {
        const auto& first = results[begin];
        size_t end = begin + 1;
        while (end < results.size() && results[end].component == first.component && results[end].deviceName == first.deviceName) ++end;
        if (first.component != previous) { out << '\n' << first.component << '\n'; previous = first.component; }
        if (!first.deviceName.empty()) out << "  " << console(safe(first.deviceName, redact)) << '\n';

        using Row = std::array<std::string, 3>;
        std::vector<Row> rows{{"Identifier", "Value", "Status"}};
        for (size_t i = begin; i < end; ++i) {
            const auto& r = results[i];
            rows.push_back({console(r.identifierType), r.available ? console(safe(r.normalizedValue, redact)) : "-", std::string(toString(r.status))});
        }
        // Count UTF-8 characters rather than bytes when padding. Values are never truncated.
        auto width = [](std::string_view text) {
            return static_cast<size_t>(std::count_if(text.begin(), text.end(), [](unsigned char c) { return (c & 0xC0) != 0x80; }));
        };
        std::array<size_t, 3> widths{};
        for (const auto& row : rows)
            for (size_t column = 0; column < widths.size(); ++column) widths[column] = std::max(widths[column], width(row[column]));
        auto border = [&] {
            out << "  +";
            for (auto size : widths) out << std::string(size + 2, '-') << '+';
            out << '\n';
        };
        border();
        for (size_t i = 0; i < rows.size(); ++i) {
            out << "  |";
            for (size_t column = 0; column < widths.size(); ++column)
                out << ' ' << rows[i][column] << std::string(widths[column] - width(rows[i][column]) + 1, ' ') << '|';
            out << '\n';
            if (i == 0) border();
        }
        border();
        if (verbose) {
            for (size_t i = begin; i < end; ++i) {
                const auto& r = results[i];
                out << "    " << console(r.identifierType) << ":\n"
                    << "      Source: " << console(r.source) << " | Confidence: " << toString(r.confidence)
                    << " | Mutable: " << (r.potentiallyMutable ? "possibly" : "no") << '\n'
                    << "      Raw: " << console(safe(r.rawValue, redact)) << '\n';
                if (!r.error.empty()) out << "      Note: " << console(safe(r.error, redact)) << '\n';
            }
        }
        begin = end;
    }
    if (!verbose && !results.empty()) out << "\nUse --verbose for sources, confidence, raw values and diagnostics.\n";
}
}

if ($inventory.schemaVersion -ne 1 -or !$inventory.redacted) { throw 'Incorrect schema or redaction mode' }
$components = @('system','motherboard','bios','tpm','storage','network','usb','gpu','sdEmmc','cpu')
foreach ($component in $components) {
    $rows = @($inventory.$component)
    if ($rows.Count -eq 0) { throw "Missing results for $component" }
    foreach ($row in $rows) {
        if ($row.component -ne $component -or !$row.source -or !$row.identifierType -or !$row.status) { throw "Incomplete row for $component" }
        if ($row.available -ne ($row.status -eq 'available')) { throw "Inconsistent availability in $component" }
        foreach ($field in @('rawValue','normalizedValue','deviceName','error')) {
            if ($row.$field -and $row.$field -ne '[redacted]') { throw "Redaction leaked $component.$field" }
        }
    }
    Write-Output "$component`: $($rows.Count) records; $(@($rows | Where-Object available).Count) available"
}
$filtered = ((& $Executable --json --redact --cpu) -join "`n") | ConvertFrom-Json
if ($LASTEXITCODE -ne 0 -or @($filtered.cpu).Count -eq 0) { throw 'Component filter failed' }
foreach ($component in $components | Where-Object { $_ -ne 'cpu' }) {
    if (@($filtered.$component).Count -ne 0) { throw "Filter included $component" }
}
if (!($filtered.cpu | Where-Object { $_.identifierType -eq 'Unique CPU serial' -and !$_.available })) { throw 'CPU uniqueness semantics missing' }

# Windows C++ Hardware Identity Reader --- Implementation Plan

## 1. Objective

Build a native Windows console application in modern C++ that
inventories hardware identifiers exposed by Windows, device firmware, or
vendor APIs.

The program should collect identifiers from:

-   Computer system / SMBIOS system UUID
-   Motherboard serial number
-   BIOS serial number
-   TPM 2.0 identity information
-   NVMe SSD serial numbers
-   SATA SSD/HDD serial numbers
-   Network adapter permanent MAC addresses
-   USB device serial numbers
-   GPU identifiers / UUIDs where available
-   SD/eMMC CID or equivalent identifiers where Windows exposes them
-   CPU identification information, while explicitly reporting that a

    x86/x64 Windows PCs

The application should **not claim that every returned value is globally
unique**. Each result should include its provenance and reliability.

### Language and toolchain

-   Visual Studio 2022 or newer
-   MSVC x64 build
-   Windows 10/11
-   CMake for the build system
-   Unicode Windows APIs (`W` variants)

## 3. Design Principles

1.  **Read only.** Do not modify firmware, device configuration,
    registry identifiers, TPM state, or network configuration.
2.  **Prefer documented Windows APIs.** Use WMI/CIM when Windows does
    not provide a simpler documented API.
3.  **Keep raw and normalized values separate.** Preserve the value
    returned by Windows and create a second normalized representation
    for comparison.
4.  **Record provenance.** Every identifier must say where it came from.
5.  **Treat absence as normal.** OEMs and device manufacturers may omit
    identifiers.
6.  **Never silently substitute identifiers.** A missing motherboard
    serial must remain missing rather than being replaced with another
    field.
7.  **Do not call an identifier unique unless its semantics justify that
    claim.**
8.  **Support multiple devices.** A PC can have multiple disks, NICs,
    GPUs, and USB devices.
9.  **Avoid unnecessary administrator requirements.** Run as a standard
    user by default and clearly report access-denied cases.
10. **Separate collection from policy.** Hardware collection should not
    itself decide whether two machines are the same machine.

A collector should return:

using HardwareResults = std::vector<HardwareIdentifier>;

## 6. Windows API Strategy by Hardware Type

### 6.1 System UUID

**Goal:** obtain the SMBIOS/system UUID representing the computer
system.

Primary implementation:

-   Query WMI class `Win32_ComputerSystemProduct`.
-   Read its `UUID` property.

Alternative/lower-level implementation:

-   Call `GetSystemFirmwareTable()` with the raw SMBIOS provider.
-   Parse the SMBIOS System Information structure (Type 1).
-   Extract the UUID field.

Recommended first implementation: WMI.

Record:

``` text
component: system
identifierType: SMBIOS System UUID
source: Win32_ComputerSystemProduct.UUID
```

Validation:

-   Reject an all-zero UUID.
-   Reject an all-`FF` UUID.
-   Detect known placeholder strings.
-   Preserve the raw UUID before normalization.

Caveat: virtual machines commonly expose virtual SMBIOS UUIDs, and
firmware/OEM tooling can sometimes change the value.

------------------------------------------------------------------------

### 6.2 Motherboard Serial Number

Primary implementation:

-   WMI class: `Win32_BaseBoard`
-   Properties:
    -   `Manufacturer`
    -   `Product`
    -   `SerialNumber`

Record each baseboard returned rather than assuming exactly one.

Validation should recognize placeholders such as:

``` text
To Be Filled By O.E.M.
Default string
None
Unknown
Not Specified
```

Do not discard these silently; mark them invalid/unreliable and retain
the raw value for diagnostics.

------------------------------------------------------------------------

### 6.3 BIOS / System Firmware Serial

Primary implementation:

-   WMI class: `Win32_BIOS`
-   Read:
    -   `SerialNumber`
    -   `Manufacturer`
    -   `SMBIOSBIOSVersion`

The BIOS serial frequently corresponds to the OEM system/service serial
rather than a serial belonging to the BIOS ROM itself. Label it
according to the Windows field instead of interpreting it as a
cryptographically unique BIOS chip ID.

------------------------------------------------------------------------

## 7. TPM 2.0

TPM requires special treatment because it is fundamentally different
from reading a disk serial.

### Goals

Determine:

1.  Whether a TPM exists.
2.  Whether it is enabled/ready.
3.  TPM specification/version information.
4.  Whether an Endorsement Key identity/certificate can be accessed
    through supported Windows interfaces.
5.  Whether the application can use TPM-backed keys for a stronger
    machine identity.

### Recommended Windows interfaces

Investigate and implement against:

-   Windows TPM Base Services (TBS)
-   CNG / NCrypt platform crypto provider
-   TPM-related WMI/CIM interfaces where appropriate

Relevant Windows components include:

``` text
tbs.h
tbs.lib
ncrypt.h
ncrypt.lib
bcrypt.h
bcrypt.lib
```

### Important architecture decision

Do **not** treat an EK private key as a readable serial number. TPM
private key material is specifically designed not to be exported.

For a robust identity system, prefer:

``` text
Application creates key pair
        ↓
Private key protected by TPM
        ↓
Public key exported
        ↓
Public-key fingerprint becomes application device identity
```

The TPM collector can separately expose TPM metadata and, where
supported and authorized, public endorsement information.

### Optional advanced mode

``` text
hwid.exe --tpm-attestation
```

This can later implement attestation rather than merely inventorying TPM
metadata.

------------------------------------------------------------------------

## 8. NVMe SSD Serial Numbers

Prefer direct storage APIs over WMI.

### Enumeration

Enumerate physical disks using:

``` text
\\.\PhysicalDrive0
\\.\PhysicalDrive1
...
```

Open each device with `CreateFileW()` using the minimum required access.

### Query

Use:

``` text
DeviceIoControl()
IOCTL_STORAGE_QUERY_PROPERTY
```

Query `StorageDeviceProperty` and parse `STORAGE_DEVICE_DESCRIPTOR`.

Useful fields include:

-   Vendor ID
-   Product ID
-   Product revision
-   Serial number

For NVMe-specific information, investigate the documented storage
protocol-specific query path where necessary.

### Output

``` text
Disk 0
Bus: NVMe
Model: ...
Serial: ...
```

Do not assume disk ordering remains stable between boots or hardware
changes.

------------------------------------------------------------------------

## 9. SATA SSD/HDD Serial Numbers

Use the same storage abstraction as NVMe where possible.

Primary query:

``` text
IOCTL_STORAGE_QUERY_PROPERTY
```

Parse:

``` cpp
STORAGE_DEVICE_DESCRIPTOR
```

Inspect bus type to distinguish:

``` text
SATA
ATA
SCSI
USB
NVMe
RAID
```

Where a controller/RAID layer hides the underlying device serial, report
that limitation instead of inventing a fallback.

A storage collector should therefore produce zero or more results:

``` cpp
HardwareResults collectStorageIdentifiers();
```

## 10. Network Adapter Permanent MAC Addresses

Do not confuse the currently configured MAC address with a permanent
hardware address.

### Enumeration

Use IP Helper API:

``` cpp
GetAdaptersAddresses()
```

This is useful for:

-   adapter enumeration
-   interface LUID/index
-   current physical address
-   friendly name
-   adapter status

### Permanent address

For adapters where Windows/network-driver interfaces expose it, query
the permanent hardware address through the appropriate NDIS/device
interface rather than assuming `GetAdaptersAddresses()` always
represents the factory address.

Collect both fields when available:

``` text
Current MAC
Permanent MAC
```

If they differ:

``` text
potentiallyMutable: true
```

Normalize MAC values as:

``` text
AA:BB:CC:DD:EE:FF
```

Filter carefully rather than blindly excluding:

-   virtual adapters
-   VPN adapters
-   Hyper-V adapters
-   loopback
-   Bluetooth
-   Wi-Fi
-   Ethernet

Expose adapter type in output so the caller can decide what to use.

------------------------------------------------------------------------

## 11. USB Device Serial Numbers

USB serial numbers are optional; many USB devices do not implement them.

### Enumeration

Use Windows device enumeration APIs, preferably Configuration Manager
APIs or SetupAPI.

Possible interfaces:

``` text
CM_Get_Device_Interface_List
SetupDiGetClassDevs
SetupDiEnumDeviceInfo
SetupDiGetDeviceInstanceId
SetupDiGetDeviceRegistryProperty
```

Useful values:

-   VID
-   PID
-   device instance ID
-   serial component of the device identity where supplied by the device
-   friendly name
-   manufacturer

Important distinction:

``` text
USB\VID_1234&PID_5678\SERIAL123
```

may contain a manufacturer-provided serial, while some Windows-created
instance identifiers are not equivalent to a factory serial.

The collector must explicitly label which form was obtained.

## 12. GPU Identifiers

GPU identity is vendor-dependent.

### Baseline implementation

Enumerate display adapters using:

-   DXGI (`IDXGIFactory`, `IDXGIAdapter`)
-   Windows device enumeration APIs

Collect:

-   vendor ID
-   device ID
-   subsystem ID
-   revision
-   adapter description
-   locally unique Windows adapter identifier where available

These identify the adapter type/instance but are **not necessarily a
globally unique physical GPU serial**.

### Vendor-specific optional providers

Add optional backends later:

``` text
NVIDIA → NVML
AMD    → vendor-supported management/API interfaces
Intel  → vendor-supported interfaces where applicable
```

Only expose a GPU UUID/serial as such when the vendor API explicitly
defines it.

Architecture:

``` cpp
class IGpuIdentityProvider
{
public:
    virtual ~IGpuIdentityProvider() = default;
    virtual HardwareResults collect() = 0;
};
```

Implement:

``` text
DxgiGpuProvider
NvidiaGpuProvider
AmdGpuProvider
IntelGpuProvider
```

The program must continue functioning when vendor libraries are absent.

------------------------------------------------------------------------

## 13. SD Card and eMMC Identity

These devices may expose CID information at the hardware/protocol level,
but generic Windows applications cannot assume direct CID access for
every reader/controller.

Implementation strategy:

1.  Enumerate storage devices.
2.  Determine bus/device type.
3.  Query documented Windows storage properties first.
4.  Attempt protocol-specific queries only when supported by the storage
    stack.
5.  Report CID as unavailable when the controller or driver does not
    expose it.

Never substitute the volume serial number for an SD/eMMC CID.

These are fundamentally different:

``` text
CID                    → hardware/device protocol identity
Volume serial number   → filesystem/format metadata
```

## 14. CPU Information

Modern x86/x64 processors generally should not be expected to expose a
usable globally unique CPU serial number to ordinary Windows software.

The CPU collector should therefore collect **identification**, not claim
uniqueness.

Use:

``` cpp

__cpuidex()
```

Collect:

-   CPU vendor
-   family
-   model
-   stepping
-   brand string
-   feature information

Optionally compare this with:

``` text
Win32_Processor.ProcessorId
```

Output should explicitly state:

``` text
Unique CPU serial: unavailable/not supported
```

Do not incorporate CPUID model information into a device identity under
the assumption that it is unique.

## 18. Error Handling

A hardware inventory utility must expect partial failure.

Do not terminate the complete scan because one collector fails.

Example:

``` text

``` text

formatted Windows error message

## 19. Privilege Model

The program should first run without elevation.

Each collector should classify its result as:

``` text
available
not supported
not present
access denied
driver does not expose value
invalid/placeholder
query failed
```

Only document administrator mode for operations that demonstrably
require it.

Do not automatically relaunch elevated.

## 20. Security and Privacy

Hardware identifiers are persistent identifiers and can become
privacy-sensitive when stored or transmitted.

Recommended rules:

-   Never transmit identifiers automatically.
-   Never write identifiers to disk unless explicitly requested.
-   Do not log TPM certificate material unnecessarily.
-   Provide `--redact` for support/debug output.
-   Avoid using a concatenation of raw serial numbers as a password or
    cryptographic secret.
-   Do not assume hashing an identifier makes a low-entropy or guessable
    identifier secret.
-   Clearly document what `--json` exposes.

Example redaction:

``` text
NVMe Serial: S3********92
MAC:         AA:BB:**:**:EE:FF
UUID:        4C4C****-****-****-****-********1234
```

------------------------------------------------------------------------

## 21. Device Fingerprinting Policy

If the eventual objective is a stable machine identifier, keep that
logic outside the collectors.

Do **not** simply calculate:

``` text
SHA256(
    motherboard_serial +
    disk_serial +
    mac_address
)
```

and assume it permanently identifies the computer.

Hardware changes make that approach brittle.

Instead separate:

``` text
Hardware inventory
        ↓
Identity policy
        ↓
Application device identity
```

For stronger identity:

``` text
First application enrollment
        ↓
Generate asymmetric key
        ↓
Protect private key using TPM/CNG
        ↓
Export public key
        ↓
SHA-256(public key)
        ↓
Application Device ID
```

Hardware serials can then be supporting telemetry rather than the root
identity.

## 24. Important Edge Cases

Handle all of the following:

-   OEM returns `"To Be Filled By O.E.M."`
-   serial field is empty
-   serial is all zeros
-   UUID is all zeros or all `FF`
-   WMI service unavailable
-   multiple motherboards/baseboards reported
-   multiple GPUs
-   multiple NICs
-   MAC randomization/current MAC differs from permanent MAC
-   virtual NICs
-   USB device has no serial descriptor
-   storage behind RAID controller
-   USB/SATA bridge substitutes its own serial
-   NVMe namespace/controller distinctions
-   TPM disabled in firmware
-   TPM present but unavailable to current process
-   GPU vendor library not installed
-   SD reader hides CID
-   virtual machine presents synthetic identifiers

## 25. Suggested API Surface

Each collector should have a narrow interface:

``` cpp
namespace hwid
{
    HardwareResults collectSystem();
    HardwareResults collectMotherboard();
    HardwareResults collectBios();
    HardwareResults collectTpm();
    HardwareResults collectStorage();
    HardwareResults collectNetwork();
    HardwareResults collectUsb();
    HardwareResults collectGpu();
    HardwareResults collectSdEmmc();
    HardwareResults collectCpu();
}
```

The application layer then orchestrates them:

``` cpp
HardwareResults collectAll()
{
    HardwareResults result;

    append(result, collectSystem());
    append(result, collectMotherboard());
    append(result, collectBios());
    append(result, collectTpm());
    append(result, collectStorage());
    append(result, collectNetwork());
    append(result, collectUsb());
    append(result, collectGpu());
    append(result, collectSdEmmc());
    append(result, collectCpu());

    return result;
}
```

A failure in one function must not prevent subsequent collectors from
running.

## 26. Dependencies

Prefer Windows SDK functionality wherever practical.

Likely Windows libraries:

``` text

ole32.lib
oleaut32.lib
iphlpapi.lib
setupapi.lib
cfgmgr32.lib
dxgi.lib
tbs.lib
ncrypt.lib

```

Exact linkage should be added only when the corresponding implementation
requires it.

For JSON, either:

1.  use a small well-maintained C++ JSON dependency, or
2.  implement a narrowly scoped JSON writer.

Do not hand-build JSON using unescaped string concatenation.

## 27. Definition of Done

Version 1 is complete when:

-   The program builds cleanly as x64 C++ on supported Windows versions.
-   Standard-user execution works for the normal inventory path.
-   Every requested hardware category has a collector.
-   Unsupported identifiers are explicitly reported rather than
    fabricated.
-   Multiple disks/NICs/GPUs/USB devices are represented independently.
-   Raw values and normalized values remain distinguishable.
-   Placeholder OEM values are detected.
-   Console and JSON output are supported.
-   Errors from one collector do not abort the entire scan.
-   The program never describes CPU model data, a volume serial, a
    transient MAC, or a Windows device instance identifier as a
    guaranteed globally unique hardware serial.
-   TPM-backed identity is kept conceptually separate from passive
    hardware inventory.
-   Tests cover physical machines and at least one virtualized
    environment.

## 28. Recommended Development Order

The lowest-risk implementation sequence is:

``` text
1. Core result/error/output framework
2. WMI helper
3. System UUID
4. Motherboard
5. BIOS
6. CPU
7. Storage
8. Network
9. USB
10. TPM
11. DXGI GPU enumeration
12. Vendor-specific GPU providers
13. SD/eMMC
14. TPM-backed application identity
15. Integration and VM testing
```

This order gets useful results quickly while leaving the hardware- and
vendor-specific portions until the common Windows infrastructure is
stable.

The critical boundary is between **inventory** and **identity**. The
inventory layer reports exactly what Windows and the hardware expose; a
