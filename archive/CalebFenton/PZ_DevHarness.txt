# PZ_DevHarness

## Commands

- The harness has no suite of its own; a mod that uses it is the test. From that mod's repository, run `dev/run-debug-client.sh --test` and `dev/run-debug-client.sh --test --mp`, plus `dev/validate-server.sh` after a change to the server's start.

## Rules

- Several mods use this repository as their `dev/harness` submodule. Keep it free of any one mod's names, paths and settings: those come from the mod's `dev/harness.conf` and its dev mod's `PZHarness.register` settings.
- A change to a conf key, a setting, a flag, a console line or a test library function updates every mod that uses the harness in the same change, and the doc that describes it: `docs/adopting.md` for the conf and the library, `docs/running.md` for flags, environment and console lines, `docs/debugging.md` for how to spend runs.
- A change reaches a mod only through its submodule pointer: push the harness, then in each mod `git -C dev/harness pull --ff-only origin master` and commit the pointer.
- Never edit `bin/` or `lib/` while one of their runs is going: bash reads a script as it runs, and an edit under it breaks that run.

## Read when needed

- Before changing the runner, the leak check or the server channel, read `mod/42/media/lua/client/PZHarness/TestLib.lua`'s header and `docs/multiplayer.md`: the rules that keep each test independent, and what a multiplayer client can and can't do.

`README.md`:

```md
# PZ_DevHarness

Automated tests for Project Zomboid Build 42 mods, played in the real game. Each test is a few lines of Lua: what a player does (pick something up, choose a menu option, craft, pull a part off a car) and what should be true afterwards. One command starts the game, plays every test with nobody at the keyboard, in single player or against a real dedicated server, then quits and tells you what broke and why.

It's fast enough that you'll run the tests after every change instead of promising yourself you'll run them before release. Renewable Energy, the mod it was built for, runs its whole suite in about a minute in single player and a little over two in multiplayer, game startup included.

## What a run looks like

A test queues what the player does in `run`, and checks the result in `validate`:

```lua
T.test("mymod_kettle_makes_tea", {
    hour = 10,
    run = function(self)
        T.give(self, "kettle", { { type = "MyMod.Kettle" } })
        T.step(function()
            local kettle = T.player():getInventory():getFirstType("MyMod.Kettle")
            ISTimedActionQueue.add(MyMod.BoilAction:new(T.player(), kettle))
        end)
        T.count(self, "after", { "MyMod.Tea" })
    end,
    validate = function(self)
        T.expect(self.counts.after["MyMod.Tea"] == 1, "boiling the kettle made no tea")
    end,
})
```

The character performs the same timed action a player would, animation and all, so the test exercises the mod's real code. Here is a trimmed run of a real Renewable Energy test that caught a multiplayer bug: after a player pulled the bulb out of a garden light, the lamp kept shining on their screen until the next game minute.

```text
$ TESTS==renewable_energy_gadgets_garden_light_remove_bulb dev/run-debug-client.sh --test --mp
RETest START 1
RETest FAIL renewable_energy_gadgets_garden_light_remove_bulb: this client's lamp went out only at a later game minute (7.75 s)
RETest DONE passed=0 failed=1 skipped=0
FAIL: not every test passed
--failed reruns: renewable_energy_gadgets_garden_light_remove_bulb
```

The script exits 0 only when every test passed and no Lua error was logged, so it can gate a commit or a release.

## What it does for you

### It plays the game for you

Zomboid already ships a test runner, in its debug menu: you launch the game, load a world, click through **Debug** > **Dev** > **Unit Tests** > **Timed Actions** > **Run All Tests**, and watch your character perform each test. The harness runs the same kind of test with no hands. It starts the game in debug mode without Steam, in a throwaway folder of its own, so your saves, settings and mod list are never touched. It loads three mods: your published mod, a dev mod that holds your tests, and the harness itself. The dev mod is never uploaded, so the mod your players download holds only game code.

Runs are silent, since the harness turns every volume down in its own folder. Only one game runs at a time across every mod that uses the harness; a second run waits its turn instead of fighting the first over ports and your keyboard.

### It reaches into the game with Java

Project Zomboid is a Java program. Lua mods, the harness's own Lua included, only get the parts of it the developers handed to Lua, and some of what a hands-free run needs isn't among them. Lua can't press "Click to start" on the loading screen, for one, so an unattended game would wait there forever.

So the harness doesn't start the game the usual way. It starts a small Java launcher of its own, [`ClickToStart.java`](java/ClickToStart.java), which starts the real game inside the same program. Sharing the program lets the launcher look at the game's internals while it runs, through Java's reflection: code can look up another class's private fields by name and change them. The launcher waits for the loading screen and sets the flag a real click would set. It also gives the game more worker threads for loading textures, models and animations; the game uses 4, and on an M3 Max the loading screen went from about 8 seconds to about 2. The dedicated server for multiplayer runs starts through a twin, [`FastServer.java`](java/FastServer.java), which does the same for the server's loading and took its start from about 18.5 seconds to about 14.

Nothing gets patched. The game's files stay as Steam installed them, and the launchers live only in the harness, never in your published mod. If a game update renames something they reach for, they print so and leave the game alone: it loads slower, or waits for you to click.

### It's quick

| | Vanilla debug menu | PZ_DevHarness |
| --- | --- | --- |
| Starting a run | Launch through Steam, load a world, click through the menus. | One command. |
| Between tests | A one-second pause so you can read the result. | The next tick. |
| Frame rate | Your frame cap, 60 frames a second by default. | Uncapped, about 260 frames a second on an M3 Max. Anything counted in ticks finishes sooner. |
| Loading screen | About 8 seconds. | About 2 seconds, with more loader threads. |
| Rerunning after you edit a test | Restart the game. | A second or two plus the tests' own time, in a game kept open with `--stay`. |
| A test that hangs | The runner waits for it forever. | It fails after 30 seconds, names what it was waiting for, and the next test starts. |
| A Lua error | The debug error handler stops the game until you notice. | The run ends at once and prints the stack trace. |
| Multiplayer | Host a server, start a second game, and join it. | `--mp`. |

You also don't have to run everything. `TESTS=<prefix>` picks tests by name, `--failed` reruns only what failed last time, and `--changed` runs the tests that cover the files you changed since your last commit, using a map from your files to your tests that you keep in the harness's config.

### It tests multiplayer on one computer

Multiplayer is where mods break quietly. Each player's game holds its own copy of the world, and the server holds another. A mod that changes one copy without telling the others works fine in single player and goes wrong on a server. `--mp` starts a dedicated server and a client that joins it as admin, on the same computer, and runs the same tests.

The test library's helpers (setting the clock, sandbox options, skills, giving items) change the client's copy and the server's, so a test written once runs in both modes. What only the server can do goes in named handlers in your dev mod's server Lua, which tests call with `T.server`. After each test, wherever a square changed, the harness compares the client's copy of it with the server's and reports each one that still disagrees as a `DESYNC`. A separate script, `dev/validate-server.sh`, boots a dedicated server with only your mod and fails if the mod logged an error while it loaded.

### Every test starts from the same world

A test that passes alone and fails after another sends you hunting in the wrong place, so the harness keeps tests apart. Between tests it resets the character: full health, empty inventory, nothing worn or held, skills restored, back on its starting square. Within a test, every helper that changes something records how to undo it (the clock, sandbox options, the power grid, the tiles, benches and vehicles a test placed), and the undos run when the test ends, pass or fail.

Then it checks. After each test the harness compares the world around the character, the character, the sandbox options and the clock with how they were before, and a test that left something behind fails, naming what it left. The world itself is held still: no zombies, and none of the random furnishing the game does when a building first loads (generators in garages, crash sites, parked cars, rats), so no test meets an object nobody placed. In multiplayer the harness also waits for the server to confirm skills, recipes and daylight before a test reads them.

### It helps you chase a flaky test

`REPEAT=20` runs the selection 20 times in one game and counts each test's passes and failures. `ORDER=shuffle` runs tests in a random order and prints the seed, so `ORDER=shuffle:<seed>` repeats that exact order. Each run also prints the slowest tests and, in multiplayer, how long each spent waiting on the server.

### It's built for AI coding assistants too

An assistant left alone with a test suite tends to rerun the same failing run hoping for a different answer. The harness won't let it: a run whose tests, settings and files haven't changed since its last verdict prints that verdict instead of starting the game, and after a test fails three runs in a row the script says to stop rerunning and change the approach. Your mod's own static checks can run before every game, so a typo costs seconds instead of a game start. Several assistants editing at once share the one game through the lock.

### It runs more than tests

A mod can register its own modes, each a `--<mode>` flag that starts the scenario, runs the mod's code and quits. Renewable Energy uses them to take the screenshots for its Workshop page, with the weather held clear so the same shot looks the same tomorrow.

## Quick start

You need macOS, Project Zomboid Build 42 installed through Steam, and a Java JDK of any version from 8 on, because the game's bundled Java can't compile the launchers.

1. Add the harness to your mod's repository:

    ```sh
    git submodule add https://github.com/CalebFenton/PZ_DevHarness.git dev/harness
    ```

2. Give the harness a `dev/harness.conf`, two one-line entry scripts and a dev mod that holds your debug scenario and tests. [Adopting PZ_DevHarness](docs/adopting.md) shows each file.

3. Run every test, then quit:

    ```sh
    dev/run-debug-client.sh --test
    ```

    The run ends with `<TAG> DONE passed=<n> failed=0 skipped=<n>` and exits 0.

4. Run the same tests against a dedicated server:

    ```sh
    dev/run-debug-client.sh --test --mp
    ```

5. While you work on a few tests, keep the game open so each rerun skips the startup:

    ```sh
    TESTS=mymod_craft_ dev/run-debug-client.sh --test --stay
    ```

#!/usr/bin/env bash
# Starts the game client in debug mode (no Steam) with its own cache dir, the mod, its dev mod and
# the harness mod enabled. A mod's dev/run-debug-client.sh runs this; docs/running.md describes the
# modes and the environment variables, and docs/adopting.md dev/harness.conf.
#
#   (no flag)        play by hand: the main menu, with the mod's debug scenario under Scenarios
#                    and its tests in the debug menu's timed action tests
#   --test           starts the scenario, runs the mod's tests and quits. Runs unattended:
#                    java/ClickToStart.java presses "Click to start", and the display is kept
#                    awake. Prints the results and exits 1 if a test failed or any Lua error was
#                    logged.
#   --test --stay    the same, but the game stays open after the run, and the next --test --stay
#                    reruns the tests in it after loading the conf's RELOAD_FILES again. Any other
#                    change to the mods restarts the game. While it waits it shows and logs
#                    "<TAG> IDLE"; it quits after 30 minutes without a run, or when another run
#                    needs the game.
#   --test --mp      the same in multiplayer: starts a dedicated server with the three mods and a
#                    client that joins it as the admin, runs the tests on the client, and fails on
#                    a problem in either log. With --stay both stay open, and the next
#                    --test --mp --stay reruns the tests, the server loading its share of the
#                    RELOAD_FILES again too.
#   --test --failed  runs only the tests that failed, or were running when the game stopped, in
#                    the last --test run of the same kind (with or without --mp)
#   --test --changed runs the tests the conf's TEST_MAP gives for the files changed since HEAD
#   --<mode>         one of the conf's MODES: starts the scenario and runs the mod's handler for it
#                    instead of the tests
#
# With --test, REPEAT=<n> runs the selection n times in one game, ORDER=reverse or
# ORDER=shuffle[:<seed>] changes the order, and LEAKS=fail (the default), warn or off sets what the
# leak check between tests does. docs/running.md and docs/debugging.md describe them.
set -euo pipefail
. "$(dirname "${BASH_SOURCE[0]}")/../lib/harness.sh"

usage() {
    local modes=
    for mode in ${MODES:-}; do
        modes="$modes | --$mode"
    done
    echo "usage: $0 [--test [--mp] [--stay] [--failed | --changed]$modes]" >&2
    exit 2
}
MODE= STAY= MP= FAILED= CHANGED=
for arg in "$@"; do
    case "$arg" in
        --test) MODE=test ;;
        --stay) STAY=1 ;;
        --mp) MP=1 ;;
        --failed) FAILED=1 ;;
        --changed) CHANGED=1 ;;
        --*)
            case " ${MODES:-} " in
                *" ${arg#--} "*) MODE=${arg#--} ;;
                *) usage ;;
            esac
            ;;
        *) usage ;;
    esac
done
if { [ -n "$STAY" ] || [ -n "$MP" ] || [ -n "$FAILED" ] || [ -n "$CHANGED" ]; } && [ "$MODE" != test ]; then
    usage
fi
if [ -n "$FAILED" ] && [ -n "$CHANGED" ]; then
    usage
fi
if { [ -n "$FAILED" ] || [ -n "$CHANGED" ]; } && [ -n "${TESTS:-}" ]; then
    echo "TESTS picks the tests itself; leave it out with --failed or --changed" >&2
    exit 2
fi
if [ -n "$MP" ]; then
    CACHE="${CACHE:-$TMP_REAL/$CACHE_NAME-mpclient}"
    SERVER_CACHE="${SERVER_CACHE:-$TMP_REAL/$CACHE_NAME-mpserver}"
    # Off the default 16261, so a real server can keep running.
    SERVER_PORT=${SERVER_PORT:-16361}
else
    CACHE="${CACHE:-$TMP_REAL/$CACHE_NAME-client}"
fi
# What the run does, comma-separated: for --test TESTS name prefixes or exact "=<name>" names
# (from --failed or --changed when given), else the variable the conf names in
# MODE_SELECTION_<mode>.
SELECTION=
MARK=$TAG
# The test runs' settings, which the runner reads with the selection.
LEAKS=${LEAKS:-fail} ORDER=${ORDER:-} ROUNDS=${REPEAT:-1}
# Where --failed finds what failed last, one line per kind of run: "<test or test-mp>
# <name>:<runs>,...", each test that failed with the number of runs of that kind in a row it has
# failed.
FAILED_KEY="test${MP:+-mp}"
# Runs in a row a test may fail before the script says reruns aren't narrowing it down.
STUCK_RUNS=3

# The exact names of the tests that failed in the last run of this kind, as a selection.
select_failed() {
    local line names
    line=$(grep "^$FAILED_KEY " "$RUNS_FAILED" 2>/dev/null | tail -1 || true)
    if [ -z "$line" ]; then
        echo "--failed: no $FAILED_KEY run has been recorded in ${RUNS_FAILED#"$REPO/"} yet" >&2
        exit 2
    fi
    names=$(sed 's/:[0-9]*//g' <<< "${line#"$FAILED_KEY "}")
    if [ -z "$names" ]; then
        echo "--failed: nothing failed in the last $FAILED_KEY run; no tests to run"
        exit 0
    fi
    echo "--failed: rerunning what failed in the last $FAILED_KEY run: ${names//,/, }"
    SELECTION="=${names//,/,=}"
}

# Every file changed since HEAD, staged, unstaged or untracked, relative to the repository, the
# harness submodule's own changes included.
changed_files() {
    local submodule=${HARNESS#"$REPO/"}
    {
        git -C "$REPO" diff --name-only HEAD
        git -C "$REPO" ls-files --others --exclude-standard
        { git -C "$HARNESS" diff --name-only HEAD; git -C "$HARNESS" ls-files --others --exclude-standard; } \
            | sed "s|^|$submodule/|"
    } | sort -u
}

# Every file of the repository and the harness submodule, tracked or untracked, relative to the
# repository.
repo_files() {
    local submodule=${HARNESS#"$REPO/"}
    git -C "$REPO" ls-files --cached --others --exclude-standard
    git -C "$HARNESS" ls-files --cached --others --exclude-standard | sed "s|^|$submodule/|"
}

# Fails the run on a TEST_MAP glob that matches no file, such as one for a file since renamed,
# whose new name then runs every test until the conf says what covers it.
check_test_map() {
    local files entry glob file found stale=
    files=$(repo_files)
    for entry in ${TEST_MAP[@]+"${TEST_MAP[@]}"}; do
        glob=${entry%%=*}
        found=
        while read -r file; do
            # shellcheck disable=SC2053 # the glob is a pattern
            if [[ $file == $glob ]]; then
                found=1
                break
            fi
        done <<< "$files"
        if [ -z "$found" ]; then
            echo "--changed: TEST_MAP's $glob matches no file" >&2
            stale=1
        fi
    done
    if [ -n "$stale" ]; then
        echo "--changed: fix TEST_MAP in dev/harness.conf" >&2
        exit 2
    fi
}

# The test prefixes the conf's TEST_MAP gives for the changed files under the mod, the dev mod and
# the harness mod, saying why for each file. A changed file there that no glob covers runs every
# test; files elsewhere, such as docs and art, run none.
select_changed() {
    local roots=("${MOD_DIR#"$REPO/"}/" "${DEV_MOD_DIR#"$REPO/"}/" "${HARNESS_MOD_DIR#"$REPO/"}/")
    local file root under matched entry glob prefixes picked= everything= relevant=
    check_test_map
    while read -r file; do
        under=
        for root in "${roots[@]}"; do
            [[ $file == "$root"* ]] && under=1
        done
        [ -n "$file" ] && [ -n "$under" ] || continue
        relevant=1
        matched=
        for entry in ${TEST_MAP[@]+"${TEST_MAP[@]}"}; do
            glob=${entry%%=*}
            prefixes=${entry#*=}
            # shellcheck disable=SC2053 # the glob is a pattern
            if [[ $file == $glob ]]; then
                matched=1
                picked="$picked,$prefixes"
                echo "--changed: $file: ${prefixes:-no tests}"
            fi
        done
        if [ -z "$matched" ]; then
            echo "--changed: $file: no TEST_MAP glob covers it, so every test runs"
            everything=1
        fi
    done < <(changed_files)
    if [ -z "$relevant" ]; then
        echo "--changed: nothing under the mods changed since HEAD; no tests to run"
        exit 0
    fi
    if [ -n "$everything" ]; then
        SELECTION=
        return
    fi
    SELECTION=$(tr ',' '\n' <<< "$picked" | sed '/^$/d' | sort -u | paste -sd, -)
    if [ -z "$SELECTION" ]; then
        echo "--changed: no test covers the changed files; no tests to run"
        exit 0
    fi
    echo "--changed: running $SELECTION"
}

if [ "$MODE" = test ]; then
    SELECTION=${TESTS:-}
    if [ -n "$FAILED" ]; then
        select_failed
    elif [ -n "$CHANGED" ]; then
        select_changed
    fi
    case $LEAKS in
        fail | warn | off) ;;
        *) echo "LEAKS is fail, warn or off" >&2; exit 2 ;;
    esac
    if ! [[ $ROUNDS =~ ^[1-9][0-9]*$ ]]; then
        echo "REPEAT is a whole number of rounds from 1" >&2
        exit 2
    fi
    case $ORDER in
        "" | reverse) ;;
        shuffle)
            # Two of bash's 15-bit random numbers, so seeds don't repeat often.
            ORDER="shuffle:$(( (RANDOM * 32768 + RANDOM) % 2147483646 ))"
            echo "order: $ORDER (ORDER=$ORDER repeats it)"
            ;;
        shuffle:*)
            [[ ${ORDER#shuffle:} =~ ^[0-9]+$ ]] || { echo "ORDER=shuffle:<seed> takes a whole number" >&2; exit 2; }
            ;;
        *) echo "ORDER is reverse, shuffle or shuffle:<seed>" >&2; exit 2 ;;
    esac
elif [ -n "$MODE" ]; then
    selection_var="MODE_SELECTION_$MODE"
    if [ -n "${!selection_var:-}" ]; then
        selection_name=${!selection_var}
        SELECTION=${!selection_name:-}
    fi
    mark_var="MODE_MARK_$MODE"
    MARK=${!mark_var:-$TAG}
fi
# A selection the mod refuses fails here rather than after the game has started.
if [ -n "$MODE" ] && declare -F "harness_check_$MODE" > /dev/null; then
    "harness_check_$MODE"
fi
# Only a game that died or hung outside a test: the runner fails a stuck test itself after its
# per-test limit (Runner.lua). A cold --mp run of a whole suite takes about 2.5 minutes, and REPEAT
# runs it that many times over. The other modes, such as a mod's long reports, keep the old cap.
if [ "$MODE" = test ]; then
    TIMEOUT=${TIMEOUT:-$((300 * ROUNDS))}
else
    TIMEOUT=${TIMEOUT:-1200}
fi

# What a --test run's verdict depends on: the kind of run, the selection and settings, and the
# contents of the files the game loads from the three mods, the harness and the conf. RUNS_LOG
# keeps it with each run.
run_fingerprint() {
    {
        printf '%s\n' "$MP" "$STAY" "$SELECTION" "$LEAKS" "$ORDER" "$ROUNDS"
        find "$MOD_DIR" "$DEV_MOD_DIR" "$HARNESS_MOD_DIR" "$HARNESS/bin" "$HARNESS/lib" "$HARNESS/java" \
            "$REPO/dev/harness.conf" -type f -print0 | sort -z | xargs -0 md5 -r
    } | md5 -q
}

# The same run on the same files gives the same verdict, so a run that already got one repeats it
# rather than spend a game on it, unless RERUN is set. A run that never reached its verdict, such
# as one a Lua error stopped, doesn't count.
if [ "$MODE" = test ]; then
    RUN_FINGERPRINT=$(run_fingerprint)
    previous=$(grep " fingerprint=$RUN_FINGERPRINT\$" "$RUNS_LOG" 2>/dev/null | grep -v " passed=- " | tail -1 || true)
    if [ -n "$previous" ] && [ -z "${RERUN:-}" ]; then
        echo "this exact run already ran at ${previous%% *}, with $(grep -o 'passed=[^ ]* failed=[^ ]* skipped=[^ ]*' <<< "$previous"), and nothing it loads has changed since"
        echo "change the code or the selection first; REPEAT=<n> measures a flaky test, and RERUN=1 runs it again when the game rather than a test failed"
        exit "$(sed -n 's/.* exit=\([0-9]*\) .*/\1/p' <<< "$previous")"
    fi
fi
if [ -n "$MODE" ]; then
    run_precheck
fi
LOG="$CACHE/console.txt"
# The harness Lua reads the run from the first file, with --stay rerun requests from the second
# and with --mp the server to join from the third, written once the server has started
# (PZHarness/Runner.lua).
HARNESS_FILE="$CACHE/Lua/PZHarness.txt"
REQUEST_FILE="$CACHE/Lua/PZHarnessRerun.txt"
CONNECT_FILE="$CACHE/Lua/PZHarnessConnect.txt"

# Whether $1, relative to the dev mod, is one of the files a rerun loads again.
reloaded() {
    local pattern
    for pattern in "${RELOAD_FILES[@]}"; do
        # shellcheck disable=SC2053 # the pattern is a glob
        [[ $1 == $pattern ]] && return 0
    done
    return 1
}

# Why a kept game can't rerun the tests: it belongs to another cache dir, part of it has stopped,
# or something it loaded only at start changed since. Prints nothing if it can.
session_stale() {
    if [ "$SESSION_CACHE" != "$CACHE" ]; then
        echo "it runs with the cache dir $SESSION_CACHE"
        return
    fi
    local pid
    for pid in $SESSION_GAMES; do
        if ! kill -0 "$pid" 2>/dev/null; then
            echo "its process $pid has stopped"
            return
        fi
    done
    local file
    while read -r file; do
        if [[ $file != "$DEV_MOD_DIR/"* ]] || ! reloaded "${file#"$DEV_MOD_DIR/"}"; then
            echo "${file#"$REPO/"} changed"
            return
        fi
    done < <(find "$DEV_MOD_DIR" "$HARNESS_MOD_DIR" -newer "$HARNESS_FILE" -type f)
    # "Files <ours> and <copy> differ" or "Only in <folder>: <name>", for every changed file.
    local changed
    changed=$(diff -rq "$MOD_DIR" "$CACHE/mods/$MOD_FOLDER" | head -1 || true)
    if [ -n "$changed" ]; then
        echo "the mod changed: $changed"
    fi
}

# Sends a kept game the tests to run, the run's settings and the files to load again, in the
# conf's order. The id names the run in console.txt. With --mp the server loads the shared and
# server files again too, from its own cache dir.
request_rerun() {
    RUN_ID="$$-$(date +%s)"
    local pattern file relative server_files=()
    {
        echo "$RUN_ID"
        echo "$SELECTION"
        printf 'option leaks=%s\noption order=%s\noption rounds=%s\n' "$LEAKS" "$ORDER" "$ROUNDS"
        for pattern in "${RELOAD_FILES[@]}"; do
            for file in "$CACHE/mods/$DEV_MOD_FOLDER/"$pattern; do
                [ -f "$file" ] || continue
                echo "$file"
                relative=${file#"$CACHE/mods/$DEV_MOD_FOLDER/"}
                if [ -n "$MP" ] && [[ $relative == */media/lua/server/* || $relative == */media/lua/shared/* ]]; then
                    server_files+=("server $SERVER_CACHE/mods/$DEV_MOD_FOLDER/$relative")
                fi
            done
        done
        if [ ${#server_files[@]} -gt 0 ]; then
            printf '%s\n' "${server_files[@]}"
        fi
    } > "$REQUEST_FILE.tmp"
    mv "$REQUEST_FILE.tmp" "$REQUEST_FILE" # whole, so the game never reads half a request
}

# Reuse your game settings (resolution, language, accepted terms of service) so a fresh cache
# dir doesn't stop at first-run screens.
prepare_cache() {
    if [ ! -f "$CACHE/options.ini" ] && [ -f "$HOME/Zomboid/options.ini" ]; then
        cp "$HOME/Zomboid/options.ini" "$CACHE/options.ini"
    fi
    # Harness runs play no sound, so they don't blare while you work. Only the volumes are zeroed:
    # the sound engine still runs, so code that plays sounds runs the same. A plain run keeps your
    # volumes.
    if [ -n "$MODE" ] && [ -f "$CACHE/options.ini" ]; then
        for key in soundVolume musicVolume ambientVolume vehicleEngineVolume jumpScareVolume voiceVolumePlayers; do
            sed -i '' "s/^$key=.*/$key=0/" "$CACHE/options.ini"
        done
    fi
    # Without this file the client empties mods/default.txt on start, as it does the first time a
    # cache dir runs a new major release (ZomboidFileSystem.resetDefaultModsForNewRelease).
    echo "If this file does not exist, default.txt will be reset to empty (no mods active)." > "$CACHE/mods/reset-mods-42_00.txt"
    # The dev mod and the harness load in every mode, so playing by hand has the scenario and the
    # tests too.
    link_dev_mods
    mkdir -p "$CACHE/Lua"
    rm -f "$REQUEST_FILE" "$CONNECT_FILE"
    # Written when playing by hand too: the tests take their console tag from it. A --test world
    # is quiet (QUIET_WORLD, lib/harness.sh); the runner sets those options before the scenario's
    # own setSandbox, which may override them.
    local quiet=
    if [ "$MODE" = test ]; then
        quiet=$(IFS=,; echo "${QUIET_WORLD[*]+${QUIET_WORLD[*]}}")
    fi
    printf 'mode=%s\nselection=%s\nstay=%s\nmp=%s\nmark=%s\ntag=%s\nleaks=%s\norder=%s\nrounds=%s\nquiet=%s\n' \
        "$MODE" "$SELECTION" "$STAY" "$MP" "$MARK" "$TAG" "$LEAKS" "$ORDER" "$ROUNDS" "$quiet" > "$HARNESS_FILE"
    cat > "$CACHE/mods/default.txt" <<EOF
VERSION = 1,

mods
{
    mod = $MOD_ID,
    mod = $HARNESS_MOD_ID,
    mod = $DEV_MOD_ID,
}

maps
{
}
EOF
    # The harness sets the scenario's forceLaunch; this debug option lets it start from the main
    # menu. A multiplayer client joins the server instead.
    printf 'Version=1\nDebugScenario.ForceLaunch=%s\n' "$([ -n "$MODE" ] && [ -z "$MP" ] && echo true || echo false)" > "$CACHE/debug-options.ini"
    if [ -n "$MP" ]; then
        # The character the client kept of the last run's server, whose world is gone.
        rm -rf "$CACHE/Saves/Multiplayer"
    fi
}

# The server of --mp: the three mods, no zombies, a quiet world, not paused while nobody plays,
# open to the client without a whitelist, on its own ports. Every harness test world has no
# zombies, so nothing attacks the character during the tests. The server runs its sandbox file as
# Lua, so the lines go after the conf's options, and the quiet ones (QUIET_WORLD) only where the
# conf's hook set nothing.
prepare_mp_server() {
    local client_cache=$CACHE sandbox option
    CACHE=$SERVER_CACHE
    link_dev_mods
    prepare_server "$MOD_ID;$HARNESS_MOD_ID;$DEV_MOD_ID" "DefaultPort=$SERVER_PORT" \
        "UDPPort=$((SERVER_PORT + 1))" Open=true PauseEmpty=false
    sandbox="$CACHE/Server/${SERVER_NAME}_SandboxVars.lua"
    if [ -f "$sandbox" ]; then
        echo "SandboxVars.Zombies = 6" >> "$sandbox"
    else
        echo "SandboxVars = { Zombies = 6 }" > "$sandbox"
    fi
    for option in ${QUIET_WORLD[@]+"${QUIET_WORLD[@]}"}; do
        echo "if SandboxVars.${option%%=*} == nil then SandboxVars.${option%%=*} = ${option#*=} end" >> "$sandbox"
    done
    timing_mark server_start
    start_server
    CACHE=$client_cache
}

install_mod
# This run's part of console.txt: all of it after a launch; in a kept game, from this run's request
# on, copied to RUN_LOG on every poll. The same for the server's log with --mp. The checks read
# files rather than pipes into grep -q, whose early exit would make pipefail report a match as a
# miss.
RUN_ID=
RUN_LOG=$LOG
SERVER_LOG= SERVER_RUN_LOG= SERVER_PID=
if [ -n "$SESSION_PID" ]; then
    # shellcheck disable=SC2086 # the client's PID, then the server's
    set -- $SESSION_GAMES
    GAME_PID=$1
    if [ -n "$MP" ]; then
        SERVER_PID=$2
        SERVER_LOG="$SERVER_CACHE/server-console.txt"
        SERVER_RUN_LOG="$SERVER_CACHE/server-console-rerun.txt"
    fi
    request_rerun
    timing_mark launch
    RUN_LOG="$CACHE/console-rerun.txt"
    echo "rerunning the tests in the game kept open by --stay (pid $SESSION_GAMES)"
    keep_games_on_exit "$SESSION_PID"
else
    prepare_cache
    GAME=("$JAVA" "${JVM_COMMON[@]}" -XstartOnFirstThread -Xmx3072m -XX:+UseZGC)
    GAME_ARGS=(-debug -nosteam -cachedir="$CACHE")
    if [ -z "$MODE" ]; then
        cd "$PZ/Java"
        exec "${GAME[@]}" -cp "$GAME_CLASSPATH" zombie.gameStates.MainScreenState "${GAME_ARGS[@]}"
    fi
    if [ -n "$MP" ]; then
        prepare_mp_server
        SERVER_RUN_LOG=$SERVER_LOG
    fi

    LAUNCHER="$CACHE/launcher"
    compile_java "$HARNESS/java/ClickToStart.java" "$LAUNCHER"

    # GLFW finds no monitor while the display sleeps, and the game can't open its window.
    # caffeinate -u wakes the display, and -d -i keep it and the computer awake until this script
    # exits.
    caffeinate -d -i -u -w $$ &
    for _ in $(seq 10); do
        system_profiler SPDisplaysDataType | grep -q "Display Asleep: Yes" || break
        sleep 1
    done

    # that output sees it end when the script exits, even if the game stays open with --stay. With
    # --mp the client boots while the server does and joins once it has started.
    timing_mark launch
    (cd "$PZ/Java" && exec "${GAME[@]}" -cp "$LAUNCHER:$GAME_CLASSPATH" ClickToStart "${GAME_ARGS[@]}" \
        < /dev/null > "$CACHE/stdout.txt" 2>&1) &

        keep_games_on_exit $!
    elif [ -n "$STAY" ]; then
        # Keeps the display awake for the kept game, after this script exits.
        caffeinate -d -i -w "$GAME_PID" < /dev/null > /dev/null 2>&1 &
        keep_games_on_exit
    else

    fi
fi

# The tests that failed in this run, or were running when it stopped, for the next --failed run of
# the same kind, each with how many such runs in a row it has failed; a run that never started its
# tests leaves the last record alone. A FAIL line names its test, as do the late failures of its
# server undos; one for a call outside any test names the handler, which no TEST line does.
record_failed_tests() {
    [ "$MODE" = test ] && logged "> $TAG START " || return 0
    local names previous name entry runs record= stuck=
    names=$(awk -v tag="$TAG" '
        index($0, "> TEST: ") { current = substr($0, index($0, "> TEST: ") + 8); ran[current] = 1; next }
        index($0, "> " tag " FAIL ") {
            name = substr($0, index($0, "> " tag " FAIL ") + length(tag) + 8)
            sub(/: .*/, "", name)
            if (name in ran) failed[name] = 1
            if (name == current) current = ""
        }
        index($0, "> " tag " PASS ") { current = "" }
        index($0, "> " tag " DONE ") { done = 1 }
        END {
            if (!done && current != "") failed[current] = 1
            for (name in failed) print name
        }' "$RUN_LOG" | sort | paste -sd, -)
    previous=$(grep "^$FAILED_KEY " "$RUNS_FAILED" 2>/dev/null | tail -1 || true)
    for name in ${names//,/ }; do
        runs=1
        for entry in ${previous//,/ }; do
            if [ "${entry%:*}" = "$name" ] && [[ ${entry##*:} =~ ^[0-9]+$ ]]; then
                runs=$((${entry##*:} + 1))
            fi
        done
        record="$record,$name:$runs"
        if [ "$runs" -ge "$STUCK_RUNS" ]; then
            stuck="$stuck $name ($runs)"
        fi
    done
    { grep -v "^$FAILED_KEY " "$RUNS_FAILED" 2>/dev/null || true; echo "$FAILED_KEY ${record#,}"; } > "$RUNS_FAILED.tmp"
    mv "$RUNS_FAILED.tmp" "$RUNS_FAILED"
    if [ -n "$names" ]; then
        echo "--failed reruns: ${names//,/, }"
    fi
    if [ -n "$stuck" ]; then
        echo "failed $STUCK_RUNS or more runs in a row:$stuck. Rerunning won't narrow it; read ${HARNESS#"$REPO/"}/docs/debugging.md and change approach first"
    fi
}

# On exit (exit_report, lib/harness.sh): records what failed for --failed, prints this run's phases
# and appends it to RUNS_LOG. A kept game's rerun has no boot or world phase, and only a game that
# quits has a quit phase. A run a Lua error stopped has a stopped phase instead of the run, up to
# the poll that saw the error.
report_timing() {
    [ -n "$MODE" ] || return 0
    record_failed_tests
    local counts
    counts=$(sed -n "s/.*> $TAG DONE \(passed=[0-9]* failed=[0-9]* skipped=[0-9]*\)\$/\1/p" "$RUN_LOG" 2>/dev/null | tail -1)
    report_run "$1" "$MODE${MP:+-mp}${SESSION_PID:+-rerun}" "${SELECTION:-all}" \
        "${counts:-passed=- failed=- skipped=-}" \
        "setup|launch|script start to the game's launch, or to the rerun request in a kept game" \
        "boot|lua|game launch to the harness's Lua" \
        "world|world|to the world loaded around the character" \
        "start|first|to the first test" \
        "run|done|to the last result" \
        "stopped|stopped|to the Lua error that stopped the run" \
        "quit|exit|to the game's exit, and with --mp the server's" \
        "server|server_ready|server launch to ready|server_start"
}

# The milestones in this run's log, each timed when a poll first sees it.
note_milestones() {
    local milestone pattern var
    for milestone in lua world first done; do
        case $milestone in
            lua) pattern="PZHarness: the dev mod registered" ;;
            world) pattern="PZHarness: starting after" ;;
            first) pattern="> TEST: " ;;
            done) pattern="> $MARK DONE" ;;
        esac
        var="TIMING_$milestone"
        if [ -z "${!var:-}" ] && logged "$pattern"; then
            timing_mark "$milestone"
        fi
    done
}

update_run_log() {
    if [ -n "$RUN_ID" ]; then
        sed -n "/> $TAG RUN $RUN_ID\$/,\$p" "$LOG" > "$RUN_LOG" 2>/dev/null || true
        if [ -n "$MP" ]; then
            sed -n "/> $TAG RUN $RUN_ID\$/,\$p" "$SERVER_LOG" > "$SERVER_RUN_LOG" 2>/dev/null || true
        fi
    fi
}
# Whether log $3 (this run's client log by default) has a line matching the extended regex $1, at
# or after the harness's first $MARK line if $2 is "harness".
logged() {
    local file=${3:-$RUN_LOG}
    [ -f "$file" ] || return 1
    RE=$1 FROM=$([ "${2:-}" = harness ] && echo "> $MARK " || true) awk '
        BEGIN { started = ENVIRON["FROM"] == "" }
        !started && index($0, ENVIRON["FROM"]) { started = 1 }
        started && $0 ~ ENVIRON["RE"] { found = 1; exit }
        END { exit !found }' "$file"
}
# In debug mode a Lua error stops the game at the error, so it never quits on its own. A stack
# trace through the mods' Lua, or any failure once the harness has started, ends the run at once
# instead of at the timeout. A Lua stack trace indents its frames once; a Java exception the game
# logs and goes on from, as multiplayer's action sync does, indents them twice and counts only in
# the scan after the run. A require warning names the mod on a WARN line instead.
lua_stopped() {
    logged "^[[:space:]]Lua\\($OUR_LUA_ERROR" \
        || logged '^Lua fail|dumping Lua stack trace|Error found in LUA file' harness
}
# A game without --stay quits when it is done; a kept one prints the DONE line and waits. A server
# goes on after a Lua error, so only the client's errors end the run early: a test waiting on the
# server gets its answer or gives up, the scan after the run finds the server's stack trace, and
# the games kept by --stay stay up for the next run.
STOPPED= DONE= SERVER_GONE=
SECONDS=0
while [ "$SECONDS" -lt "$TIMEOUT" ]; do
    kill -0 "$GAME_PID" 2>/dev/null || break
    if [ -n "$MP" ]; then
        if [ -z "${SERVER_QUIT:-}" ] && ! kill -0 "$SERVER_PID" 2>/dev/null; then
            SERVER_GONE=1
            break
        fi
        if [ ! -f "$CONNECT_FILE" ] && server_started; then
            timing_mark server_ready
            printf 'host=127.0.0.1\nport=%s\nuser=%s\npassword=%s\n' "$SERVER_PORT" "$SERVER_ADMIN" \
                "$SERVER_ADMIN_PASSWORD" > "$CONNECT_FILE.tmp"
            mv "$CONNECT_FILE.tmp" "$CONNECT_FILE"
        fi
    fi
    update_run_log
    note_milestones
    if lua_stopped; then
        STOPPED=1
        timing_mark stopped
        sleep 2 # lets the rest of the stack trace reach the log
        update_run_log
        break
    fi
    if logged "> $TAG DONE "; then
        if [ -n "$STAY" ]; then
            DONE=1
            break
        fi
        # The server saves and quits while the client does.
        quit_server
    fi
    sleep 0.5
done
# A client that quits right after its last line can be gone before a poll sees that line, and the
# loop then ends at its first check, so the log gets one more look.
update_run_log
note_milestones
if [ -n "$STOPPED" ]; then
    echo "FAIL: a Lua error stopped the game; the stack trace from $LOG:"
    grep -n -A20 'dumping Lua stack trace' "$RUN_LOG" | grep -v -E '^[0-9]+-\s+(se\.krka|java\.|zombie\.)' | head -40
    stop_games
    exit 1
fi
if [ -n "$SERVER_GONE" ]; then
    echo "FAIL: the server stopped; the end of $SERVER_CACHE/stdout.txt:"
    tail -n 20 "$SERVER_CACHE/stdout.txt"
    stop_games
    exit 1
fi
if [ -z "$DONE" ] && kill -0 "$GAME_PID" 2>/dev/null; then
    echo "FAIL: no result after ${TIMEOUT}s; stopping the game"
    stop_games
    exit 1
fi
# The server's log counts up to its exit: saving the world runs the mods' code too.
if [ -n "$MP" ] && [ -z "$STAY" ]; then
    stop_server
fi
# The quit phase runs until the client has exited and, with --mp, the server has saved and exited.
if ! kill -0 "$GAME_PID" 2>/dev/null; then
    timing_mark exit
fi

echo "log: $LOG"
if [ -n "$MP" ]; then
    echo "server log: $SERVER_LOG"
fi
if ! logged "$MARK"; then
    echo "FAIL: the game stopped before the harness ran; the harness's lines and the end of $CACHE/stdout.txt:"
    grep -o "PZHarness: .*" "$RUN_LOG" || true
    tail -n 20 "$CACHE/stdout.txt"
    exit 1
fi
grep -o "$MARK.*" "$RUN_LOG" | grep -v "^$TAG RUN " | uniq || true
# Anything the mod logs counts, from loading on. A mod mistake can also surface as an error in
# vanilla Lua, such as a crafting window drawing an item the mod defined badly, so every Lua error
# counts once the harness has started, and so does any exception logged through the three mods'
# Lua; before that, vanilla logs errors of its own.
if grep -n -E "$MOD_ERROR" "$RUN_LOG" \
    || sed -n "/> $MARK /,\$p" "$RUN_LOG" | grep -n -E "^ERROR: Lua|LuaManager.*Exception|-- file: |$OUR_LUA_ERROR"; then
    echo "FAIL: Lua errors were logged"
    exit 1
fi
# The server's log as validate-server.sh reads it, plus stack traces through the dev mod and the
# harness mod, and the failures the harness's server half reports.
if [ -n "$MP" ]; then
    # A stack trace repeats in several forms, so the first lines say enough.
    problems=$(server_problems "$SERVER_RUN_LOG" "$OUR_LUA_ERROR|$TAG SERVER FAIL" || true)
    if [ -n "$problems" ]; then
        head -30 <<< "$problems"
        echo "FAIL: the server logged problems"
        exit 1
    fi
fi
if [ "$MODE" != test ]; then
    if ! logged "$MARK DONE"; then
        echo "FAIL: the harness didn't finish"
        exit 1
    fi
    if declare -F "harness_after_$MODE" > /dev/null; then
        "harness_after_$MODE"
    else
        echo "PASS"
    fi
    exit 0
fi
if ! logged "$TAG DONE passed=[1-9][0-9]* failed=0 skipped=[0-9]+$"; then
    echo "FAIL: not every test passed"
    exit 1
fi
echo "PASS"

#!/usr/bin/env bash
# Boots a throwaway dedicated server (no Steam, isolated cache dir) with only the mod enabled,
# waits for it to finish loading, stops it, and fails if the mod logged a problem: a Lua stack
# trace through the mod, or a line matching the conf's SERVER_PROBLEMS that doesn't match
# SERVER_IGNORE. The server loads the mod's tiles, scripts, sandbox options, shared and server
# Lua, and loot tables. The conf's harness_server_setup hook can add files to the server's config,
# such as its sandbox options, in "$CACHE/Server/$SERVER_NAME"*.
#
# CACHE overrides the cache dir (default: $TMPDIR/<CACHE_NAME>-server), and TIMEOUT the seconds
# the server may take to start (default 900).
set -euo pipefail
. "$(dirname "${BASH_SOURCE[0]}")/../lib/harness.sh"

CACHE="${CACHE:-$TMP_REAL/$CACHE_NAME-server}"
TIMEOUT=${TIMEOUT:-900}
# For the conf's hooks: this server serves no --mp run.
MP=

# On exit (exit_report, lib/harness.sh): prints the run's phases and appends it to RUNS_LOG.
report_timing() {
    report_run "$1" validate - "passed=- failed=- skipped=-" \
        "setup|launch|script start to the server's launch" \
        "boot|ready|server launch to ready" \
        "quit|exit|to the server's exit"
}

run_precheck
acquire_game_lock
# The phases are timed from here, after any wait for another script's game.
timing_mark start
prepare_server "$MOD_ID"
timing_mark launch
start_server
stop_games_on_exit

started=
SECONDS=0
while [ "$SECONDS" -lt "$TIMEOUT" ] && kill -0 "$SERVER_PID" 2>/dev/null; do
    if server_started; then
        timing_mark ready
        started=1
        break
    fi
    sleep 1
done
stop_server
timing_mark exit

echo "log: $SERVER_LOG"
if [ -z "$started" ]; then
    echo "FAIL: server did not start"
    exit 1
fi
if server_problems "$SERVER_LOG"; then
    echo "FAIL: the mod logged problems"
    exit 1
fi
echo "PASS: server started and the mod logged no problems"

```md
# Adopting PZ_DevHarness

How a mod takes the harness on, what it tells the harness about itself, and the test library its tests use. The [README](../README.md) says what the harness is for; [running.md](running.md) covers the run script and [multiplayer.md](multiplayer.md) the `--mp` mode.

## Layout

| Path | What it is |
| --- | --- |
| `bin/run-client.sh` | The client runner behind a mod's `dev/run-debug-client.sh`, single player and multiplayer (`--mp`). |
| `bin/validate-server.sh` | Boots a throwaway dedicated server with the mod and fails on anything the mod logs. |
| `lib/harness.sh` | Paths, JVM arguments, the game lock, `install_mod`, `compile_java`, and the dedicated server both scripts start (`prepare_server`, `start_server`, `stop_server`, `server_problems`). A mod's own dev scripts may source it. |
| `java/ClickToStart.java` | Starts the client, presses "Click to start" on the loading screen and gives the asset loader more threads (`java/AssetLoading.java`). |
| `java/FastServer.java` | Starts the dedicated server of `--mp` and `validate-server.sh` with the same wider asset loader. |
| `mod/42/` | The harness mod (`cf_test_harness`): `client/PZHarness/Runner.lua`, `TestLib.lua`, `ServerCalls.lua` and `Leaks.lua`, the leak check between tests; `server/PZHarness/ServerHandlers.lua`, the server's half of the tests' server channel, and `ServerFixtures.lua`, the server's half of the two-sided fixtures; `shared/PZHarness/Fixtures.lua`, what both halves do, `Checks.lua`, expectations for server handlers, and `Snapshot.lua`, what the leak check reads on each side. |

## Adopting it

The harness sits in the mod's repository at `dev/harness`:

```sh
git submodule add https://github.com/CalebFenton/PZ_DevHarness.git dev/harness
```

The mod then needs three things.

### `dev/harness.conf`

Sourced bash. Paths are relative to the repository. The mod's id and name come from its
`mod.info`, so they aren't repeated here.

| Key | Meaning |
| --- | --- |
| `MOD_DIR` | The published mod's folder, such as `Contents/mods/MyMod`. It is copied into the cache. |
| `DEV_MOD_DIR` | The dev mod's folder, such as `dev/MyModDevHarness`. It is linked into the cache. |
| `CACHE_NAME` | Cache dirs go to `$TMPDIR/<name>-client`, `-server`, `-mpclient`, `-mpserver` and (by convention for the mod's own scripts) `-check`. |
| `TAG` | The console tag of the tests' lines, such as `MyModTest`. |
| `RELOAD_FILES` | A bash array of globs, relative to the dev mod, of the files a kept game loads again for a rerun, in load order (the mod's test library first). With `--mp` the server loads those under `media/lua/server` and `media/lua/shared` again too, so list the dev mod's server handler files here. |
| `MODES` | The mod's other modes, space-separated; each becomes a `--<mode>` flag. |
| `MODE_MARK_<mode>` | The console mark of the mode's lines; the run waits for `<mark> DONE`. |
| `MODE_SELECTION_<mode>` | Optional: the environment variable whose value the mode's handler gets as its selection, as `TESTS` is for `--test`. |
| `TEST_MAP` | Optional: a bash array of `'<glob>=<prefix>,<prefix>'` entries for `--test --changed`. Each glob is matched against the paths changed since `HEAD`, relative to the repository, with bash's `[[ == ]]`, where `*` crosses `/`; every entry a file matches adds its test name prefixes, and an empty list (`'<glob>='`) adds none. A changed file under the mod, the dev mod or the harness mod that no glob matches runs every test; files elsewhere run none. Leave files every test depends on unmatched. `--changed` refuses to run while a glob matches no file, and the runner fails a prefix that names no test, so a rename shows up in the map at once. |
| `PRECHECK` | Optional: a bash array, the command every game run of the harness runs first from the repository, such as the mod's Lua compile and static checks. If it fails, no game starts. |
| `QUIET_WORLD` | Optional: a bash array of `Key=value` sandbox options that make a `--test` world quiet, replacing the harness's list ([running.md](running.md#a-quiet-world)); `QUIET_WORLD=()` keeps the world's own population. |
| `SERVER_PROBLEMS` | Optional: an extended regex of server log lines that count as the mod's problems, besides stack traces through it. |
| `SERVER_IGNORE` | Optional: an extended regex of matching lines that don't count. |

Hooks, bash functions the conf may define:

| Hook | When it runs |
| --- | --- |
| `harness_check_<mode>` | Before the lock and the launch. `$SELECTION` holds the selection; exit nonzero to refuse it, so a typo fails at once. |
| `harness_after_<mode>` | After a run of the mode that finished cleanly, instead of the plain `PASS`, such as to post-process screenshots in `$CACHE/Screenshots`. |
| `harness_server_setup` | After a server's `$CACHE/Server/$SERVER_NAME.ini` is written: in `validate-server.sh`, and for the server of `--mp`, whose sandbox then gets `Zombies = 6` and the `QUIET_WORLD` options it doesn't set appended; add files such as `${SERVER_NAME}_SandboxVars.lua`. `$MP` is `1` for the `--mp` server. |

Hooks can read `$REPO`, `$CACHE`, `$MOD_DIR`, `$DEV_MOD_DIR` (absolute by then), `$MODE` and `$MP`.

### The dev mod

`<DEV_MOD_DIR>/42/mod.info` with `require=<the mod's id>,cf_test_harness`, holding the debug
scenario (a `debugScenarios` entry), the tests, the fixtures that know the mod's objects and the
handlers of the mod's modes. Nothing of it is published, so the published mod carries game code
only. One file registers the mod with the runner at load:

```lua
require "PZHarness/Runner"
require "MyMod/Debug/MyModDebugScenario"

PZHarness.register({
    scenario = "MyModScenario",   -- its key in debugScenarios; every mode starts it
    prefix = "mymod_",            -- --test runs the TimedActionTests whose names start with it
    modes = {
        -- run(selection, done) starts once the world around the character has loaded and
        -- calls done() when finished; done prints "<mark> DONE" and quits. The flags are optional;
        -- see [capture settings](#capture-settings).
        shots = { uncapped = true, clearWeather = true, fastUI = true,
            run = function(selection, done) Shots.capture(selection, done) end },
    },
    onStart = function(mode) end, -- optional, after the scenario's own onStart in every mode
    tests = {                     -- the test library's settings, all optional
        hour = 10,                -- tests run at this hour unless their spec gives one
        perks = { Perks.Electricity }, -- restored after every test
        sandbox = "MyMod",        -- SandboxVars.MyMod, which T.setSandbox tries first
        sandboxChanged = function() end, -- after T.setSandbox sets or restores an option
        setup = function(self, spec) end, -- before every spec.run; may push undos with T.defer
        recipePrefix = "MyMod_",  -- for T.recipeNames, T.learnRecipes, T.craftTest
        isFreeSquare = function(square, indoors) return square:isFree(false) end, -- for T.squares
        remove = function(object) return false end, -- true if it removed one of the mod's objects
        leakRadius = 32,          -- squares each way the leak check reads; past where T.squares looks by default
        leakLevels = { 0, 1 },    -- z levels the leak check reads; the character's own by default
        leakIgnore = { "^mymod_puddle" }, -- Lua patterns over "<sprite>@<class>" the leak check leaves out, past the built-in ones
    },
})
```

The mod's test library inherits the shared one and adds its fixtures:

```lua
require "PZHarness/TestLib"
MyModTest = setmetatable({}, { __index = PZHarness.Test })
local T = MyModTest

function T.gadget(self, square) return T.tile(self, square, "mymod_01_0") end
```

Test files register tests with `T.test(name, spec)`; `PZHarness/TestLib.lua` explains the spec,
the restore stack and the rules that keep each test independent of the ones before it.

What only the authority can do goes in the dev mod's server Lua, as named handlers that tests call
with `T.server` (see [multiplayer.md](multiplayer.md)):

```lua
-- <DEV_MOD_DIR>/42/media/lua/server/MyMod/Debug/MyModTestServer.lua
require "PZHarness/ServerHandlers"

PZHarness.serverHandler("placeThing", function(player, args, defer)
    local square = getSquare(args.x, args.y, args.z)
    if not square then return nil, "a loaded square for the thing" end -- fails the test as T.need does
    local thing = MyMod.place(square)
    defer(function() MyMod.remove(thing) end) -- undone on the server when the calling test ends
    return { x = args.x, y = args.y, z = args.z } -- plain values: strings, numbers, booleans, tables
end)
```

A handler that checks many things on the server collects what it found wrong with
`PZHarness.Checks.new()`, from `PZHarness/Checks.lua`, and answers with the list for the test to
report. It returns `expect, expectNear, failures`: `expect` and `expectNear` work as the test
library's do, and fill `failures`:

```lua
require "PZHarness/Checks"

PZHarness.serverHandler("thingsStocked", function()
    local expect, expectNear, failures = PZHarness.Checks.new()
    expect(MyMod.stock ~= nil, "no stock table")
    expectNear("the stock's weight", MyMod.stockWeight(), 2.5)
    return { failures = failures }
end)
```

## The test library

`PZHarness.Test`, from `PZHarness/TestLib.lua`:

- Registering: `test(name, spec)`, `craftTest(name, spec)`. `spec.spOnly` or `spec.mpOnly`, a reason string, keeps a test out of the other mode. A test still busy after 30 seconds of real time fails with what it was waiting on (the queued action's type, or which server answer or wait; `waitUntil(condition, maxFrames, what)` names a wait), its queue is cleared, its undos run and the next test starts; `spec.timeoutSeconds` raises the limit for a test that is slow on purpose. A test whose starting square still hasn't loaded, some seconds after the test before it took the character far away, fails without running, and the next one waits for the square again.
- Expectations: `expect`, `expectNear`, `need`. Once a test misses something, its later queued steps and waits don't run.
- Restore stack, two-sided (see [two-sided fixtures](multiplayer.md#two-sided-fixtures)): `defer`, `onTick`, `setTime`, `setPerk`, `setSandbox`, `setMultiplier`, `setGrid`, `setMechanicsCheat`, `makeDark`, `changeItem`; `spec.instant` and the `perks` setting too. A multiplayer server times every action in real time, and an instant vehicle part install or uninstall on a client stops as invalid once the server has moved the part, so a test turns `setMechanicsCheat` on around those instead.
- Queue: `wait`, `waitUntil`, `step`. What a step queues runs right after it, in order (vanilla's adding-actions mode), and a clear of the queue inside it (`luautils.walkAdj`) drops only that. Any other clear of the queue while the test's own waits and steps are still in it, such as a timed action that turns invalid or is refused, fails the test at once with the action that was running, and validate doesn't run.
- The server: `server(self, name, args)` calls the dev mod's handler `name` and leaves its answer in `self.server[name]` exactly as the handler returned it, so `false`, `0` and `nil` arrive as themselves; `serverUntil(self, name, args, done, maxMs)` calls it until `done(reply)`; `give(self, name, items)`; `count(self, name, types, opts)`.
- Verdicts: `printVerdict(name, failures, seconds)` prints a test's PASS or FAIL line. The harness runner prints it once its leak check after the test is done ([running.md](running.md#leaks-and-desyncs)); the debug menu's runner gets it from validate.
- Squares and fixtures: `squares`, `track`; placed by the server: `placeTile`, `placeBench`, `placeVehicle`; placed and picked up by the character, as a player does with the moveables cursor: `placeAsPlayer(self, square, itemType, sprite, modData)` (a handle `{ x, y, z, square }`, `object` once this client has it, removed when the test ends) and `pickUpAsPlayer(self, handleOrSquare, sprite)`; this game only: `tile`, `placeMoveable`, `bench`, `vehicle`; `lineUpTrailer`.
- Crafting: `recipeNames`, `learnRecipes`, `forgetRecipes`, `recipeInputs`, `addRecipeInputs` (this game only), `inputItem(input, prefer)`, `placeWorkTable`, `craftRefusal`, `startCraft`. `inputItem` is the script item `recipeInputs` picks for one of a recipe's inputs: the first of its possible items named in `prefer`, else the first that isn't a generic `Base.Moveable`. Any test that starts a craft with `startCraft` and fails also reports why the game refused it, so a mod's own craft tests get that without `craftTest`.
- Lookups: `player`, `objectWithSprite`, `countPairs`; `PZHarness.Fixtures` has these and `vehicleById` for server handlers too, `ring(x, y, r)`, which iterates (`for sx, sy in ...`) over the squares at exactly `r` squares from x, y, each once, for a search that widens ring by ring from the nearest, and `teleportToMiddle(player, x, y, z)`: `teleportTo` alone leaves the character on the square's north-west corner, from where vanilla's `walkAdj` takes a square two to the north or west as in reach, walks nowhere, and an action that needs the square adjacent stops.
- Walking: `standNextTo(square)` puts the character where vanilla's `walkAdj` would walk it, so the walk a menu option or an action queues first has no way to go; walking takes real time, which neither the instant cheat nor the frame rate shortens. `placeAsPlayer` and `pickUpAsPlayer` do it themselves.

## Capture settings

Flags of a registered mode, for modes that take screenshots. They take effect just before `run`;
`done()` puts the UI rate back before the game quits and saves its options, so `options.ini`
never keeps it.

| Flag | What it does |
| --- | --- |
| `uncapped` | Draws as many frames as the machine can, as `--test` does; [running.md](running.md#why-it-is-fast-and-what-that-costs) explains why that's safe. |
| `clearWeather` | No cloud, fog or rain, at once and however the weather turns during the run: it stops the weather and sets the admin values of the climate's cloud, fog and precipitation floats to 0. Stopping the weather alone leaves fog to fade out over seconds. |
| `fastUI` | Draws the UI 120 times a second, the `uiRenderFPS` option's highest. The UI draws at its own rate and the frames in between show its last drawing, so a step that waits for the UI to draw (`Events.OnPostUIDraw`) waits less. |

The lighting rate stays the player's (`lightFPS`, 15 by default). `setLightingFPS` takes up to
120. At 60, with its lighting waits counted in passes, a screenshot run that waits on the lighting
at seven spots took 13 seconds instead of 19, but its shots changed: a clock change had less time
to darken the scene before the shot. At 120 the thread fell behind, and a sweep held for passes of
that rate left squares dark.

# Debugging with the harness

Which run to reach for, and how to read a failure, so a change takes a handful of game runs
rather than dozens. A game run is the most expensive step of a change, a fresh one most of all, so
each one should be able to tell you something the last one didn't. [running.md](running.md)
describes every flag and line named here.

## What to run when

1. After every edit, the mod's static check, if it has one (it takes seconds and needs no game).
   The conf's `PRECHECK` runs it before every game run as well.
2. While you work on a change, a kept game and only the tests it touches:

    ```sh
    dev/run-debug-client.sh --test --stay --changed          # the tests TEST_MAP gives for your changes
    TESTS=mymod_craft_ dev/run-debug-client.sh --test --stay # or name them
    ```

    Add `--mp` when the change touches what the server does or sends. A kept game reloads only
    the conf's `RELOAD_FILES` (test files and server handler files); a change to anything else
    restarts it, which the script does on its own.
3. Once, before you commit, the whole suite in fresh games, in both modes:

    ```sh
    dev/run-debug-client.sh --test
    dev/run-debug-client.sh --test --mp
    ```

The script won't repeat a run whose selection, settings and files haven't changed since it last
got a verdict: it prints that verdict instead ([repeats](running.md#repeats)). Set `RERUN=1` only
when the game rather than a test failed, such as a crash before the tests started.

## Several agents, one game

Only one game runs at a time; every other run waits for the lock, and each fresh one pays the
game's start. Let the agents that edit run the static check, and have one agent run the game for
all of them, with everyone's changes in one run.

## A test fails

1. Read the `FAIL` line's reasons, the `LEAK` and `DESYNC` lines above it, and the log whose path
   the script prints, before changing anything. The reasons name what was missing, what the
   server answered, the action that cleared the queue, or what a stopped test was waiting on.
2. If that doesn't explain it, write down the explanations that fit, add the one diagnostic that
   tells them apart (an `expect` with the value in its message, or a `print`), and rerun only the
   failures: `dev/run-debug-client.sh --test --stay --failed`.
3. Fix, then rerun the failures once more, then the suite before you commit.
4. When the script says a test has failed three runs in a row, stop rerunning. Write down what
   each run ruled out and change the approach: a different diagnostic, a smaller test, or reading
   the game's code (decompiled Java and its Lua) for what the step really does.

## It passes alone and fails in the suite

Something an earlier test left behind, or the order, changes it.

1. Read the `LEAK` and `DESYNC` lines of the full run. With `LEAKS=fail`, the default, the test
   that left something behind fails itself, so it is usually the first failure in the run, not
   the one you were looking at.
2. Change the order rather than guessing: `ORDER=reverse` or `ORDER=shuffle`, with the narrowest
   `TESTS` that still fails. A shuffle prints its seed; `ORDER=shuffle:<seed>` repeats it.
3. Never bisect by hand in a kept game. What every earlier run built stays in its world, so
   each run there starts somewhere new, and a result there says little about a fresh game. The
   kept game prints `DIRTY` lines for what its last run left behind; start a fresh game (leave
   out `--stay`) when it does.

## It fails now and then

`REPEAT=<n>` runs the selection n times in one game and prints each test's passes and failures:

```sh
REPEAT=20 TESTS=mymod_world_trailer_ dev/run-debug-client.sh --test --stay
```

Add `ORDER=shuffle` to mix the order between rounds as well.

## Gotchas

- A timed action that turns invalid or is refused stops, and that empties the character's whole
  action queue, the test's later waits and steps included. The harness fails the test at once,
  naming the action that was running, and skips validate, which would read what the lost steps
  never made. Look at why that action refused, such as its `isValid` or a skill check.
- A server handler's answer reaches the test exactly as returned: `false`, `0` and `nil` arrive as
  themselves, so check them before you index them.
- In debug mode a Lua error stops the game in its error handler, `pcall` or not, and the run ends
  there. A validate that indexes something a failed step never made ends the whole run, so guard
  every value a step might not have set (`T.need` in run, a nil check in validate).
- The server sends an object it adds to a square, and later changes to it, by its place in the
  square's list of objects. A client copy whose square holds a different list, such as after an
  object came and went quickly, applies the change to the wrong object or none: that shows as a
  `DESYNC` line on that square.
- A `LEAK` on an object nobody's test touches, which changes on both sides as game time passes,
  is the world rather than a test. The leak check already leaves out crops, erosion and grass; add
  the dev mod's own such sprites to its `leakIgnore` setting rather than switching the check off.
- A `--test` world doesn't populate itself ([a quiet world](running.md#a-quiet-world)): no
  generators, cars, survivor houses or other stories appear on their own. A test that needs one of
  those places it. A world object nobody's test placed, or a test that passes only with a vanilla
  generator or car nearby, means a mod's sandbox settings turned some of that back on, or the
  mod's own code placed it.

# Multiplayer

How `--test --mp` runs a mod's tests against a dedicated server, and what a test written once needs to run in both modes.

`--test --mp` takes the lock once, then:

1. Prepares two cache dirs, `$TMPDIR/<CACHE_NAME>-mpserver` and `-mpclient`, each with a copy of
   the mod and links to the harness mod and the dev mod.
2. Writes the server's `harness.ini` (the three mods, ports 16361 and 16362, `Open`, `PauseEmpty`
   off) and runs the conf's `harness_server_setup`, then appends `Zombies = 6` to its sandbox, so
   the world has no zombies, as the scenarios' do, and the `QUIET_WORLD` options the hook didn't
   set ([a quiet world](running.md#a-quiet-world)). Every cold run starts a new world.
3. Starts the server with FastServer, through `start_server` in `lib/harness.sh` as
   `validate-server.sh` does, and the client with ClickToStart at the same time. The client waits
   at the main menu until the script writes `<client cache>/Lua/PZHarnessConnect.txt`, once the
   server's log says it started, then joins as the server's admin: a `-debug` client must have the
   ConnectWithDebug capability. Overlapping the boots saves seconds on every run; joining before
   the server listens would only fail.
4. The runner skips character creation (the default unemployed survivor), takes the character to
   the scenario's `startLoc`, waits for the world to load, runs the scenario's `onStart` and the
   mod's on the client, and runs the tests as in single player.
5. After `DONE` the server gets `quit` on its console and saves while the client quits; the script
   scans the client's log as in single player and the server's up to its exit as
   `validate-server.sh` does, plus stack traces through the dev mod and the harness mod and
   `SERVER FAIL` lines. Both processes stop on any exit of the script.

A cold run takes about 44 seconds on an M3 Max: 18 for the server to start (the client boots
meanwhile), 7 to join, 11 to load the world and reach the start, then the tests, then 7 for the
server to save and exit. A rerun in a kept `--mp --stay` game takes under a second plus the tests:
the server first loads its share of `RELOAD_FILES` again (the dev mod's `media/lua/server` and
`media/lua/shared` files) and marks the run in its log, then the client loads its files and
reruns. A change to any other file restarts both, as does either process having stopped. The kept
client quits after its idle time and the server goes with it; the lock is free once both have.

## The server channel

Tests are written once and run in both modes. On a multiplayer client the character, its
inventory and the world are the client's copies, and the mod's server Lua (which usually returns
early when `isClient()`) is empty, so what only the authority can do goes through `T.server`:

- `PZHarness.serverHandler(name, fn)` in the dev mod's server Lua registers `fn(player, args,
  defer)`, which returns a table of plain values (or nil and what is missing). `player` is the
  server's copy of the calling character. `defer(undo)` takes back what it built when the calling
  test ends, on the server, in order with the test's own undos; a handler that fails has its undos
  run at once.
- `T.server(self, name, args)` queues the call and a wait for its answer, which lands in
  `self.server[name]`. `args` may be a function of `self`, called when the call goes out, to use an
  earlier answer. A failed or missing answer fails the test as `T.need` does and drops the steps
  queued after it.
- Single player calls the handler in the same Lua state, at once. Multiplayer sends a client
  command (module `PZHarness`) and the server answers with a server command a tick or more later;
  an answer lost for 15 seconds fails the call. The runner starts the next test only once every
  request of the last one, its undos above all, has its answer, so no test meets what the one
  before built. An undo the server reports failed after the verdict prints its own `FAIL` line and
  counts in `DONE`.

A test that can't run in one mode says why: `spOnly = "<why>"` or `mpOnly = "<why>"` in its spec.
The runner skips it in the other mode and prints `<TAG> SKIP <name>: single player only: <why>`
(or `multiplayer only`). A missing reason, or both fields, fails the test in every mode.

## Two-sided fixtures

The library's fixtures act on both copies, so a test written once runs in both modes and single
player behaves as before:

- Setters (`setSandbox`, `setTime`, `setMultiplier`, `setGrid`, `setPerk`, `setMechanicsCheat`,
  `changeItem`, the test's `instant` and `perks`) change this game's copy at once; on a multiplayer
  client they also send the change to the server (handlers named `PZHarness.*` in
  `ServerFixtures.lua`) at once and queue a wait for its answer, so actions queued after them start
  once the server has it. The server undoes it when the test ends. A dev mod's server Lua sets
  `PZHarness.serverSettings.sandboxChanged` for what the client's `tests.sandboxChanged` does.
  A client lights its squares with the daylight the server sends it, which the server does only
  every ten game minutes, so the server's `setTime` (and its undo) makes its next climate tick
  send it; `makeDark` then waits, up to 10 seconds, for this client's light to follow.
- Items: `T.give(self, name, items)` (`{ type, count, uses, condition, modData, worn, equip }`)
  makes them on the server, which sends them; once this client has them it puts them on and in
  hand (`PZHarness.dress`: clothing synced before its item reaches the client as a stray copy),
  and `self.items[name]` holds this client's copies. A dev mod's handler gives its own items with
  `PZHarness.giveItem(player, item, { worn, equip })` and lists the results as `given` in its
  reply; `T.server` then does the same. `T.count` counts the server's inventory.
- World: `placeTile`, `placeBench` and `placeVehicle` place on the server and return a handle at
  once whose `.object` (`.vehicle`) is this client's copy after a queued wait; the server removes
  them when the test ends, through `PZHarness.serverSettings.remove(object)` if set.
  `PZHarness.serverSettings.spawnVehicle(script, square, facing, args)` may make the vehicles.
  The server gives a new vehicle the id it freed last, often the previous test's vehicle's, so
  `placeVehicle` never takes a copy it found for an earlier handle, which a client still holds
  until it takes the removal.
  On a multiplayer client it also waits 300 ms after its copy arrives: a client meeting a new
  vehicle id can ask for two full updates, the server sends the second in place of pending part
  changes, and a client that has the vehicle takes only its position from it, so a part change
  made in between would never reach the copy.
  `placeAsPlayer` gives the item (`give`), and the character places it with the moveables action,
  whose `complete()` the server carries out; `PZHarness.trackPlaced` then removes it on the server
  when the test ends, as above.
  `T.placeWorkTable`, `T.learnRecipes` and `T.forgetRecipes` work outside tests too, as in a
  scenario's onStart; `PZHarness.ServerCalls.callOutsideTest(name, args, onReply)` calls any
  handler there.
- The runner resets the server's copy of the character before every test too, and after the
  scenario's and the mod's onStart copies the client's perk levels and known recipes to it. The
  first test starts once the server has them and this client shows the levels again: the server
  replaces the client's perk list with its own copy's every second (`PlayerXpPacket`), and one it
  sent before it had the levels can land after its answer, leaving the skills too low for the first
  crafts. Waiting more than 5 seconds for that prints a `FAIL` of its own. For the same reason
  `setPerk` on a multiplayer client puts its level back on this client whenever such a sync
  changes it, until the test ends; a stale sync otherwise made a mid-run craft "skills too low".
- After each reset the runner refreshes the inventory windows at once, in both modes. Crafts and
  the craft menu take their inputs from the containers those windows list, which otherwise catch up
  only when the UI next draws; a multiplayer character starts with a key ring, and its removed
  container, still listed, can't be named to the server ("Unable to resolve container location"),
  so the first test's craft never started.

## What a client can and can't do

- Client Lua runs on the client only: setting `SandboxVars`, the clock, the game speed or the grid
  directly changes the client's copy, which the server overwrites or ignores; use the setters
  above. The server's own sandbox at start comes from `harness_server_setup`.
- Objects a client places with `AddTileObject` (`T.tile`, `T.bench`) exist on that client only,
  and items it adds to the inventory aren't on the server: a timed action with `complete()` runs on
  the server, which can't find them. `ActionManager.sendAction` then logs "Unable to resolve
  container location", which fails the run. Use the two-sided fixtures or a server handler.
- An action's `complete()` runs on the server, and what it removes (an item the action used) can
  reach the client before the action ends there; an `isValid()` that then fails stops the action,
  and `ISBaseTimedAction:stop` empties the whole action queue, dropping the test's later steps.
- The server never sends a client the recipes it forgets (`SyncPlayerFieldsPacket`), and the game
  deletes a drainable item whose uses run out (`DrainableComboItem.update`).
- Commands through `sendClientCommand`, the Global Object System's syncs to the client's copies,
  and timed actions without `complete()` (such as the harness's own waits) work as in a real game.
- The client is admin, so permission checks the server makes for players aren't exercised.
- `getUsername()` of the client's character can differ from the account (`admin`) the server sees;
  don't key on it.

## Known noise and limits

- Joining resets the client's Lua (`Core.ResetLua`), so every mod's Lua loads twice on the
  client: once at boot, as in single player, and once as a multiplayer client. Load-time side
  effects outside Lua (files, Java state) happen twice. The reset also logs a
  `NoSuchFileException` for each mod without `media/AnimSets`; vanilla's, harmless, and not
  counted.
- The client doesn't pause when it loses focus, but like any run it takes keyboard focus while its
  window is up.
- Only `--test` runs in multiplayer; the mod's other modes are single player.

What `dev/run-debug-client.sh` does with each flag, why a run is fast, and the rules every run follows. [debugging.md](debugging.md) says which run to reach for when.

## Flags and environment

`dev/run-debug-client.sh`:

| Flags | What happens |
| --- | --- |
| none | Play by hand: the main menu, with the scenario under Scenarios and the tests under Debug menu > Dev > Unit Tests > Timed Actions. |
| `--test` | Runs every test of the mod and quits. Exits 1 on a failure or any Lua error. |
| `--test --stay` | The same, but the game stays open; the next `--test --stay` reruns the tests in it. |
| `--test --mp` | The same in multiplayer: a dedicated server and a client that joins it; see [multiplayer.md](multiplayer.md). |
| `--test --mp --stay` | Both stay open; the next `--test --mp --stay` reruns the tests in them. |
| `--test --failed` | Runs only the tests that failed in the last `--test` run of the same kind (with or without `--mp`), and the one a stopped run was in. |
| `--test --changed` | Runs the tests the conf's `TEST_MAP` gives for the files changed since `HEAD`, staged, unstaged or untracked, and prints each file's share and why. A changed file under the mods that no glob covers runs every test; with nothing changed under the mods, nothing runs. |
| `--<mode>` | Runs the mod's handler for the mode and quits. |

`--failed` and `--changed` combine with `--mp` and `--stay`, not with each other or with `TESTS`.

Environment: `TESTS=<prefix>,...` runs only the tests whose names start with one of them, and
`=<name>` in the list names one test exactly; `REPEAT=<n>` runs the selection n times over in one
game and ends with a `<TAG> REPEAT <name> passed=<n> failed=<n>` line per test, the most failed
first; `ORDER=reverse` runs the tests in reverse order, and `ORDER=shuffle` in an order from a
seed the script picks and prints, which `ORDER=shuffle:<seed>` repeats; `LEAKS=fail` (the
default), `warn` or `off` sets what the [leak check](#leaks-and-desyncs) does; `TIMEOUT` caps a
run in seconds (default 300 for `--test`, times `REPEAT`, enough for a cold `--mp` run of a
whole suite, so it only catches a game that died; 1200 for the other modes); `CACHE` moves the
cache dir (with `--mp` the client's; `SERVER_CACHE` the server's); `SERVER_PORT` moves the
`--mp` server off 16361 (it also takes the next port); `JAVAC` names the compiler for
`ClickToStart.java` (any JDK from 8 on; the game's own Java has none); `PZ_APP` names another
game `Contents` folder; `RERUN=1` runs a `--test` run the script would refuse as a
[repeat](#repeats).

Console lines, in `<cache>/console.txt`: `<TAG> START <n>`, `<TAG> ORDER <order>` and
`<TAG> REPEAT <n> rounds` when set, `<TAG> LEAKS <mode>`, `TEST: <name>`, `<TAG> LEAK <name>: <what>`
and `<TAG> DESYNC <name>: <square> client [...] server [...]` for what a test left behind,
`<TAG> PASS <name>`, `<TAG> FAIL <name>: <reasons>`, `<TAG> SKIP <name>: <why>` for each test that
opted out of this mode, each of those three ending with the test's wall time, `(<s> s)`, and
`<TAG> FAIL <entry>: the selection names no test` for a `TESTS` entry that matches no test; then the
`REPEAT` counts, `<TAG> SLOWEST` lines, `<TAG> TIME <s> s, <n> frames`,
`<TAG> DONE passed=<n> failed=<n> skipped=<n>`; with `--stay` also `<TAG> RUN <id>`,
`<TAG> DIRTY <name>: <what>` for what the last run in the kept game left behind, and
`<TAG> IDLE ...`. With `--mp` the server's log (`<server cache>/server-console.txt`) gets
`<TAG> SERVER FAIL <test>: <error>` for a handler or undo that failed, and `<TAG> RUN <id>` for a
rerun. The script prints every line with the run's mark and both logs' paths, and exits 0 only if
the run finished, at least one test passed, nothing failed and no Lua error was logged on either
side.

## A quiet world

A `--test` world doesn't populate itself: the world normally fills in a chunk or a building the
first time it loads, at random, and in the middle of a run that can put a generator, a crash
site or a parked car beside a test that never placed one, and make one run differ from the next.
`QUIET_WORLD` in `lib/harness.sh` lists the sandbox options that stop it, each with the vanilla
code it turns off: generator spawning, survivor houses and other building stories, vehicle and
zone stories, ranches, animal tracks and paths, rats and cockroaches, parked and jammed cars,
annotated maps (each of which makes a building a stash), house alarms, the helicopter and the
random meta events. In single player the runner sets them before the scenario's `setSandbox`,
which runs after and may set any of them back; on the `--mp` server they are appended to its
sandbox file wherever the conf's `harness_server_setup` set nothing. A conf that sets
`QUIET_WORLD` itself replaces the list. Other modes (`--promo`, `--art`, a mod's reports) and
`validate-server.sh` keep the world's own population.

## Leaks and desyncs

Between tests, and after the last, the runner resets the character and takes a snapshot of the
world around it (`shared/PZHarness/Snapshot.lua`), which it compares with the one from before the
test that just ended: the objects on every square within the `leakRadius` setting (by default a
little past where `T.squares` looks) on the `leakLevels` z levels (the character's own by
default), each as its sprite or item type and class, with generators and light switches on or
off; the vehicles there; whether a sparse grid of those squares has power; the character's perk
levels, known recipes and what it holds after the reset; where it starts; the sandbox options;
the grid; the game speed; the climate's admin overrides; and the clock, which may only have run
on. It leaves out what the world keeps globally, such as the global mod data and the records of
the global object systems (farming, troughs, a mod's own): those grow with every chunk that loads
for the first time, so a test that only travels would seem to leave them changed.

The comparison leaves out objects the world changes by itself, and grass, which goes from a
square something was placed on and never comes back: crops and garden plants, erosion's grass,
plants, trees, bushes, cracks and roof snow, and grass overlays (`Snapshot.DEFAULT_IGNORE`). The
dev mod's `leakIgnore` setting adds Lua patterns, matched against `<sprite>@<class>`. A square
whose objects differ only by those doesn't count.

In multiplayer the server snapshots its copy ("PZHarness.snapshot") while the client snapshots
its own, and the server's differences are the ones reported for objects, vehicles, perks, recipes
and the clock, since the client only copies those from it. The client reports its own state (what
it holds, the power it works out itself, the options) and compares its squares with the server's
wherever either side saw one change. What the server sent can still be on its way, so a
difference between the copies, or a change of the client's own state, costs a second look half a
second later, and only what is still there is reported.

Each difference prints a `LEAK` line (the server's start with "on the server"), and each square
where the copies still differ a `DESYNC` line, at most a handful per test with a count of the
rest, before the test's verdict. With `LEAKS=fail` they fail the test, as its reasons; with
`LEAKS=warn` they only print; `LEAKS=off` skips the snapshots. A check that finds nothing costs one
snapshot, taken on both sides at once in multiplayer, a few tens of milliseconds; the last
`SLOWEST` line says how long the checks took in all. A kept `--stay` game prints what its last
run left behind as `DIRTY` lines when the next run starts, since that run starts on top of it.

## Choosing tests

`--failed` reads `dev/.runs-failed` in the mod's repository, which every `--test` run that got as
far as its tests rewrites for its kind (`test` or `test-mp`): the tests with a `FAIL` line, and
the test a Lua error or the timeout stopped, each with the number of runs of that kind in a row it
has failed. A run whose tests all passed leaves the list empty, and `--failed` then runs nothing.
The mod should gitignore it, as it does `dev/.runs.log`. At the end of a run with failures the
script prints `--failed reruns: <names>`, and, for a test that has failed three runs in a row, a
line that says reruns aren't narrowing it down and points at [debugging.md](debugging.md).

`--changed` reads `git diff --name-only HEAD` and the untracked files, of the repository and of
the harness submodule, and the conf's `TEST_MAP` ([adopting.md](adopting.md#devharnessconf)). It
refuses to run while a `TEST_MAP` glob matches no file in the repository.

### Repeats

A `--test` run's verdict depends on the kind of run (`--mp`, `--stay`), the selection, `LEAKS`,
`ORDER` and `REPEAT`, and the files the game loads: the three mods, the harness's scripts and the
conf. `dev/.runs.log` keeps a fingerprint of those with each run, and a run whose fingerprint
already has a verdict there doesn't start a game: the script prints that verdict and exits with
that run's status. A run that never got its verdict, such as one a Lua error stopped, doesn't
count. `RERUN=1` runs it anyway, for when the game rather than a test failed.

### Checks before a run

The conf's `PRECHECK` ([adopting.md](adopting.md#devharnessconf)) runs before every harness game,
`validate-server.sh` too, and no game starts if it fails.

## Where the time goes

The `<TAG> SLOWEST <s> s <name>` lines name the slowest tests, slowest first, and in multiplayer
how long each had a server answer outstanding (`(server <s> s)`). The last `SLOWEST` line splits
the run into the time in tests and the time between them: the runner waiting for the character's
square to load again after a test that went far, the leak checks, and in multiplayer the
server's resets and undos. In multiplayer it adds how much of both had a server answer
outstanding.

On exit, `run-client.sh` and `validate-server.sh` print a `timing: <phase> <s> s (<what>)` line
per phase, each from the end of the one before, then `timing: total`. The clock starts once the
script holds the game lock, so a wait for another script's game doesn't count. The phases are
`setup` (to the game's launch; in a kept game, to the rerun request), `boot` (to the harness's
Lua), `world` (to the world loaded around the character), `start` (to the first test), `run` (to
the last result), `quit` (to the game's exit, and with `--mp` to the server's after it saves), and
with a fresh `--mp` server `server` (its launch to ready, beside the client's boot). A run a Lua
error stopped has `stopped` (to the poll that saw the error) in place of `run` and no `quit`.
`validate-server.sh` has `setup`, `boot` and `quit` for its server. A phase the run never reached
is left out. The script reads the milestones off the console as it polls it, so they are good to
about half a second.

Each run also appends one line to `dev/.runs.log` in the mod's repository, which the mod should
gitignore: the date, `mode=` (`test`, `test-mp`, a mode's name, `validate`; `-rerun` for a run in
a kept game), `selection=` (`TESTS`, the mode's selection, or `all`), the counts of the `DONE`
line, `exit=` (the script's exit status), each phase as `<phase>=<s>`, `total=`, and for `--test`
`fingerprint=`, which the script reads to refuse a [repeat](#repeats).

## Why it is fast, and what that costs

- No pause between tests. The vanilla runner pauses a second after each test so you can read its
  result; the harness runs the same resets (full health, empty inventory, nothing worn or held,
  the build cheat off, the character back where the test started) and starts the next test on
  the next tick.
- Uncapped frames. Game time per second doesn't depend on the frame rate, so more frames a second
  only shorten what is counted in ticks. `--test` and modes registered `uncapped` draw as many
  frames as they can (about 260 a second on an M3 Max, against 60). A test therefore waits with
  `waitUntil` on the condition it needs, never for a fixed number of frames. Every mode loads
  uncapped, since the main menu and the loading screen step per frame; the others go back to 60
  when the scenario starts.
- More asset loader threads. The game loads textures, meshes and animations on 4 threads, and the
  loading screen waits about 8 seconds for them with all 4 busy. ClickToStart swaps in a pool of
  up to 12 (the cores less 4), which cuts that wait to about 2 seconds. A dedicated server waits
  for its models and animations the same way before it starts, and FastServer gives it the same
  pool, which halves that wait.
- Settling by loaded chunks. A run starts once one square in every chunk 40 squares around the
  character has loaded, not after a fixed delay.
- Fast UI in captures. A mode registered `fastUI` draws the UI at its highest rate, so its steps
  that wait for the UI to draw wait less.
- `--test --stay`. Starting and quitting the game costs about 21 seconds. A kept game reruns the
  tests in a second or two plus their own time: the runner unregisters the mod's tests, runs
  `RELOAD_FILES` again with `reloadLuaFile` and reruns. `reloadLuaFile` ignores a file's
  `Events.*.Add` calls (`LuaCompiler.rewriteEvents`), so only files that just register tests or
  server handlers reload safely; a change to anything else in the dev mod, to the harness mod, or
  to the published mod restarts the game. What earlier runs left in the kept world stays there, so
  finish with a plain `--test`. The kept game shows and logs `<TAG> IDLE`, draws 24 frames a second
  while it waits, and quits after 30 minutes without a run or when another run needs the game.
- Early stop. In debug mode a Lua error stops the game in its error handler, so it never quits on
  its own. A Lua stack trace through any of the three mods, or any Lua failure once the harness
  has started, ends the run at once and prints the trace. An exception the game logs and goes on
  from (its frames indented twice), and anything on a server, which never stops at an error, fail
  the run in the scan after it instead.
- Silent. Harness runs set every volume in the cache's `options.ini` to 0; the sound engine still
  runs. Playing by hand keeps your volumes.

## Other behaviour

- One game at a time. Every script that starts a game, for any mod, takes the lock
  `$TMPDIR/PZ_DevHarness-game.lock` and waits while another holds it; a lock whose owner died
  is taken over. A kept `--stay` game (with `--mp` its client and server) holds the lock itself,
  and the next run that needs the game stops it, unless that run is a `--stay` run of the same
  cache dir that can rerun in it.
- The published mod is copied into the cache's `mods` folder, not linked, and the cache dir is
  under the real path of `$TMPDIR`: the game reads tile depth maps by absolute path and refuses
  paths through a symlink (`ZomboidFileSystem.validatePrefix`). The dev mod and the harness mod
  have no tiles and are linked.
- The runner reads the run from `<cache>/Lua/PZHarness.txt`, rerun requests from
  `<cache>/Lua/PZHarnessRerun.txt` and, with `--mp`, the server to join from
  `<cache>/Lua/PZHarnessConnect.txt`. Without the first file, as in a game the script didn't
  start, there is no mode, and the tests print under the tag `PZHarness`.
- `debug-options.ini` sets `DebugScenario.ForceLaunch` in single player harness modes, so the
  scenario the runner marks `forceLaunch` starts from the main menu, and the runner turns off
  pausing when the window loses focus.
- A run takes keyboard focus while its window is up, and a keypress there (Escape opens the pause
  menu) can break it, so leave it alone until it quits.
- Each mode's run deletes the `<mode>_*.png` screenshots in `<cache>/Screenshots` before it
  starts, so name a mode's screenshots after it.

`java/AssetLoading.java`:

```java
import java.lang.reflect.Field;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

/**
 * FileSystemImpl loads textures, meshes, animations and depth maps on a pool of at most 4 threads,
 * and both the client's loading screen and the dedicated server's start wait for all of them, with
 * all 4 threads busy throughout. ClickToStart and FastServer swap in a wider pool once the game has
 * created GameWindow.fileSystem.
 */
final class AssetLoading {
    private AssetLoading() {
    }

    /**
     * Gives GameWindow.fileSystem a pool of up to 16 threads. Tasks it has already handed to the old
     * pool finish there; the game keeps at most 16 tasks in flight, so more threads would idle.
     */
    static void widen() {
        try {
            Object fileSystem = Class.forName("zombie.GameWindow").getField("fileSystem").get(null);
            int threads = Math.min(16, Math.max(4, Runtime.getRuntime().availableProcessors() - 4));
            ExecutorService pool = Executors.newFixedThreadPool(threads, task -> {
                Thread thread = new Thread(task, "AssetLoader");
                thread.setDaemon(true); // never holds the JVM open after the game quits
                return thread;
            });
            Field executor = fileSystem.getClass().getDeclaredField("executor");
            executor.setAccessible(true);
            executor.set(fileSystem, pool);
            System.out.println("PZHarness: asset loading on " + threads + " threads");
        } catch (Exception e) {
            // Only slower: the game keeps its own pool.
            System.out.println("PZHarness: couldn't widen asset loading: " + e);
        }
    }
}

`java/ClickToStart.java`:

```java
import java.lang.reflect.Field;

/**
 * Starts the game client and presses "Click to start" whenever the loading screen shows it, so
 * the unattended runs of bin/run-client.sh (--test and the mod's own modes) need no one at the
 * computer. It also gives the game's asset loader more threads (AssetLoading), which shortens
 * loading.
 *
 * GameLoadingState.update() continues only after a real left click, a joypad A press, or its
 * private forceDone flag, and Lua can reach none of them, so this sets forceDone. The game runs its
 * loop on a thread named "MainThread", created by GameWindow.InitGameThread(). This waits for that
 * thread before touching GameWindow, because reading a static field of a class that isn't
 * initialized yet would initialize it here, out of the game's startup order.
 */
public class ClickToStart {
    private static final long POLL_MS = 500;

    public static void main(String[] args) throws Exception {
        Thread clicker = new Thread(ClickToStart::clickWhenAsked, "ClickToStart");
        clicker.setDaemon(true);
        clicker.start();
        Class.forName("zombie.gameStates.MainScreenState").getMethod("main", String[].class).invoke(null, (Object) args);
    }

    private static void clickWhenAsked() {
        try {
            while (!gameThreadStarted()) {
                Thread.sleep(POLL_MS);
            }
            AssetLoading.widen();
            ClassLoader loader = ClickToStart.class.getClassLoader();
            Field states = Class.forName("zombie.GameWindow").getField("states");
            Field current = Class.forName("zombie.gameStates.GameStateMachine").getField("current");
            // Not initialized here: the game creates the instance before its fields are read.
            Class<?> loading = Class.forName("zombie.gameStates.GameLoadingState", false, loader);
            Field showedClickToSkip = accessible(loading.getDeclaredField("showedClickToSkip"));
            Field forceDone = accessible(loading.getDeclaredField("forceDone"));
            while (true) {
                Object state = current.get(states.get(null));
                if (loading.isInstance(state) && showedClickToSkip.getBoolean(null)) {
                    forceDone.setBoolean(state, true);
                    System.out.println("ClickToStart: pressed Click to start");
                    while (current.get(states.get(null)) == state) {
                        Thread.sleep(POLL_MS);
                    }
                }
                Thread.sleep(POLL_MS);
            }
        } catch (Exception e) {
            System.out.println("ClickToStart: failed, click by hand");
            e.printStackTrace(System.out);
        }
    }

    private static boolean gameThreadStarted() {
        for (Thread thread : Thread.getAllStackTraces().keySet()) {
            if ("MainThread".equals(thread.getName())) {
                return true;
            }
        }
        return false;
    }

    private static Field accessible(Field field) {
        field.setAccessible(true);
        return field;
    }
}

`java/FastServer.java`:

```java
/**
 * Starts the dedicated server with more asset loader threads, as ClickToStart does for the client:
 * before it starts, the server waits for the game's models, animations and clothing to load on the
 * same pool of at most 4 threads, all of them busy throughout.
 *
 * Reading a static field of a class that isn't initialized yet would initialize it here, out of
 * the server's startup order, so this waits until the server's main thread is in the loop of
 * GameServer.doMinimumInit that waits for GameWindow.fileSystem's loads, which only runs once
 * GameWindow is initialized.
 */
public class FastServer {
    private static final long POLL_MS = 20;

    public static void main(String[] args) throws Exception {
        Thread main = Thread.currentThread();
        Thread widener = new Thread(() -> widenOnceLoading(main), "FastServer");
        widener.setDaemon(true);
        widener.start();
        Class.forName("zombie.network.GameServer").getMethod("main", String[].class).invoke(null, (Object) args);
    }

    private static void widenOnceLoading(Thread main) {
        try {
            while (!waitingForAssets(main)) {
                if (!main.isAlive()) {
                    return;
                }
                Thread.sleep(POLL_MS);
            }
            AssetLoading.widen();
        } catch (InterruptedException e) {
            // Only slower: the server keeps its own pool.
        }
    }

    private static boolean waitingForAssets(Thread main) {
        boolean inFileSystem = false;
        for (StackTraceElement frame : main.getStackTrace()) {
            if (frame.getClassName().equals("zombie.fileSystem.FileSystemImpl")) {
                inFileSystem = true;
            } else if (inFileSystem && frame.getClassName().equals("zombie.network.GameServer")
                    && frame.getMethodName().equals("doMinimumInit")) {
                return true;
            }
        }
        return false;
    }
}

# Sourced by the harness scripts and by a mod's own dev scripts. The harness sits in the mod's
# repository at dev/harness, and the mod describes itself in dev/harness.conf (see docs/adopting.md).

# The value of `key=` in a mod.info.
mod_info() {
    sed -n "s/^$2=//p" "$1/42/mod.info" | head -1
}

literal_regex() {
    printf '%s' "$1" | sed 's/[][\.|$(){}?+*^]/\\&/g'
}

MOD_FOLDER="$(basename "$MOD_DIR")"

DEV_MOD_DIR="$REPO/$DEV_MOD_DIR"
DEV_MOD_FOLDER="$(basename "$DEV_MOD_DIR")"

HARNESS_MOD_DIR="$HARNESS/mod"
HARNESS_MOD_FOLDER=PZTestHarness
HARNESS_MOD_ID="$(mod_info "$HARNESS_MOD_DIR" id)"

# Lua stack traces name a mod as "(MOD:<name in mod.info>)". MOD_ERROR matches the published mod,
# OUR_LUA_ERROR any of the three mods a harness run loads.
MOD_ERROR="\\(MOD:$(literal_regex "$(mod_info "$MOD_DIR" name)")\\)"
OUR_LUA_ERROR="\\(MOD:($(literal_regex "$(mod_info "$MOD_DIR" name)")|$(literal_regex "$(mod_info "$DEV_MOD_DIR" name)")|$(literal_regex "$(mod_info "$HARNESS_MOD_DIR" name)"))\\)"

# GAME_CLASSPATH is relative to.

    --add-exports=java.base/jdk.internal.misc=ALL-UNNAMED -Dzomboid.steam=0 -Dzomboid.znetlog=1
    -XX:-OmitStackTraceInFastThrow)

# The sandbox options of a --test world, as Key=value: the world fills itself in when a chunk or
# building first loads, and some of it at random, so a test could meet objects nobody placed and
# a run differ from the last. A conf that sets QUIET_WORLD itself (=() for none) replaces the
# list, and the mod's own sandbox settings win over it (docs/running.md, "A quiet world").
if ! declare -p QUIET_WORLD > /dev/null 2>&1; then

        GeneratorSpawning=1   # None: no generators in garages and sheds (IsoCell) or in loot
        SurvivorHouseChance=1 # Never: no building stories, which furnish, barricade and stock houses
        VehicleStoryChance=1  # Never: no crash sites and roadside camps
        ZoneStoryChance=1     # Never: no campsites, picnics and other stories in zones
        AnimalRanchChance=1   # Never: no ranches with their animals, troughs and fences
        AnimalTrackChance=1   # Never: no animal tracks left on squares
        AnimalPathChance=1    # Never: no animal paths among the world's zones
        MaximumRatIndex=0     # no rats and cockroaches in buildings (RBBasic)
        CarSpawnRate=1        # None: no parked or jammed cars where fixtures go (IsoChunk.AddVehicles)
        AnnotatedMapChance=1  # Never: no annotated maps in loot, each of which makes a building a stash
        Alarm=1               # Never: no house alarms going off when a test enters a building
        Helicopter=1          # Never: no helicopter event
        MetaEvent=1           # Never: no distant gunshots and other random sounds
    )
fi

# The game reads depth maps by absolute path and refuses paths outside the mod folders and the
# cache dir without resolving symlinks (ZomboidFileSystem.validatePrefix), so a symlinked mod, or a
# cache under macOS's /var (really /private/var), loses its tile depth maps. Hence a real copy of
# the published mod, in a cache dir under a path with no symlink in it.
TMP_REAL="$(cd "${TMPDIR:-/tmp}" && pwd -P)"

# Compiles a dev Java file, and the files of its folder it uses, into a directory when one of
# those sources is newer than its class. The game's own Java has no compiler, so it needs a JDK's
# javac (or JAVAC); class files for Java 8 run on the game's newer JVM, and any JDK from 8 on can
# write them.
compile_java() {
    local source=$1 dir=$2
    local class folder
    class="$dir/$(basename "$source" .java).class"
    folder=$(dirname "$source")
    if [ ! -f "$class" ] || [ -n "$(find "$folder" -maxdepth 1 -name '*.java' -newer "$class")" ]; then
        mkdir -p "$dir"
        "${JAVAC:-javac}" -nowarn -Xlint:-options -source 8 -target 8 -sourcepath "$folder" -d "$dir" "$source"
    fi
}

install_mod() {
    mkdir -p "$CACHE/mods"
    # rsync copies only what changed; an old symlink in its place has to go first.
    if [ -L "$CACHE/mods/$MOD_FOLDER" ]; then
        rm "$CACHE/mods/$MOD_FOLDER"
    fi

# Only one game process started by these scripts runs at a time, client or server, whichever mod
# started it: several copies of the scripts may run at once, and parallel games starve each other
# of memory and fight over the display. macOS has no flock, so the lock is a directory, which mkdir
# creates atomically, holding the owner's PID. A lock whose owner has died is taken over: a script
# killed outright never runs its EXIT trap, and the manual client execs into the game.
#
# A game kept open by run-client.sh --stay owns the lock itself once its script exits: the lock's
# pid is the owner's, and its "session" file holds the owner's PID, the cache dir and the PIDs of
# the game's processes. The owner is the game itself, or with --mp a keeper that exits once the
# client and the server have. The next script to want the game takes the lock and the game over;
# with the argument "reuse" it leaves the game running and sets SESSION_PID, SESSION_CACHE and
# SESSION_GAMES, and otherwise it stops the game.
GAME_LOCK="${TMPDIR:-/tmp}/PZ_DevHarness-game.lock"

acquire_game_lock() {
    local owner said=
    SESSION_PID= SESSION_CACHE= SESSION_GAMES=
    until mkdir "$GAME_LOCK" 2>/dev/null; do
        owner=$(cat "$GAME_LOCK/pid" 2>/dev/null || true)
        if [ -n "$owner" ] && ! kill -0 "$owner" 2>/dev/null; then
            # Moving the lock aside first means two waiters can't both remove it, and the second
            # remove the lock the first then took.
            mv "$GAME_LOCK" "$GAME_LOCK.stale.$$" 2>/dev/null && rm -rf "$GAME_LOCK.stale.$$"
            continue
        fi
        # No pid yet: the owner is between mkdir and writing it, or died there.
        if [ -z "$owner" ] && [ -d "$GAME_LOCK" ] \
            && [ $(( $(date +%s) - $(stat -f %m "$GAME_LOCK" 2>/dev/null || date +%s) )) -gt 30 ]; then
            mv "$GAME_LOCK" "$GAME_LOCK.stale.$$" 2>/dev/null && rm -rf "$GAME_LOCK.stale.$$"
            continue
        fi
        if claim_session; then
            break
        fi
        if [ -z "$said" ]; then
            echo "waiting for the game another dev script started (pid ${owner:-unknown}) to exit"
            said=1
        fi
        sleep 2
    done
    echo $$ > "$GAME_LOCK/pid"
    trap 'exit_report $?; release_game_lock' EXIT
    if [ -n "$SESSION_PID" ] && [ "${1:-}" != reuse ]; then
        echo "stopping the game kept open by --stay"
        stop_session
    fi
}

# Takes over the lock of a kept game nobody is using: its session file names it, and the lock's pid
# is the owner's own. The claim directory lets only one of several waiters do so.
claim_session() {
    [ -f "$GAME_LOCK/session" ] && mkdir "$GAME_LOCK/claim" 2>/dev/null || return 1
    local pid cache games
    { read -r pid && read -r cache && read -r games; } < "$GAME_LOCK/session" 2>/dev/null || true
    if [ -z "$pid" ] || [ "$(cat "$GAME_LOCK/pid" 2>/dev/null)" != "$pid" ]; then
        rmdir "$GAME_LOCK/claim"
        return 1
    fi
    SESSION_PID=$pid SESSION_CACHE=$cache SESSION_GAMES=${games:-$pid}
    echo $$ > "$GAME_LOCK/pid"
    rm -f "$GAME_LOCK/session"
    rmdir "$GAME_LOCK/claim"
}

release_game_lock() {
    if [ "$(cat "$GAME_LOCK/pid" 2>/dev/null)" = "$$" ]; then
        rm -rf "$GAME_LOCK"
    fi
}

# Stops the game with PID $1 and waits until it has exited, whether or not this script started it.
stop_pid() {
    kill "$1" 2>/dev/null || true
    wait "$1" 2>/dev/null || true
    while kill -0 "$1" 2>/dev/null; do
        sleep 0.5
    done
}

# The client first, so it doesn't see its server go.
stop_session() {
    local pid
    for pid in $SESSION_GAMES; do
        stop_pid "$pid"
    done
    stop_pid "$SESSION_PID"
    SESSION_PID= SESSION_GAMES=
}

# The game processes of this script: GAME_PID, the client, and SERVER_PID, a dedicated server
# (start_server). Stops the client, then the server.
stop_games() {
    if [ -n "${GAME_PID:-}" ]; then
        stop_pid "$GAME_PID"
    fi
    if [ -n "${SERVER_PID:-}" ]; then
        stop_server
    fi
}

# Background jobs of a script ignore Ctrl-C, so a game started in the background would outlive the
# script. Stops the games when the script exits, and releases the lock only once they have exited.
stop_games_on_exit() {
    trap 'exit_report $?; stop_games; release_game_lock' EXIT
}

# For --stay: when the script exits, hands the lock to the kept game if all of it still runs, with
# $1 as the lock's owner (the client by default).
keep_games_on_exit() {
    LOCK_OWNER=${1:-$GAME_PID}
    trap 'exit_report $?; hand_lock_to_game' EXIT
}

hand_lock_to_game() {
    local games="$GAME_PID${SERVER_PID:+ $SERVER_PID}" pid running=1
    for pid in $games $LOCK_OWNER; do
        kill -0 "$pid" 2>/dev/null || running=
    done

        echo "$LOCK_OWNER" > "$GAME_LOCK/pid"
        echo "the game stays open (pid $games); the next --stay run of the same kind reruns the tests in it"
    else
        stop_games
        release_game_lock
    fi

# Run timing --------------------------------------------------------------------------------------

# One line per run of the client and server scripts, for a look at where the time goes across many
# runs and for run-client.sh to know a run it has seen, and what failed in the last test run of
# each kind, for run-client.sh --failed. The mod's .gitignore lists both.
RUNS_LOG="$REPO/dev/.runs.log"
RUNS_FAILED="$REPO/dev/.runs-failed"

# Wall-clock seconds to a tenth: macOS's date has no fractions, and its bash no EPOCHREALTIME.
now() {
    perl -MTime::HiRes=time -e 'printf "%.1f\n", time'
}

# Notes the time of milestone $1 in TIMING_$1, the first time only, so a script can call it on
# every poll.
timing_mark() {
    local var="TIMING_$1"
    if [ -z "${!var:-}" ]; then
        printf -v "$var" '%s' "$(now)"
    fi
}

seconds_between() {
    awk -v from="$1" -v to="$2" 'BEGIN { printf "%.1f", to - from }'
}

# Prints a "timing:" line per phase and the total since TIMING_start, and appends the run to
# RUNS_LOG. $1 is the exit status, $2 the mode, $3 the selection, $4 the test counts; each further
# argument is a phase, "key|milestone|what": it runs from the last milestone reached before it
# (TIMING_start first) to its own, and a milestone the run never reached leaves its phase out. A
# fourth field, "|from", names the milestone a phase runs from instead, for one that overlaps the
# others, such as a server booting while the client does.
report_run() {
    local status=$1 mode=$2 selection=$3 counts=$4
    shift 4
    [ -n "${TIMING_start:-}" ] || return 0
    local previous=$TIMING_start fields= phase key milestone what from var at begin seconds
    for phase in "$@"; do
        IFS='|' read -r key milestone what from <<< "$phase"
        var="TIMING_$milestone"
        at=${!var:-}
        [ -n "$at" ] || continue
        if [ -n "$from" ]; then
            var="TIMING_$from"
            begin=${!var:-}
            [ -n "$begin" ] || continue
        else
            begin=$previous
            previous=$at
        fi
        seconds=$(seconds_between "$begin" "$at")
        echo "timing: $key $seconds s ($what)"
        fields="$fields $key=$seconds"
    done
    seconds=$(seconds_between "$TIMING_start" "$(now)")
    echo "timing: total $seconds s"
    printf '%s mode=%s selection=%s %s exit=%s%s total=%s%s\n' "$(date +%Y-%m-%dT%H:%M:%S%z)" "$mode" \
        "$selection" "$counts" "$status" "$fields" "$seconds" "${RUN_FINGERPRINT:+ fingerprint=$RUN_FINGERPRINT}" >> "$RUNS_LOG"
}

# The EXIT traps call this first, with the script's exit status; a script that times its run
# defines report_timing, which calls report_run.
exit_report() {
    if declare -F report_timing > /dev/null; then
        report_timing "$1" || true
    fi
}

    fi

-- Development only, not published. The runner's leak check between tests (PZHarness/Runner.lua):
-- a snapshot of this game's copy around the character (shared/PZHarness/Snapshot.lua), compared
-- with the one before the last test.
--
-- In multiplayer the server takes its own ("PZHarness.snapshot" in
-- server/PZHarness/ServerFixtures.lua) while this client takes its copy's, and reports what
-- changed in its copy, which is the one that counts for objects and vehicles. This client then
-- compares the two copies on every square either side saw change. What the server sent can still
-- be on its way, so only a difference, or a change of this client's own state, costs a second look
-- once that has had time to arrive, and only what is still there is reported.

require "PZHarness/Snapshot"
require "PZHarness/ServerCalls"

PZHarness = PZHarness or {}
local Leaks = {}
PZHarness.Leaks = Leaks

local SETTLE_MS = 500

-- This game's snapshot the next check compares with, and whether the server's baseline starts
-- over with the next call.
local baseline
local fresh = true

--- Forgets the baselines on both sides, so the next check only takes them, as at a run's start.
function Leaks.reset()
    baseline = nil
    fresh = true
end

local function askServer(args, onAnswer)
    PZHarness.ServerCalls.send("call", { name = "PZHarness.snapshot", test = "PZHarness.snapshot", args = args }, onAnswer)
end

local function differs(a, b)
    local Snapshot = PZHarness.Snapshot
    return Snapshot.syncSignature(a) ~= Snapshot.syncSignature(b)
end

-- The squares where the copies may differ: changed on this client and not on the server, or on
-- both but to different looks, or on the server and not here.
local function suspectSquares(snapshot, clientChanged, serverChanged)
    local serverSigs, suspects, seen = {}, {}, {}
    for i = 1, #serverChanged - 1, 2 do
        serverSigs[serverChanged[i]] = serverChanged[i + 1]
    end
    for _, key in ipairs(clientChanged) do
        seen[key] = true
        local server = serverSigs[key]
        if server == nil or differs(server, snapshot.squares[key]) then
            table.insert(suspects, key)
        end
    end
    for key, server in pairs(serverSigs) do
        local client = snapshot.squares[key]
        if not seen[key] and client and differs(server, client) then
            table.insert(suspects, key)
        end
    end
    return suspects
end

--- Starts a check around `character`'s square, `radius` squares each way on each of `levels` (z
--- levels; the character's own by default), leaving out the objects the patterns in `ignore`
--- match. Returns a function to call every tick: nil until the check is done, then
--- { leaks = { lines }, desyncs = { lines } }, both empty the first time, when there is nothing
--- yet to compare with.
function Leaks.start(character, radius, levels, ignore)
    local Snapshot = PZHarness.Snapshot
    local result = { leaks = {}, desyncs = {} }
    local phase, area, before, snapshot, answer, peek, settleUntil, ownChanges, suspects

    local function look()
        local square = character:getCurrentSquare()
        if not square then
            return result
        end
        local x, y, z = square:getX(), square:getY(), square:getZ()
        area = { x = x, y = y, z = z, radius = radius, levels = levels or { z }, ignore = ignore, copy = isClient() }
        if not isClient() then
            snapshot = Snapshot.take(area, character)
            if baseline then
                Snapshot.addLines(result.leaks, Snapshot.diff(baseline, snapshot))
            end
            baseline = snapshot
            return result
        end
        askServer({ x = x, y = y, z = z, radius = radius, levels = area.levels, ignore = ignore, fresh = fresh },
            function(reply) answer = reply end)
        before, snapshot = baseline, Snapshot.take(area, character)
        baseline = snapshot
        phase = "answer"
        return nil
    end

    -- The server's lines count as they are; this client's square changes only as suspects, and
    -- its own state (power it works out itself, what it holds) and the clock only on the server.
    local function compare()
        fresh = false
        if answer.error then
            table.insert(result.leaks, "the server's leak check failed: " .. tostring(answer.error))
            return result
        end
        for _, line in ipairs(answer.reply.leaks or {}) do
            table.insert(result.leaks, "on the server, " .. line)
        end
        if not before then
            return result
        end
        local report = Snapshot.diff(before, snapshot, { clock = false })
        ownChanges = #report.other > 0
        suspects = suspectSquares(snapshot, report.changed, answer.reply.changed or {})
        if not ownChanges and #suspects == 0 then
            return result
        end
        phase, settleUntil = "settle", getTimestampMs() + SETTLE_MS
        return nil
    end

    -- After the second look this client's own changes that remain are leaks, and the suspect
    -- squares go to the server to compare with how they look here now.
    local function lookAgain()
        if ownChanges then
            snapshot = Snapshot.take(area, character)
            baseline = snapshot
            for _, line in ipairs(Snapshot.diff(before, snapshot, { clock = false }).other) do
                table.insert(result.leaks, line)
            end
        end
        if #suspects == 0 then
            return result
        end
        askServer({ peek = suspects, ignore = ignore }, function(reply) peek = reply end)
        phase = "peek"
        return nil
    end

    local function compareSquares()
        if peek.error then
            table.insert(result.leaks, "the server's leak check failed: " .. tostring(peek.error))
            return result
        end
        local sigs = peek.reply.sigs or {}
        for i = 1, #sigs - 1, 2 do
            local key, server = sigs[i], sigs[i + 1]
            local client = Snapshot.signatureAt(key, ignore)
            -- The next check compares with how the square looks here now.
            baseline.squares[key] = client or nil
            if server and client and differs(server, client) then
                table.insert(result.desyncs, Snapshot.where(key) .. " client [" .. Snapshot.syncSignature(client)
                    .. "] server [" .. Snapshot.syncSignature(server) .. "]")
            end
        end
        return result
    end

    phase = "look"
    return function()
        if phase == "look" then
            return look()
        elseif phase == "answer" then
            return answer and compare() or nil
        elseif phase == "settle" then
            return getTimestampMs() >= settleUntil and lookAgain() or nil
        end
        return peek and compareSquares() or nil
    end
end

return Leaks

end

-- The selected tests to run, and those skipped in this mode as "<name>: <why>"; both sorted. Then
-- the selection's entries that name no test at all, such as a typo or a TEST_MAP entry for a test
-- that has since been renamed.
local function testNames()
    local result, skipped, used = {}, {}, {}
    for name, entry in pairs(TimedActionTests.getTests()) do
        if selected(name) then
            local reason = skipReason(entry)
            table.insert(reason and skipped or result, reason and name .. ": " .. reason or name)
            for _, filter in ipairs(filters) do
                used[filter] = used[filter] or matchesFilter(name, filter)
            end
        end
    end
    local unmatched = {}
    for _, filter in ipairs(filters) do
        if not used[filter] then
            table.insert(unmatched, filter)
        end
    end
    table.sort(result)
    table.sort(skipped)
    return result, skipped, unmatched
end

-- Random numbers from 1 to n that the same seed repeats (Park and Miller's generator: the products
-- stay exact in a double), since ZombRand can't be seeded.
local function seededRandom(seed)
    local value = seed % 2147483646 + 1
    return function(n)
        value = (value * 16807) % 2147483647
        return value % n + 1
    end
end

-- `names` in the run's order (ORDER: "reverse", or "shuffle:<seed>"), `rounds` times over
-- (REPEAT), each round of a shuffle in a new order.
local function orderedRounds(names, order, rounds)
    local seed = tonumber(string.match(order, "^shuffle:(%d+)$"))
    local random = seed and seededRandom(seed)
    local result = {}
    for _ = 1, rounds do
        local round = {}
        for i, name in ipairs(names) do
            round[order == "reverse" and #names + 1 - i or i] = name
        end
        if random then
            for i = #round, 2, -1 do
                local j = random(i)
                round[i], round[j] = round[j], round[i]
            end
        end
        for _, name in ipairs(round) do
            table.insert(result, name)
        end
    end
    return result
end

-- The inventory windows hold the containers that crafts and the craft menu take their inputs from
-- (ISInventoryPaneContextMenu.getContainers), and catch up with a change only when the UI next
-- draws: until then they keep a bag the reset just took away, such as the key ring a multiplayer
-- character starts with, whose container the client can't name to the server
-- ("Unable to resolve container location"), so the action never reaches it.
local function refreshInventoryWindows()
    for _, page in ipairs({ getPlayerInventory(0), getPlayerLoot(0) }) do
        if page then
            page.inventoryPane.inventoryPage:refreshBackpacks()
        end
    end
end

-- What the last run in this game left behind, as "<test>: <what>", which a kept game's next run
-- reports first: it is still in the world that run starts from.
local leftBehind = {}

-- Prints up to LEAK_LINES_SHOWN of `lines` as "<tag> <kind> <prefix><line>", then how many more.
local function printCapped(kind, prefix, lines)
    for i, line in ipairs(lines) do
        if i > LEAK_LINES_SHOWN then
            print(string.format("%s %s %sand %d more", run.tag, kind, prefix, #lines - LEAK_LINES_SHOWN))
            return
        end
        print(run.tag .. " " .. kind .. " " .. prefix .. line)
    end
end

local function countVerdict(state, name, passed)
    local tally = state.tally[name] or { passed = 0, failed = 0 }
    state.tally[name] = tally
    if passed then
        state.passed, tally.passed = state.passed + 1, tally.passed + 1
    else
        state.failed, tally.failed = state.failed + 1, tally.failed + 1
    end
end

-- Prints the verdict of the test that just ended, once the leak check after it is done: its LEAK
-- and DESYNC lines first, which with LEAKS=fail also fail it.
local function settleVerdict(state, found)
    local verdict = state.verdict
    state.verdict = nil
    if not verdict then
        return
    end
    local failures = verdict.failures
    local findings = {}
    for _, line in ipairs(found and found.leaks or {}) do
        table.insert(findings, { kind = "LEAK", line = line })
    end
    for _, line in ipairs(found and found.desyncs or {}) do
        table.insert(findings, { kind = "DESYNC", line = line })
    end
    for i, finding in ipairs(findings) do
        if i > LEAK_LINES_SHOWN then
            local rest = #findings - LEAK_LINES_SHOWN
            print(string.format("%s LEAK %s: and %d more", run.tag, verdict.name, rest))
            if state.leaks == "fail" then
                table.insert(failures, rest .. " more leaks and desyncs")
            end
            break
        end
        print(run.tag .. " " .. finding.kind .. " " .. verdict.name .. ": " .. finding.line)
        table.insert(leftBehind, verdict.name .. ": " .. finding.line)
        if state.leaks == "fail" then
            table.insert(failures, (finding.kind == "LEAK" and "left behind " or "client and server differ at ") .. finding.line)
        end
    end
    PZHarness.Test.printVerdict(verdict.name, failures, verdict.seconds)
    countVerdict(state, verdict.name, #failures == 0)
end

-- The current test is done once its action queue is empty, or stopped once it overruns its limit
-- (TEST_TIMEOUT_SECONDS or its spec's timeoutSeconds): its queue cleared, and validate() fails it
-- with what it was waiting on. Then validate() runs, and its verdict waits for the leak check
-- (settleVerdict); the test's wall time and its time waiting on the server go to the run's
-- summary, and the cheat and the character go back to where the test started.
local function finishCurrentTest(state)
    local current, player = state.current, state.player
    local queue = ISTimedActionQueue.getTimedActionQueue(player).queue
    if queue[1] then
        local limit = current.timeoutSeconds or TEST_TIMEOUT_SECONDS
        if getTimestampMs() - state.testStartMs < limit * 1000 then
            return
        end
        current.timedOut = string.format("still running after %d s, waiting on %s", limit,
            PZHarness.Test.describeAction(queue[1]))
        ISTimedActionQueue.clear(player)
    end
    local passed = not current.validate or current:validate()
    state.current = nil
    state.doneMs = getTimestampMs()
    -- TestLib's validate leaves its failures and the test's time; a test registered some other way
    -- has only its verdict.
    local seconds = current.seconds or (state.doneMs - state.testStartMs) / 1000
    state.verdict = { name = state.name, seconds = seconds,
        failures = current.failures or (passed and {} or { "validate failed" }) }
    table.insert(state.times, {
        name = state.name,
        seconds = seconds,
        serverSeconds = (PZHarness.ServerCalls.waitedMs() - state.testServerMs) / 1000,
    })
    ISBuildMenu.cheat = state.wasCheat
    PZHarness.Fixtures.teleportToMiddle(player, state.start.x, state.start.y, state.start.z)
end

-- Whether the leak check may come, then the next test or the end of the run: the character's
-- square has loaded again after a test that went far, or SQUARE_WAIT_MS have passed; the server
-- has answered what the last test sent it, its undos above all, so a test never meets what the
-- one before built; and, in multiplayer, the server has reset its copy of the character, which the
-- first call asks for.
local function readyForNextTest(state)
    if not state.player:getCurrentSquare() and getTimestampMs() - state.doneMs < SQUARE_WAIT_MS then
        return false
    end
    if PZHarness.ServerCalls.busy() then
        return false
    end
    local nextIndex = state.index + 1
    if isClient() and state.resetFor ~= nextIndex and (state.names[nextIndex] or state.leaks ~= "off") then
        state.resetFor = nextIndex
        PZHarness.ServerCalls.callOutsideTest("PZHarness.reset", {})
        return false
    end
    return true
end

-- Between two tests, and after the last: the runner's reset of the character, then the leak check
-- (PZHarness/Leaks.lua), which compares the world with how it was before the test that just ended,
-- then that test's verdict. Returns true once all of it is done. A check whose square never loaded
-- is skipped.
local function checkBetweenTests(state)
    if state.checkedFor == state.index then
        return true
    end
    if not state.check then
        -- Before the snapshot, so what the reset takes away doesn't count as left behind.
        PZHarness.Fixtures.resetCharacter(state.player)
        refreshInventoryWindows()
        if state.leaks == "off" or not state.player:getCurrentSquare() then
            settleVerdict(state, nil)
            state.checkedFor = state.index
            return true
        end
        state.checkStartMs = getTimestampMs()
        state.check = PZHarness.Leaks.start(state.player, state.leakRadius, state.leakLevels, state.leakIgnore)
    end
    local found = state.check()
    if not found then
        return false
    end
    state.check = nil
    state.leakMs = state.leakMs + getTimestampMs() - state.checkStartMs
    settleVerdict(state, found)
    state.checkedFor = state.index
    return true
end

-- Starts test `name` from the character's square, which the leak check's reset has just reset. If
-- that square still hasn't loaded since the last test took the character far away, the test fails
-- without running, since nothing could bring the character back to where it started, and the next
-- one waits again. The time since the last test ended counts as between tests in the run's summary.
local function startNextTest(state, name)
    local player = state.player
    state.gapMs = state.gapMs + getTimestampMs() - state.doneMs
    print("TEST: " .. name)
    local here = player:getCurrentSquare()
    if not here then
        print(string.format("%s FAIL %s: the character's square was still unloaded %d s after the last test%s",
            run.tag, name, SQUARE_WAIT_MS / 1000, PZHarness.tookSuffix(0)))
        countVerdict(state, name, false)
        state.doneMs = getTimestampMs()
        return
    end
    state.name = name
    state.current = state.tests[name]
    state.start = { x = here:getX(), y = here:getY(), z = here:getZ() }
    player:Say(name)
    state.wasCheat = ISBuildMenu.cheat
    ISBuildMenu.cheat = false
    state.testStartMs = getTimestampMs()
    state.testServerMs = PZHarness.ServerCalls.waitedMs()
    state.current:run()
end

-- Prints the SLOWEST_COUNT slowest tests, then where the run's time went: in the tests, between
-- them (square loads, the server's resets and undos the runner waits for, the leak checks), and in
-- multiplayer how much of both had a server answer outstanding.
local function printSlowest(state)
    local times = state.times
    table.sort(times, function(a, b)
        if a.seconds ~= b.seconds then
            return a.seconds > b.seconds
        end
        return a.name < b.name
    end)
    local inTests = 0
    for i, entry in ipairs(times) do
        inTests = inTests + entry.seconds
        if i <= SLOWEST_COUNT then
            print(string.format("%s SLOWEST %.2f s %s%s", run.tag, entry.seconds, entry.name,
                isClient() and string.format(" (server %.2f s)", entry.serverSeconds) or ""))
        end
    end
    local summary = string.format("%s SLOWEST %.1f s in tests, %.1f s between them (%.1f s of it checking for leaks)",
        run.tag, inTests, state.gapMs / 1000, state.leakMs / 1000)
    if isClient() then
        summary = summary .. string.format(", %.1f s of it all waiting on the server",
            (PZHarness.ServerCalls.waitedMs() - state.serverStartMs) / 1000)
    end
    print(summary)
end

-- With REPEAT, how often each test passed and failed, the most failed first.
local function printTally(state)
    local names = {}
    for name in pairs(state.tally) do
        table.insert(names, name)
    end
    table.sort(names, function(a, b)
        local failedA, failedB = state.tally[a].failed, state.tally[b].failed
        if failedA ~= failedB then
            return failedA > failedB
        end
        return a < b
    end)
    for _, name in ipairs(names) do
        local tally = state.tally[name]
        print(string.format("%s REPEAT %s passed=%d failed=%d", run.tag, name, tally.passed, tally.failed))
    end
end

-- Prints the skipped tests, the counts of a repeated run, the slowest tests, the time the run took
-- and its verdict, counting the failures that came after their tests' verdicts, then calls
-- onDone().
local function finishRun(state)
    PZHarness.runnerOwnsVerdicts = false
    state.gapMs = state.gapMs + getTimestampMs() - state.doneMs
    local failed = state.failed + PZHarness.ServerCalls.lateFailures - state.lateFailures
    for _, skip in ipairs(state.skipped) do
        print(run.tag .. " SKIP " .. skip .. PZHarness.tookSuffix(0))
    end
    if state.rounds > 1 then
        printTally(state)
    end
    printSlowest(state)
    local seconds = (getTimestampMs() - state.startedMs) / 1000
    print(string.format("%s TIME %.1f s, %d frames (%.0f a second)", run.tag, seconds, state.ticks,
        state.ticks / math.max(seconds, 0.001)))
    print(run.tag .. " DONE passed=" .. state.passed .. " failed=" .. failed .. " skipped=" .. #state.skipped)
    state.onDone()
end

-- The leak check's mode (LEAKS: "fail", "warn" or "off"), its radius, its z levels, and the
-- patterns of the objects it leaves out: the built-in ones and the dev mod's `leakIgnore`.
local function leakSettings()
    local mode = run.leaks ~= nil and run.leaks ~= "" and run.leaks or "fail"
    local tests = PZHarness.config.tests
    local ignore = {}
    for _, list in ipairs({ PZHarness.Snapshot.DEFAULT_IGNORE, tests.leakIgnore or {} }) do
        for _, pattern in ipairs(list) do
            table.insert(ignore, pattern)
        end
    end
    return mode, tests.leakRadius or PZHarness.Test.SEARCH_RADIUS + LEAK_MARGIN, tests.leakLevels, ignore
end

-- What the last run in this game left behind, before this one starts on top of it.
local function printLeftBehind()
    if #leftBehind > 0 then
        printCapped("DIRTY", "", leftBehind)
        leftBehind = {}
    end
end

-- Runs the selected tests one after another with the resets of the debug menu's runner (RunTest
-- and OnTick in vanilla Tests/TimedActionsTests.lua, whose locals Lua can't reach): before each
-- test full health, an empty inventory, nothing worn or held, the inventory windows caught up with
-- that, ISBuildMenu.cheat off and the test's name said aloud; validate() once the action queue is
-- empty; then the cheat back and the character back in the middle of the square the test started
-- on. Vanilla pauses a second after every test so you can read the result; here the next test
-- starts on the next tick, or once readyForNextTest says so and the leak check after the last
-- test is done (checkBetweenTests). In multiplayer the server's copy of the character gets the
-- same reset first (PZHarness.Fixtures.resetCharacter). The run's ORDER, REPEAT and LEAKS come
-- from `run` (PZHarness.txt, or a --stay request). Calls onDone() at the end.
local function runTests(onDone)
    local names, skipped, unmatched = testNames()
    local rounds = math.max(1, tonumber(run.rounds) or 1)
    local order = run.order or ""
    local leaks, leakRadius, leakLevels, leakIgnore = leakSettings()
    printLeftBehind()
    names = orderedRounds(names, order, rounds)
    print(run.tag .. " START " .. #names)
    if order ~= "" then
        print(run.tag .. " ORDER " .. order)
    end
    if rounds > 1 then
        print(run.tag .. " REPEAT " .. rounds .. " rounds")
    end
    print(run.tag .. " LEAKS " .. leaks .. (leaks ~= "off" and ", " .. leakRadius .. " squares around the character" or ""))
    for _, filter in ipairs(unmatched) do
        print(run.tag .. " FAIL " .. filter .. ": the selection names no test")
    end
    PZHarness.Leaks.reset()
    PZHarness.runnerOwnsVerdicts = true
    local startedMs = getTimestampMs()
    -- `start` holds where the current test started, as numbers: the square object itself goes back
    -- to the pool when a test takes the character far enough for its chunk to unload, and comes
    -- back as some other square (IsoGridSquare.discard, getNew), so teleporting to its coordinates
    -- then lands somewhere else entirely.
    local state = {
        names = names, skipped = skipped, tests = TimedActionTests.getTests(), onDone = onDone,
        rounds = rounds, leaks = leaks, leakRadius = leakRadius, leakLevels = leakLevels, leakIgnore = leakIgnore,
        passed = 0, failed = #unmatched, index = 0, ticks = 0, startedMs = startedMs, doneMs = startedMs,
        lateFailures = PZHarness.ServerCalls.lateFailures,
        -- For the summary: each test's { name, seconds, serverSeconds }, the time between tests and
        -- the part of it the leak checks took, the server waits so far, which a kept game's
        -- earlier runs add to, and each test's passes and failures over the rounds.
        times = {}, gapMs = 0, leakMs = 0, serverStartMs = PZHarness.ServerCalls.waitedMs(), tally = {},
        current = nil, name = nil, player = nil, start = nil, wasCheat = nil, resetFor = nil,
        testStartMs = nil, testServerMs = nil,
        -- The verdict waiting for the leak check, the check under way, and the test index it ran
        -- after.
        verdict = nil, check = nil, checkStartMs = nil, checkedFor = nil,
    }
    local function onTick()
        state.ticks = state.ticks + 1
        if state.current then
            finishCurrentTest(state)
            return
        end
        state.player = getSpecificPlayer(0)
        if not readyForNextTest(state) or not checkBetweenTests(state) then
            return
        end
        state.index = state.index + 1
        local name = state.names[state.index]
        if name then
            startNextTest(state, name)
        else
            Events.OnTick.Remove(onTick)
            finishRun(state)
        end
    end
    Events.OnTick.Add(onTick)
end

-- The request run-client.sh writes to REQUEST_FILE: an id, the selection (TESTS prefixes and
-- "=<name>" names), then "option <key>=<value>" lines for the run's settings (leaks, order,
-- rounds), then the Lua files to run again, in the order the mod listed them: this game's paths,
-- then, with --mp, "server " and the server's paths of those it loads too. Nil if there is none.
local function readRequest()
    local reader = getFileReader(REQUEST_FILE, false)
    if not reader then
        return nil
    end
    local request = { id = reader:readLine(), tests = reader:readLine(), options = {}, files = {}, serverFiles = {} }
    local line = reader:readLine()
    while line do
        local key, value = string.match(line, "^option (%w+)=(.*)$")
        local serverFile = string.match(line, "^server (.*)$")
        if key then
            request.options[key] = value
        else
            table.insert(serverFile and request.serverFiles or request.files, serverFile or line)
        end
        line = reader:readLine()
    end
    reader:close()
    return request
end

-- What the kept game shows on screen and prints while it waits for a request, so whoever watches
-- the window can tell an idle game from a stuck one.
local IDLE_TEXT = run.tag .. " IDLE waiting for the next --stay run (quits after " .. STAY_IDLE_MS / 60000 .. " minutes)"

local IdleNote = ISUIElement:derive("PZHarnessIdleNote")

function IdleNote:render()
    self:drawText(IDLE_TEXT, 0, 0, 1, 1, 0.4, 1, UIFont.Large)
end

-- Runs the tests again for every new request until STAY_IDLE_MS pass without one. reloadLuaFile
-- runs a file again but ignores its Events.*.Add calls (LuaCompiler.rewriteEvents), which suits
-- test files: they only register tests, or server handlers. Every test of the mod is unregistered
-- first, so a test that was renamed or deleted doesn't run again. In multiplayer the server
-- reloads its files first and marks the run in its log.
local function serveReruns()
    local performance = getPerformance()
    local fps, uncapped = performance:getFramerate(), performance:isFramerateUncapped()
    local note = IdleNote:new(40, 40, getCore():getScreenWidth() - 80, 40)
    note:initialise()
    local handled
    local waitingSince, ticks = getTimestampMs(), 0
    local onTick
    local function idle()
        performance:setFramerateUncapped(false)
        performance:setFramerate(IDLE_FPS)
        print(IDLE_TEXT)
        note:addToUIManager()
        waitingSince = getTimestampMs()
        Events.OnTick.Add(onTick)
    end
    onTick = function()
        ticks = ticks + 1
        if ticks % REQUEST_POLL_TICKS ~= 0 then
            return
        end
        if getTimestampMs() - waitingSince > STAY_IDLE_MS then
            Events.OnTick.Remove(onTick)
            print(run.tag .. " STAY ends: no request for " .. STAY_IDLE_MS / 60000 .. " minutes")
            getCore():quitToDesktop()
            return
        end
        local request = readRequest()
        if not request or not request.id or request.id == handled then
            return
        end
        handled = request.id
        Events.OnTick.Remove(onTick)
        note:removeFromUIManager()
        performance:setFramerate(fps)
        performance:setFramerateUncapped(uncapped)
        print(run.tag .. " RUN " .. request.id)
        local function rerun()
            local tests = TimedActionTests.getTests()
            local registered = {}
            for name in pairs(tests) do
                if startsWith(name, PZHarness.config.prefix) then
                    table.insert(registered, name)
                end
            end
            for _, name in ipairs(registered) do
                tests[name] = nil
            end
            for _, file in ipairs(request.files) do
                reloadLuaFile(file)
            end
            setFilters(request.tests)
            for key, value in pairs(request.options) do
                run[key] = value
            end
            runTests(idle)
        end
        if not isClient() then
            rerun()
            return
        end
        -- A failure is in the server's log as SERVER FAIL, which fails the run.
        PZHarness.ServerCalls.send("reload", { run = request.id, files = request.serverFiles }, rerun)
    end
    idle()
end

local function quit()
    getCore():quitToDesktop()
end

-- The player's uiRenderFPS while fastUI holds. done() puts it back before the game quits, which
-- saves the options, so options.ini never keeps the mode's rate.
local savedUIFps

-- What a mode handler calls when it is done.
local function done()
    if savedUIFps then
        getCore():setOptionUIRenderFPS(savedUIFps)
        savedUIFps = nil
    end
    print(run.mark .. " DONE")
    quit()
end

-- A clear, still day at once: no cloud, fog or rain however the weather turns during the run.
-- Stopping the weather alone leaves its fog to fade out over seconds; the admin values hold until
-- switched off.
local function clearWeather()
    local climate = getClimateManager()
    climate:stopWeatherAndThunder()
    for _, id in ipairs({ ClimateManager.FLOAT_CLOUD_INTENSITY, ClimateManager.FLOAT_FOG_INTENSITY,
        ClimateManager.FLOAT_PRECIPITATION_INTENSITY }) do
        local float = climate:getClimateFloat(id)
        float:setEnableAdmin(true)
        float:setAdminValue(0)
    end
end

-- The UI draws at its own rate (Core.StartFrameUI) and the frames in between show its last
-- drawing, so a mode that waits for the UI to draw waits less at the highest rate.
local function fastUI()
    savedUIFps = getCore():getOptionUIRenderFPS()
    getCore():setOptionUIRenderFPS(FAST_UI_FPS)
end

local function worldLoaded()
    local square = getSpecificPlayer(0):getCurrentSquare()
    if not square then
        return false
    end
    local cell, x, y = getCell(), square:getX(), square:getY()
    for dx = -LOADED_RADIUS, LOADED_RADIUS, 8 do
        for dy = -LOADED_RADIUS, LOADED_RADIUS, 8 do
            if not cell:getGridSquare(x + dx, y + dy, 0) then
                return false
            end
        end
    end
    return true
end

-- Runs `start` once the world around the character has loaded.
local function afterSettling(start)
    local ticks = 0
    local function onTick()
        ticks = ticks + 1
        if worldLoaded() or ticks >= SETTLE_MAX_TICKS then
            Events.OnTick.Remove(onTick)
            print("PZHarness: starting after " .. ticks .. " ticks")
            start()
        end
    end
    Events.OnTick.Add(onTick)
end

local function startMode()
    if run.mode == "test" then
        setFilters(run.selection)
        runTests(run.stay and serveReruns or quit)
        return
    end
    local mode = PZHarness.config.modes[run.mode]
    if not mode then
        print("PZHarness: the dev mod registered no mode " .. run.mode)
        quit()
        return
    end
    if mode.clearWeather then
        clearWeather()
    end
    if mode.fastUI then
        fastUI()
    end
    mode.run(run.selection, done)
end

-- Multiplayer (--mp) -----------------------------------------------------------------------------

-- How long the character may take to reach the scenario's start, whose chunks the server sends.
local START_WAIT_MS = 30000
-- How long the client may take, after the server's answers, to show the onStart perk levels again.
local SETUP_SYNC_MS = 5000

-- Joins the server once run-client.sh says it has started, with the call the server list's
-- Connect button makes. The client and the server boot at the same time, which saves the
-- client's boot from a run; connecting before the server listens would only fail.
local function connectWhenServerUp()
    -- Joining resets Lua (Core.ResetLua), which fires OnMainMenuEnter again in a client that is
    -- already joining; isClient() holds from then on.
    if isClient() then
        return
    end
    local ticks = 0
    local function poll()
        ticks = ticks + 1
        local server = ticks % CONNECT_POLL_TICKS == 0 and readKeys(CONNECT_FILE)
        if not server then
            return
        end
        Events.OnFETick.Remove(poll)
        print("PZHarness: joining " .. server.host .. ":" .. server.port .. " as " .. server.user)
        ConnectToServer.instance:connect(MainScreen.instance.bottomPanel, "", server.user, server.password,
            server.host, "", server.port, "", false, true, 1)
    end
    Events.OnFETick.Add(poll)
end

-- After vanilla's OnConnected, which shows a new character the spawn region list or character

-- Whether every perk of the character is at its level in `levels` (Fixtures.perkLevels).
local function hasPerkLevels(player, levels)

-- Copies the perk levels and known recipes onStart gave this client's character to the server's
-- copy, which crafts and actions check, and calls `start` once the server has them and this
-- client shows them. The server replaces this client's perk list with its own copy's every second
-- (NetworkPlayerManager, PlayerXpPacket), and one it sent before it had the levels can land after
-- its answer, so the first test would find the skills too low: the wait holds until a sync after
-- the answers has rebuilt the list (new PerkInfo objects) with the levels, at most SETUP_SYNC_MS.
-- Recipes the server sends are only added (SyncPlayerFieldsPacket), so they can't go back.
local function copySetupToServer(start)
    local player = getSpecificPlayer(0)
    local levels = PZHarness.Fixtures.perkLevels(player)
    PZHarness.ServerCalls.callOutsideTest("PZHarness.setPerkLevels", { levels = levels })
    PZHarness.ServerCalls.callOutsideTest("PZHarness.learnRecipes", { names = PZHarness.Fixtures.knownRecipes(player) })
    local perkList = player:getPerkList()
    local answeredMs, before
    local function onTick()
        if PZHarness.ServerCalls.busy() then
            return
        end
        if not answeredMs then
            answeredMs = getTimestampMs()
            before = not perkList:isEmpty() and perkList:get(0) or nil
        end
        local synced = before == nil or perkList:isEmpty() or perkList:get(0) ~= before
        if not (synced and hasPerkLevels(player, levels)) then
            if getTimestampMs() - answeredMs < SETUP_SYNC_MS then
                return
            end
            print(run.tag .. " FAIL PZHarness.setPerkLevels: this client never showed the onStart perk levels again")
            PZHarness.ServerCalls.lateFailures = PZHarness.ServerCalls.lateFailures + 1
        end
        Events.OnTick.Remove(onTick)
        start()
    end
    Events.OnTick.Add(onTick)
end

-- The server places a new character on a point of a spawn region (CreatePlayerPacket), so the

--- Called once by the dev mod, at load. `config`:
--- - `scenario`: the key of the mod's scenario in `debugScenarios`, which every mode starts.
--- - `prefix`: the name prefix of the mod's tests in TimedActionTests; --test runs those.
--- - `modes`: the mod's other modes by name, each `{ run = function(selection, done), uncapped,
---   clearWeather, fastUI }`. `run` is called once the world has loaded, with the selection
---   run-client.sh passed, and calls `done()` when it has finished. `uncapped` draws as many
---   frames as the machine can; `clearWeather` clears the sky at once and keeps it clear; `fastUI`
---   draws the UI at its highest rate until `done()`, which puts the option back.
--- - `onStart(mode)`: optional, called after the scenario's own onStart in every mode.
--- - `tests`: settings of the test library, see PZHarness/TestLib.lua.
--- With --mp no scenario starts: the client joins the server, the runner takes the character to
--- the scenario's `startLoc` and calls its onStart and the mod's (see Multiplayer above).
function PZHarness.register(config)
    PZHarness.config = {
        scenario = config.scenario,
        prefix = config.prefix or "",
        modes = config.modes or {},
        onStart = config.onStart,
        tests = config.tests or {},
    }
    if run.mode == "" then
        return
    end
    -- run-client.sh times the game's boot up to the first of these; --mp prints one again after
    -- joining resets the Lua.
    print("PZHarness: the dev mod registered for " .. run.mode)

    -- Single player pauses when the window loses focus, and paused games don't tick, so the run
    -- would stop whenever someone switches to another window.
    getCore():setOptionPauseOnFocusloss(false)

    -- Game time per second doesn't depend on the frame rate (FPSTracking), so more frames a second
    -- only shorten what is counted in ticks: the tests' waits for the game to apply a change, and
    -- from here on the world loading. Measured on an M3 Max, uncapped draws about 260 frames a
    -- second against 60. The option can't do it: Core.loadOptions resets uncappedFPS to false and
    -- frameRate to 60. Every mode loads uncapped: the main menu and the loading screen step per
    -- frame, and the game takes at most 16 loaded assets a frame. A mode whose steps wait fixed
    -- tick counts goes back to 60 when the scenario starts, before its first step.
    local mode = PZHarness.config.modes[run.mode]
    local uncapped = run.mode == "test" or (mode and mode.uncapped)
    getPerformance():setFramerateUncapped(true)
    if run.mp then
        return
    end

    local scenario = debugScenarios[config.scenario]
    scenario.forceLaunch = true

    -- A --test world is quiet: the options run-client.sh lists (QUIET_WORLD in lib/harness.sh)
    -- go in before the new world is made, and the scenario's own setSandbox after them, so the
    -- mod's settings win.
    local quiet = run.mode == "test" and run.quiet or ""
    if quiet ~= "" then
        local originalSetSandbox = scenario.setSandbox
        scenario.setSandbox = function()
            for key, value in string.gmatch(quiet, "([%w_]+)=([^,]+)") do
                if value == "true" or value == "false" then
                    SandboxVars[key] = value == "true"
                else
                    SandboxVars[key] = tonumber(value) or value
                end
            end
            if originalSetSandbox then
                originalSetSandbox()
            end
        end
    end

    local originalOnStart = scenario.onStart
    scenario.onStart = function()
        if not uncapped then
            getPerformance():setFramerateUncapped(false)
        end
        originalOnStart()
        if PZHarness.config.onStart then
            PZHarness.config.onStart(run.mode)
        end
        afterSettling(startMode)
    end
end

return PZHarness

-- Development only, not published. The client's half of the tests' server channel; the server's
-- half, and how a dev mod registers handlers, is in server/PZHarness/ServerHandlers.lua. Tests use
-- it through PZHarness.Test.server, the runner for --stay reruns. In single player the server's
-- half runs in this Lua state and answers at once, in the same tick; in multiplayer a request
-- travels as a client command and its answer as a server command, a tick or more later.

PZHarness = PZHarness or {}
local ServerCalls = {}
PZHarness.ServerCalls = ServerCalls

local MODULE = "PZHarness"
-- An answer that takes longer is lost: the server logged why, or stopped.
local ANSWER_MS = 15000

-- Unanswered requests by id: { onAnswer, sentMs }.
local pending = {}
local lastId = 0
-- Real milliseconds with at least one request unanswered, up to the last time none was, and since
-- when one has been unanswered now; overlapping requests count once.
local waitedMs, waitingSinceMs = 0, nil

-- Failures that arrive after their test's verdict, such as a server undo that failed; the runner
-- counts them.
ServerCalls.lateFailures = 0

--- Sends a request of `kind` ("call", "unwind" or "reload") and calls `onAnswer(answer)` with the
--- server's answer, or with `{ error = ... }` if none comes.
function ServerCalls.send(kind, request, onAnswer)
    lastId = lastId + 1
    request.id = lastId
    request.tag = PZHarness.run.tag
    local player = getSpecificPlayer(0)
    if not isClient() then
        onAnswer(PZHarness.ServerHandlers.handle(player, kind, request))
        return
    end
    if not ServerCalls.busy() then
        waitingSinceMs = getTimestampMs()
    end
    pending[lastId] = { onAnswer = onAnswer, sentMs = getTimestampMs() }
    sendClientCommand(player, MODULE, kind, request)
end

--- Whether a request is still waiting for its answer.
function ServerCalls.busy()
    for _ in pairs(pending) do
        return true
    end
    return false
end

--- Real milliseconds so far that some request was waiting for its answer, for the runner's summary
--- of where a run's time went. Always 0 in single player, which answers at once.
function ServerCalls.waitedMs()
    return waitedMs + (waitingSinceMs and getTimestampMs() - waitingSinceMs or 0)
end

--- Calls the server handler `name` for something outside any one test, such as the runner's reset
--- or a scenario's setup, and `onReply(reply)` with its reply, exactly as the handler returned it:
--- false, 0 or nil too. A failure prints a FAIL line of its own, which the runner counts as it
--- does a late undo's, and never calls onReply.
function ServerCalls.callOutsideTest(name, args, onReply)
    ServerCalls.send("call", { name = name, test = name, args = args or {} }, function(answer)
        local problem = answer.error or answer.missing
        if problem then
            print(PZHarness.run.tag .. " FAIL " .. name .. ": " .. tostring(problem))
            ServerCalls.lateFailures = ServerCalls.lateFailures + 1
        elseif onReply then
            onReply(answer.reply)
        end
    end)
end

local function answered(id, answer)
    local entry = pending[id]
    pending[id] = nil
    if entry and not ServerCalls.busy() then
        waitedMs = waitedMs + getTimestampMs() - waitingSinceMs
        waitingSinceMs = nil
    end
    if entry then
        entry.onAnswer(answer)
    end
end

Events.OnServerCommand.Add(function(module, command, args)
    if module == MODULE and command == "reply" then
        answered(args.id, args)
    end
end)

-- Runs every frame of the whole game, nearly always with nothing pending, so it returns before
-- allocating anything then.
Events.OnTick.Add(function()
    if not ServerCalls.busy() then
        return
    end
    local now, lost = getTimestampMs(), {}
    for id, entry in pairs(pending) do
        if now - entry.sentMs > ANSWER_MS then
            table.insert(lost, id)
        end
    end
    for _, id in ipairs(lost) do
        answered(id, { id = id, error = "no answer from the server within " .. ANSWER_MS / 1000 .. " s" })
    end
end)

return ServerCalls

-- Queue ----------------------------------------------------------------------------------------

-- Holds the action queue, so the runner validates only once the world has caught up: until
-- `done()` holds or `total` ticks pass, calling `onTick(n)` every tick. What onTick queues goes
-- right after the wait, in order (vanilla's adding-actions mode, ISQueueActionsAction), and a
-- clear of the queue meanwhile, as luautils.walkAdj makes, drops only that. Once the running test
-- misses a fixture (T.need), every wait ends at once without calling anything, since what comes
-- after would work on the missing fixture.
local Wait = ISBaseTimedAction:derive("PZHarnessWait")

function Wait:isValid()
    return true
end

function Wait:update()
    if active and #active.missing > 0 then
        self:forceComplete()
        return
    end
    self.ticks = self.ticks + 1
    if self.onTick then
        self:beginAddingActions()
        self.onTick(self.ticks)
        self:endAddingActions()
    end
    if self.ticks >= self.total or (self.done and self.done()) then
        self:forceComplete()
    end
end

function Wait:new(character, total, onTick, done)

    o.total, o.onTick, o.done, o.ticks = total, onTick, done, 0
    o.stopOnWalk, o.stopOnRun, o.stopOnAim = false, false, false
    o.maxTime = -1

-- A test's own wait that goes without finishing means a timed action emptied the queue: one that
-- turned invalid or was refused stops (ISBaseTimedAction.stop), and that cancels everything queued
-- after it, so the test's later steps would silently never run and validate would read what they
-- never made. The test then fails with the action that was running. A step's own clear of what
-- it added (adding-actions mode, as luautils.walkAdj does) drops only that, on purpose.
local function noteLostWait(wait)

    if not test or test ~= active or test.queueCleared then
        return

    local queue = ISTimedActionQueue.getTimedActionQueue(wait.character)
    if queue:isCurrentActionAddingOtherActions() then
        return
    end
    test.queueCleared = "the action queue was cleared while " .. T.describeAction(queue.queue[1] or wait)
        .. " was running; a refused or invalid timed action stops the whole queue"
end

-- The queued steps after the current one, which a failed server call leaves nothing to work on.
local function dropQueuedSteps()

    for i = #queue, 2, -1 do
        table.remove(queue, i)
    end

    if queue[1] and queue[1]._numAddedActions then
        queue[1]._numAddedActions = 0
    end
end

-- Sends the call of the server handler `name` at once and handles its answer: the server's undo,
-- a failure (as T.need does, dropping the steps queued after it), `onReply(reply)` with the reply
-- exactly as the handler returned it (false, 0 and nil too), and the items a table reply lists as
-- `given` (PZHarness.giveItem): once the client has them, worn and held as they should be (the
-- server dresses the character only then, "PZHarness.dress"), their client copies land in
-- self.items[itemsKey]. Returns the condition a queued wait polls until all of it is done.
local function call(self, name, args, itemsKey, onReply)
    local phase, given, sinceMs = "asking", nil, nil
    local function fail(what)
        T.need(self, nil, what)
        dropQueuedSteps()
        phase = "done"
    end
    local function ask(handler, handlerArgs, onAnswer)
        PZHarness.ServerCalls.send("call", { name = handler, test = self.name, args = handlerArgs }, function(answer)
            if answer.undo then
                local function undo() unwindOnServer(self, handler, answer.id) end
                -- An answer can come after the verdict once a missing fixture ended the test's waits.
                if self.unwound then undo() else T.defer(self, undo) end
            end
            if answer.error or answer.missing then
                fail(answer.missing or "the server's " .. handler .. ", which failed: " .. answer.error)
                return
            end
            onAnswer(answer.reply)
        end)
    end
    ask(name, args or {}, function(reply)
        if onReply then
            onReply(reply)
        end
        given, sinceMs = type(reply) == "table" and reply.given or nil, getTimestampMs()
        phase = given and "receiving" or "done"
    end)
    return function()
        if phase == "receiving" or phase == "dressing" then
            local items = clientCopies(given)
            if items and phase == "receiving" and needsDressing(given) then
                phase = "asking"
                ask("PZHarness.dress", { given = given }, function()
                    phase, sinceMs = "dressing", getTimestampMs()
                end)
            elseif items and dressedAsGiven(items, given) then
                self.items[itemsKey] = items
                phase = "done"
            elseif getTimestampMs() - sinceMs > RECEIVE_MS then
                fail("this client's copies of what the server's " .. name .. " gave")
            end
        end
        return phase == "done"
    end
end

-- Queues a call that goes out once the actions queued before it are done, and a wait for all of
-- it. `args` may be a function of `self`.
local function queueCall(self, name, args, itemsKey, onReply)
    local poll
    T.step(function()
        poll = call(self, name, type(args) == "function" and args(self) or args or {}, itemsKey, onReply)
    end)
    -- The answer, or the error ServerCalls gives a lost one, always comes, so no frame cap. A step
    -- skipped after a missing fixture leaves no poll.
    T.waitUntil(function() return not poll or poll() end, math.huge, "the server's answer to " .. name)
end

--- Queues a call of the server handler `name` (see server/PZHarness/ServerHandlers.lua) and a
--- wait for its answer, which lands in `self.server[name]` exactly as the handler returned it, so
--- a handler's false, 0 or nil reaches the test as that. `args` is a table of plain values
--- (strings, numbers, booleans and tables of them), or a function of `self` returning one, called
--- when the call goes out, so it can use an earlier answer. In single player the handler runs in
--- this game and answers at once; in multiplayer it runs on the server. What it deferred is undone
--- on its side when the test ends, in order with the test's own undos. A handler that fails, or
--- answers that something is missing, fails the test as T.need does and drops the steps queued
--- after the call. A handler that gave the character items lists them in its reply as `given`
--- (PZHarness.giveItem); the wait then lasts until this client has them, worn and held as asked,
--- and puts this client's copies in `self.items[name]`.
function T.server(self, name, args)
    queueCall(self, name, args, name, function(reply) self.server[name] = reply end)
end

--- Queues calls of the server handler `name`, one at a time, until `done(reply)` holds or `maxMs`
--- of real time (15 seconds unless given) pass, for server state that changes later, such as what
--- an action's complete() does after the client's perform(). The last reply lands in
--- `self.server[name]`; running out of time just ends the wait, so validate checks what it waited
--- for. `args` as for T.server; a failed call fails the test as T.server's does.
function T.serverUntil(self, name, args, done, maxMs)
    local poll, sinceMs
    T.waitUntil(function()
        sinceMs = sinceMs or getTimestampMs()
        if poll then
            if not poll() then
                return false
            end
            if done(self.server[name]) or getTimestampMs() - sinceMs > (maxMs or RECEIVE_MS) then
                return true
            end
        end
        poll = call(self, name, type(args) == "function" and args(self) or args or {}, name, function(reply)
            self.server[name] = reply
        end)
        return false
    end, math.huge, "the server's answers to " .. name)
end

--- Gives the character `items` the way the server does: each a table { type = full type, count,
--- uses (fraction of a full drainable item), condition, modData (keys to set), worn = true,
--- equip = "primary", "secondary" or "both" }. Queued like T.server; this client's copies land in
--- `self.items[name]`, `count` of each in the order given. In multiplayer the server makes them,
--- sends them here and then puts them on and in hand, so actions that run on the server find them.
--- The runner empties the inventory before the next test.
function T.give(self, name, items)
    queueCall(self, "PZHarness.give", { items = items }, name)
end

--- Queues a count of each of `types` in the inventory of the server's copy of the character, bags
--- included, into `self.counts[name][fullType]`. With `opts.dropped`, items dropped on the squares
--- around the character count too and go away, as a craft drops what doesn't fit.
function T.count(self, name, types, opts)
    queueCall(self, "PZHarness.count", { types = types, dropped = opts and opts.dropped or nil }, nil, function(reply)
        self.counts[name] = reply.counts
    end)
end

-- The server's half of a two-sided fixture (server/PZHarness/ServerFixtures.lua), on a
-- multiplayer client only: sent at once, so it reaches the server before any later T.server call,
-- with a wait for its answer queued, so the actions queued after the fixture start only once the
-- server has made the change. Single player has made it already, in its one copy.
local function alsoOnServer(self, name, args, onReply)
    if isClient() then
        T.waitUntil(call(self, name, args, nil, onReply), math.huge, "the server's answer to " .. name)
    end
end

-- The same for two-sided helpers that take no test, which scenarios call too: a failure prints a
-- FAIL line of its own. `ready(reply)`, if given, holds once this client has what the server did.
local function alsoOnServerOutsideTest(name, args, ready)
    if not isClient() then
        return
    end
    local answered, reply, sinceMs = false, nil, nil
    PZHarness.ServerCalls.callOutsideTest(name, args, function(answer)
        answered, reply, sinceMs = true, answer, getTimestampMs()
    end)
    T.waitUntil(function()
        if not answered then
            return not PZHarness.ServerCalls.busy()
        end
        if not ready or ready(reply) then
            return true
        end
        if getTimestampMs() - sinceMs > RECEIVE_MS then
            print(PZHarness.run.tag .. " FAIL " .. name .. ": this client never got what the server did")
            PZHarness.ServerCalls.lateFailures = PZHarness.ServerCalls.lateFailures + 1
            return true
        end
        return false
    end, math.huge, "the server's answer to " .. name)
end

-- Restore stack --------------------------------------------------------------------------------

--- Runs `undo` when the test ends, before the undos pushed earlier.
function T.defer(self, undo)
    table.insert(self.undo, undo)
end

--- Calls `fn` every tick until the test ends.
function T.onTick(self, fn)
    Events.OnTick.Add(fn)
    T.defer(self, function() Events.OnTick.Remove(fn) end)
end

-- The setters below are two-sided: they change this game's copy at once, and on a multiplayer
-- client the server's copy too (see alsoOnServer), which the server undoes when the test ends.

function T.setTime(self, hour)
    T.defer(self, PZHarness.Fixtures.setTime(hour))
    alsoOnServer(self, "PZHarness.setTime", { hour = hour }, function()
        -- A clock sync the server sent before it changed the time may have come in since.
        getGameTime():setTimeOfDay(hour)
    end)
end

--- Sets the character's level of `perk` for the test. On a multiplayer client the server replaces
--- this client's perk list with its own copy's every second (PlayerXpPacket), and one it sent
--- before it had the level can land after its answer, so the client's checks (the craft menu, an
--- action's isValid) would see the old level: until the test ends, this client puts its level
--- back whenever such a sync changes it. Waiting for a sync after the answer would cost up to a
--- second per call.
function T.setPerk(self, perk, level)
    local p = T.player()
    T.defer(self, PZHarness.Fixtures.setPerk(p, perk, level))
    alsoOnServer(self, "PZHarness.setPerk", { perk = perk:getId(), level = level })
    if isClient() then
        T.onTick(self, function()
            if p:getPerkLevel(perk) ~= level then
                p:setPerkLevelDebug(perk, level)
            end
        end)
    end
end

local function sandboxChanged()
    if settings().sandboxChanged then
        settings().sandboxChanged()
    end
end

--- Sets a sandbox option of the mod (SandboxVars[settings.sandbox]) or, failing that, of the
--- game. An option in neither is recorded as missing rather than created. The server calls its
--- own `PZHarness.serverSettings.sandboxChanged` (server/PZHarness/ServerFixtures.lua).
function T.setSandbox(self, key, value)
    local options = PZHarness.Fixtures.sandboxOptions(settings().sandbox, key)
    if not T.need(self, options, "the sandbox option " .. key) then return end
    T.defer(self, PZHarness.Fixtures.setSandbox(options, key, value, sandboxChanged))
    alsoOnServer(self, "PZHarness.setSandbox", { table = settings().sandbox, key = key, value = value })
end

--- The game runs `multiplier` times as fast: the clock and every timed action alike. The game drops
--- back to 1 when the character moves without a path or a zombie comes close.
function T.setMultiplier(self, multiplier)
    T.defer(self, PZHarness.Fixtures.setMultiplier(multiplier))
    alsoOnServer(self, "PZHarness.setMultiplier", { multiplier = multiplier })
end

--- Vanilla's mechanics cheat on or off for the character, on both sides (Fixtures.setMechanicsCheat).
--- A multiplayer server times a vehicle part's install and uninstall in real time, and the instant
--- cheat can't shorten them there: an instant action on a client checks isValid again once the
--- server has moved the part, fails, and empties the action queue. The mechanics cheat skips that
--- check, so a test turns it on around the action, after reading canInstallPart and
--- canUninstallPart itself.
function T.setMechanicsCheat(self, on)
    T.defer(self, PZHarness.Fixtures.setMechanicsCheat(T.player(), on))
    alsoOnServer(self, "PZHarness.setMechanicsCheat", { on = on })
end

-- In multiplayer a generator taken away while this client's copy of its square holds a different
-- list of objects (a test's own objects come and go fast) keeps its squares powered here: the
-- switch-off names it by its place on the square and misses, and the chunks drop a generator's
-- squares only when they load again (IsoChunk.checkForMissingGenerators). So with the grid off a
-- test starts with no power but what it brings itself.
local function dropStaleGeneratorPower()
    local square = T.player():getCurrentSquare()
    if not square then return end
    local cell, reach = getCell(), math.floor(SandboxVars.GeneratorTileRange / 8) + 2
    local wx, wy = math.floor(square:getX() / 8), math.floor(square:getY() / 8)
    for x = wx - reach, wx + reach do
        for y = wy - reach, wy + reach do
            local chunk = cell:getChunk(x, y)
            if chunk then
                chunk:checkForMissingGenerators()
            end
        end
    end
end

--- The power grid on or off. Off, it also clears power a generator taken away left behind.
function T.setGrid(self, on)
    T.defer(self, PZHarness.Fixtures.setGrid(on))
    alsoOnServer(self, "PZHarness.setGrid", { on = on })
    if not on then
        dropStaleGeneratorPower()
    end
end

--- Midnight with the grid off, dark where the character stands; queues a wait for the light to
--- follow the clock.
function T.makeDark(self)
    T.setGrid(self, false)
    T.setTime(self, 0)
    waitForLight(false)
end

--- Changes `item`, a client copy such as T.give's, as `changes` says: `condition`, `uses` (the
--- fraction of a full drainable item), `modData` (keys to set); in multiplayer the server's copy
--- too, which it then sends here. Not undone: the runner empties the inventory before the next test.
function T.changeItem(self, item, changes)
    PZHarness.Fixtures.changeItem(item, changes)
    alsoOnServer(self, "PZHarness.changeItem", { id = item:getID(), changes = changes })
end

-- Registering tests ----------------------------------------------------------------------------

-- Why spec's opt-out of single player or multiplayer is malformed, or nil. The reason is required
-- so that every skip says why in the run's summary.
local function optOutProblem(spec)
    if spec.spOnly ~= nil and spec.mpOnly ~= nil then
        return "spOnly and mpOnly both set: the test would run nowhere"
    end
    for _, key in ipairs({ "spOnly", "mpOnly" }) do
        local reason = spec[key]
        if reason ~= nil and (type(reason) ~= "string" or reason == "") then
            return key .. " needs the reason as a string"
        end
    end
    return nil
end

-- The spec's own start of a test, once the light has caught up: the instant cheat, the hour, the
-- sandbox options, the mod's setup, then spec.run unless a fixture is already missing.
local function startSpec(self, spec, hour)
    -- The server makes the actions a multiplayer client sends it, so it decides their length.
    T.defer(self, PZHarness.Fixtures.setInstant(T.player(), spec.instant == true))
    alsoOnServer(self, "PZHarness.setInstant", { on = spec.instant == true })
    if hour then
        T.setTime(self, hour)
    end
    for key, value in pairs(spec.sandbox or {}) do
        T.setSandbox(self, key, value)
    end
    if settings().setup then
        settings().setup(self, spec)
    end
    if spec.run and #self.missing == 0 then
        spec.run(self)
    end
end

-- The runner's run of a registered test: a fresh `self`, an undo that gives back the perks of the
-- `perks` setting, then startSpec. A malformed opt-out runs nothing; validate reports it.
local function runEntry(entry, name, spec, problem)
    local self = { name = name, undo = {}, missing = {}, used = {}, server = {}, items = {}, counts = {},
        startedMs = getTimestampMs() }
    entry.state = self
    active = self
    if problem then
        return
    end
    local p = T.player()
    local perks = {}
    for _, perk in pairs(settings().perks or {}) do
        perks[perk:getId()] = p:getPerkLevel(perk)
    end
    -- Actions and crafts that give experience level up the server's copy as well, so it gets back
    -- these levels too.
    T.defer(self, function()
        PZHarness.Fixtures.setPerkLevels(p, perks)
        if isClient() then
            PZHarness.ServerCalls.callOutsideTest("PZHarness.setPerkLevels", { levels = perks })
        end
    end)
    -- Read now, not when the test registers: the dev mod may register its settings after its test
    -- files have loaded.
    local hour = spec.hour or settings().hour
    -- The light lags a clock or grid change by some frames, and the previous test may have ended
    -- in the dark.
    if not hour or lit() then
        startSpec(self, spec, hour)
    else
        waitForLight(true)
        T.step(function() startSpec(self, spec, hour) end)
    end
end

-- Runs the test's restore stack newest first. A server undo that single player answers at once
-- still lands in this test's failures while `unwinding` is set.
local function unwindTest(self)
    unwinding = true
    for i = #self.undo, 1, -1 do
        self.undo[i]()
    end
    unwinding = false
    self.unwound = true
end

--- Prints a test's verdict: "<tag> PASS <name> (<s> s)", or FAIL with `failures` as its reasons.
--- The harness runner calls it once it has checked the test for leaks; the debug menu's runner
--- gets it from validate.
function T.printVerdict(name, failures, seconds)
    local took = PZHarness.tookSuffix(seconds)
    if #failures > 0 then
        print(PZHarness.run.tag .. " FAIL " .. name .. ": " .. table.concat(failures, "; ") .. took)
    else
        print(PZHarness.run.tag .. " PASS " .. name .. took)
    end
end

-- The runner's validate of a registered test: its failures (a malformed opt-out, the runner's
-- timeout, a cleared action queue, a missing fixture, or spec.validate's), then spec.cleanup and
-- the undos. Leaves the failures in `entry.failures` and the test's wall time, from its run to the
-- end of its undos, in `entry.seconds`, and returns whether the test passed. The verdict is
-- printed here only when the harness runner isn't running the test (PZHarness.runnerOwnsVerdicts),
-- since the runner adds what its leak check finds first.
local function validateEntry(entry, name, spec, problem)
    local self = entry.state or { undo = {}, missing = { "a run before validate" } }
    entry.state = nil
    failures = {}
    if problem then
        table.insert(failures, problem)
    elseif entry.timedOut then
        -- The runner stopped the test (Runner.lua): what validate reads may never have come.
        table.insert(failures, entry.timedOut)
        entry.timedOut = nil
    elseif self.queueCleared then
        -- The steps after the action that emptied the queue never ran, so validate would read
        -- what they never made.
        table.insert(failures, self.queueCleared)
    elseif #self.missing > 0 then
        table.insert(failures, "missing " .. table.concat(self.missing, "; "))
    elseif spec.validate then
        spec.validate(self)
        -- The menu and the crafting windows refuse a craft without saying why.
        if #failures > 0 and self.refusal then
            table.insert(failures, "the game refused the craft: " .. self.refusal)
        end
    end
    if spec.cleanup then
        spec.cleanup(self)
    end
    unwindTest(self)
    active = nil
    entry.seconds = self.startedMs and (getTimestampMs() - self.startedMs) / 1000 or 0
    entry.failures = failures
    if not PZHarness.runnerOwnsVerdicts then
        T.printVerdict(name, failures, entry.seconds)
    end
    return #failures == 0
end

--- Registers test `name`. `spec`: run(self), validate(self), cleanup(self), all optional; `hour`;
--- `instant`; `sandbox` (option = value, see T.setSandbox); `spOnly` or `mpOnly`, the reason the
--- test runs only in single player or only in multiplayer; anything else the mod's setup reads.
function T.test(name, spec)
    local problem = optOutProblem(spec)
    TimedActionTests.getTests()[name] = {
        -- The runner reads these to skip the test in the other mode.
        spOnly = not problem and spec.spOnly or nil,
        mpOnly = not problem and spec.mpOnly or nil,
        -- The runner's per-test limit in real seconds, if the test needs more than its default.
        timeoutSeconds = spec.timeoutSeconds,
        run = function(entry) runEntry(entry, name, spec, problem) end,
        validate = function(entry) return validateEntry(entry, name, spec, problem) end,
    }
end

-- Squares --------------------------------------------------------------------------------------

local function squareOf(near)
    if not near then
        return T.player():getCurrentSquare()
    end
    return instanceof(near, "IsoGridSquare") and near or near:getSquare()
end

local function isFreeSquare(square, indoors)
    if settings().isFreeSquare then
        return settings().isFreeSquare(square, indoors)
    end
    return square:isFree(false) and square:getVehicleContainer() == nil and square:isOutside() ~= indoors
end

-- Up to `count` free squares; see T.squares.
local function freeSquares(self, count, opts)
    local center = squareOf(opts.near)
    local found = {}
    if not center or count < 1 then return found end
    local z = center:getZ()
    for radius = opts.minDistance or 1, SEARCH_RADIUS do
        for x, y in PZHarness.Fixtures.ring(center:getX(), center:getY(), radius) do
            local square = getSquare(x, y, z)
            if square and not self.used[square]
                and isFreeSquare(square, opts.indoors == true)
                and (not opts.bare or square:getObjects():size() == 1) then
                self.used[square] = true
                table.insert(found, square)
                if #found == count then
                    return found
                end
            end
        end
    end
    return found
end

--- `count` free squares (the `isFreeSquare` setting) around `opts.near` (a square or object; the
--- character's square by default), nearest first and at least `opts.minDistance` tiles away:
--- indoors when `opts.indoors`, else outdoors; holding only their floor when `opts.bare`. Each
--- square goes to one fixture per test. Nil unless all are found.
function T.squares(self, count, opts)
    local found = freeSquares(self, count, opts or {})
    return #found == count and found or nil
end

-- Fixtures -------------------------------------------------------------------------------------

--- Removes `thing` (an IsoObject or a vehicle) when the test ends, the way the game does, so the
--- mods' removal handlers run. Returns `thing`.
function T.track(self, thing)
    T.defer(self, function()
        if instanceof(thing, "BaseVehicle") then
            thing:permanentlyRemove()
        elseif thing:getObjectIndex() ~= -1 then
            if settings().remove and settings().remove(thing) then
                return
            end
            -- Squares stay powered by a running generator that leaves them.
            if instanceof(thing, "IsoGenerator") and thing:isActivated() then
                thing:setActivated(false)
            end
            thing:getSquare():transmitRemoveItemFromSquare(thing)
        end
    end)
    return thing
end

--- A tile object of `sprite` on `square`, with `modData`.
function T.tile(self, square, sprite, modData)
    local object = IsoObject.new(square, sprite, "PZHarness")
    for key, value in pairs(modData or {}) do
        object:getModData()[key] = value
    end
    square:AddTileObject(object)
    return T.track(self, object)
end

--- Places a new `itemType` on `square` the way the moveables cursor does, with `modData` on the
--- item first. Returns the placed object.
function T.placeMoveable(self, square, itemType, sprite, modData)
    local item = instanceItem(itemType)
    for key, value in pairs(modData or {}) do
        item:getModData()[key] = value
    end
    T.player():getInventory():AddItem(item)
    ISMoveableSpriteProps.new(sprite):placeMoveable(T.player(), square, item:getWorldSprite(), true)
    local object = T.objectWithSprite(square, sprite)
    return T.need(self, object and T.track(self, object), "a placed " .. itemType)
end

-- A free square next to the character, with no wall in between, for a bench of `entity`; nil, and
-- missing, without one.
local function benchSquare(self, entity)
    local here = T.player():getSquare()
    for _, direction in ipairs({ IsoDirections.S, IsoDirections.E, IsoDirections.N, IsoDirections.W }) do
        local next = here:getAdjacentSquare(direction)
        if next and not self.used[next] and next:isFree(false) and not here:isBlockedTo(next) then
            self.used[next] = true
            return next
        end
    end
    return T.need(self, nil, "a free square next to the character for a " .. entity)
end

--- A workstation of the entity script `entity` (such as "Base.Kiln_Small"), drawn as `sprite`,
--- on a free square next to the character, who is using it as its crafting window makes them.
--- Returns the object. On a multiplayer client it exists here only: use T.placeBench.
function T.bench(self, entity, sprite)
    local script = T.need(self, getScriptManager():getGameEntityScript(entity), "the entity script " .. entity)
    local square = script and benchSquare(self, entity)
    if not square then
        return nil
    end
    local bench = IsoObject.new(square, sprite, entity)
    GameEntityFactory.CreateIsoObjectEntity(bench, script, true)
    square:AddTileObject(bench)
    T.track(self, bench)
    bench:setUsingPlayer(T.player())
    return T.need(self, bench:getComponent(ComponentType.CraftBench) and bench, "a craft bench in " .. entity)
end

-- Sends the call of handler `name`, which places something, and queues a wait until `find()`
-- finds this client's copy, into handle[key] ("object" unless given); `onReply(reply)` gets the
-- answer first. Single player finds it at once.
local function placeOnServer(self, handle, name, args, find, what, key, onReply)
    key = key or "object"
    local poll = call(self, name, args, nil, onReply)
    local sinceMs
    local function ready()
        handle[key] = find()
        return handle[key] ~= nil
    end
    if poll() then
        ready()
    end
    T.waitUntil(function()
        if not poll() then
            return false
        end
        if #self.missing > 0 or ready() then
            return true
        end
        sinceMs = sinceMs or getTimestampMs()
        if getTimestampMs() - sinceMs > RECEIVE_MS then
            T.need(self, nil, "this client's copy of " .. what)
            return true
        end
        return false
    end, math.huge, "this client's copy of " .. what)
    return handle
end

--- A tile object of `sprite` on `square`, with `modData`, placed the way the authority does: on
--- the server in multiplayer, which sends it to the clients. Removed when the test ends, by the
--- dev mod's `PZHarness.serverSettings.remove` if it takes it (server/PZHarness/ServerFixtures.lua),
--- else the vanilla way. Returns a handle { x, y, z, square } at once; handle.object is this
--- client's copy, there at once in single player and after a queued wait in multiplayer.
function T.placeTile(self, square, sprite, modData)
    local handle = { x = square:getX(), y = square:getY(), z = square:getZ(), square = square }
    local args = { x = handle.x, y = handle.y, z = handle.z, sprite = sprite, modData = modData }
    return placeOnServer(self, handle, "PZHarness.tile", args, function()
        return T.objectWithSprite(getSquare(handle.x, handle.y, handle.z), sprite)
    end, "a " .. sprite)
end

--- T.bench placed the way the authority does, as T.placeTile places a tile: returns a handle
--- { x, y, z, square } at once, or nil without a free square, and handle.object is this client's
--- copy of the bench once it has one.
function T.placeBench(self, entity, sprite)
    local square = benchSquare(self, entity)
    if not square then
        return nil
    end
    local handle = { x = square:getX(), y = square:getY(), z = square:getZ(), square = square }
    local args = { x = handle.x, y = handle.y, z = handle.z, entity = entity, sprite = sprite }

-- Queues a wait until `condition()` holds on this client, at most RECEIVE_MS.
local function waitOnClient(condition)
    local sinceMs
    T.waitUntil(function()
        sinceMs = sinceMs or getTimestampMs()
        return condition() or getTimestampMs() - sinceMs > RECEIVE_MS
    end, math.huge)
end

--- Puts the character in the middle of the free square next to `square` that vanilla's walkAdj

-- Queues the moveables action `mode` ("place" or "pickup") of `sprite` on `square` the way the
-- moveables cursor does (ISMoveableCursor.create): the character walks next to the square and the
-- action does the job, in multiplayer in its complete() on the server. The character first stands
-- next to the square (T.standNextTo), in the middle of a square, as vanilla's walkAdj misjudges the
-- reach from a square's edge. Returns false if the character can't get there.
local function moveablesAction(square, mode, sprite, item, object)

    T.standNextTo(square)

    if not props:walkToAndEquip(p, square, mode, sprite) then
        return false
    end
    local direction = props:getFaceDirectionFromSpriteName(sprite)
    ISTimedActionQueue.add(ISMoveablesAction:new(p, square, mode, sprite, object, direction, item, nil))
    return true

--- Queues placing a new `itemType`, with `modData` on the item, on `square` the way a player does:

--- action, which a multiplayer server carries out. What it placed goes when the test ends, as
--- T.placeTile's does. Returns a handle { x, y, z, square } at once; handle.object is this client's
--- copy of the placed object, drawn as `sprite`, once it has arrived.

    local key = "PZHarness.placeAsPlayer" .. self.placedAsPlayer
    local handle = { x = square:getX(), y = square:getY(), z = square:getZ(), square = square }
    T.give(self, key, { { type = itemType, modData = modData } })
    T.step(function()

            return

        waitOnClient(function() return T.objectWithSprite(square, sprite) ~= nil end)
        T.server(self, "PZHarness.trackPlaced", { x = handle.x, y = handle.y, z = handle.z, sprite = sprite })
        T.step(function()
            handle.object = T.need(self, T.objectWithSprite(square, sprite), "this client's copy of a placed " .. itemType)
        end)
    end)

--- Queues picking up the object drawn as `sprite` on `at` (a square, or a handle with a `square`)

--- A vehicle of `script` facing north on `opts.square`, else on open ground near `opts.near`
--- (the character by default). Returns the vehicle. On a multiplayer client it exists here only:

-- This client's copies of the vehicles T.placeVehicle found, to the handle each was found for.
-- The server hands a new vehicle the id it freed last (VehicleIDMap keeps freed ids on a stack),
-- often the one the previous test's undo just removed, and a client that hasn't taken that
-- removal yet still finds the old copy under the id, which then never updates. A copy found for
-- one handle is never taken for another.
local foundVehicles = {}
-- How long a multiplayer client waits after its copy of a new vehicle arrives, for the server's
-- second full update of it (see T.placeVehicle): three of the server's 100 ms send cycles.
local VEHICLE_SETTLE_MS = 300

--- T.vehicle placed the way the authority does: on the server in multiplayer, which sends it to
--- the clients nearby; removed when the test ends. `opts`: `square` or `near` as for T.vehicle,
--- `facing` ("N" unless given), `args` (plain values for the dev mod's
--- PZHarness.serverSettings.spawnVehicle, which makes the vehicle if it returns one). Returns a
--- handle at once. Once the server has answered, handle.id (shared by the server and its clients;
--- PZHarness.Fixtures.vehicleById finds it on either side), x, y, z and square say where it went,
--- and after a queued wait handle.vehicle is this client's copy.
function T.placeVehicle(self, script, opts)
    opts = opts or {}
    local squares = {}
    for _, square in ipairs(vehicleSquares(self, opts)) do
        table.insert(squares, { x = square:getX(), y = square:getY(), z = square:getZ() })
    end
    local handle = {}
    local args = { script = script, squares = squares, facing = opts.facing, args = opts.args }
    placeOnServer(self, handle, "PZHarness.vehicle", args, function()
        local vehicle = PZHarness.Fixtures.vehicleById(handle.id, handle)
        if not vehicle or vehicle:isRemovedFromWorld() or (foundVehicles[vehicle] or handle) ~= handle then
            return nil
        end
        foundVehicles[vehicle] = handle
        return vehicle
    end, "a " .. script, "vehicle", function(reply)
        handle.id, handle.x, handle.y, handle.z = reply.id, reply.x, reply.y, reply.z
        handle.square = getSquare(reply.x, reply.y, reply.z)
    end)
    -- A client that meets a vehicle id it doesn't know asks for a full update, and can ask twice.
    -- The server sends the second instead of the part changes it has pending and clears them,
    -- while a client that already has the vehicle takes only its position from a full update
    -- (VehicleManager.sendVehicles, VehicleFullUpdatePacket): a part change made before the second
    -- one arrives is lost here until that part changes again. The server sends every 100 ms.
    if isClient() then
        local sinceMs
        T.waitUntil(function()
            sinceMs = sinceMs or getTimestampMs()
            return getTimestampMs() - sinceMs >= VEHICLE_SETTLE_MS
        end, math.huge, "the second full update of a " .. script)
    end
    return handle
end

--- The script Item the harness gives for `input`, a recipe's InputScript, or nil when it has no
--- possible item: the first of its possible items listed in `prefer` (full names), else its first
--- possible item other than a generic Base.Moveable, else its first.
function T.inputItem(input, prefer)
    local possible = input:getPossibleInputItems()
    for _, wanted in ipairs(prefer or {}) do
        for j = 0, possible:size() - 1 do
            if possible:get(j):getFullName() == wanted then
                return possible:get(j)
            end
        end
    end
    for j = 0, possible:size() - 1 do
        if possible:get(j):getFullName() ~= "Base.Moveable" then
            return possible:get(j)
        end
    end
    return possible:size() > 0 and possible:get(0) or nil

--- What one craft of `recipe` takes, tools included, as T.give items: each input gets
--- T.inputItem's choice; a drainable input that counts uses gets one full item. Also returns the

function T.recipeInputs(recipe, prefer)

        else

        end

end

-- The crafting logic the game starts `recipe` from the item `from` with: the right-click menu's,
-- with a table in reach as the surface, or with `bench` (from T.bench) the bench window's.
local function craftLogic(recipe, from, bench)
    local p = T.player()

    if bench then
        logic = HandcraftLogic.new(p, bench:getComponent(ComponentType.CraftBench), bench)
    else
        logic = HandcraftLogic.new(p, nil, nil)
        logic:setIsoObject(logic:findCraftSurface(p, 2))
    end

    logic:setRecipeFromContextClick(recipe, from)
    return logic
end

-- Why the game would refuse to start this craft, or nil if it would start it. The menu and the
-- crafting windows refuse without saying why.
function T.craftRefusal(recipe, from, bench)
    local p = T.player()
    local logic = craftLogic(recipe, from, bench)
    if logic:canPerformCurrentRecipe() then
        return nil
    elseif not p:isRecipeActuallyKnown(recipe) then
        return "recipe not known"
    elseif not recipe:characterHasRequiredSkills(p) then
        return "skills too low"
    elseif recipe:isAnySurfaceCraft() and not logic:isCharacterInRangeOfWorkbench() then
        return "no table in reach"
    elseif p:tooDarkToRead() then
        return "too dark"
    end
    local missing = {}
    local inputs = recipe:getInputs()
    for i = 0, inputs:size() - 1 do
        local data = logic:getRecipeData():getDataForInputScript(inputs:get(i))
        if data and not data:isInputItemsSatisfied() then
            table.insert(missing, inputs:get(i):getOriginalLine())
        end
    end
    return "missing " .. table.concat(missing, "; ")
end

--- Starts crafting `recipe` from the item `from` the way the right-click menu does or, with
--- `bench` (from T.bench), the way the bench's crafting window does. Adds why the game refused
--- to `self.refusal`, which the test's failures then end with.
function T.startCraft(self, recipe, from, bench)
    local refusal = T.craftRefusal(recipe, from, bench)
    if refusal then
        self.refusal = (self.refusal and self.refusal .. "; " or "") .. recipe:getName() .. ": " .. refusal
    end
    if bench then
        ISEntityUI.HandcraftStart(T.player(), craftLogic(recipe, from, bench), false, true)
    else
        ISInventoryPaneContextMenu.OnNewCraft(from, recipe, T.player():getPlayerNum(), false)
    end
end

--- Registers a test that crafts `spec.recipe` from the first `spec.from` item the way the
--- right-click menu does or, with `spec.bench` ({ entity script, sprite }, see T.bench), at that
--- workstation the way its crafting window does; instantly unless `spec.instant` is false. The
--- character knows every recipe of the mod, has at least the levels the recipe requires, stands
--- by a table, and carries exactly the inputs of one craft (T.recipeInputs with `spec.prefer`,
--- given with T.give, so this client's copies are in `self.items.inputs`) and whatever
--- `spec.setup(self)` adds; setup runs once the inputs are there, and the craft starts after the
--- waits it queued, once there is light to craft by. validate() expects the counts in
--- `spec.counts` in the inventory of the server's copy of the character or dropped at its feet
--- (T.count, into `self.counts.craft`), then runs `spec.validate(self)`. `spec.after(self)`, if
--- given, runs in a step after that count, before validate, to queue more reads of what the
--- craft made. A failing test also reports why the game refused the craft.
function T.craftTest(name, spec)
    local counted = {}
    for fullType in pairs(spec.counts or {}) do
        table.insert(counted, fullType)
    end
    T.test(name, {
        sandbox = spec.sandbox,
        hour = spec.hour,
        instant = spec.instant ~= false,
        spOnly = spec.spOnly,
        mpOnly = spec.mpOnly,
        run = function(self)
            local p = T.player()
            local recipe = T.need(self, getScriptManager():getCraftRecipe(spec.recipe), "the recipe " .. spec.recipe)
            if not recipe then return end
            T.learnRecipes(p)
            T.placeWorkTable(p)
            local bench = spec.bench and T.placeBench(self, spec.bench[1], spec.bench[2])
            if spec.bench and not bench then return end
            for i = 0, recipe:getRequiredSkillCount() - 1 do
                local skill = recipe:getRequiredSkill(i)
                if p:getPerkLevel(skill:getPerk()) < skill:getLevel() then
                    T.setPerk(self, skill:getPerk(), skill:getLevel())
                end
            end
            local inputs, unmatched = T.recipeInputs(recipe, spec.prefer)
            if not T.need(self, #unmatched == 0, "an item for " .. table.concat(unmatched, "; ")) then return end
            T.give(self, "inputs", inputs)
            T.step(function()
                if spec.setup then
                    spec.setup(self)
                end
                -- The light can still lag the clock the previous test put back, and the game
                -- refuses a craft in the dark; the test is about the craft, not the dusk.
                waitForLight(true)
                T.step(function()
                    local from = T.need(self, p:getInventory():getFirstTypeRecurse(spec.from), "a " .. spec.from .. " to craft from")
                    if not from then return end
                    T.startCraft(self, recipe, from, bench and bench.object)
                    -- Queued after the craft's actions, which T.startCraft has just queued.
                    T.count(self, "craft", counted, { dropped = true })
                    if spec.after then
                        T.step(function() spec.after(self) end)
                    end
                end)
            end)
        end,
        validate = function(self)
            local counts = self.counts.craft or {}
            for fullType, count in pairs(spec.counts or {}) do
                local actual = counts[fullType]
                T.expect(actual == count, tostring(actual) .. " " .. fullType .. ", expected " .. count)
            end
            if spec.validate then
                spec.validate(self)
            end
        end,
    })
end

return T

local baselines = {}

-- Snapshots the server's copy around `args` (x, y, z, radius, levels, ignore) and the caller's
-- character, compares it with the last one (none after `args.fresh`) and keeps it for the next.
-- Answers with what changed (`leaks`, lines) and, as a flat list of key and signature pairs
-- (`changed`), the squares that changed, for the client to compare with its copy. With
-- `args.peek`, a list of square keys, it only answers with their signatures now (`sigs`), for
-- the client's second look at squares where the two copies differed.
handler("PZHarness.snapshot", function(player, args)
    local Snapshot = PZHarness.Snapshot
    if args.peek then
        local sigs = {}
        for _, key in ipairs(args.peek) do
            table.insert(sigs, key)
            table.insert(sigs, Snapshot.signatureAt(key, args.ignore))
        end
        return { sigs = sigs }
    end
    local snapshot = Snapshot.take(args, player)
    local owner = player:getUsername()
    local baseline = not args.fresh and baselines[owner] or nil
    baselines[owner] = snapshot
    if not baseline then
        return { leaks = {}, changed = {} }
    end
    local report = Snapshot.diff(baseline, snapshot)
    local changed = {}
    for _, key in ipairs(report.changed) do
        table.insert(changed, key)
        table.insert(changed, snapshot.squares[key])
    end
    return { leaks = Snapshot.addLines({}, report), changed = changed }
end)

```lua
-- Development only, not published. The server's half of the tests' server channel; the client's
-- half is client/PZHarness/ServerCalls.lua, and tests use it through PZHarness.Test.server. The
-- dev mod registers named handlers from its own server Lua:
--
--   require "PZHarness/ServerHandlers"
--   PZHarness.serverHandler("placeThing", function(player, args, defer)
--       local thing = ...                     -- build it the way the authority does
--       defer(function() ... end)             -- undone on the server when the calling test ends
--       return { x = ..., y = ... }           -- plain values only: they may cross the network
--   end)
--
-- A handler may instead return nil and what is missing ("a loaded square for the bank"), which
-- fails the test the way T.need does. In single player the client calls Handlers.handle in the
-- same Lua state; on a dedicated server the requests arrive as client commands and the answers go
-- back as server commands. The registry exists on a multiplayer client too, which loads server Lua
-- as well, so a dev mod's handler file needs no guard; only a server or single player answers.

PZHarness = PZHarness or {}
local Handlers = {}
PZHarness.ServerHandlers = Handlers

local MODULE = "PZHarness"

local handlers = {}
-- What each call's handler deferred, by caller and call id, until its test ends.
local undos = {}

--- Registers `fn(player, args, defer)` as the server handler `name`, replacing any earlier one,
--- so a reloaded handler file takes effect.
function PZHarness.serverHandler(name, fn)
    handlers[name] = fn
end

local function undoKey(player, id)
    return player:getUsername() .. "#" .. tostring(id)
end

-- Runs the undos newest first, each whatever the others do. Returns their errors.
local function unwind(list)
    local errors = {}
    for i = #list, 1, -1 do
        local ok, err = pcall(list[i])
        if not ok then
            table.insert(errors, tostring(err))
        end
    end
    return errors
end

local function call(player, request)
    local handler = handlers[request.name]
    if not handler then
        return { error = "no server handler " .. tostring(request.name) }
    end
    local list = {}
    local function defer(undo)
        table.insert(list, undo)
    end
    local ok, reply, missing = pcall(handler, player, request.args or {}, defer)
    if not ok then
        -- What the handler built before it failed goes at once: no test unwinds a failed call.
        local errors = unwind(list)
        table.insert(errors, 1, tostring(reply))
        return { error = table.concat(errors, "; ") }
    end
    -- Only a call that left something to undo costs the test an unwind request.
    if #list > 0 then
        undos[undoKey(player, request.id)] = list
    end
    return { reply = reply, missing = missing, undo = #list > 0 }
end

local function unwindCall(player, request)
    local key = undoKey(player, request.call)
    local errors = unwind(undos[key] or {})
    undos[key] = nil
    return { error = #errors > 0 and table.concat(errors, "; ") or nil }
end

-- A --stay rerun: marks the run in the server's log, where run-client.sh reads this run's part
-- from, and loads the dev mod's reloadable server and shared files again. reloadLuaFile ignores a
-- file's Events.*.Add calls, so only files that just register handlers reload safely.
local function reload(_, request)
    if request.run then
        print(request.tag .. " RUN " .. request.run)
    end
    local errors = {}
    for _, file in ipairs(request.files or {}) do
        local ok, err = pcall(reloadLuaFile, file)
        if not ok then
            table.insert(errors, file .. ": " .. tostring(err))
        end
    end
    return { error = #errors > 0 and table.concat(errors, "; ") or nil }
end

local kinds = { call = call, unwind = unwindCall, reload = reload }

--- Serves one request of `player`'s client; `kind` is "call", "unwind" or "reload". Returns the
--- answer. A failure also goes to the server's log as "<tag> SERVER FAIL <test>: <error>", which
--- run-client.sh counts.
function Handlers.handle(player, kind, request)
    local answer = kinds[kind](player, request)
    answer.id = request.id
    if answer.error then
        print(tostring(request.tag) .. " SERVER FAIL " .. tostring(request.test or kind) .. ": " .. answer.error)
    end
    return answer
end

if isServer() then
    Events.OnClientCommand.Add(function(module, command, player, args)
        if module == MODULE and kinds[command] then
            sendServerCommand(player, MODULE, "reply", Handlers.handle(player, command, args or {}))
        end
    end)
end

return Handlers

-- Development only, not published. Expectations outside a test's validate, such as a dev mod's
-- server handler that checks many things and answers with what it found wrong. Shared, so the test
-- library's own expectNear (client/PZHarness/TestLib.lua) compares and words a miss the same way.

PZHarness = PZHarness or {}
local Checks = {}
PZHarness.Checks = Checks

-- How far apart two numbers may be and still count as equal, unless a check says otherwise.
local DEFAULT_TOLERANCE = 0.0001

--- Whether `actual` is a number within `tolerance` of `expected`, and the message for when it isn't.
function Checks.near(label, actual, expected, tolerance)
    local ok = type(actual) == "number" and math.abs(actual - expected) <= (tolerance or DEFAULT_TOLERANCE)
    return ok, label .. " is " .. tostring(actual) .. ", expected " .. expected
end

--- A fresh list of failures and the two functions that fill it: `expect(condition, message)`
--- records `message` when `condition` is nil or false, and `expectNear(label, actual, expected,
--- tolerance)` records "<label> is <actual>, expected <expected>" when `actual` isn't a number
--- within `tolerance` of `expected`. Both return whether the expectation held. Returns `expect,
--- expectNear, failures`.
function Checks.new()
    local failures = {}
    local function expect(condition, message)
        if not condition then
            table.insert(failures, message)
        end
        return condition
    end
    local function expectNear(label, actual, expected, tolerance)
        local ok, message = Checks.near(label, actual, expected, tolerance)
        return expect(ok, message)
    end
    return expect, expectNear, failures
end

return Checks

-- How far from `near` vehicleById looks in single player, in squares.
local VEHICLE_SEARCH = 6

--- The vehicle with this id, or nil. A multiplayer server and its clients share vehicle ids
--- (getVehicleById). Single player keeps them elsewhere (VehicleIDMap), so there the vehicle is
--- found over the squares within a few of `near` ({ x, y, z }).
function Fixtures.vehicleById(id, near)
    if id == nil then
        return nil
    end
    local vehicle = getVehicleById(id)
    if vehicle or not near then
        return vehicle
    end
    for dx = -VEHICLE_SEARCH, VEHICLE_SEARCH do
        for dy = -VEHICLE_SEARCH, VEHICLE_SEARCH do
            local square = getSquare(near.x + dx, near.y + dy, near.z)
            local found = square and square:getVehicleContainer()
            if found and found:getId() == id then
                return found
            end
        end
    end
    return nil
end

--- Iterates over every square at Chebyshev distance exactly `r` from (x, y), each once, as
--- `for sx, sy in Fixtures.ring(x, y, r) do`; (x, y) itself when `r` is 0. Rings of growing `r`
--- make a nearest-first search that skips the squares smaller rings already tried.
function Fixtures.ring(x, y, r)
    -- Column by column from the west, each north to south: the edge columns whole, the ones
    -- between only their two ends.
    local dx, dy = -r, -r - 1
    return function()
        if math.abs(dx) == r and dy < r then
            dy = dy + 1
        elseif dy < r then
            dy = r
        else
            dx = dx + 1
            if dx > r then
                return nil
            end
            dy = -r
        end
        return x + dx, y + dy
    end
end

--- Turns `car` and `trailer` square to `facing` ("N", "E", "S" or "W") and moves the trailer so its
--- coupler sits on the car's tow bar, as a player lines them up to hitch: vanilla hitches a trailer
--- only with the two points within a square and the vehicles near parallel
--- (BaseVehicle.canAttachTrailer). addVehicleDebug skews each heading by up to about 11 degrees at
--- random, and a hitch left to pull a trailer in from farther off can fail to or jackknife it.
function Fixtures.lineUpTrailer(car, trailer, facing)
    -- The rotation addVehicleDebug gives a heading, before its random skew.
    local yaw = ((IsoDirections[facing]:toAngle() + math.pi) * 180 / math.pi) % 360
    car:setAngles(0, yaw, 0)
    trailer:setAngles(0, yaw, 0)
    local towing = car:getTowingWorldPos("trailer", Vector3f.new())
    local towed = trailer:getTowedByWorldPos("trailer", Vector3f.new())
    local transform = trailer:getWorldTransform(Transform.new())
    local origin = transform:getOrigin()
    -- The transform's x and z are the world's x and y.
    origin:set(origin:x() + towing:x() - towed:x(), origin:y(), origin:z() + towing:y() - towed:y())
    trailer:setWorldTransform(transform)
end

--- Puts the character in the middle of the square at x, y, z. teleportTo alone leaves it on the
--- square's north-west corner (IsoGameCharacter.teleportTo floors), from where vanilla's walkAdj
--- counts a square two to the north or west as within reach (1.6 tiles of its middle) and walks
--- nowhere, while actions that need the square adjacent, such as ISMoveablesAction, then stop and
--- empty the queue.
function Fixtures.teleportToMiddle(player, x, y, z)
    player:teleportTo(x, y, z)
    player:setX(x + 0.5)
    player:setY(y + 0.5)
    player:setLastX(x + 0.5)
    player:setLastY(y + 0.5)
end

--- Changes `item` as `changes` says: `condition`, `uses` (the fraction of a full drainable item,
--- setCurrentUsesFloat), `modData` (keys to set). Returns the item.
function Fixtures.changeItem(item, changes)
    if changes.condition then
        item:setCondition(changes.condition)
    end
    if changes.uses then
        item:setCurrentUsesFloat(changes.uses)
    end
    for key, value in pairs(changes.modData or {}) do
        item:getModData()[key] = value
    end
    return item
end

return Fixtures

-- Development only, not published. What a test may leave behind in one side's copy of the game,
-- read cheaply enough to compare before and after every test: the objects on each square around
-- the character, the vehicles and powered squares among them, the character's lasting state, the
-- sandbox options, the grid, the clock and the climate overrides. Shared, so the server reads its
-- own copy the same way (the runner's leak check, client/PZHarness/Leaks.lua, and the
-- "PZHarness.snapshot" handler in server/PZHarness/ServerFixtures.lua).

PZHarness = PZHarness or {}
local Snapshot = {}
PZHarness.Snapshot = Snapshot

-- A vehicle covers a few squares each way, so every other square still finds it; a generator
-- powers a wide area, so a sparse grid of squares sees power come or go.
local VEHICLE_STRIDE = 2
local POWER_STRIDE = 4
-- Squares are keyed by one number. Basements go below level 0, so levels are shifted up.
local KEY_SPAN = 100000
local LEVEL_SHIFT = 64

--- Lua patterns over an object's "<look>@<class>" that the comparison leaves out: the world
--- changes these by itself as time passes (crops grow, wilt and die; erosion spreads grass,
--- plants, trees, cracks and snow), and grass goes from a square something is placed on, which
--- nothing puts back. A dev mod adds its own with the `leakIgnore` setting.
Snapshot.DEFAULT_IGNORE = {
    "^vegetation_farming", "^vegetation_gardening", "^blends_grassoverlays", "^e_", "^d_plants",
    "^d_generic", "^d_floorleaves", "^d_trash", "^d_streetcracks", "^d_wallcracks", "^f_bushes",
    "^f_flowerbed", "^f_wallvines",
}

local function squareKey(x, y, z)
    return ((z + LEVEL_SHIFT) * KEY_SPAN + y) * KEY_SPAN + x
end

local function keyCoordinates(key)
    return key % KEY_SPAN, math.floor(key / KEY_SPAN) % KEY_SPAN, math.floor(key / (KEY_SPAN * KEY_SPAN)) - LEVEL_SHIFT
end

--- "x,y,z" for a square key.
function Snapshot.where(key)
    local x, y, z = keyCoordinates(key)
    return x .. "," .. y .. "," .. z
end

-- One object as "<look>@<class>": the sprite, or a world item's type, with "*" while a generator
-- or light switch is on. getObjectName is the class for the classes that override it, and the
-- object's name or "IsoObject" otherwise.
local function objectToken(object)
    local class = object:getObjectName()
    local look
    if class == "WorldInventoryItem" then
        local item = object:getItem()
        look = "item:" .. (item and item:getFullType() or "?")
    else
        look = object:getTextureName() or "-"
    end
    if (class == "IsoGenerator" or class == "LightSwitch") and object:isActivated() then
        look = look .. "*"
    end
    return look .. "@" .. class
end

-- Whether each token is ignored, worked out once per token and ignore list, since the same few
-- sprites cover most squares and every pattern costs a string search.
local ignoreKey, ignorePatterns, ignoreCache

local function useIgnore(patterns)
    local key = table.concat(patterns, "\n")
    if key ~= ignoreKey then
        ignoreKey, ignorePatterns, ignoreCache = key, patterns, {}
    end
end

local function ignored(token)
    local hit = ignoreCache[token]
    if hit == nil then
        hit = false
        for _, pattern in ipairs(ignorePatterns) do
            if string.find(token, pattern) then
                hit = true
                break
            end
        end
        ignoreCache[token] = hit
    end
    return hit
end

local function squareSignature(square)
    local objects = square:getObjects()
    local count = objects:size()
    if count == 1 then
        local token = objectToken(objects:get(0))
        return ignored(token) and "" or token
    end
    local tokens = {}
    for i = 0, count - 1 do
        local token = objectToken(objects:get(i))
        if not ignored(token) then
            tokens[#tokens + 1] = token
        end
    end
    return table.concat(tokens, ";")
end

--- The signature of the square with key `key` in this game now, leaving out what `ignore`
--- matches, or false if it isn't loaded.
function Snapshot.signatureAt(key, ignore)
    useIgnore(ignore)
    local square = getCell():getGridSquare(keyCoordinates(key))
    return square and squareSignature(square) or false
end

--- A square's signature as the other side's copy should have it too: the looks without the
--- classes, since a name given on one side need not travel.
function Snapshot.syncSignature(signature)
    return (string.gsub(signature, "@[^;]*", ""))
end

local function sandboxValues(state)
    for key, value in pairs(SandboxVars) do
        if type(value) == "table" then
            for inner, innerValue in pairs(value) do
                if type(innerValue) ~= "table" and type(innerValue) ~= "function" then
                    state["sandbox " .. key .. "." .. inner] = tostring(innerValue)
                end
            end
        elseif type(value) ~= "function" then
            state["sandbox " .. key] = tostring(value)
        end
    end
end

-- A multiplayer client's perk levels and known recipes are copies the server sends when it likes,
-- so only the server's count there.
local function characterState(state, character, copy)
    if not copy then
        for i = 0, PerkFactory.PerkList:size() - 1 do
            local perk = PerkFactory.PerkList:get(i)
            state["perk " .. perk:getId()] = character:getPerkLevel(perk)
        end
        state["known recipes"] = character:getKnownRecipes():size()
    end
    state["inventory items after the reset"] = character:getInventory():getItems():size()
    state["worn items after the reset"] = character:getWornItems():size()
    local primary, secondary = character:getPrimaryHandItem(), character:getSecondaryHandItem()
    state["primary hand after the reset"] = primary and primary:getFullType() or "nothing"
    state["secondary hand after the reset"] = secondary and secondary:getFullType() or "nothing"

    state["the grid"] = getWorld():isHydroPowerOn() and "on" or "off"
    local shut = getSandboxOptions():getOptionByName("ElecShutModifier")

        state["the grid's shutoff day"] = tostring(shut:getValue())

--- What `opts` covers in this game: the squares within `opts.radius` of x, y on each of
--- `opts.levels` (z levels), leaving out the objects `opts.ignore` matches, and, with
--- `character`, that character's state; `opts.copy` leaves out what a multiplayer client only
--- copies from the server. Squares that aren't loaded are left out.
function Snapshot.take(opts, character)
    useIgnore(opts.ignore)
    local snapshot = {
        x = opts.x, y = opts.y, z = opts.z,
        squares = {}, vehicles = {}, powered = {}, state = {},
        worldHours = getGameTime():getWorldAgeHours(),
        realMs = getTimestampMs(),
        minutesPerDay = getGameTime():getMinutesPerDay(),
    }
    local cell, squares, vehicles, powered = getCell(), snapshot.squares, snapshot.vehicles, snapshot.powered
    local r = opts.radius
    for _, z in ipairs(opts.levels) do
        for x = opts.x - r, opts.x + r do
            for y = opts.y - r, opts.y + r do
                local square = cell:getGridSquare(x, y, z)
                if square then
                    local key = squareKey(x, y, z)
                    squares[key] = squareSignature(square)
                    if x % VEHICLE_STRIDE == 0 and y % VEHICLE_STRIDE == 0 then
                        local vehicle = square:getVehicleContainer()
                        if vehicle then
                            vehicles[vehicle:getId()] = vehicle:getScriptName()
                        end
                    end
                    if x % POWER_STRIDE == 0 and y % POWER_STRIDE == 0 then
                        powered[key] = square:haveElectricity()
                    end
                end
            end
        end
    end
    worldState(snapshot.state)
    if character then
        characterState(snapshot.state, character, opts.copy)
    end
    return snapshot
end

-- The clock runs between two snapshots; a test that set it and didn't set it back moves it much
-- further, or back. Slack for a test that sets its own hour and puts the clock back.
local CLOCK_SLACK_HOURS = 0.25

local function clockLine(before, after)
    local seconds = (after.realMs - before.realMs) / 1000
    local expected = seconds / (before.minutesPerDay * 60) * 24
    local moved = after.worldHours - before.worldHours
    if math.abs(moved - expected) > math.max(CLOCK_SLACK_HOURS, expected * 2) then
        return string.format("the clock moved %.2f hours in %.1f s of real time", moved, seconds)
    end
    return nil
end

local function powerLines(lines, before, after)
    local gained, lost, gainedAt, lostAt = 0, 0, nil, nil
    for key, now in pairs(after.powered) do
        local was = before.powered[key]
        if was ~= nil and was ~= now then
            if now then
                gained, gainedAt = gained + 1, gainedAt or key
            else
                lost, lostAt = lost + 1, lostAt or key
            end
        end
    end
    if gained > 0 then
        table.insert(lines, gained .. " sampled squares gained power, such as " .. Snapshot.where(gainedAt))
    end
    if lost > 0 then
        table.insert(lines, lost .. " sampled squares lost power, such as " .. Snapshot.where(lostAt))
    end
end

--- What differs from `before` to `after`, as readable lines: `squares` (with the keys of those
--- squares in `changed`), `vehicles`, and `other` (power, the character's start and state, the
--- options, the grid, the climate, and the clock unless `opts.clock` is false). Squares loaded in
--- only one of them are left out. A snapshot around another square compares only what isn't on
--- the squares.
function Snapshot.diff(before, after, opts)
    local report = { squares = {}, vehicles = {}, other = {}, changed = {} }
    if before.x ~= after.x or before.y ~= after.y or before.z ~= after.z then
        table.insert(report.other, string.format("the character starts at %d,%d,%d, not %d,%d,%d where the test began",
            after.x, after.y, after.z, before.x, before.y, before.z))
    else
        for key, signature in pairs(after.squares) do
            local was = before.squares[key]
            if was and was ~= signature then
                table.insert(report.changed, key)
                table.insert(report.squares, "square " .. Snapshot.where(key) .. " holds [" .. signature .. "], was [" .. was .. "]")
            end
        end
        for id, script in pairs(after.vehicles) do
            if not before.vehicles[id] then
                table.insert(report.vehicles, "a " .. script .. " (vehicle " .. id .. ") is still there")
            end
        end
        for id, script in pairs(before.vehicles) do
            if not after.vehicles[id] then
                table.insert(report.vehicles, "the " .. script .. " (vehicle " .. id .. ") that stood there is gone")
            end
        end
        powerLines(report.other, before, after)
    end
    for key, value in pairs(after.state) do
        if before.state[key] ~= value then
            table.insert(report.other, key .. " is " .. tostring(value) .. ", was " .. tostring(before.state[key] or "unset"))
        end
    end
    for key, value in pairs(before.state) do
        if after.state[key] == nil then
            table.insert(report.other, key .. " is unset, was " .. tostring(value))
        end
    end
    local clock = not (opts and opts.clock == false) and clockLine(before, after)
    if clock then
        table.insert(report.other, clock)
    end
    return report
end

--- Every line of a diff's report, each after `prefix` (if given), appended to `lines`.
function Snapshot.addLines(lines, report, prefix)
    for _, kind in ipairs({ "squares", "vehicles", "other" }) do
        for _, line in ipairs(report[kind]) do
            table.insert(lines, (prefix or "") .. line)
        end
    end
    return lines
end

return Snapshot
