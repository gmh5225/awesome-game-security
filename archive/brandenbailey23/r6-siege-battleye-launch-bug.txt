# Rainbow Six Siege (Steam) — Game terminated during anti-cheat handshake after Y11S3 update; works only when launched via `RainbowSixHelper.exe`

**Status:** Open · **Platform:** PC (Steam, app 359550) · **Report date:** 2026-09-08 (local, UTC-07:00)

## Environment

| Component | Detail |
|---|---|
| OS | Windows 11 Pro 25H2, build 26200.9445 |
| Hardware | HP Z4 G4 (Xeon W-2155), NVIDIA RTX 3060, 64 GB RAM |
| Game version | `Y11S3.0.0.1_C9879602_D2383527_S125572_116592546` (per `%LOCALAPPDATA%\Ubisoft\r6s\R6Status.ini`) |
| Distribution | Steam (files verified via "Verify integrity of game files" — **clean**, no modifications reported) |
| Anti-cheats | BattlEye (via `RainbowSix_BE.exe` / `BEService`) **and** Ubisoft Sentinel (`sen_service` / `sen_driver.sys`) |
| Other security | Windows Defender (real-time), HP Wolf Security (Sure Click endpoint active; Sure Sense disabled) |

**No cheats, hacks, or modified game files are in use.** Steam integrity verification completes with no errors. Both `RainbowSix.exe` and `RainbowSixHelper.exe` are byte-identical (same SHA-256) and are both tracked as legitimate executables by Ubisoft Connect's launcher state (`R6Status.ini`).

---

## Summary

After a game update/reinstall on **2026-09-08**, launching Siege through the **standard paths** (Steam Play button, Ubisoft Connect, or `RainbowSix.exe` via a launcher) results in the anti-cheat **terminating the game client ~1 minute into startup** — *after* BattlEye's service and kernel driver load successfully, and *after* the game connects to Ubisoft's backend. There is **no crash dialog and no error event logged locally**; the process exits cleanly/deliberately.

Launching the **same game binary** directly via `RainbowSixHelper.exe` (identical file, located in the same install folder) **works reliably** and allows normal play.

An earlier symptom — BattlEye service installation failure `(4, 30000020)` — was resolved on our side (see "What was tried"), but the client termination described above persists for the standard launch paths.

## Symptoms (exact)

1. **Standard-path launches (Steam Play / Ubisoft Connect / `RainbowSix.exe`):**
   - BattlEye console may appear briefly; BattlEye service and `BEDaisy.sys` register and load (verified in event log).
   - The game shows its startup/"Updating security measures" phase, then the client **closes** without an error dialog.
   - Ubisoft Connect returns to its home screen.
2. **Direct launch (`RainbowSixHelper.exe`):** game boots normally to the menu and is playable.

## Root-cause hypothesis

The failure is isolated to the **standard launch path's bootstrapping role of `RainbowSix.exe`** (Steam Play / Ubisoft Connect), not to the game binary, BattlEye, the kernel driver, or game files:

- The same bytes launched as `RainbowSixHelper.exe` run perfectly.
- The client is terminated only after BattlEye init **and** after connecting to Ubisoft's backend — consistent with a **server-side or client-side security/version negotiation failure** during the "security measures"/session handshake that the standard path performs and the direct path does not.
- Possibly related to the dual anti-cheat (BattlEye + Sentinel) sequencing introduced/updated in Y11S3, or to the backend expecting a build component that the update on 2026-09-08 did not deliver.

Suggested areas for Ubisoft/BattlEye to check: session rejection reasons for this account/game version on 2026-09-08 (backend logs), why `RainbowSix.exe` (launcher role) terminates the client while the identical `RainbowSixHelper.exe` (game role) succeeds, and the "Steam info is not available" errors in the game-starter log.
