# AI Agent Operating Instructions (`AGENTS.md`)

This file defines mandatory rules for any AI coding or CLI agent (Claude Code, Codex, Antigravity, or similar) executing or adapting this repository for a user.

## Core Rules

1. **Read before acting.** Read `README.md` and the relevant guides in `docs/` (`01-environment.md` through `08-technical-findings.md`) before running commands or editing files.
2. **Never hardcode environment values.** Never assume or reuse device serials, IP addresses, ADB ports, usernames, home paths, or UIDs from documentation. Detect every value at runtime on the user's machine and guest.
3. **Use the interactive question tool whenever ADB is inaccessible or ambiguous.**
   - Before running any guest command, check `adb devices`.
   - If `adb` is missing, if zero reachable devices are in `device` state (for example, disconnected, `offline`, or `unauthorized`), or if more than one device is connected, **automatically invoke your interactive question tool** (or ask the user directly if your runtime has no structured question tool) to request the target `<DEVICE_ID>` / `<HOST_IP>:<PORT>` or instruct the user to enable/reconnect ADB before proceeding.
   - Never silently guess which ADB target to modify.
4. **Never target a physical device's `/system` partition.** Confirm the target is a virtual Android instance (such as VPhoneOS) before any write operation.
5. **No Magisk.** Do not install, recommend, or introduce Magisk, Magisk modules, or Zygisk.
6. **Compare detected target against the tested reference.**
   - Tested reference: VPhoneOS `5.2.6`, Android `7.1.2` (SDK `25`), `arm64-v8a` (`zygote64_32`), built-in `su` root, SELinux `Enforcing`.
   - Exact match: follow the documented steps and scripts.
   - Any difference (different virtualization app such as MEmu, different Android version/SDK, different ABI, different root manager): explain the difference clearly, label the adapted path **Untested**, assess compatibility, and obtain explicit user approval before modifying anything. Stop immediately if incompatible (for example, `ro.build.version.sdk != 25` or `ro.product.cpu.abi != arm64-v8a` for `xposed-v89-sdk25-arm64.zip`).
7. **Verify checksums and signatures first.** Always run `./scripts/verify-resources.sh` before staging or installing any bundled ZIP or APK.
8. **Back up and obtain approval before risky steps.** Run `./scripts/backup-stock-system.sh`, encourage a VM snapshot where storage allows, and get explicit user confirmation before writing to `/system`.
9. **Pause only for genuine manual steps.** Pause with exact instructions and expected outcomes for manual VPhoneOS reboots (after flashing Xposed v89, and after enabling CorePatch) or when ADB requires user reconnection. Verify state after each resume before advancing.
10. **Verify every stage with real command output.** Never claim a step succeeded without running read-only verification (`./scripts/verify-setup.sh`, `error.log`, `apksigner`, `dumpsys package`). Limit troubleshooting retries to 2-3 targeted attempts before pausing to report findings and ask the user.
11. **Protect privacy.** Never commit or paste personal identifiers, serial numbers, IPs, account names, tokens, or raw host paths into repository files.

![VPhoneOS Android 7 Setup Banner](assets/banner.svg)

# VPhoneOS Android 7 — Xposed Framework v89 + CorePatch Setup

Verified, reproducible documentation, scripts, checksums, and an AI-agent automation prompt for installing **Xposed Framework v89**, **Xposed Installer 3.1.5**, and a **custom Android 7.1.2 (SDK 25) build of CorePatch 2.2** on **VPhoneOS Android 7.1.2 (`arm64-v8a`)** to enable installing unsigned APKs — using built-in VPhoneOS root only (**no Magisk, Magisk modules, or Zygisk**).

> **Security Notice**
> Disabling Android APK signature verification removes a core integrity and trust boundary. Perform this setup **only inside an isolated virtual Android instance** (such as VPhoneOS), never on a physical daily-driver device or any instance holding sensitive accounts or personal data. See [Reverting or Disabling](docs/05-unsigned-apk-installation.md#disabling-corepatch-or-reverting-xposed) for how to turn off signature bypass or restore stock `/system` files.

---

## Tested Reference Environment

These values describe the exact environment where this setup was executed and verified. They are a **compatibility reference**, not values to hardcode for your own machine.

| Layer | Tested Reference | Evidence |
|---|---|---|
| Host OS / Shell | Android 15 (API 35), `arm64-v8a`, Termux `0.118.3` (`bash`) | Verified |
| Host Tools | `adb 1.0.41` (`35.0.2`), `OpenJDK 21`, `apktool 3.0.3-dirty`, Android SDK build-tools `37.0.0`, `unzip`, `sha256sum` | Verified |
| Virtualization App | VPhoneOS `5.2.6` | Observed |
| Guest OS / API | VPhoneOS Android `7.1.2` (Nougat, SDK `25`), security patch `2017-08-05`, image build date `2025-05-17` | Verified |
| Guest Architecture | `arm64-v8a` primary (`arm64-v8a, armeabi-v7a, armeabi`), `zygote64_32`, kernel `4.14.42-titan` | Verified |
| Guest Storage / Crypto | `/system` ext4 (`ro` default), `ro.crypto.state=unsupported` | Verified |
| Guest SELinux | `Enforcing` (`getenforce`) | Verified |
| Guest Root | Built-in VPhoneOS `su` (`16 com.thirdparty.superuser`); **no Magisk** | Verified |
| Connection | TCP/wireless ADB (`adb connect <HOST_IP>:<PORT>`) | Verified |

---

## Requirements

- A VPhoneOS Android 7.1.2 (`arm64-v8a`, SDK `25`) virtual instance with built-in root (`su`) and ADB enabled.
- A host shell with `adb`, `unzip`, and `sha256sum` (or `shasum` on macOS). `apksigner` or `keytool` is optional for extra APK certificate verification.
- At least `50 MB` free on guest `/system` (tested instance had `0.9 GB` free) for Xposed files plus compressed `.orig.gz` backups.
- Ability to manually reboot the VPhoneOS virtual instance from VPhoneOS's restart/power action.

---

## Quick Start

### Option A: AI-Agent Automated Path (Claude Code, Codex, Antigravity, or Similar CLI Agents)

1. Open [prompts/ai-agent-setup.md](prompts/ai-agent-setup.md) and copy the single prompt block into your CLI agent.
2. Connect ADB to your VPhoneOS instance (or let the agent prompt you if ADB is unreachable or multiple targets exist).
3. Approve the compatibility check and `/system` flash confirmation when prompted, and perform the two manual VPhoneOS reboots when instructed.

### Option B: Manual Guided Path

Run all host commands from the cloned repository root (`<REPO_DIR>`). If more than one ADB device is connected, pass `-s <DEVICE_ID>` (or set `ADB_SERIAL=<DEVICE_ID>`). On Termux hosts where `/usr/bin/env` is not present without `termux-exec`, prefix script calls with `bash` (for example `bash scripts/verify-resources.sh`).

```bash
# 1. Verify bundled archive/APK SHA-256 checksums and signing certificates
./scripts/verify-resources.sh

# 2. Inspect guest compatibility read-only (must match SDK 25, arm64-v8a, uid=0 root)
./scripts/inspect-guest.sh

# 3. Back up stock guest ART and Zygote binaries locally (also take a VPhoneOS snapshot if space permits)
./scripts/backup-stock-system.sh

# 4. Flash Xposed Framework v89 atomically onto /system (with .orig.gz and _original backups)
./scripts/flash-xposed-v89.sh
```

**Manual step 1:** Reboot the VPhoneOS instance cleanly from VPhoneOS's restart/power menu, reconnect ADB if needed, then verify pure Xposed Framework activation before enabling CorePatch:

```bash
# 5. Verify Xposed v89 is active in both Zygotes under SELinux Enforcing
./scripts/verify-setup.sh

# 6. Install Xposed Installer 3.1.5 + CorePatch SDK 25 and enable CorePatch in Xposed
./scripts/enable-corepatch.sh
```

**Manual step 2:** Reboot the VPhoneOS instance cleanly a second time so Zygote and `system_server` load CorePatch, then verify activation and test an unsigned APK:

```bash
# 7. Verify CorePatch SDK25 hooks are active in error.log and test unsigned APK verification
./scripts/verify-setup.sh --test-apk <PATH_TO_UNSIGNED_APK>

# 8. Install your unsigned APK over ADB
adb -s <DEVICE_ID> install <PATH_TO_UNSIGNED_APK>
```

For full step-by-step explanations, expected outputs, and manual fallbacks, follow the sequential guides under `docs/`.

- **Corresponding GPL-2.0 source code:** `resources/corepatch-sdk25-src/`
- **Upstream repository:** `https://github.com/LSPosed/CorePatch` (originally `coderstory/CorePatch`, based on commit `1e453cf66ce3a622c9f363090dcaecdaf7e3ab37`)
- **License:** GNU General Public License, Version 2.0 (`GPL-2.0`). Full license text is included at `resources/corepatch-sdk25-src/LICENSE`.
- **Summary of modifications made to upstream `1e453cf`:**
  1. Replaced SDK 28+ `PackageParser` / `SigningDetails` / `ApkSignatureVerifier` hooks in `CorePatch.java` with SDK 25 (`Android 7.1.2`) compatible hooks targeting `PackageParser.collectCertificates(Package, File, int)` and `PackageManagerService` (`systemReady`, `checkDowngrade`, `verifySignaturesLP`, `compareSignatures`, `compareSignaturesCompat`, `compareSignaturesRecover`).
  2. Added `ThreadLocal<Integer>` scoping (`COLLECT_DEPTH`) around `PackageParser.collectCertificates(Package, File, int)` so `MessageDigest.isEqual`, `Signature.verify`, `OpenSSLSignature.engineVerify`, `OpenSSLSignatureRawRSA.engineVerify`, and `StrictJarVerifier.<init>` bypasses only apply during APK certificate collection and never affect TLS or normal app cryptography.
  3. Added dummy X.509 certificate injection when `collectCertificates` throws `PackageParserException` with `-103` (`INSTALL_PARSE_FAILED_NO_CERTIFICATES`), `-104`, or `-105` on valid APK archives containing `AndroidManifest.xml`.
  4. Fixed the upstream preference filename mismatch in `XposedHelper.java` (`"conf.xml"` to match `MainActivity` instead of `"config"`).
  5. Updated `xposeddescription` in `AndroidManifest.xml` and `blog2` in `res/values/strings.xml`, and inlined the adaptive icon gradient for clean AAPT2 rebuilds.

# 02 — Flashing Xposed Framework v89 (No Magisk)

## Purpose

Install official Xposed Framework v89 (`xposed-v89-sdk25-arm64.zip`) onto `/system` using VPhoneOS's built-in root (`su`) via an atomic live-flashing script that preserves `.orig.gz` and `_original` backups and exact SELinux contexts (`zygote_exec`, `dex2oat_exec`, `system_file`).

This method intentionally avoids Magisk, Magisk modules, and Zygisk.

---

## Why an Atomic Script Instead of Running `flash-script.sh` Directly Live

The official `xposed-v89-sdk25-arm64.zip` includes `META-INF/com/google/android/flash-script.sh`, which was designed for offline recovery (TWRP). Running it verbatim while Android is live has two hazards on VPhoneOS:

1. **Temporary missing-library window (Observed/Analyzed):** `flash-script.sh` moves `/system/lib64/libart.so` to `libart.so.orig`, compresses it with `gzip`, and only then copies the replacement `libart.so`. For roughly 1 second, `/system/lib64/libart.so` does not exist on disk.
2. **Inline `su -c` failure on long commands (Verified):** Running long multi-line commands via `adb shell 'su -c "..."'` exited with status `255` on VPhoneOS without executing. Pushing a standalone shell file to `/data/local/tmp/` and running `su -c "sh <script>"` worked cleanly (Verified).

`scripts/guest-flash-xposed-v89.sh` follows the exact file list, ownership, permissions, SELinux contexts, `.orig.gz` backups, and `_original` backups of upstream `flash-script.sh`, while copying brand-new files (`xposed.prop`, `XposedBridge.jar`, `libxposed_art.so`) first and replacing existing binaries via same-filesystem `mv -f` atomic renames (`rename(2)`), eliminating any missing-file window (Verified).

# 04 — CorePatch SDK 25 Port and Activation

## Purpose

Install and activate a patched Android 7.1.2 (SDK 25) compatible build of CorePatch (`resources/CorePatch_sdk25_patched.apk`) in Xposed Framework v89 so Android's `PackageParser` and `PackageManagerService` accept unsigned APKs.

---

## Why Stock `Core+Patch+v2.2.apk` Was Not Suitable for SDK 25

Inspection of upstream `LSPosed/CorePatch` (`coderstory/CorePatch`, commit `1e453cf` / v2.2) against VPhoneOS's actual `boot-framework.oat` and `services.odex` bytecode revealed six concrete incompatibilities and bugs (Verified via static bytecode analysis and `oatdump` on VPhoneOS):

1. **Unconditional Android 9+ (SDK 28+) APIs:** Stock CorePatch v2.2 hooks `PackageParser$SigningDetails`, `Package.mVersionCodeMajor`, `ApkSignatureVerifier`, and `PackageManagerServiceUtils.verifySignatures`, none of which exist on Android 7.1.2 (SDK 25).
2. **Shared-preferences filename mismatch:** `MainActivity` writes toggles to `"conf.xml"` (`/data/data/com.coderstory.toolkit/shared_prefs/conf.xml.xml`), whereas stock `XposedHelper` read `"config"`.
3. **Inlined constant reflection:** Stock CorePatch reflected `ApkSignatureSchemeV2Verifier.SF_ATTRIBUTE_ANDROID_APK_SIGNED_ID`, which does not exist as a field in VPhoneOS's `boot-framework.oat`.
4. **Global cryptographic verifier hooks:** Unscoped hooks on `MessageDigest.isEqual` and `OpenSSLSignature.engineVerify` in `initZygote` weaken TLS and app cryptography across every process.
5. **Broken platform signature guard and live memory mutation:** Stock `compareSignatures` iterated the wrong field for platform signature checks, and `checkDowngrade` zeroed `Package.mVersionCode` in memory instead of returning early.
6. **Unsigned APK crash in SDK 25 `StrictJarFile`:** On SDK 25, installing an APK without `META-INF/MANIFEST.MF` causes `PackageParser.collectCertificates(Package, File, int)` -> `new StrictJarFile(...)` -> `StrictJarManifest.read(null)` to throw `NullPointerException: Attempt to get length of null array`, wrapped in `PackageParserException` with error `-103` (`INSTALL_PARSE_FAILED_NO_CERTIFICATES`).

---

## What `CorePatch_sdk25_patched.apk` Changes

Full GPL-2.0 source code is included under `resources/corepatch-sdk25-src/`. Key changes in `CorePatch.java` and `XposedHelper.java` (Verified):

- **Scoped crypto bypass (`COLLECT_DEPTH`):** A `ThreadLocal<Integer>` counter wraps `PackageParser.collectCertificates(Package, File, int)` (the single choke point called by both `parseApkLite(File, 256)` and `collectCertificatesInternal(Package, int)`). Hooks on `MessageDigest.isEqual`, `Signature.verify`, `OpenSSLSignature.engineVerify`, `OpenSSLSignatureRawRSA.engineVerify`, and `StrictJarVerifier.<init>` (`args[3] = false`) only trigger while `COLLECT_DEPTH > 0`.
- **Unsigned APK recovery:** When `collectCertificates(Package, File, int)` throws a `PackageParserException` with error `-103`, `-104`, or `-105` on a valid ZIP containing `AndroidManifest.xml` (and `authcreak` is enabled, default `true`), `CorePatch` populates `mCertificates`, `mSignatures`, and `mSigningKeys` with a valid X.509 dummy certificate and clears the exception (`param.setResult(null)`).
- **SDK 25 `PackageManagerService` hooks (`android` / `android`):**
  - `systemReady`: loads platform signatures for the platform-signature guard.
  - `checkDowngrade`: returns early (`setResult(null)`) when `downgrade` is enabled (default `true`) without mutating `mVersionCode`.
  - `verifySignaturesLP`, `compareSignatures`, `compareSignaturesCompat`, `compareSignaturesRecover`: respect `authcreak` (default `true`) and `zipauthcreak` (default `false`) while preserving the platform-signature guard (including `sharedUser`).
- **Fixed preferences sync:** `XposedHelper` reads `new XSharedPreferences("com.coderstory.toolkit", "conf.xml")`.

### Default Toggles Used During Verification

| Preference Key | UI Label | Default Used | Purpose |
|---|---|---|---|
| `authcreak` | Disable package manager signature verification | `true` (Enabled) | Enables unsigned and modified APK certificate acceptance |
| `downgrade` | Allow downgrade installation | `true` (Enabled) | Allows installing lower `versionCode` APKs |
| `zipauthcreak` | Disable signature comparison across different keys | `false` (Disabled) | Keeps cross-signature overwrite disabled by default |

# 07 — Troubleshooting

Each entry below documents an actual failure mode encountered during setup or verification, its root cause, the fix, and its evidence classification.

---

## 1. Downloaded `Xposed-89.zip` or `XposedInstaller-3.1.5.zip` Is Missing Flashable Binaries or APK

- **Symptom:** Unzipping a GitHub tag archive named `Xposed-89.zip` (approx. `49 KB`) or `XposedInstaller-3.1.5.zip` (approx. `1.1 MB`) reveals C++/Java source files instead of `system/framework/XposedBridge.jar`, `system/bin/app_process64_xposed`, or `XposedInstaller_3.1.5.apk`.
- **Cause:** GitHub tag/release archives download repository source trees rather than compiled Xposed release artifacts.
- **Solution:** Use the verified release files bundled in this repository (`resources/xposed-v89-sdk25-arm64.zip` at `8,272,548` bytes and `resources/XposedInstaller_3.1.5.apk` at `3,105,672` bytes) and run `./scripts/verify-resources.sh` to validate their SHA-256 hashes and signing certificate (`CN=rovo89`) before use.
- **Evidence:** **Verified**.

---

## 2. Multi-Line `adb shell 'su -c "..."'` Fails with Exit Code `255`

- **Symptom:** Running a long or multi-line command through `adb -s <DEVICE_ID> shell 'su -c "..."'` exits immediately with status `255` and produces no output or changes on `/system`.
- **Cause:** VPhoneOS's built-in `su` wrapper (`16 com.thirdparty.superuser`) rejects or truncates complex multi-line `-c` command strings passed over ADB shell quoting layers.
- **Solution:** Push a standalone POSIX shell script to `/data/local/tmp/` and invoke it via `adb -s <DEVICE_ID> shell 'su -c "sh /data/local/tmp/<script>.sh"'`. All modifying scripts in `scripts/` (`flash-xposed-v89.sh`, `revert-xposed-v89.sh`) already follow this pattern using `scripts/guest-flash-xposed-v89.sh`.
- **Evidence:** **Verified**.

---

## 3. After Flashing, Live `/system` Files Still Show Stock Hashes or `Links: 0` Before Reboot

- **Symptom:** Immediately after `scripts/flash-xposed-v89.sh` completes cleanly, checking `stat` or `md5sum` on `/system/bin/app_process64`, `/system/bin/app_process32`, `/system/lib/libart.so`, or `/system/lib64/libart.so` in a new shell may still show the old stock MD5 hash, `Links: 0`, and `Change: 1970-01-01`.
- **Cause:** On VPhoneOS (`4.14.42-titan`), built-in `su` operates in a separate mount namespace from PID 1, `toybox mount -o remount,rw /system` stacks a writable mount rather than mutating PID 1's mount cleanly, and active `zygote64`/`zygote` mappings keep unlinked stock inodes pinned in the dentry cache until reboot.
- **Solution:** Do **not** panic and do **not** flash a second time (re-flashing would overwrite `.orig.gz` backups if guards were bypassed). Verify the written files in a fresh mount view (which `guest-flash-xposed-v89.sh` checks) and perform a clean manual VPhoneOS reboot from VPhoneOS's restart/power menu. After reboot, all 16 flashed Xposed files become active cleanly. See [08-technical-findings.md](08-technical-findings.md) for the full mount-namespace analysis.
- **Evidence:** **Verified**.

---

## 4. `sha256sum: not found` Inside the Android 7.1.2 Guest Shell

- **Symptom:** Running `sha256sum` inside `adb shell` fails with `sha256sum: not found`.
- **Cause:** Android 7.1.2's guest `toybox` build includes `md5sum` and `cksum`, not `sha256sum`.
- **Solution:** Run `sha256sum` on the **host** (`./scripts/verify-resources.sh`) and use `md5sum` inside the **guest** (`guest-flash-xposed-v89.sh` verifies flashed files with `md5sum`).
- **Evidence:** **Verified**.

---

## 5. Xposed Logs `Cannot load any modules` / `modules.list was not found`

- **Symptom:** After enabling CorePatch in `/data/data/de.robv.android.xposed.installer/conf/modules.list` and rebooting, Xposed's `error.log` reports `Cannot load any modules because /data/user_de/0/de.robv.android.xposed.installer/conf/modules.list was not found`.
- **Cause:** Even though VPhoneOS reports `ro.crypto.state=unsupported`, Xposed Framework v89 (`requires:fbe_aware=1`) and Xposed Installer 3.1.5 read `conf/modules.list` and write `log/error.log` under Device-Encrypted storage (`/data/user_de/0/de.robv.android.xposed.installer/`), which is a distinct inode from `/data/data/de.robv.android.xposed.installer/` on VPhoneOS.
- **Solution:** Write the module APK path to `/data/user_de/0/de.robv.android.xposed.installer/conf/modules.list` (owned by Xposed Installer's UID/GID, mode `0644`, SELinux context `u:object_r:app_data_file:s0`) and sync `enabled_modules.xml` under `/data/data/de.robv.android.xposed.installer/shared_prefs/`. `scripts/enable-corepatch.sh` handles both paths automatically.
- **Evidence:** **Verified**.

---

## 6. Stock Upstream CorePatch v2.2 Fails to Load or Does Not Bypass Signatures on Android 7.1.2 (SDK 25)

- **Symptom:** Installing unmodified upstream `Core+Patch+v2.2.apk` on Android 7.1.2 results in `ClassNotFoundError` / `NoSuchMethodError` in `error.log` (referencing `SigningDetails`, `ApkSignatureVerifier`, or Android 9/10 `PackageParser` signatures), and unsigned APKs still fail with `INSTALL_PARSE_FAILED_NO_CERTIFICATES`.
- **Cause:** Upstream CorePatch v2.2 targets Android 9–10 (`SDK 28–29`), where Android replaced Android 7's `PackageParser.collectCertificates(Package, File, int)` and `Signature[]` APIs with `PackageParser.SigningDetails` and `ApkSignatureVerifier`.
- **Solution:** Install the SDK 25 build included in this repository (`resources/CorePatch_sdk25_patched.apk`), built from the GPL-2.0 source in `resources/corepatch-sdk25-src/`. See [04-corepatch.md](04-corepatch.md) for the exact hook changes.
- **Evidence:** **Verified**.

---

## 7. CorePatch Toggles Appear Enabled in UI but Hooks Read All Settings as `false`

- **Symptom:** Toggling switches inside the CorePatch app UI does not activate downgrade or signature bypass hooks, or `XSharedPreferences` always reads default values.
- **Cause:** Two separate issues affect CorePatch on Android 7.1.2:
  1. Upstream `XposedHelper.java` opened `XSharedPreferences(package, "config")`, while `MainActivity.java` saved settings to `getSharedPreferences("conf.xml", MODE_WORLD_READABLE)` (creating `conf.xml.xml`).
  2. On Android 7, if `shared_prefs/conf.xml.xml` or its parent directories are not world-readable (`0755` directories, `0644` file), `system_server` cannot read the file through `XSharedPreferences`.
- **Solution:** Use `resources/CorePatch_sdk25_patched.apk` (which fixes `XposedHelper.java` to read `"conf.xml"`) and run `./scripts/enable-corepatch.sh` to write `conf.xml.xml` with permissions `0644` and `0755` parent directories.
- **Evidence:** **Verified**.

---

## 8. Rebuilding CorePatch from Source Fails in `aapt2` on `$ic_launcher_foreground__0`

- **Symptom:** Rebuilding decoded CorePatch resources with `apktool` and modern `aapt2` fails with an invalid resource filename error on `$ic_launcher_foreground__0.xml` or `public.xml`.
- **Cause:** Decompiled adaptive icon gradient split files generated by older Android build tools use a `$`-prefixed name (`$ic_launcher_foreground__0`) that newer `aapt2` rejects as an illegal resource identifier.
- **Solution:** Inline the `<gradient>` directly inside `res/drawable-v24/ic_launcher_foreground.xml` using `<aapt:attr name="android:fillColor">` and remove the `$`-prefixed file and its `public.xml` entry. This fix is already applied in `resources/corepatch-sdk25-src/app/src/main/res/drawable-v24/ic_launcher_foreground.xml`.
- **Evidence:** **Verified**.

---

## 9. `apksigner` Drops v1 JAR Signature When Signing Rebuilt CorePatch (`minSdkVersion=24`)

- **Symptom:** A freshly signed rebuild of CorePatch installs on Android 7.1.2, or fails to parse cleanly on older Android tooling, because `META-INF/*.SF` / `*.RSA` entries are missing.
- **Cause:** Newer versions of `apksigner` may omit v1 JAR signing by default or emit v3/v4 schemes when `minSdkVersion >= 24`. Android 7.1.2 supports v1 and v2 signatures (not v3/v4).
- **Solution:** Explicitly specify `--v1-signing-enabled true --v2-signing-enabled true --v3-signing-enabled false --v4-signing-enabled false` when signing rebuilt APKs for SDK 25. `resources/CorePatch_sdk25_patched.apk` was signed and verified with both v1 and v2 enabled.
- **Evidence:** **Verified**.

---

## 10. `adb install` Hangs Indefinitely at `Performing Streamed Install`

- **Symptom:** Running `adb -s <DEVICE_ID> install <APK>` prints `Performing Streamed Install` and hangs indefinitely; checking `/data/app/` on the guest shows a 0-byte `vmdl*.tmp/base.apk`.
- **Cause:** After booting with Xposed's replaced ART libraries (`libart.so`, `libart-compiler.so`), Android's `BackgroundDexOptService` schedules `dex2oat --compiler-filter=speed` on large installed apps (especially `com.google.android.gms`). On virtualized `arm64`, GMS `arm` compilation can run until ART's 570-second watchdog timeout (`art/dex2oat/dex2oat.cc:461`) and immediately trigger `arm64` compilation next, holding `PackageManagerService.mInstallLock` / `installd` so `adb install` blocks.
- **Solution:**
  1. Check for an active background `dex2oat` process on the guest:
     ```bash
     adb -s <DEVICE_ID> shell 'ps | grep dex2oat'
     ```
  2. Either wait for background optimization to finish, or terminate the stalled GMS `dex2oat` child process (read-only check first; confirm the PID belongs to `dex2oat` compiling `com.google.android.gms`, never `zygote` or `system_server`):
     ```bash
     adb -s <DEVICE_ID> shell 'su -c "kill <DEX2OAT_PID>"'
     ```
  3. Retry `adb -s <DEVICE_ID> install <PATH_TO_UNSIGNED_APK>`. In our verified session, clearing the stuck GMS `dex2oat` child unblocked `adb install` immediately, returning `Success` in roughly 30 seconds.
- **Evidence:** **Verified**.

## 11. Unsigned App Installs and Launches, Then Fails with `Caller isn't signed with recognized keys`

- **Symptom:** An unsigned APK installs with `Success` and launches, but fails when invoking Google Sign-In or privileged Google Play Services APIs, logging `SecurityException: Caller isn't signed with recognized keys` or `GoogleCertificatesRslt: not allowed`.
- **Cause:** CorePatch installs unsigned APKs by injecting a synthetic X.509 dummy certificate during `PackageParser.collectCertificates`. Android PackageManager accepts the app, but Google Play Services (`com.google.android.gms`) performs an independent runtime check comparing the caller's signing certificate against Google's own certificate allowlist.
- **Solution:** This is expected GMS security behavior, not a CorePatch or Xposed installation bug. CorePatch's scope ends at Android package parsing and installation; bypassing GMS server/client allowlist verification is outside this setup.
- **Evidence:** **Verified**.

---

## 12. ADB Target Missing, Offline, Unauthorized, or Multiple Devices Attached

- **Symptom:** Any script in `scripts/` exits with an ADB target error (`No online ADB devices found` or `Multiple ADB devices detected`).
- **Cause:** VPhoneOS ADB is not yet connected over TCP, the guest rebooted and dropped the session, or another device/emulator is also attached to `adb`.
- **Solution:**
  1. Re-check VPhoneOS ADB settings inside the instance and run `adb connect <HOST_IP>:<PORT>`.
  2. Confirm `adb devices` lists your VPhoneOS instance as `device` (not `offline` or `unauthorized`).
  3. If more than one device is listed, pass `-s <DEVICE_ID>` (or set `ADB_SERIAL=<DEVICE_ID>`) to every script.
- **Evidence:** **Verified**.

# 08 — Technical Findings

This document summarizes the concrete system, bytecode, and security findings uncovered while getting Xposed Framework v89 and CorePatch working on VPhoneOS Android 7.1.2 (SDK 25, `arm64-v8a`) without Magisk.

---

## 1. VPhoneOS Mount-Namespace Isolation and Pinned Dcache (`Links: 0`)

**Evidence:** **Verified**.

On the tested VPhoneOS Android 7.1.2 image (kernel `4.14.42-titan`, `/system` mounted from `/dev/block/mtdblock0`):

1. **Distinct mount namespaces:** Commands executed through built-in `su` (`16 com.thirdparty.superuser`) run in a mount namespace distinct from `PID 1` (`/proc/1/ns/mnt` differs from `su`'s `/proc/self/ns/mnt`).
2. **Stacked `remount,rw` mounts:** Calling `toybox mount -o remount,rw /system` inside `su` stacks a writable mount over `/system` rather than transitioning PID 1's mount view in place.
3. **Why live binaries must be replaced atomically:** While VPhoneOS is running, `zygote64` and `zygote` hold active executable mappings (`mmap`) on `/system/bin/app_process64`, `/system/bin/app_process32`, `/system/lib/libart.so`, `/system/lib/libart-compiler.so`, `/system/lib/libsigchain.so`, `/system/lib64/libart.so`, `/system/lib64/libart-compiler.so`, and `/system/lib64/libsigchain.so`.
   - Overwriting those files in place (`cp` directly onto the target path) would corrupt mapped pages of live ART processes and crash the instance mid-flash.
   - Staging each new binary to `<target>.xposed_new`, setting ownership/mode/SELinux context, and replacing the directory entry via atomic `mv` (`rename(2)`) unlinks the old stock inode without mutating its data blocks, leaving the running Zygotes stable until reboot.
4. **Why pre-reboot checks can look misleading:** Immediately after atomic replacement, inspecting the eight active Zygote/ART paths from PID 1's mount view can display the still-pinned stock inodes (`Links: 0`, `Change: 1970-01-01`, stock MD5). Fresh lookups against the underlying `/dev/block/mtdblock0` mount confirm all 16 flashed files persisted with exact expected MD5 hashes; after a clean VPhoneOS reboot, PID 1 mounts the new inodes directly.

---

## 2. Android 7.1.2 (SDK 25) `PackageParser.collectCertificates` Path for Unsigned APKs

**Evidence:** **Verified** (inspected directly via `oatdump` against guest `/system/framework/arm64/boot-framework.oat` and `/system/framework/oat/arm64/services.odex`).

Unlike Android 9+ (`SDK 28+`), which delegates APK signature checks to `android.util.apk.ApkSignatureVerifier` and `PackageParser.SigningDetails`, Android 7.1.2 performs certificate parsing directly inside:

```java
android.content.pm.PackageParser.collectCertificates(Package pkg, File apkFile, int parseFlags)
```

When an APK contains no JAR signature entries (`META-INF/MANIFEST.MF` missing):

1. `PackageParser.collectCertificates` opens the archive with `new android.util.jar.StrictJarFile(apkPath, true, true)`.
2. `StrictJarFile` attempts to parse `META-INF/MANIFEST.MF` by passing the raw byte buffer (which is `null`) into `StrictJarManifest.read(byte[])`.
3. `StrictJarManifest.read(null)` throws `java.lang.NullPointerException: Attempt to get length of null array`.
4. `PackageParser.collectCertificates` catches the exception and wraps it in `PackageParser.PackageParserException` with error code `-103` (`PackageManager.INSTALL_PARSE_FAILED_NO_CERTIFICATES`), aborting installation.

---

## 3. Scoped Crypto Hooks and Synthetic Dummy Certificate Injection

**Evidence:** **Verified**.

To accept unsigned and re-signed APKs on SDK 25 without weakening general system cryptography (such as HTTPS/TLS verification):

1. **Thread-local scoping (`COLLECT_DEPTH`):**
   - `CorePatch.java` hooks `PackageParser.collectCertificates(Package, File, int)` in `beforeHookedMethod` (incrementing a `ThreadLocal<Integer>` depth counter) and `afterHookedMethod` (decrementing in `finally`).
   - Low-level cryptographic bypasses in `initZygote`:
     - `java.security.MessageDigest.isEqual(byte[], byte[])`
     - `java.security.Signature.verify(byte[])` and `verify(byte[], int, int)`
     - `com.android.org.conscrypt.OpenSSLSignature.engineVerify(byte[])`
     - `com.android.org.conscrypt.OpenSSLSignatureRawRSA.engineVerify(byte[])`
     - `android.util.jar.StrictJarVerifier.<init>(...)` (disabling strict manifest verification flag)
   - Every one of those hooks checks `isInCollectCertificates()` (`COLLECT_DEPTH > 0`) and **passes through untouched** for all non-PackageParser callers.
2. **Dummy X.509 certificate injection (`afterHookedMethod`):**
   - When `collectCertificates` finishes with a `PackageParserException` whose `error` field is `-103` (`INSTALL_PARSE_FAILED_NO_CERTIFICATES`), `-104` (`INSTALL_PARSE_FAILED_INCONSISTENT_CERTIFICATES`), or `-105` (`INSTALL_PARSE_FAILED_CERTIFICATE_ENCODING`), CorePatch checks that `apkFile` is a valid ZIP archive containing `AndroidManifest.xml`.
   - If valid, it clears the thrown exception and populates `pkg.mCertificates`, `pkg.mSignatures`, and `pkg.mSigningKeys` (`android.util.ArraySet<PublicKey>`) with a synthetic self-signed X.509 certificate embedded in `CorePatch.java`, logging:
     `CorePatch SDK25: injected dummy cert for <filename> (err=<code)>`.
3. **`PackageManagerService` hooks (`system_server`):**
   - `systemReady()` (confirmation log)
   - `checkDowngrade(Package, PackageSetting)` (returns `null` when `downgr` is enabled)
   - `verifySignaturesLP(...)` (returns `true` when `digestCreak` or `authcreak` is enabled)
   - `compareSignatures(Signature[], Signature[])` (returns `SIGNATURE_MATCH` = `0` when enabled)
   - `compareSignaturesCompat(...)` and `compareSignaturesRecover(...)` (returns `SIGNATURE_MATCH` = `0` when enabled)

---

## 4. Android 7.1.2 `user_de` Storage Split (`ro.crypto.state=unsupported`)

**Evidence:** **Verified**.

Android 7.0 introduced Direct Boot with separate Device-Encrypted (`/data/user_de/0/<pkg>`) and Credential-Encrypted (`/data/data/<pkg>` / `/data/user/0/<pkg>`) directories.

- Xposed Framework v89 declares `requires:fbe_aware=1` in its installer metadata and compiles `XposedBridge.jar` to read module lists and write logs under `/data/user_de/0/de.robv.android.xposed.installer/`.
- Even though VPhoneOS sets `ro.crypto.state=unsupported`, `/data/user_de/0/de.robv.android.xposed.installer` and `/data/data/de.robv.android.xposed.installer` exist as **separate directories with distinct inodes**:
  - Runtime module loader reads: `/data/user_de/0/de.robv.android.xposed.installer/conf/modules.list`
  - Runtime log output writes: `/data/user_de/0/de.robv.android.xposed.installer/log/error.log`
  - Installer UI checkbox state lives at: `/data/data/de.robv.android.xposed.installer/shared_prefs/enabled_modules.xml`

Updating only `/data/data/.../conf/modules.list` causes Xposed to load zero modules on reboot. Both directories must be kept in sync.

---

## 5. SELinux `Enforcing` Compatibility Without Magisk

**Evidence:** **Verified**.

Many legacy Android 7 guides recommend setting SELinux to `Permissive` or relying on Magisk's `sepolicy` injection. Neither is needed on VPhoneOS Android 7.1.2 when file contexts are applied properly:

| Path | Required SELinux Context | Required Mode |
|---|---|---|
| `/system/bin/app_process32_xposed`, `/system/bin/app_process64_xposed` | `u:object_r:zygote_exec:s0` | `0755` (`0:2000`) |
| `/system/bin/dex2oat`, `/system/bin/patchoat` | `u:object_r:dex2oat_exec:s0` | `0755` (`0:2000`) |
| `/system/bin/oatdump` | `u:object_r:system_file:s0` | `0755` (`0:2000`) |
| `/system/framework/XposedBridge.jar`, `/system/xposed.prop`, `/system/lib*/lib*.so` | `u:object_r:system_file:s0` | `0644` (`0:0`) |
| `/data/user_de/0/de.robv.android.xposed.installer/conf/modules.list` | `u:object_r:app_data_file:s0` | `0644` (installer UID:GID) |
| `/data/data/com.coderstory.toolkit/shared_prefs/conf.xml.xml` | `u:object_r:app_data_file:s0` | `0644` (CorePatch UID:GID) |

Under these labels, VPhoneOS boots cleanly with `getenforce` returning `Enforcing`, Xposed logs `SELinux enabled: yes, enforcing: yes` in both Zygotes, and `logcat` reports zero `avc: denied` errors.

---

## 6. Post-Flash ART `BackgroundDexOptService` Contention

**Evidence:** **Verified**.

Replacing stock `/system/lib{,64}/libart.so` and `libart-compiler.so` with Xposed's ART binaries invalidates or triggers background re-compilation of installed packages by `BackgroundDexOptService`.

- On the tested VPhoneOS instance, `dex2oat --compiler-filter=speed` started compiling `com.google.android.gms` (`arm` first, which hit ART's 570-second watchdog timeout at `art/dex2oat/dex2oat.cc:461`, immediately followed by `arm64`).
- While `installd` executes `dex2oat` under `PackageManagerService.mInstallLock`, concurrent `adb install` commands block at `Performing Streamed Install` with an empty `vmdl*.tmp/base.apk`.
- Terminating only the stalled GMS `dex2oat` child process released the lock immediately and allowed `adb install` to complete with `Success` in roughly 30 seconds.

        @Override

    private X509Certificate fakeCertificate;

    @Override
    public void initZygote(StartupParam startupParam) {
        initFakeIdentity();
        hookPackageParser();
        hookCryptoVerifiers();
        XposedBridge.log("CorePatch SDK25: initZygote initialized");
    }

    @Override
    public void handleLoadPackage(XC_LoadPackage.LoadPackageParam lpparam) {
        if (!"android".equals(lpparam.packageName) || !"android".equals(lpparam.processName)) {
            return;
        }
        hookPackageManagerService(lpparam.classLoader);
        XposedBridge.log("CorePatch SDK25: system_server hooks installed");

    private void initFakeIdentity() {
        try {
            byte[] certBytes = hexToBytes(FAKE_CERT_HEX);
            CertificateFactory factory = CertificateFactory.getInstance("X.509");
            X509Certificate cert = (X509Certificate) factory.generateCertificate(new ByteArrayInputStream(certBytes));
            fakeCertificate = cert;
            fakeSignature = new Signature(cert.getEncoded());
            fakePublicKey = cert.getPublicKey();
        } catch (Throwable t) {
            XposedBridge.log("CorePatch SDK25: failed to init fake identity");
            XposedBridge.log(t);
        }
    }

    private void hookPackageParser() {
        Class<?> packageParserClass = findClassSafe("android.content.pm.PackageParser", null);
        if (packageParserClass == null) {
            XposedBridge.log("CorePatch SDK25: PackageParser not found");
            return;
        }

        // Hook only collectCertificates(Package, File, int); both parseApkLite and collectCertificatesInternal call it.
        XC_MethodHook collectHook = new XC_MethodHook() {
            @Override
            protected void beforeHookedMethod(MethodHookParam param) {
                COLLECT_DEPTH.set(COLLECT_DEPTH.get() + 1);
            }

            @Override
            protected void afterHookedMethod(MethodHookParam param) {
                try {
                    if (param.hasThrowable() && isPrefEnabled("authcreak", true)) {
                        maybeRecoverUnsignedPackage(param);
                    }
                } finally {
                    int depth = COLLECT_DEPTH.get();
                    COLLECT_DEPTH.set(Math.max(0, depth - 1));
                }
            }
        };

        int hookedCount = 0;
        for (Method method : packageParserClass.getDeclaredMethods()) {
            if ("collectCertificates".equals(method.getName()) && method.getParameterTypes().length == 3) {
                XposedBridge.hookMethod(method, collectHook);
                hookedCount++;
            }
        }
        if (hookedCount == 0) {
            XposedBridge.log("CorePatch SDK25: failed to hook 3-arg PackageParser.collectCertificates");
        }
    }

    private void hookCryptoVerifiers() {
        hookAllMethodsSafe("java.security.MessageDigest", null, "isEqual", new XC_MethodHook() {

        hookAllMethodsSafe("java.security.Signature", null, "verify", new XC_MethodHook() {
            @Override
            protected void beforeHookedMethod(MethodHookParam param) {
                if (isInCollectCertificates() && isPrefEnabled("authcreak", true)) {

                }
            }
        });

        hookAllMethodsSafe("com.android.org.conscrypt.OpenSSLSignatureRawRSA", null, "engineVerify", engineVerifyHook);

        hookAllConstructorsSafe("android.util.jar.StrictJarVerifier", null, new XC_MethodHook() {

    private void hookPackageManagerService(ClassLoader classLoader) {
        Class<?> pmsClass = findClassSafe("com.android.server.pm.PackageManagerService", classLoader);

            @Override
            protected void beforeHookedMethod(MethodHookParam param) {

                    // Return early instead of zeroing Package.mVersionCode in memory.
                    param.setResult(null);
                }

                    return;
                }
                if (param.args != null && param.args.length >= 1 && !allowDifferentSig) {
                    if (isPlatformSignedSetting(param.args[0])) {
                        return;
                    }
                }
                param.setResult(null);
            }
        });

        hookAllMethodsSafe(pmsClass, "compareSignatures", new XC_MethodHook() {
            @Override
            protected void beforeHookedMethod(MethodHookParam param) {
                if (!isPrefEnabled("zipauthcreak", false)) {
                    return;
                }
                if (param.args == null || param.args.length < 2) {
                    return;
                }
                Signature[] first = (Signature[]) param.args[0];
                Signature[] second = (Signature[]) param.args[1];
                if (first == null || second == null) {
                    return;
                }
                if (containsPlatformSignature(first) || containsPlatformSignature(second)) {
                    return;
                }
                param.setResult(PackageManager.SIGNATURE_MATCH);
            }
        });

            @Override

                    }
                    param.setResult(PackageManager.SIGNATURE_MATCH);

            }
        };
        hookAllMethodsSafe(pmsClass, "compareSignaturesCompat", compatRecoverHook);
        hookAllMethodsSafe(pmsClass, "compareSignaturesRecover", compatRecoverHook);
    }

    private void maybeRecoverUnsignedPackage(XC_MethodHook.MethodHookParam param) {
        if (fakeCertificate == null || fakeSignature == null || fakePublicKey == null) {
            return;
        }
        int err = extractPackageParserError(param.getThrowable());
        if (err != INSTALL_PARSE_FAILED_NO_CERTIFICATES
                && err != INSTALL_PARSE_FAILED_INCONSISTENT_CERTIFICATES
                && err != INSTALL_PARSE_FAILED_CERTIFICATE_ENCODING) {
            return;
        }
        if (param.args == null || param.args.length < 2 || param.args[0] == null || !(param.args[1] instanceof File)) {
            return;
        }
        Object pkg = param.args[0];
        File apkFile = (File) param.args[1];
        if (!hasAndroidManifest(apkFile)) {
            return;
        }

        if (XposedHelpers.getObjectField(pkg, "mCertificates") == null || err == INSTALL_PARSE_FAILED_INCONSISTENT_CERTIFICATES) {
            XposedHelpers.setObjectField(pkg, "mCertificates", new Certificate[][]{new Certificate[]{fakeCertificate}});
            XposedHelpers.setObjectField(pkg, "mSignatures", new Signature[]{fakeSignature});
            ArraySet<PublicKey> keys = new ArraySet<>(1);
            keys.add(fakePublicKey);
            XposedHelpers.setObjectField(pkg, "mSigningKeys", keys);
        }
        XposedBridge.log("CorePatch SDK25: injected dummy cert for " + apkFile.getName() + " (err=" + err + ")");
        param.setResult(null);
    }

    private int extractPackageParserError(Throwable throwable) {
        Class<?> ppeClass = findClassSafe("android.content.pm.PackageParser$PackageParserException", null);
        if (ppeClass == null) {
            return 0;
        }
        for (Throwable cur = throwable; cur != null; cur = cur.getCause()) {
            if (ppeClass.isInstance(cur)) {
                try {
                    return XposedHelpers.getIntField(cur, "error");
                } catch (Throwable ignored) {
                    return 0;
                }
            }
        }
        return 0;
    }

    private static boolean hasAndroidManifest(File apkFile) {
        if (!apkFile.isFile()) {
            return false;
        }
        try (ZipFile zf = new ZipFile(apkFile)) {
            return zf.getEntry("AndroidManifest.xml") != null;
        } catch (Throwable t) {
            return false;
        }
    }

    private void loadPlatformSignatures(Object pms) {
        try {
            PackageInfo info = (PackageInfo) XposedHelpers.callMethod(pms, "getPackageInfo", "android", PackageManager.GET_SIGNATURES, 0);
            if (info != null && info.signatures != null) {
                platformSignatures = new HashSet<>(Arrays.asList(info.signatures));
            }
        } catch (Throwable t) {
            XposedBridge.log("CorePatch SDK25: failed to read platform signatures");
            XposedBridge.log(t);
        }
    }

    private boolean isPlatformSignedSetting(Object pkgSetting) {
        if (pkgSetting == null || platformSignatures == null) {
            return false;
        }
        try {
            Object pkgSigs = XposedHelpers.getObjectField(pkgSetting, "signatures");
            if (isPlatformSignedPackageSignatures(pkgSigs)) {
                return true;
            }
            Object sharedUser = XposedHelpers.getObjectField(pkgSetting, "sharedUser");
            if (sharedUser != null) {
                Object sharedSigs = XposedHelpers.getObjectField(sharedUser, "signatures");
                return isPlatformSignedPackageSignatures(sharedSigs);
            }
            return false;
        } catch (Throwable ignored) {
            return false;
        }
    }

    private boolean isPlatformSignedPackageSignatures(Object pkgSigs) {
        if (pkgSigs == null || platformSignatures == null) {
            return false;
        }
        try {
            Signature[] sigs = (Signature[]) XposedHelpers.getObjectField(pkgSigs, "mSignatures");
            return containsPlatformSignature(sigs);
        } catch (Throwable ignored) {
            return false;
        }
    }

    private boolean containsPlatformSignature(Signature[] sigs) {
        Set<Signature> plat = platformSignatures;
        if (sigs == null || plat == null) {
            return false;
        }
        for (Signature sig : sigs) {
            if (sig != null && plat.contains(sig)) {
                return true;
            }
        }
        return false;
    }

    private static boolean isInCollectCertificates() {
        Integer depth = COLLECT_DEPTH.get();
        return depth != null && depth > 0;
    }

    private static byte[] hexToBytes(String hex) {
        int len = hex.length();
        byte[] out = new byte[len / 2];
        for (int i = 0; i < len; i += 2) {
            int hi = Character.digit(hex.charAt(i), 16);
            int lo = Character.digit(hex.charAt(i + 1), 16);
            out[i / 2] = (byte) ((hi << 4) + lo);
        }
        return out;
    }

package toolkit.coderstory;

import java.util.Set;

import de.robv.android.xposed.XC_MethodHook;
import de.robv.android.xposed.XSharedPreferences;
import de.robv.android.xposed.XposedBridge;
import de.robv.android.xposed.XposedHelpers;

/** Base Xposed helper providing shared-preference access and safe reflection hooking. */
public class XposedHelper {
    // MainActivity writes preferences to "conf.xml" (conf.xml.xml); match that exact filename.
    protected final XSharedPreferences prefs = new XSharedPreferences("com.coderstory.toolkit", "conf.xml");

    {
        prefs.makeWorldReadable();
        prefs.reload();
    }

    /** Reloads preferences on change and returns a boolean preference flag. */
    protected boolean isPrefEnabled(String key, boolean defaultValue) {
        if (prefs.hasFileChanged()) {
            prefs.reload();
        }
        return prefs.getBoolean(key, defaultValue);
    }

    /** Resolves a class without throwing ClassNotFoundError. */
    public static Class<?> findClassSafe(String className, ClassLoader classLoader) {
        try {
            return Class.forName(className, false, classLoader);
        } catch (Throwable t) {
            return null;
        }
    }

    /** Hooks all overloads of a method by class name, logging unexpected errors. */
    public static void hookAllMethodsSafe(String className, ClassLoader classLoader, String methodName, XC_MethodHook callback) {
        Class<?> clazz = findClassSafe(className, classLoader);
        if (clazz == null) {
            XposedBridge.log("CorePatch: class not found for hook: " + className + "#" + methodName);
            return;
        }
        hookAllMethodsSafe(clazz, methodName, callback);
    }

    /** Hooks all overloads of a method on a resolved class. */
    public static void hookAllMethodsSafe(Class<?> clazz, String methodName, XC_MethodHook callback) {
        if (clazz == null) {
            return;
        }
        try {
            Set<XC_MethodHook.Unhook> hooks = XposedBridge.hookAllMethods(clazz, methodName, callback);
            if (hooks == null || hooks.isEmpty()) {
                XposedBridge.log("CorePatch: no methods hooked for " + clazz.getName() + "#" + methodName);
            }
        } catch (Throwable t) {
            XposedBridge.log(t);
        }
    }

    /** Hooks all constructors of a class by name. */
    public static void hookAllConstructorsSafe(String className, ClassLoader classLoader, XC_MethodHook callback) {
        Class<?> clazz = findClassSafe(className, classLoader);
        if (clazz == null) {
            XposedBridge.log("CorePatch: class not found for ctor hook: " + className);
            return;
        }
        try {
            XposedBridge.hookAllConstructors(clazz, callback);
        } catch (Throwable t) {
            XposedBridge.log(t);
        }
    }
}

#!/usr/bin/env bash
# Pulls unmodified stock ART and Zygote binaries plus SELinux context metadata from the guest.
# Read-only on the guest; writes locally to <BACKUP_DIR>.
# Usage: ./scripts/backup-stock-system.sh [-s <DEVICE_ID>] [BACKUP_DIR]

set -euo pipefail
source "$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)/common.sh"

parse_common_args "$@"
resolve_adb_device

BACKUP_DIR="${REMAINING_ARGS[0]:-$REPO_ROOT/backups/stock-$(date +%Y%m%d-%H%M%S)}"
mkdir -p "$BACKUP_DIR/system/bin" "$BACKUP_DIR/system/lib" "$BACKUP_DIR/system/lib64"

if adb_run shell '[ -f /system/xposed.prop ]' >/dev/null 2>&1; then
  log_warn "/system/xposed.prop already exists on the guest. Pulled files may already be Xposed-modified."
fi

FILES=(
  /system/bin/app_process32
  /system/bin/app_process64
  /system/bin/dex2oat
  /system/bin/oatdump
  /system/bin/patchoat
  /system/lib/libart.so
  /system/lib/libart-compiler.so
  /system/lib/libart-disassembler.so
  /system/lib/libsigchain.so
  /system/lib64/libart.so
  /system/lib64/libart-compiler.so
  /system/lib64/libart-disassembler.so
  /system/lib64/libsigchain.so
)

log_info "Pulling stock /system files into $BACKUP_DIR..."
pulled=0
for f in "${FILES[@]}"; do
  if adb_run shell "[ -e '$f' ]" </dev/null; then
    adb_run pull "$f" "$BACKUP_DIR$f" >/dev/null
    pulled=$((pulled + 1))
  else
    log_info "Skipping absent file on guest: $f"
  fi
done

adb_run shell 'ls -lZ /system/bin/app_process* /system/bin/dex2oat /system/bin/oatdump /system/bin/patchoat /system/lib/libart* /system/lib/libsigchain.so /system/lib64/libart* /system/lib64/libsigchain.so 2>&1 || true' \
  > "$BACKUP_DIR/stock_ls_lZ.txt"

(
  cd "$BACKUP_DIR"
  find system -type f | sort | while IFS= read -r rel; do
    printf '%s  %s\n' "$(sha256_file "$rel")" "$rel"
  done
) > "$BACKUP_DIR/stock_sha256.txt"

log_info "Backed up $pulled files to $BACKUP_DIR."
log_info "Checksums saved to $BACKUP_DIR/stock_sha256.txt and labels to $BACKUP_DIR/stock_ls_lZ.txt."

`scripts/common.sh`:

```sh
#!/usr/bin/env bash
# Shared portable helpers for VPhoneOS Android 7.1.2 Xposed + CorePatch scripts.
# Never hardcodes device serials, IP addresses, ports, or user home paths.

set -euo pipefail

SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)"
REPO_ROOT="$(cd -- "$SCRIPT_DIR/.." && pwd)"

ADB_TARGET="${ADB_SERIAL:-}"
AUTO_YES="${AUTO_YES:-0}"

log_info() { printf '[INFO] %s\n' "$*"; }
log_warn() { printf '[WARN] %s\n' "$*" >&2; }
log_err()  { printf '[ERROR] %s\n' "$*" >&2; }

require_cmd() {
  local cmd="$1"
  if ! command -v "$cmd" >/dev/null 2>&1; then
    log_err "Required command not found in PATH: $cmd"
    exit 1
  fi
}

sha256_file() {
  local file="$1"
  if command -v sha256sum >/dev/null 2>&1; then
    sha256sum "$file" | awk '{print $1}'
  elif command -v shasum >/dev/null 2>&1; then
    shasum -a 256 "$file" | awk '{print $1}'
  else
    log_err "Neither sha256sum nor shasum is available."
    exit 1
  fi
}

parse_common_args() {
  REMAINING_ARGS=()
  while [ "$#" -gt 0 ]; do
    case "$1" in
      -s|--serial)
        if [ "$#" -lt 2 ]; then
          log_err "Missing value for $1"
          exit 1
        fi
        ADB_TARGET="$2"
        shift 2
        ;;
      -y|--yes)
        AUTO_YES=1
        shift
        ;;
      *)
        REMAINING_ARGS+=("$1")
        shift
        ;;
    esac
  done
}

resolve_adb_device() {
  require_cmd adb

  if [ -n "$ADB_TARGET" ]; then
    local state
    state="$(adb -s "$ADB_TARGET" get-state 2>/dev/null || true)"
    if [ "$state" != "device" ]; then
      log_err "ADB target '$ADB_TARGET' is not reachable or not in 'device' state (got: '${state:-none}')."
      log_err "Check wireless/USB ADB in VPhoneOS and reconnect (for example: adb connect <HOST_IP>:<PORT>)."
      exit 2
    fi
    log_info "Using specified ADB target: $ADB_TARGET"
    return 0
  fi

  local devices=()
  while IFS= read -r line; do
    [ -n "$line" ] && devices+=("$line")
  done < <(adb devices | awk 'NR>1 && $2=="device" {print $1}')

  if [ "${#devices[@]}" -eq 0 ]; then
    log_err "No reachable ADB devices detected."
    log_err "Enable ADB inside VPhoneOS, connect it (adb connect <HOST_IP>:<PORT>), or pass -s <DEVICE_ID>."
    exit 2
  elif [ "${#devices[@]}" -gt 1 ]; then
    log_err "Multiple ADB devices detected; refusing to guess:"
    printf '  - %s\n' "${devices[@]}" >&2
    log_err "Re-run with -s <DEVICE_ID> or set ADB_SERIAL=<DEVICE_ID>."
    exit 3
  fi

  ADB_TARGET="${devices[0]}"
  log_info "Auto-detected single ADB target: $ADB_TARGET"
}

adb_run() {
  adb -s "$ADB_TARGET" "$@"
}

adb_root_sh() {
  local cmd="$1"
  adb -s "$ADB_TARGET" shell "su -c '$cmd'"
}

confirm_action() {
  local prompt="$1"
  if [ "$AUTO_YES" = "1" ]; then
    log_info "Proceeding without interactive prompt (--yes): $prompt"
    return 0
  fi
  if [ ! -t 0 ]; then
    log_err "Refusing destructive/modifying action in non-interactive shell without --yes."
    exit 1
  fi
  printf '%s [y/N]: ' "$prompt"
  local reply=""
  read -r reply
  case "$reply" in
    y|Y|yes|YES) return 0 ;;
    *)
      log_info "Cancelled by user."
      exit 0
      ;;
  esac
}

    log_err "CorePatch_sdk25_patched.apk did not verify under v2 scheme"
    exit 1
  fi
  if ! printf '%s\n' "$CP_OUT" | grep -qi "$EXPECTED_COREPATCH_CERT_SHA256"; then
    log_err "CorePatch_sdk25_patched.apk certificate SHA-256 mismatch!"
    exit 1
  fi
  log_info "CorePatch_sdk25_patched.apk verified (v1 + v2, SHA-256 matches)."
elif command -v keytool >/dev/null 2>&1; then
  log_warn "apksigner not found; falling back to keytool certificate inspection."
  XI_KT="$(keytool -printcert -jarfile "$REPO_ROOT/resources/XposedInstaller_3.1.5.apk" 2>&1)"
  printf '%s\n' "$XI_KT" | grep -q "CN=rovo89" || { log_err "XposedInstaller CN=rovo89 not found"; exit 1; }
  log_info "keytool confirmed CN=rovo89 on XposedInstaller_3.1.5.apk."
else
  log_warn "Neither apksigner nor keytool found; skipped APK certificate check (SHA-256 checksums already verified)."
fi

log_info "All resource verification checks passed."

#!/usr/bin/env bash
# Read-only verification of Xposed Framework v89, Xposed Installer 3.1.5, CorePatch SDK 25,
# SELinux status, and optional local check that a candidate test APK is genuinely unsigned.
# Usage: ./scripts/verify-setup.sh [-s <DEVICE_ID>] [--test-apk <PATH_TO_UNSIGNED_APK>]

set -euo pipefail
source "$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)/common.sh"

TEST_APK=""
FILTERED_ARGS=()
while [ "$#" -gt 0 ]; do
  case "$1" in
    --test-apk)
      [ "$#" -ge 2 ] || { log_err "Missing path for --test-apk"; exit 1; }
      TEST_APK="$2"
      shift 2
      ;;
    *)
      FILTERED_ARGS+=("$1")
      shift
      ;;
  esac
done

parse_common_args "${FILTERED_ARGS[@]}"
resolve_adb_device

log_info "Running read-only setup verification on $ADB_TARGET..."

adb_run shell 'su -c "
echo \"=== 1. Xposed Framework Files & Symlinks ===\"
cat /system/xposed.prop 2>&1 || true
ls -lZ /system/bin/app_process /system/bin/app_process32 /system/bin/app_process32_xposed /system/bin/app_process64 /system/bin/app_process64_xposed /system/framework/XposedBridge.jar /system/lib/libxposed_art.so /system/lib64/libxposed_art.so 2>&1 || true

echo \"=== 2. SELinux Status ===\"
getenforce 2>&1 || true

echo \"=== 3. Active Zygote Mappings ===\"
for proc in zygote64 zygote; do
  p=\"\$(pidof \"\$proc\" 2>/dev/null || ps | grep -E \" \$proc\$\" | sed -n \"s/^[^ ]* *\\([0-9][0-9]*\\).*/\\1/p\" | head -n 1)\"
  if [ -n \"\$p\" ]; then
    echo \"-- \$proc (PID \$p) --\"
    grep -E \"app_process|libxposed_art|XposedBridge\" \"/proc/\$p/maps\" | sed \"s/.* \\//\\//\" | sort -u || true
  fi
done

echo \"=== 4. Installed Packages & Module Config ===\"
dumpsys package de.robv.android.xposed.installer | grep -E \"versionCode|versionName\" | head -n 2 || true
dumpsys package com.coderstory.toolkit | grep -E \"versionCode|versionName\" | head -n 2 || true
echo \"modules.list:\"
cat /data/user_de/0/de.robv.android.xposed.installer/conf/modules.list 2>&1 || true
echo \"CorePatch prefs permissions:\"
ls -laZ /data/data/com.coderstory.toolkit/shared_prefs/conf.xml.xml 2>&1 || true

echo \"=== 5. Xposed Log Verification (error.log) ===\"
grep -E \"Starting Xposed|SELinux enabled|Loading modules|Loading class|CorePatch SDK25\" /data/user_de/0/de.robv.android.xposed.installer/log/error.log 2>&1 || true

echo \"=== 6. Recent SELinux AVC Denials ===\"
avc=\"\$(logcat -d | grep -i \"avc: denied\" | tail -n 10 || true)\"
if [ -n \"\$avc\" ]; then
  echo \"\$avc\"
else
  echo \"(none found in current logcat buffer)\"
fi
"'

if [ -n "$TEST_APK" ]; then
  echo ""
  log_info "Checking that local test APK is genuinely unsigned: $TEST_APK"
  if [ ! -f "$TEST_APK" ]; then
    log_err "Test APK not found: $TEST_APK"
    exit 1
  fi
  if command -v apksigner >/dev/null 2>&1; then
    if apksigner verify --verbose "$TEST_APK" 2>&1; then

    else
      log_info "Confirmed unsigned: apksigner rejected the test APK as expected."
    fi
  else
    if unzip -l "$TEST_APK" | grep -qE 'META-INF/(MANIFEST\.MF|.*\.(SF|RSA|DSA|EC))$'; then
      log_warn "Test APK contains META-INF signature entries."
    else
      log_info "Confirmed no META-INF v1 signature files present (install apksigner for full v1/v2/v3 verification)."
    fi
  fi
fi

log_info "Read-only verification complete."
