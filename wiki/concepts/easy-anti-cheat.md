# Easy Anti-Cheat

Epic’s Easy Anti-Cheat (EAC): multi-component architecture with service, kernel driver, and game-facing protections—process integrity, memory inspection, and runtime driver loading with strong client-side enforcement. Used by titles such as Fortnite, Apex Legends, and Rust. (source: wiki/sources/skills/anti-cheat.md)

## Research angles

Callback/handle surfaces ([[kernel-callbacks]]), memory/manual-map detection, driver trust and [[byovd]] blocklists, interaction with [[hvci]]/DSE, and DMA detection pipelines shared with other modern ACs.

Kernel-module integrity: historical PoC [[cveac-2020]] (WDK driver) targets an EAC kernel vulnerability with module enum, PE parse, hooks, and runtime code manipulation—Integrity Checks research lane. (source: wiki/sources/descriptions/thesecretclub__CVEAC-2020.md) Driver self-integrity analysis such as [[bypassing-easyanticheat-integrity-check]] (gmh5225; CreateProcess/LoadImage notify validation of EAC driver sections; Capstone garbage-instruction deobfuscator; reconstructed C++ section-by-section compare against stored driver copy; Bypassing integrity check lane) documents how EAC protects its own `.sys` image from tamper. (source: wiki/sources/descriptions/gmh5225__Bypassing-EasyAntiCheat-Integrity-check.md) Call-hierarchy abuse PoCs such as [[hiearchy-eac]] (Sinclairq; kernel driver PoC; hooks verification routines to redirect reads toward a cleaned image copy; module-load monitoring + EAC driver boundary tracking; stack/register spoofing during integrity accesses; Integrity Checks lane) study a complementary bypass surface beside static section comparison. (source: wiki/sources/descriptions/Sinclairq__hiearchy-eac.md)

Overlay / screenshot monitoring is another research surface: PoCs such as [[eac-overlay]] explore alternate rendering surfaces or window manipulation to draw ESP without tripping EAC overlay detection. (source: wiki/sources/descriptions/xBrunoMedeiros__eac-overlay.md)

Server-side / EOS session lane: leaked EAC server implementations such as [[eac-leak]] (chaeyk; C++ server + EOS SDK; anti-cheat session handling; game-server ↔ EAC cloud validation protocol RE) complement client-side reversed-source archives by exposing how dedicated servers register and validate sessions through Epic Online Services. (source: wiki/sources/descriptions/chaeyk__eac-leak.md)

Client-interface stub lane: x64 DLL emulators such as [[eac-emu]] (Rat431; exports expected EAC anti-cheat API functions with placeholder implementations; C++ plus assembly patch helpers; PoC for RE and compatibility testing of software linking against EAC components) let researchers exercise client integration surfaces without loading the real module—complementary to VAC-side emulators such as [[vac-emulator]]. (source: wiki/sources/descriptions/Rat431__EAC_Emu.md)

Static RE prep: utilities such as [[eac-extractor-utility]] locate EAC components in game directories and the Windows driver store, decrypt/extract the kernel driver, user-mode modules, and configuration for offline binary analysis. (source: wiki/sources/descriptions/lguilhermee__EAC-Extractor-Utility.md) Runtime capture samples such as [[eac-runtime-extractor]] (gmh5225; MinHook on file I/O + driver-load paths; dumps the EAC kernel driver from memory before it touches disk) complement disk-based extraction when studying the live driver load pipeline. (source: wiki/sources/descriptions/gmh5225__EAC-Runtime-Extractor.md) Reversed-source archives such as [[eazy-anti-cheat-src]] (gmh5225; reimplemented detection routines, driver communication, and integrity validation from EAC binary analysis; cheat / explore anticheat:eac [Reversed Source]) and [[eac-easyanticheat-src-1]] (gmh5225; reconstructed/leaked EAC components with internal detection routines, driver communication protocols, and client-side integrity validation) complement extraction with readable source-level structure for offline study. (source: wiki/sources/descriptions/gmh5225__EazyAntiCheatSRC.md) (source: wiki/sources/descriptions/gmh5225__EAC-EasyAntiCheat-Src-1.md) Raw IDA decompilation dumps such as [[easyanticheat-reversing]] (gmh5225; IDA Pro 7.7 export of `EasyAntiCheat.sys`; searchable C-like driver output with registry strings and policy routines) provide text-searchable driver logic without reopening the IDB. (source: wiki/sources/descriptions/gmh5225__EasyAntiCheat-Reversing.md) Mixed study bundles such as [[eac]] (gmh5225; reversed `easyanticheat.sys` callback logic—driver dispatch validation, Process Hacker detection, blacklisted-driver checks, `ntoskrnl` patch scanning, driver hashing—plus EAC/EOS SDK binaries, headers, and `EOS_FileDecryptionTool`) pair callback-focused reversed driver source with integration artifacts beside pure decompile dumps. (source: wiki/sources/descriptions/gmh5225__EAC.md) Updated devirtualized driver internals such as [[eac-reversal]] (ch4ncellor; reversed callback checks, driver dispatch verification, callback enumeration, certificate validation, and code integrity routines as C++ pseudocode from the devirtualized EAC binary; builds on VMP2 devirtualization and community EAC analysis) provide a maintained reference for kernel-mode detection and driver validation study. (source: wiki/sources/descriptions/ch4ncellor__EAC-Reversal.md) Raw shellcode memory dumps such as [[eac-shellcode-1]] (gmh5225; ~8.5 MB `shellcode_size0x82C000.mem` from a protected-game dumper ~Mar 2023; hook entry points at base+0x79204 and base+0x79304) supply offline sample material for EAC user-mode shellcode layout and hook-driven execution flow. (source: wiki/sources/descriptions/gmh5225__EAC-shellcode-1.md) Recovered driver assembly such as [[eac-vmcheck-asm]] (gmh5225; `vmCheck.asm` from `easyanticheat.sys` `vm` directory; `CheckVM` → `ExecVMREAD` VMREAD probe with VM-found / VM-not-found branches) preserves exact EAC virtualization-check control flow for offline RE. (source: wiki/sources/descriptions/gmh5225__EAC-VmCheck.asm.md)

HWID / hardware-fingerprint lane: open-source kernel HWID spoofer reference [[eac-spoofer-meme]] (zensenzay; C kernel driver + C++ usermode controller via custom IOCTLs; rewrites SMBIOS, disk/NVMe serials, MAC, GPU/PCI IDs, CPUID via VT-x/SVM mini-hypervisors, EFI/ACPI, and registry machine IDs; disk I/O completion hooks and registry PCI/USB alias redirection; optional artifact cleanup—studies how EAC-class ACs collect hardware fingerprints and kernel-level evasion) complements runtime bypass samples. (source: wiki/sources/descriptions/zensenzay__eac-spoofer-meme.md)

Offensive bypass lane: repos such as [[eac-bypass]] explore kernel driver and shader-based techniques to evade EAC runtime checks. (source: wiki/sources/descriptions/ksoju__Eac-Bypass.md) Debug-oriented PoCs such as [[eac-dbp]] (Schnocker; kernel driver + user-mode module; callback/minifilter/control-path interference + user-layer API interception; Visual Studio/WDK; controlled RE and security testing of EAC-protected processes; Debug lane) study how to attach debuggers and inspect EAC-protected game processes without tripping selected kernel enforcement paths. (source: wiki/sources/descriptions/Schnocker__EAC_dbp.md) Kernel driver UD samples such as [[eac-driver-ud-for-now]] (gmh5225; cross-process memory R/W via stealth KM↔UM channel; avoids EAC driver-scan and known kernel-cheat detection vectors; README `[Sample]`) study evasion of EAC's own-driver enumeration beside other stealth-I/O channels. (source: wiki/sources/descriptions/gmh5225__EAC-Driver-UD-for-now.md) Win32k syscall channels such as [[eac-bypass-1]] (`NtMapVisualRelativePoints`; C++ driver development; cheat / driver communication) study stealth KM↔UM I/O alongside EAC evasion. (source: wiki/sources/descriptions/gmh5225__eac-bypass-1.md) HalDispatchTable-backed `NtQueryIntervalProfile` control channels such as [[eac-injector-driver]] (manual-map driver; `CODE_DISABLE`/`CODE_RESTORE`; suspend/resume `EasyAntiCheat.sys` threads + temporary object-callback disable; DLL-injection workflow; gmh5225) extend that lane with syscall-backed EAC state toggling. (source: wiki/sources/descriptions/gmh5225__Eac-Injector-Driver.md) Kernel report-packet suppression samples such as [[eac-kernel-packet-fucker]] (gmh5225; hijacks EAC's dynamically imported `ExAllocatePoolWithTag` via a writable section pointer so ~33 KB kernel violation reports fail allocation and are discarded before backend upload) study how outbound EAC telemetry depends on pool allocation. (source: wiki/sources/descriptions/gmh5225__EAC-Kernel-Packet-Fucker.md) Hydra-channel hook samples such as [[eac-hydrahook]] (gmh5225; hooks EAC's Hydra kernel-to-usermode communication path to intercept and suppress detection reports before backend upload) study the KM↔UM Hydra transport separately from allocator sabotage. (source: wiki/sources/descriptions/gmh5225__EAC-HydraHook.md) Cheat Engine tool-detection bypass samples such as [[ce-easyanticheat-bypass]] patch or hide CE process, window class, driver, and memory-access signatures so scan/edit workflows run on EAC-protected games—useful for studying how EAC fingerprints common debugging tools. (source: wiki/sources/descriptions/gmh5225__ce-EasyAntiCheat-Bypass.md) Documented memory-signature corpora such as [[eac-easyanticheatmemorysig]] (gmh5225; byte patterns EAC scans for to identify known cheat frameworks, injectors, and hack modules in process memory) complement those evasion samples with the offensive fingerprint reference set. (source: wiki/sources/descriptions/gmh5225__EAC-EasyAntiCheatMemorySig.md)

CR3 / page-table root lane: minimal UM+KM teaching samples such as [[eac-cr3-bypass]] demonstrate bypassing EAC checks tied to CR3 via coordinated kernel driver + usermode code. (source: wiki/sources/descriptions/kprprivate__EAC-CR3-BYPASS.md) Compact research sample [[eac-cr3-shuffle]] (SamuelTulach; C++; physical memory range walking, directory-base discovery, VA→PA translation checks; reference material on CR3 shuffling complicating external memory inspection; cheat / Bypassing CR3 protection) focuses on EAC CR3-shuffle behavior for paging and anti-cheat internals study. (source: wiki/sources/descriptions/SamuelTulach__eac_cr3_shuffle.md) PFN-backed directory-base enumeration PoC [[enum-real-dirbase]] (Rythorndoran; C++ WDK driver; physical memory structures, kernel pattern scan, MmPfnDatabase walk; recovers real process CR3 for hidden/protected address-space study; cheat / Find real dirbase) complements shuffle-focused samples with low-level physical enumeration. (source: wiki/sources/descriptions/Rythorndoran__enum_real_dirbase.md)

Linux / Proton lane: Elden Ring CE tables such as [[elden-ring-ct-tga]] document protonhax launch + Wine-hosted Cheat Engine attach against Steam app `1245620`, with optional EAC launcher disable—useful for studying how EAC-protected titles behave under Proton-hosted cheat tooling. (source: wiki/sources/descriptions/inuNorii__Elden-Ring-CT-TGA.md)

Windows launcher lane: Elden Ring custom launcher samples such as [[eldenringlauncher]] (ImGui/SDL2 GUI; launch-parameter configuration; optional EAC bypass + mod loading) illustrate launcher-level [[easy-anti-cheat]] interface and bypass patterns on FromSoftware titles beside in-process cheat tooling. (source: wiki/sources/descriptions/gmh5225__EldenRingLauncher.md)

Modding coexistence lane: Ghost Recon Wildlands first-person camera mods such as [[ghost-recon-wildlands-first-person-no-eac]] (Firejumper93; `dxgi.dll` proxy + in-process memory writes on AnvilNext 2.0; deliberately does not disable or bypass EAC; studies how solo/co-op gameplay mods coexist with anti-cheat on current builds) contrast the offensive bypass lane—useful for modding policy and detection-boundary research rather than evasion tooling. (source: wiki/sources/descriptions/Firejumper93__Ghost-Recon-Wildlands-First-Person-No-EAC.md)

Fortnite internal lane: samples such as [[fortnite-triadz]] (Triadz; UE4 engine hooking; ESP / aimbot / exploitation; in-process game-object + render access) and updated Ritz forks such as [[fortnite-internal-updated-ritz]] (refreshed offsets + EAC bypass for newer builds) illustrate internal cheat architecture and EAC detection surfaces on EAC-protected UE4 titles. ZeroGui-overlay samples such as [[zerogui-fortnite-internal]] (visuals-only ESP enabled; aimbot / exploits disabled) narrow that lane to in-process render/visual study on Fortnite without full combat modules. Exploit-chain documentation such as [[fortnite-exploits]] (client vulns; UE4 features; EAC bypass for injection / memory access) complements those runnable samples for researchers mapping Fortnite-specific bypass paths. External Fortnite samples such as [[volto-external-spowar-ud-eac-be-fortnite-external-cheat]] (gmh5225; C/C++; kernel driver + overlay; HWID-spoof / EAC-evasion naming; out-of-process RPM), [[fortnite-ud-external]] (gmh5225; stealthy out-of-process memory reads; ESP / aimbot; BattlEye + EAC evasion framing), [[fortnite-cheato-ud-eac-be]] (JeanToBinks; C++; user-mode process memory reads + Unreal transform math + DirectX-style overlay; player structure extraction + entity visualization; cheat dev + EAC evasion research framing), and [[serenity-gg-fn-and-loader]] (gmh5225; C/C++; kernel driver + shader work + module loader) illustrate the complementary external lane on the same EAC-protected title.
